# 全模块授权接入契约（D-0027）

状态：实施前契约。不是已完成接口清单。资源及入口细目以本阶段人工核对后的闭合目录为准，不由旧 page key 自动生成。

## 模块接口

业务调用只依赖 `resource_access(db, identity, resource, action)`、返回的资源上下文和对象/查询计划。`identity` 必须是经验签并重查数据库的类型化主体，或服务器保存的受控委派；普通 `UserContext.role/permissions` 只可作领域适配输出，不能作为新授权输入。统一层负责当前实名主体、grant 校验、Cerbos、版本及故障处理；领域层负责可信关系与 ORM 绑定、字段用途和现行业务状态。HTTP、工具与任务调用同一受保护应用服务，不由工具 import HTTP handler。

| 数据 | 类型/含义 | 为什么需要 |
|---|---|---|
| principal | 稳定用户主键、用户名、当前登录版本及有效状态 | 不以旧 token 的 role/permissions 证明授权；用户名仅用于显示与审计兼容 |
| resource | 闭合目录中的稳定 snake_case ID | 同名列在不同业务合同中可以有不同含义，不能全局按列名推断 |
| action | 目录明确列出的读取、面板、导出或写入能力 | 读取不隐含写入；面板显示与实际 API 使用相同能力 |
| grant | 该用户/资源的一条动作、范围、信息组合及版本 | 保持范围与字段配对，不能将不同 grant 做笛卡尔积 |
| access | 不可变的领域上下文、字段决定及范围计划 | 每次从原始身份构造，不能修改共享 request ctx 后串到另一资源 |
| scope | 具名范围及可信关系来源；空集合与 all 分开 | 范围必须在 SQL 聚合/分页之前执行，NULL 与未知归属不能变成全量 |
| bindings | 由服务端领域代码提供的 ORM 列、关系与受控操作符 | 请求 JSON 不得指定 SQL、政策或任意字段表达式 |
| delegation | 服务器签发的主体主键、授权版本、任务用途及资源动作 | 排队工作不能沿用永久有效的旧 UserContext；每次执行边界重载 |

资源具有一条字段合同；不同信息粒度、不同对象集合和不同完整字段例外应拆资源。展示面可使用 `show_*` 动作，必须依赖其实际数据读取能力；后端按具名数据动作及范围/字段决定查询。纯图形切换明确继承同一信息能力，无须制造重复数据授权。跨资源页面只组合各自结果，不合并它们的权限。

展示关闭不隐含撤销同一信息在其他已授权视图中的读取权。例如概览与排行共用分组统计时，隐藏排行面板不会自动禁止概览读取分组数据；要禁止该类数据，必须撤销共同的 `read_groups` 能力。服务端不相信客户端传入的 tab 名作为数据授权依据。目录逐面板列出 `display_actions` 与 `data_requirements`，权限中心明确展示二者依赖。

数据服务相同不等于入口授权相同。原准入不同的池订单与公司看板池订单保留 `pool_order_facts` / `company_pool_order_facts` 独立 Grant，复用底层投影，迁移不能把两页旧资格 OR 成一个新允许集合。

## 能力与管理协议

现有销售端点在兼容期保留；新通用协议并行提供，前端切换后旧写端点必须转交同一写服务或显式退役，不维持两套写权限实现。

| 接口 | 契约 |
|---|---|
| `GET /api/authz/me` | 当前主体、catalog version、授权 epoch、所有已登记资源的实现/运行状态、逐动作 allow/deny/requires_context、范围类别、范围内信息组及拒绝原因；不返回 SQL、他人归属或全部项目 ID；no-store |
| `GET /api/authz/catalog` | 管理目录：资源/面板/动作中文标签、合法范围、字段及依赖、迁移状态、旧来源；未知资源不接受配置 |
| `GET /api/authz/users/{username}/modules` | 管理员读取该账号规范 Grant 包、资源版本、epoch、模板来源/快照和整资源个人调整；目标诊断不写入操作者能力缓存 |
| `PUT /api/authz/users/{username}/modules` | 提交 catalog version、expected epoch、逐资源 expected version 和完整资源替换；可显式携带客户关系变更，由同一事务编排；未提交资源保持原状；缺省不改共享关系 |
| `GET/PUT /api/authz/templates/{code}/modules` | 版本化规范 Grant 包；模板保存不修改已套用账号，管理员模板/最后管理员等既有保护保留 |
| `POST /api/authz/templates/{code}/sync` | dry-run 预览/指纹 → 明确执行；显示动作、范围和字段差异，复核目录/模板/所有目标版本；默认保留整资源个人调整，显式清除才恢复模板值 |

模板与个人调整采用完整资源配置覆盖，不能逐个合并 scope 和 fields。规范账号 Grant 是运行时唯一允许来源；模板快照/调整是编排来源元数据。所有写入必须经过同一个规范化服务：校验目录与依赖、读取实时管理员、按稳定主键锁住参与账号、复核版本、写 grant/来源/关系/审计、递增 epoch 后提交。先预检身份再取得完整锁集合，不能先锁自己再按不同顺序锁另一管理员。

完整覆盖的键存在性必须保存。显式覆盖即使恰与模板相等也不自动压缩；显式空 actions 是拒绝覆盖。`clear_override` 恢复账号已保存的模板快照，不能暗中追随最新模板。最新模板的同步预览绑定明确的稳定目标集合、目录/模板版本、目标 epoch、各资源版本、来源版本和覆盖存在性；执行时不纳入预览之后新加入的成员。仅来源变化且有效数值相等也递增用于预览冲突检查的版本。S0 中无法证明来源的已有 Grant 在导入来源元数据时按显式个人覆盖保存，不凭“恰好等于模板”猜继承关系。

快照每个资源的 `decisions` 映射为 `action → {effect, reason}`；未知动作不在 allow 集合，前端按 deny 处理。`requires_context` 不启用操作按钮：由现有对象 API 在确认稳定对象 ID、当前主体及 epoch、资源动作、对象版本和查询范围后返回对象 capabilities。对象决定不得跨对象/主体/epoch 复用；资源范围内字段列表不能被误用为任意项目的字段许可。

`PUT modules` 是显式资源 patch：未列出的资源保持；列出资源必须包含全部配置及 expected version；`actions=[]` 表示撤销该资源全部能力并保留递增版本的拒绝记录，防删除重建导致版本 ABA。空 updates 明确拒绝，不能被解释为删除全部或恢复默认。客户关系未提供则保持，提供空数组则清空；所有客户关系写入口必须锁住账号、复验 expected epoch 并递增 epoch。项目关系仍走既有项目版本/挂靠事务，领域访问每次读取当前关系；不能只凭账号 epoch 证明项目关系未变。

一般账号资料保存、新建/复制、模板指派、现有账号批量增减/套模板以及停用必须纳入该编排；迁移后提交旧布尔权限时不得返回“成功但新授权不变”。现有批量入口选择转交规范编排或显式退役，未接入时不保留旧布尔写入口作为第二个真值。与新授权有关的赋权只允许当前实名管理员，不从旧 account_manage 推导。新账号只有在显式应用模板/授权时获得能力。

普通资料字段与安全属性按实际用途划分：display_name 可按账号资料能力编辑；salesperson_name、角色资格、模板、授权包与客户关系必须交实时实名授权管理员。管理他人凭据 reset_password 也仅允许授权管理员；本人自助改密仍走既有入口。统一模式暂将仍被未迁域用作权限的 role/base_role 显示为只读，不把它们作为自由职位分类编辑。含安全属性的混合请求必须整体授权及提交，不能资料部分成功、权限部分静默忽略。

服务端明确返回 `authorization_mode`。默认 `legacy_compat` 保留未启用候选时的现行协议；`unified_modules` 使用规范授权编辑，旧 permissions/overrides/布尔 keys 改权请求整体拒绝，待实施资源只读。这个过渡状态不算完成迁移，也不靠前端猜测环境变量。新模式建号、模板 metadata 与模块包的保存必须采用同一服务器事务；批量授权不能由浏览器循环若干 PUT 代替。

统一模式的 apply/sync 仅替换规范授权包及 `authorization_profile` 中的新模板来源，不改既有 role 或旧 template_code/version/template_perms/perm_overrides 快照。前端新模板标签从新来源读取，不能拿旧模板列误报。新账号默认为非管理员 readonly 分类；显式创建/升降 admin 或更改销售人员映射属于独立受保护 security_change 命令，需实时管理员与预览/CAS，不能由套模板隐式触发。未迁域的旧行为因此不会在套用新模板时暗中变化；各域迁移仍按自己的执行定义和存量迁移切换。

锁序分为两类：纯授权管理按必要的管理员名册锁 → 模板稳定顺序 → 全部 actor/target 用户数值 ID 顺序 → Grant/客户关系；此路径不进入项目事务。领域写保持既有 state/project/assignment 等领域锁在先，再一次按数值 ID 取得 actor/target/owner 完整用户集合的最终所需锁强度，随后重验身份、Grant 和当前关系。HTTP 写依赖只做无锁预检，不能先持有用户共享锁再等待领域锁；不得事后追加更小 ID 或将共享锁升级为排他锁。任何拒绝回滚整个根事务，包括预备阶段可能创建的状态行。只读快照可在短事务内使用用户共享锁。

## 数据范围适配

1. `all` 仅表示该资源已定义的信息全集，不代表全站所有数据。库存汇总的内部销售计算不自动赋予销售明细读取权。
2. `assigned_customers` 使用 D-0026 的稳定客户关系；查询常量保持 ID 精度，条件进入每个事实查询。此范围不外推到没有客户归属合同的采购。
3. 维保分别命名目录、汇总、直达详情、完整工作簿、仓库操作的项目集合。复用现有稳定 project_id、有效 manager/viewer 挂靠和 canonical salesperson 语义；保留旧字符串销售关系不等于已经完成其主键化治理。
4. 若同一用户的普通字段可以看全项目、完整金额只能看本项目，应由两个资源合同分别查询/授权。不能在一个 UserContext 上取最大字段集合。
5. 原有全公司聚合与逐单禁读分别保存成能力；禁止先读取所有明细再由浏览器隐藏。客户/供应商字段不可见时，候选、过滤、排序和维度同样受约束。

对象能力另带领域的 `authorization_revision`。维保负责人/viewer 变化未必改变账号 epoch 或 project.version，必须读取实际有效 assignment 与覆盖该动作的 workbook revision 等关系版本；不能把主档 version 当全部关系的版本。任务即使 epoch 未变，在执行/发布时仍重跑对象关系决定。前端版本隔离缓存不替代服务器实时检查。

## 前端接入

复用现有 Provider 的会话隔离、请求序号、abort、focus/visibility 刷新和失效事件。新增通用资源能力读取和 Boundary；未确认、未知、暂停、故障均不发受保护请求。菜单、路由、重定向、面板、按钮和对象操作消费服务端决定，不自行推导新角色政策。

单账号、模板及批量预览共用 `ModuleGrantEditor`，沿用 AntD 与已实现的 CheckboxMultiSelect。非法依赖显示原因，不能在用户无明确选择时自动补高权限。客户关系独立展示，共享归属/空范围可见；模板同步不复制人员的对象关系。

## 文件与任务适配

生成文件和持久消息须记录来源授权合同；新请求重鉴权。业务原件以整件所含内容审查，不能只检一张预览页。无法验证旧产物的当前合法性时拒绝重新提供，不伪造血缘。用户历史已下载副本不在服务端撤权承诺内。

任务启动保存受限制的服务器委派信息；执行前、每个独立文件事务前、工具调用前和发布结果前检查实时主体和 epoch。内部读模型刷新作为已授权业务命令的既有副作用保留；系统任务和外部机器服务主体单列用途，不能借人类 admin 绕过政策。

## 机器检查与人工复审

运行时路由集合、工具注册表、任务入口和文件出口与目录逐项相等；业务资源动作与政策相等；面板与路由有明确归属。集合闭合只能证明没有漏登记，领域非干扰、跨对象、撤权、并发、迁移不扩权及真实引擎反例用于证明规则生效。

新增字段或入口未登记时测试失败；不能以新增一条描述就把未实现标为 migrated。每个阶段仍须独立多角度审查和精确 SHA 的全量 CI 后才能推进。

## S1 实现边界与性能约束

完整目录首先区分待实施的合同元数据与可执行的资源定义。尚未接入的域可以出现在覆盖账本和只读目录中，但不得因登记就允许写入有效 Grant、生成 allow 决定或显示为已迁移。各域切换时同时加入执行定义、策略、保守存量迁移及入口测试。未知字段和动作没有默认允许或自动映射。

当前单资源主干扩展为通用协议时，保留同一请求事务内实时主体与授权的一致性。能力快照批量读取账号 Grant；不能按资源重复查用户、逐个加载项目关系或逐个新建 PDP 连接。Cerbos 的 `CheckResources` 原生支持同一主体的一批异类资源，批量请求中的主体按资源 ID 保存配对的 Grant，策略只读取对应资源的配置，禁止将动作或字段提升成主体的全局并集。查询计划仍按实际请求资源与可信关系生成；快照不预先计算全部项目集合。官方接口依据：[Cerbos API](https://docs.cerbos.dev/cerbos/latest/api/)。

新增资源级开关必须同时表达未切换、启用、暂停三个状态。暂停不能恢复旧权限；切换关闭仅适用于尚未迁移的资源。部署默认配置、旧销售专用配置和新统一配置的优先级要有冲突测试，不能让两个环境变量分别控制前端快照与后端执行。

S1 引入按资源的持久 cutover 记录，保存切换目录版本与时间。可信部署配置显式要求启用时，由启动初始化在独立短事务内幂等登记已实现资源；不在 `/me` 或普通业务请求里写入。已有切换记录但当前配置撤去启用/请求兼容时，运行状态为 suspended 或启动失败；无记录且配置要求启用而初始化未完成时同样失败关闭，不能回旧允许。无记录且未要求启用才可 legacy。控制面 `authorization_mode` 与资源是否已经切换不同，不能用模式开关抹去持久权威。S4 删除不再需要的旧路径；S1 即须覆盖销售资源的这一闭环。

S1 的安全反例至少包括：失效/停用/已删除实名主体；旧 role/perms 不能伪造新允许；资源 A 的范围或字段不能进入资源 B；目录版本或账号 epoch 过期；首次创建与撤销重建的版本冲突；两个管理员互改锁序；模板保存不修改账号；同步保留整资源覆盖且不复制客户关系；旧账号及批量写入口不能形成第二真值；前端目标诊断不能污染操作者快照。查询数量与 PDP 调用数量应以真实多资源用例约束，避免每增加一个模块就增加一次数据库和网络往返。
