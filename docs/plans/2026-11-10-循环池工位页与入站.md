# 循环池工位页与 itsp 入站

决策: D-0057。协议以 `docs/integrations/cycle-sell-intent-v1.md` §10 为准。本文只规定本仓库要交付的块、检测和验收。

## 不做

- 不新增表、不新增列。现有 `maintenance_cycle_unit`、`maintenance_cycle_event`、`maintenance_cycle_sell_intent` 够用。
- 不写库存、氚云、变卖台账。
- 不实现 spareparts-shop、不合帖、不调用闲管家、不打开 `SHOP_CYCLE_SELL_ENABLED`。
- 不合入 HOLD #520 / #521 / #522，不部署。

## 块

| 块 | 约定 | 检测 | 验收 |
| --- | --- | --- | --- |
| 回调摘要 | `CYCLE_SELL_CALLBACK_TOKEN_SHA256` 默认空；与出站 token 的摘要不能相同 | `Settings` 校验测试 | 空配置时三个 POST 为 404，且数据库无变化 |
| requeue | §10.1 | `test_cycle_sell_inbound.py` | blocked 只把 `available_at` 调到现在；delivered 再调不改行 |
| mark-sold 回调 | §10.2 | 同上，并计数 `inventory` 与 `maintenance_bad_salvage` | 同一 `shopOrderLineId` 第二次 200 且只有一条事件；人工已售无该行号时 409 |
| revert-sold | §10.3 | 同上 | 只改 outcome 回 `to_shop`；工位仍是 `closed`；意图行数不变 |
| 主管查询 | §10.4 | API 测试 | 回收岗 403；主管看到 `read_status`；工人响应仍无序列号 |
| 工位页 | 一个入口 `/maintenance/cycle`。五个 `page_cycle_*` 任一即可见，admin 没有键也不可见。按钮只提交既有 `/api/cycle` 动作 | vitest：导航门闩、回收岗能自测、主管才能看投递、表格不渲染序列号列 | 页面动作与 §6 工位规则一致；409 展示服务端 detail |

合帖键保持 `(partId, conditionBucket)`。本页不提交价格。
