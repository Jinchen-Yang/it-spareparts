# 目录源技术版本一致性修复方案

决策：D-0049，承接 D-0048/D-36。

## 触发与范围

真实业务双事务反证说明，事务开始时间不能充当同一 PN 的更新顺序。消费者无法仅凭倒退时间戳区分迟到旧快照与合法最终状态。保留消费端防旧保护，在源数据库统一约束更新版本，不逐处改写高危 ETL 或治理业务。

新增迁移在 f1 之后创建 BEFORE UPDATE 行触发器，只比较普通列，排除 PostgreSQL 在 BEFORE 阶段尚未计算的 STORED 生成列。实际变化时保证 updated_at 严格大于旧值并采用真实时钟；原样重复导入不推进。INSERT、业务字段、历史数据和既有读 API 字段保持。

## 验证

- 原代码真实复现：先开始事务等待同 PN 主数据锁，在较新事务之后提交，最终资料完整但时间倒退，真实消费端误拒绝。
- 修复后用同一业务入口和真实锁等待验证合法最终快照被接受、迟到旧快照仍拒绝；补精度、回滚、ORM/Core、规格 touch 与导入无变化契约。
- 新迁移往返、唯一 head、ORM 零漂移及既有数据完整性。测试中的历史时间应通过真实旧行插入建模，不能在产品约束中新增测试绕过。
- 重新执行受影响的目录/导入测试与最终提交的全部必需 CI。

## 发布门禁

先只读核对生产源与商城 guard 实际使用的稳定身份和版本，采集两轮并检查源在窗口内是否变化。发现源版本落后于镜像或身份不可对应时阻断，不回填生产记录。

源端旧 writer 在商城新防旧逻辑启用之前冻结，并保留精确身份与恢复回执。商城完成后，主系统控制器只接受明确受审的预冻结交接，再备份/真实恢复、迁移、蓝绿切换。两个控制器的保护集合保持严格，不能把另一系统合法发布泛化成忽略任意漂移。具体预冻结交接代码与异常恢复须独立复审和测试通过后才能执行。

该计划不是上线回执；最终 SHA、标签、镜像、备份恢复、迁移头和 0/5/15/30 分钟观察由主会话按实际结果记录。
