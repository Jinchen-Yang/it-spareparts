# 库存管理分析的离线来源接入

离线命令从氚云仓单导出读取单头和备件明细，用于库存管理分析。库存余额、人工修正和业务单据状态由原有业务流程维护。分析页面只查询这份投影。

## 支持的来源

| 页签 | 单头、日期与归属 | 货品与数量 |
| --- | --- | --- |
| 入库单 / 入库单号 | 入库单号、入库日期、入库类别、仓储中心、拣货人员、测试人员及完成日期 | 备件明细按备件 PN、入库数量与单位记录。单头另存整机 PN、描述、整机数量和单位。仓库与库位使用可读名称。 |
| 返库单 | 返库单号、返库日期、返库类别、仓储中心、拣货人员、测试人员及完成日期 | 备件明细按返库数量、单位、品牌、大类、测试结果及入库位置记录。两个同名的明细入库库位中，取紧邻“入库仓库”右侧的可读库位。整机数量取单头“整机返库数”。 |
| 直采直退 | 退货单号、退货日期、退货类型、退货人员 | 明细产品名称用于型号展示，产品描述、退货数量、单位、大类和品牌取对应明细列。退货人员记作该业务经办。 |
| 发货单号 / 出库_发货单 | CKD 出库单号、出库日期、出库类别、仓储中心、出库仓库、拣货人员、数据状态 | 备件用数据 ID、PN、实际出库数量及原单位，保留所在仓库和库位。整机按单头整机 PN、描述、出库数及单位展示。 |

实际出库遵循 D-0066。库存管理分析按出库拣货岗位归集，按数据状态统计已生效业务量，并在收发总览标明各出库仓已导入的业务日。支持按来源分文件或合并成同一工作簿。同一来源出现两个别名页签会拒绝整本。「重点保留」和隐藏的 Hidden_Options_ 选项页跳过，其他页签将报告尚未支持。

## 文件与更新契约

- 导出**完整单据及其全部子行**。可按日期筛选单据。子行经 Excel 筛选裁切后重新保存的文件无法表达整单的明细集合。
- 按页签和中文字段识别。双表头模板还检查单号、单头 ID、子行 ID 和修改时间的技术字段配对。读取已保存的单元格值，公式仅取现有缓存，外部链接不刷新，附件列不进入投影。
- 纵向合并的单头按连续子行展开。源单头 ID、业务单号及子行 ID 在各自来源内校验。空白行结束当前单据区段。日期从对应业务日期读取，“修改时间(必填)”按源本地时间比较版本。个人工作量取实际岗位，仓管员名单与本仓测试人员名单保留在原始文件。
- 空文本和缺失数量存为空，真实的零值保留。数量必须可被十进制 Numeric(20,6) 精确表示。不同单位保留原值。文件中的取消单据以原状态投影，后续由查询按经营口径筛选。
- 按来源及单头 ID 应用较新的完整单据，其子行与此版导出一致。未出现在本次文件中的历史单据保留。相同修改时间且投影内容相同的记录计入 unchanged，明细顺序调整不影响判断。旧版本或同一时间但内容冲突时拒绝整份文件。需在源系统核对修改时间与完整导出。
- 使用一个 PostgreSQL 事务完成多来源、多批写入。并发导入按事务锁串行复核版本，任一批校验或保存失败将回滚本次文件。页面读取已提交的版本。

## 操作

持有「数据导入」权限的实名账号可在「数据导入 → 仓单工作簿导入」选择一份 .xlsx，提交后查看导入作业。系统先校验整本，再更新库存分析。作业与批次详情显示各业务页签的单据及明细数，以及新增、更新和未变更单据数。

在 backend 目录校验文件，可先核对各页签的单据数与子行数。默认模式只解析文件。

```sh
uv run python -m scripts.import_warehouse_analytics /path/to/收货统计.xlsx
```

目标数据库完成本版本迁移后，通过环境变量 DATABASE_URL 显式选择该库，再应用同一文件。结果中的 inserted、updated、unchanged 均按单据计数。

```sh
uv run python -m scripts.import_warehouse_analytics /path/to/收货统计.xlsx --apply
```

应用后可重跑同一文件核对 unchanged，再在看板按来源、业务日期核对单数、匹配行数及同单位数量。资料的首末业务日期用于检查窗口覆盖，各仓的实际出库以仓库 CKD 为准。
