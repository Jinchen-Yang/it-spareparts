## 实施边界与验证入口

三路独立只读分析覆盖后端数据边界、前端交互与回执查询性能。采用以下方案：

1. 通过既有确认 HTTP 接口控制两次影响计算的结果，分别覆盖全局锁后、行锁后复验；对 executable 和摘要分别制造漂移，核对 409 及完整业务快照零写。独立临时禁用各复验，证明对应测试失败，再恢复实现。
2. 构造合法 delivery 外键且其他需求身份完全匹配的领用，验证只提示且保留；临时移除 delivery 排除条件证明测试失败。
3. 需求及可靠关联领用增加只读人工标记，复用 D-34 现有身份、字段保护函数。前端明确领用标签指向关联需求，确认区只统计有效需求和精确关联领用。保护账本、人工身份已在原实体摘要内，派生 DTO 字段不改变摘要输入、请求摘要或已有回执语义。不修改字段保护模块、执行集合或 executable。
4. 幂等键按实名操作者全局查询，不能用当前批次、时间限制代替，否则漏掉跨批次误用。保留查询语义，为私有回执对象建立表达式 GIN（支持 `?` 的 jsonb_ops），只建索引；并发建索引使用 Alembic autocommit_block。真实 PostgreSQL 合成数据 EXPLAIN 与迁移链测试验证。
5. 未知结果保留原请求和候选身份，允许关闭/返回；重新打开只读查询候选及回执，显式重试才 POST 原请求。新增只读回执接口沿用项目、实名、动作权限并按操作者及候选绑定，避免已成功候选从列表消失后失去恢复入口。账号/项目隔离与迟到响应门禁保留。

测试沿用既有 HTTP、组件交互、真实 PostgreSQL 迁移边界；逐条先红后绿。所有测试由主代理串行启动，启动前读取 `/proc/loadavg`，一分钟负载大于 10 则等待。pytest 不开多进程、Vitest 最多两个 worker，只跑相关子集。专用 PostgreSQL 15 容器为 `itsp-laneB-6bfu-20261020`，日志在工作树外指定目录，前端复用 lockfile 相同的依赖软链并于结束删除。
