## 范围与实现约束

- 行 PATCH 扩展 quantity、serial_number、remark、demand_order_no、
  PN/part_id 身份组，保留 no_return 三态。省略保持；需求关联显式空串清空，
  同项目归属仍由现有 helper 校验。PN 与 part_id 成组提交。
- 独立 `PATCH /api/maintenance/site-issues/{issue_id}/header` 使用 issue CAS，
  接收 issue_no、issue_date、receiver、issued_by、site_location。可空旧头不强迫补造；
  地址明确清空与省略区分。锁全部有效行，响应说明整单影响；日期/单号走原语全单重价，
  重号拒绝，不隐式合单。
- 行/头共享幂等锁 → workbook state → project → issue → 稳定顺序明细锁，
  锁后复验实名、账号、页面/动作/成本权限、项目范围；默认原语负责事实、
  成本、审计、事件、版本，外壳负责 CAS、回执、一次 revision 和原子提交。
- 允许有效 page_manual/workbook（含 V1 历史）/legacy。原生及发货来源继续拒绝；
  单头整单含有效发货行时保守拒绝，避免只改地址绕过来源守卫。
- 抽屉按行事实/单头分区独立保存，仅传实际修改字段；显示整单影响和只读成本。
  409 保留草稿并要求显式重读，未知结果冻结原键原载荷核对，
  成功回执不因后续刷新失败丢失。读取通过稳定 issue_id，不依赖可修改单号或筛选分页。
- 不写收货关联、库存、WBDD 字段保护账本；不新增人工成本输入、返还容量守卫或 ITSP-3 状态。
  #422 的容量实现由独立候选交付与联合验收。

## 三路分析

后端证据：现有原语已支持全部字段与成本副作用；无需修改
`maintenance_project_master_workbook.py`。原语不是权限/CAS/幂等外壳，必须保留 #423 的调用职责。
前端证据：search DTO 已有全部可编辑头/行字段与成本，新增精确身份过滤以安全重读。
独立风险审查：单头地址变更不会触发原语遍历发货行，因此入口须对整单主动复验来源；
指纹区分行/头入口；不从 PN 推断需求归属。

## 测试场景与边界

测试 seam 已由任务授权：真实 PostgreSQL 的公共 HTTP 命令/回读/工作簿 apply，
以及前端抽屉交互。开发验证不替代用户点按。

| 场景 | 起点与动作 | 预期 |
|---|---|---|
| T1 | 有权实名用户，四类允许历史来源，逐项修改行及五头字段 | 稳定身份/source 保留；原生/发货来源拒绝 |
| T2 | 同单多行，仅提交一行，再修改地址 | 其他行不作废，地址整单生效，其他单不动 |
| T3 | 旧抽屉、旧 V2、旧补价与页面修改交叉提交 | 各入口按既有 CAS/三路合并拒绝冲突；未改字段保留 |
| T4 | 人工价、日期窗口/需求证据，改量/PN/关联/日期/号 | 沿原语重价、PN 清旧人工证据、未知不补零；地址/备注不重价；失败全回滚 |
| T5 | 同项目/跨项目/未归属/不存在关联及显式清空 | 非法关联稳定 409，混合合法修改也零写，收货 source_order_id 不动 |
| T9 | 权限缺失/锁等待撤权/重复键/两连接竞争/未知结果 | 当前授权复验、原回执、冲突保留草稿、不自动换版本重试 |

每次 test/build/npm ci 前运行任务指定 `gate.sh`；75 则等 60 秒再查；
只跑定向文件，一个测试进程，Vitest forks/单 worker/不并行文件。

由仓库夹具新建独占测试库。证据及计数在发布说明补齐。
