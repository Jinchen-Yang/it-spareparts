# 采购分析接入核对（#550 / D-0064）

基线 `3cbb72a4`。各看板日期默认近 30 天，含上海业务日今天，可切换到其他区间。接口前缀 `/api/purchases/analytics`。

| 看板/问题 | 事实字段及粒度 | 已有读口与需补部分 |
| --- | --- | --- |
| 维度榜、类型内 PN 榜 | 采购单 purchaser、source_type_raw、supplier_id；批次行 part_id、qty、unit；dim_part 品类、PN 和目录描述；有效池 | summary 有单维度，pn-boards 有两个固定榜。补全域 Top、单位选择和目录描述。 |
| 紧凑矩阵、自选交叉 | 两个真实维度的交集；含行轴时以匹配行计额 | 现有订单 API 只支持一个 group_key；需有界行列、单独求边际、携带精确条件分页钻取。供应商名包含查询不能代替供应商身份。 |
| 人员与趋势 | 去重采购单、单头批次行、每单行数、不同供应商、order_date | 已有 summary 及日/月趋势，补有界维度指标。采购员≠关联销售员。 |
| 期间变化 | 两个相邻等长日期域，按同维度聚合 | 上期数据与当期须在排序截断前对齐；缺基数须注明。 |
| 采购结构、共同供货 | 原始类型、供应商身份、PN 与同单位数量 | 类型已有，补供应商交叉及共享 PN 的真实订单证据。 |
| 销采关联 | linked_sales_order_no、关联销售单 customer_id、salesperson；已有权限内的 project_names | orders 有单据上下文；补按精确关系的分布/钻取。采购产品为行描述，目录为补充。 |
| PN 互通池、专题价格 | part_pool_member、有效 part_pool、当前价格政策，采购行有效样本、未税购价、数量、单位、核查结果 | 既有池价格服务和采购 PN 双榜口径不同；需按采购筛选的可比分页读口。 |
| 订单及单号浮窗 | 采购/销售单号、行 PN、行描述或目录描述、数量与单位、品类 | 已有 orders 与 orders/{id}；列表按页，补范围内货品预览，销售单只展示关联采购。 |

通过只读快照在独立数据库验证金额、数量、单据及缺失单位。正式候选要求主线的离职销售可见性字段。性能读数与验证见[实量验收记录](../../handoff/2026-11-19-采购分析实量验收.md)。

## 已接入的正式读口

页面入口为 `/purchases/analytics`。无参数打开「30 天」的多框排行，旧的单维分组链接进入「汇总与导出」。以下路径相对于 `/api/purchases/analytics`。请求按当前看板发起，读取采购分析需要页面权限及 admin 或 boss 角色。

| 看板 | 用到的字段与统计口径 | 正式接口 |
| --- | --- | --- |
| 多框排行、两类 PN 榜 | 采购员、类型原文、供应商 ID、目录大类、目录 PN、有效池。全范围排序后截取 3/5/10 项。维保需求、销售订单分别叠加类型条件。顶部总数独立去重。 | `cube`，单轴和全域合计 |
| 专题榜 | 大额单按可见采购单金额排，人员按处理行数排，供应商按覆盖的 PN 数排。主供占比为同 PN、同单位最大已知供货方数量 / 全部数量；缺数或存在负数量的组不进入此比例。两张价格榜按超出池均价或可比人工上限的比例排。 | `cube`、`concentration`、`pool/parts` |
| 紧凑矩阵、自选交叉 | 人员、类型、供应商、PN、大类、池、采购周任选两轴；周一起算。矩阵分开排两轴，格子为实际交集。行合计覆盖未显示列，单均分母为该行去重单数。缺金额时保留缺值。 | `cube`，紧凑图最多 5 × 5 格，自选表行列独立翻页 |
| 期间对比 | 日期闭区间与紧邻的等长上期，各自聚合同一维度后对齐，新增和消失分组也参加排序。变动率仅在上期有可比基数时计算；上期钻取携带上期日期。 | `cube?compare=true` |
| 人员与节奏 | `purchaser` 的去重采购单数、单头批次行数、采购额、不同 PN 数、已知供应商数及指定单位采购量。同一批人员可按任一列排序，日期趋势按自然时间取数。 | `buyer-ranks`、`cube`（按人、供应商、采购类型、日/月）与 `chart-sample` |
| 结构与供货关系 | 类型原文及金额、同单位采购量，供应商依 `supplier_id` 区分身份。选择中心供应商时，以相同范围内双方都成交的 PN 为证据，两边分别下钻。 | `cube`、`shared-pns` |
| 销采关联 | 采购单记录的关联销售单号匹配销售事实，同号按最小销售单 ID 确定客户和销售员。类型 × 客户的采购构成、客户/销售人员的单数与采购支出散点均来自这一关系。项目名称只在单据上下文中展开。 | `cube`、`document-preview`、`orders` |
| PN 与互通池 | 以物料主键和单位分行。经营量覆盖全部符合条件的采购事实。正式价格样本取单价和数量均为正、日期有效且不晚于今天、未被确认源错的单头批次行，先换算到未税，再按数量加权。供应商区间展示这些样本的最低、最高和均价。池均价与成员采用相同筛选及单位。 | `pool/parts`、`pool/sources`、`pool/members` |
| 筛选、预览与下钻 | 人员、客户、类型沿用既有候选；PN/池/单位按当前范围搜索。采购单或关联销售单按单号精确取可见行，浮窗将 PN、品类分别按单位小计。订单列表和抽屉沿用上层日期与行条件。 | `options`、`product-options`、`document-preview`、`orders`、`orders/{order_id}` |

金额取值沿用 D-39 的含税、未税、实付及未标税率规则。订单指标用单头金额；涉及行维度时逐行计算金额并相加，抽屉可同时核对匹配行合计与整单金额。池的人工上限只有金额字段；本页仅在有效成员主档能确定共同单位且与成交单位相符时比较上限。无单位、无可比价或无上限时显示缺值。成本、客户、供应商及池价格权限同时约束候选、指标和访问路径。

矩阵按需分页返回格子、独立边际及准确合计，成交行留在数据库。订单页默认取 50 张；货品浮窗最多展示 8 个 PN/单位和 8 个品类/单位组合。看板按页下载查询结果。原采购导入入口继续以每块 1 MiB 将上传文件流式写入临时文件；本次查看看板无需重新上传业务数据。已登录页面对相同参数的请求合并，在内存中短时复用结果，切换账号、刷新数据时重建缓存。浏览器返回恢复原筛选、指标和抽屉层级。

## 人员总榜怎样看

单据数反映经手频次，明细行数反映逐行处理量；采购额反映经手资金，不同 PN 数反映型号覆盖，供应商数反映经手的供货方范围。件数必须指定成交单位。同一总榜采用一个基准范围，下钻到个人后再展开供应商、采购类型和节奏。每个指标单独排名。

同一人可能经手多种单位。总榜初始量列取「件」，允许切换单位。全局已按单位筛选时沿用这个单位。
