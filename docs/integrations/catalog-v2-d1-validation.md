# D1 发布与读取实现边界及验证

决策: D-36。基线 `319e25f6`，仅实现 catalog-v2 §1–4、§6–9 的主数据库生产者。
D2 人工命令与商城消费应用不在此改动范围；新读凭据和后台循环默认关闭。

## 数据路径

源 ORM / Core / bulk / upsert → PG 行触发器同事务捕获及 revision →
单发布者先取 advisory 会话锁 → RR 一致快照 → 安全 txid 与固定点闭包 →
完整聚合、逻辑批、投影、水位、具体捕获标记同事务提交 →
独立读凭据 → 固定快照 / 增量批 / 持久分片 → 商城自行 staging。
源当前值只在 `/parts/{part_id}` 提供，不能作为消费方水位。

## 已批准测试边界

使用任务已明确的公共接口，不新增业务决策。所有数据库测试通过每次 pytest
新建的隔离 PostgreSQL 数据库执行，基址限 `127.0.0.1:55510/spareparts_test`。

| 场景 / 起点 | 操作 | 预期 |
| --- | --- | --- |
| 离线规范输入 | 调用 C/H 和各对象 hash | §8 字面摘要、435 字节；排序、decimal、缺字段与 null 分开；非法值拒绝 |
| 各类源写入口 | ORM、Core、bulk、upsert；真实无变化 UPDATE | 捕获 txid、完整旧新父；真实变化才 bump；导入原语义保留 |
| 已 ready 的 seed | T1 改 A，T2 改 A+B | 同批闭包包含 B；不能把 T2 的 A 配 T1 的日志发布 |
| 较低捕获 ID 事务未提交 | 较高 ID 先提交，再提交低 ID | xmin 阻挡不安全组；两者最终都发布，不用 ID 当水位 |
| 已发布身份组 | merge / unmerge / 路径压缩 / alias 换属与删除 | 完整父节点、重定向与 alias_moves；删除不复活 |
| 参数已存在 | 仅删除参数行 | 完整节点 specs 缺该键；形成增量 |
| PN 物理删除 | publish-once | stopped + 报警，水位不动；显式新 epoch seed 恢复 |
| 固定快照客户端 | 创建后源改写、分页重读 | 快照 count/hash/items 固定；跨客户端/limit/epoch 游标拒绝 |

| 只读调用方 | 空增量、过期、未知字段、超体积、未配置及 v1 token | 约定水位与统一错误信封；D2 路由不存在 |
| 旧 v1 客户端 | v1 list / snapshots | 原字段集及 DTO 兼容，不混入 v2 |
