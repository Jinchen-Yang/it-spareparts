# ITSP-2 领用行批量返还要求实施与验收

- 日期：2026-10-20；基线：`319e25f6`；分支：`feat/batch-no-return`。
- 跟踪：[issue #421](https://github.com/Jinchen-Yang/it-spareparts/issues/421)。
- 决策: D-31
- 依据：D-31 第 5 款、D-32 第 2/6 款及 [领用事实编辑原语契约](maintenance-site-issue-facts-v1.md)。
- 范围：项目领用明细的人工三态批量更正，逐行事务、逐行回执；收货属性批量继续使用既有入口。

## 实施选择

新增单行 `PATCH /api/maintenance/site-issues/{issue_id}/lines/{issue_line_id}`，本轮只接收 `changes.no_return`。选择窄接口以隔离 PN 身份、数量重价与需求单归属的额外验收面；ITSP-8 可扩展字段白名单，继续消费同一原语。`changes={}` 不改行；显式 `null` 恢复按规则判断。

入口复用 `page_maintenance`、`action_maintenance_site_issue_manage`、`data_purchase_cost`、项目范围和实名身份。命令使用现有 `maintenance_site_issue_command(action=correct)`，指纹包含入口名、稳定身份、意图、版本、原因和操作者。锁序保持幂等事务锁→工作簿 state→项目→领用单→行，锁后复读、复验权限、CAS，再调用默认 `apply_locked_site_issue_edits`，一次 revision bump 与回执同事务提交。

支持原语已允许的 `page_manual/workbook/legacy` 有效行；`site_issue_v2` 及带原生发货身份的行保持拒绝。不复用人工整单替换，不修改未选行；不改高危 master workbook 实现。

前端冻结选中行及原因，逐行调用；同单后续行使用上次成功回执的 issue version。按原始三态相等判断“未变化”，不能把规则算出的免返当作显式 true。结果逐行展示成功、未变化、冲突、失败或结果未知；仅未知请求可携原载荷、原幂等键核对。成功后刷新，刷新失败不得重发成功命令。

## 三路分析与边界

- 用户路径：领用明细独立选择，三个动作均需填写原因；“是否应返还”的是对应 false，否对应 true。当前服务端返还要求仍是显示依据。
- 领域边界：项目免返标注只提醒，不生成命令；标准硬盘默认免返、逐行明确设置优先。没有实际返还状态，也不改变收货、数量、PN、成本或免返规则。
- 技术风险：同单版本传递、幂等跨入口碰撞、等待锁期间撤权/数据漂移、审计失败回滚及旧 Excel 冲突。后端和前端分别单写者，完成后独立反例复核。

## 公共测试边界与验收场景

用户任务已授权以下测试边界：HTTP PATCH/GET、工作簿导出-校验-应用、React UI 与 API 编排；真实 PG 验证事务/并发，数据库读数用于核验审计、命令、revision 与业务副作用。

| 初始条件/角色 | 操作 | 预期 |
|---|---|---|
| 有权实名用户；三种允许来源；标准硬盘与非硬盘 | 依次设免返、应返、按规则 | true/false/null 正确保存，省略不变；标准硬盘恢复规则后免返 |
| 同单两条选中行 | 顺序批量执行 | 下一条使用前条回执单版本，两行各一份事实及返还要求审计 |
| 原始值已等于目标 | 执行批量 | UI 显示未变化，不调用 PATCH |
| 旧单/行版本或他人同时编辑 | 提交 PATCH | 409 携当前版本，零事实/审计/回执/revision 写入 |
| 同键重复或跨入口/不同载荷 | 重试 | 同载荷回原回执；不同载荷拒绝，零重复更正 |
| 无动作权、范围外、共享身份或锁等待期间撤权 | 提交/回放 | 拒绝且零业务写入 |
| 作废行、错误所属单、原生来源 | 提交 PATCH | 4xx，不复活，不伪造发货身份 |
| 事先导出工作簿 | 网页更正后回传过期更改 | revision 推进，既有冲突规则拒绝覆盖 |
| 已有数量/PN/成本/实际收货 | 只更正 no_return | 原事实与成本证据完全保持，未选行有效性不变 |
| 业务审计或回执保存失败 | 提交 PATCH | 全事务回滚，可安全重新读取 |
| 批量含成功/409/422/网络未知 | 执行并读结果 | 逐行清楚展示；成功不重发；未知原键核对；切项目不续发旧队列 |
| 有权限与只读用户，桌面及窄屏 | 点三个动作、取消、键盘输入原因 | 权限正确；必填原因；收货属性批量仍可用 |

## 交付与回退

无 schema 变更，不做数据回填。本轮续接遵守共享主机资源限制：只使用既有专用 PostgreSQL `itsp-laneA-itsp2-20261020`（localhost:32871），后端逐文件执行定向 pytest，前端依次执行 tsc、单 worker 定向 Vitest、vite build；同一时间最多一个测试进程，每次先检查负载与可用内存。全量测试留给后续 CI，不运行本地全量套件或浏览器。UI 由组件测试验证，仍待用户点按验收。仅本地提交并写 PR 草稿，不推送、不创建 PR、不合并、不部署；容器由操作者清理。

撤回候选代码可移除新入口与按钮；已成功更正的事实和审计保留，业务撤销必须由有权人按新版本执行反向更正。无需 schema downgrade。
