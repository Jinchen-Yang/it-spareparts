# DEV-05C1 确定性金额疑点检测器规格

## 1. 一句话目标

把采购、销售 ETL 已经确定性产生的 `amount_mismatch` 数据提示，转换为可由数据维护人员逐条核实、留痕的正式数据疑点。

本切片只记录和展示历史事实，不判定员工能力，不阻断导入，不自动排除经营统计，也不改变采购、销售、利润、库存、互通池均价或约束价。

## 2. 规则与统一口径

- 规则代码：`amount_mismatch`
- 规则版本：`etl-v1`
- 命中条件：`abs(行金额 - 数量 × 单价) > 0.05`
- 边界：差额等于 `0.05` 不命中；数量、单价或行金额为空时不命中。
- 唯一口径源：复用 `app.etl.anomaly.AMOUNT_TOL` 与 `app.etl.anomaly.line_flags`，检测器不得复制另一份容差或判断式。
- 疑点含义：仅表示“金额关系需要人工核实”，不是“源数据错误”，也不是员工评价。

`zero_price`、相邻采购价倍数、数量单位、SN/自贴码等规则不在本切片启用。

## 3. 实时导入检测

采购或销售事实行成功写入后，在同一导入事务内检测本批次实际出现的事实行：

1. 只处理采购、销售，不接库存、维保和费用。
2. 按事实行当前落库值重新调用 `line_flags`；不把 `anomaly_flags` 中的其他提示整体转成疑点。
3. 命中时调用 DEV-05A 唯一写入口 `create_or_refresh_issue`。
4. `detected_by` 优先记录真实上传账号；没有登录上下文的受控内部导入明确记录 `system:etl-import`，不得伪造员工姓名。
5. 证据快照只包含规则复核所需字段：数量、单价、行金额、计算金额、绝对差额、容差和检测来源；不写员工评价。
6. 源指纹只取稳定的源业务字段，不包含批次 ID、检测时间等运行信息。同一内容重复导入不得创建第二条疑点或无意义刷新版本。
7. 若已人工确认的疑点对应源字段发生变化且新值仍命中，复用 DEV-05A 状态机将旧结论置为 `source_changed`；由核实人员重新打开并基于新证据处理。
8. 若源字段变化后不再命中，既有已确认或待核实结论同样失效并标记为 `source_changed`，证据明确记录“当前源数据已不再命中”；不得静默保留旧结论，也不得自动标为数据正确。

检测器失败必须回滚整次导入事务，避免出现“事实已更新、疑点未同步”的分裂状态。导入报告增加检测统计，但不得改变原有行数与经营重算口径。

## 4. 历史回扫 dry-run

提供只读服务和命令行入口，对存量采购/销售事实按同一 `line_flags` 规则扫描：

- 命令必须显式带 `--dry-run`；本切片不提供执行写入模式。
- 可按 `purchase`、`sales` 或全部侧别扫描，并限制确定性样本条数。
- 返回扫描行数、命中行数、已有正式疑点数、待新增数、需刷新数、当前不再命中但已有疑点数，以及按稳定顺序输出的样本。
- 同一数据库快照与同一参数重复运行，统计和样本完全一致。
- dry-run 不调用 `create_or_refresh_issue`，不写疑点、审计、事实表或任何经营派生字段。

历史实际写入、分批执行、失败恢复和生产调度另行评审，不在本切片开放。

## 5. TDD 公开验收缝隙

测试只通过以下公开接口观察行为，不断言私有函数调用次数：

1. `pipeline.run_import(...)`：真实导入后出现正式疑点；同内容 upsert 重导幂等；源值变化时旧结论失效；非采购销售不触发。
2. `data_quality_amount_mismatch.preview_history(...)`：同快照重复 dry-run 结果一致，且前后疑点、审计与核心经营摘要不变。
3. `data_quality.create_or_refresh_issue(...)`：相同源指纹即使批次归属变化也不产生无意义刷新；源指纹变化继续遵循 DEV-05A 状态机。
4. CLI：缺少 `--dry-run` 失败关闭；显式 dry-run 输出可复核 JSON 且零写入。

## 6. 验收与发布门槛

### 合并门槛

1. 0.05 边界、空值、采购和销售路径有回归测试。
2. 重复导入同一业务内容只保留一条当前疑点，不增加版本和 refresh 审计。
3. 源仍命中与源不再命中两种变化都让旧人工结论失效，且保留原事实和完整审计。
4. `detected_by` 为真实上传账号或明确系统身份，不能为空。
5. dry-run 两次输出一致，且疑点、审计、采购、销售、利润、库存和池表零变化。
6. 检测前后经营 KPI、利润字段和库存摘要逐项相同。
7. 后端全量测试、Alembic check、`git diff --check`、Standards/Spec 与权限安全复审通过。

### 生产门槛

1. 合并后先在生产快照 staging 运行 dry-run，只核对规模与样本，不写历史疑点。
2. 备份数据库，并保存旧应用镜像与精确提交 SHA。
3. 用有治理权限、无成本权限、无治理页面三档账号复核疑点队列现有脱敏与权限边界。
4. 对新导入采购/销售各至少一条命中与一条不命中样本做闭环验证。
5. 对账部署前后经营 KPI、利润、库存和池统计完全一致，观察错误日志至少 30 分钟。

本切片无数据库迁移；若未来开放历史实际写入，必须另做执行计划、批次边界、回滚与生产复核。

## 7. 明确非目标

- 不启用相邻价倍数、数量单位、零价、SN 或自贴码自动疑点。
- 不提供历史回扫 apply，不新增定时任务。
- 不自动确认源错误，不自动排除任何样本。
- 不修改利润、库存、互通池分析、价格约束或员工排名。
- 不新增报价、询价、提交、审批、拦截或员工评价能力。
