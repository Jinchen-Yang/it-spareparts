# DEV-05B1 数据疑点规则校准预览规格

## 一句话目标

让数据维护人员在不修改任何业务数据的前提下，看清“如果未来采用某个采购价倍率规则，会圈出多少待核实候选、分布在哪里、抽到哪些真实样本”。

本功能不是异常检测器，更不是错误判定器。页面、接口和文档统一使用“候选”“待核实”“模拟预览”。

## 使用人和决策

- 数据维护人员：查看候选规模与样本，组织业务校准。
- 采购负责人：解释指定采购、紧急采购、整包拆零等正常业务差异。
- 老板或管理员：在拿到正反样本后决定未来规则方向与可承受工作量。

DEV-05B1 只帮助形成决策证据，不提供启用规则、保存阈值、员工评价或责任认定。

## 本次范围

规则代码为 `purchase_adjacent_price_ratio`，预览版本为 `preview-v1`。

### 可比相邻对

1. 只取已生效、非未来、`part_id`、数量和单价均有效且为正的采购行。
2. 采购价复用正式未税口径：明确不含税取原价，其余按 13% 换算为未税价。
3. 在同一 `part_id + 采购类型` 内，按 `order_date, order_id, line_id` 排序并比较前一条。
4. 倍率为两笔价格中较大值除以较小值；方向另行标记为本次变贵或本次变便宜。
5. 查询时间窗只限制“本次采购行”；时间窗之前最近一笔仍可作为前值，避免月初第一笔失去比较基准。

### 固定预览

- 固定并排展示 2、3、5、10 倍四档，不允许保存为正式阈值。
- 每档展示可比相邻对、候选数、候选率、本次变贵、本次变便宜。
- 展示采购类型分层结果。
- 返回确定性样本：同一数据快照和参数重复查询，样本集合与顺序必须相同。
- 响应包含规则版本、数据截止时间和样本边界，便于复核。

## 权限和隐私

- 接口必须同时要求 `page_governance` 与 `data_purchase_cost`。
- 缺少采购成本权限时整体返回 403，不能只遮金额后保留倍率、排序或样本，因为这些仍可反推价格。
- 本切片不展示供应商、客户或经办人，防止先看人员身份再判断数据。
- 本切片只有采购侧，不接入销售客户范围逻辑。

## 接口

`GET /api/data-quality/calibration/purchase-price`

参数：

- `date_from`、`date_to`：可选，限制当前采购行日期。
- `purchase_type`：可选，只查看某一采购类型。
- `sample_limit`：每个阈值/方向的样本上限，服务端限定范围。

响应至少包含：

- `rule_code`、`rule_version`、`generated_at`、`data_through`。
- `eligible_pairs`、`distinct_parts`。
- 四档阈值汇总。
- 采购类型分布。
- 确定性样本的当前行与前一行、PN、订单号、日期、数量、税口径、未税价、倍率和方向。

不提供 POST、PUT、DELETE，不提供批量生成疑点端点。

## 零写入红线

预览服务不得调用 DEV-05A 的疑点创建/刷新服务，不接导入、定时任务、利润重算或看板统计。每次请求前后：

- `fact_data_quality_issue` 和 `sys_audit_log` 行数不变。
- 采购、销售、库存、利润和互通池相关业务表内容不变。
- 不新增数据库迁移。

## 性能边界

- 一次请求只执行一次相邻窗口计算，不能为四个阈值重复扫描四遍。
- 样本响应设置硬上限，防止把真实明细整表导出。
- 数据快照当前规模约 8.8 万采购行；预研聚合约 169ms、样本约 120ms。
- staging 目标：五并发下 p95 小于 1 秒、p99 小于 2 秒；单查询 statement timeout 为 3 秒。
- 暂不新增索引；只有 EXPLAIN 证明瓶颈后才评估，避免拖慢导入。

## 验收条件

1. 四档统计与独立 SQL 一致。
2. 相同参数重复查询的统计与样本完全一致。
3. 日期边界、同日排序、采购类型分区、税价换算、涨跌方向均有测试。
4. 取消、未来、零价、无型号行不进入可比集合。
5. 缺页面或成本权限返回 403，响应和错误不能反推价格。
6. 预览前后疑点、审计和业务表零变化。
7. 页面加载失败清空旧结果，快速切换筛选时旧响应不能覆盖新结果。
8. 390px 可用，无整页横向滚动；页面没有启用、保存、确认错误或批量生成按钮。

## 明确非目标

- 不自动创建或确认疑点，不历史回扫。
- 不保存黄金样本或候选阈值；样本标注单独作为后续切片评审。
- 不做数量单位、包装、SN、自贴码或销售金额规则。
- 不改变利润、库存、池均价、经营看板或员工排名。
- 不清除健康状态中的既有告警。

## 进入 DEV-05C 前必须拿到的业务答案

至少提供 3 个“应该进入待核实”的正例和 3 个“倍率虽高但正常”的负例，并说明采购类型、税价、数量单位、整包拆零、指定品牌和紧急采购背景。同时确认：

1. 正式规则只看突然变贵，还是涨跌都看。
2. 各采购类型是否分开，指定采购是否单列。
3. 单位和包装变化如何比较。
4. 同一天多笔采购的业务顺序口径。
5. 数据维护人员每天最多能核实多少条。

未形成书面口径前，不进入自动建疑点的 DEV-05C。
