# DEV-05A 数据疑点人工核实地基——验收记录

## 结论

DEV-05A 已满足合并条件。它只建立“发现疑点后，由有权限人员逐条核实并留痕”的基础设施；疑点不等于错误，本版本不自动扫描历史数据、不自动判错、不改订单、库存、成本、利润或经营统计。

本版本带数据库迁移，合并后不可直接跳过发布门禁部署生产。

## 交付范围

- 采购行、销售行疑点的独立记录与人工结论状态。
- 清单筛选、明细查看、逐条确认、重新打开和完整审计轨迹。
- `action_data_quality_review` 动作权限；写入还必须同时拥有数据治理页面权限和采购成本可见权限。
- 销售人员客户范围隔离、成本字段脱敏、核实意见与审计内容防旁路泄漏。
- 数据治理页新增“价格与数量疑点”页签，支持桌面端和移动端。
- 迁移降级失败即停：存在核实数据时禁止用 schema downgrade 作为生产回滚方式。

## 明确不做

- 不设置自动异常阈值，不批量生成历史疑点。
- 不把疑点直接标成错误，不自动排除订单或数据。
- 不修改利润、库存、成本、看板或导入结果。
- 不做批量确认，不做 SN 重复检测。

## 权限与浏览器验收

- 角色覆盖：管理员、核实员、只读用户、成本受限用户。
- 受限用户看不到价格、核实意见、证据指纹和审计前后值，也不能执行确认或重新打开。
- 限定客户范围的销售账号无法枚举、搜索、查看或修改其他客户的销售疑点。
- 清单/详情请求均有代次守卫，旧响应不会覆盖新筛选或重新打开已经关闭的抽屉。
- 1440px 桌面端和 390px 移动端真实浏览器验收通过；移动端无整页横向滚动，指标卡两列排列，关键页签直接可见，详情抽屉全屏可用。

## 生产发布门禁

生产发布前必须全部满足：

1. 先做并校验 PostgreSQL 备份，记录旧代码 SHA 与回滚镜像。
2. 精确部署合并后的 `main` SHA，执行 `alembic upgrade head`。
3. 确认新疑点表初始为空；本版本不会自动扫描并生成历史疑点。
4. 确认管理员/老板拥有 `action_data_quality_review`，其他职位模板默认关闭。
5. 执行健康检查、登录、权限矩阵和数据治理页冒烟。
6. 观察生产日志与错误指标至少 30 分钟。

达到以上门禁后方可判定“可生产”。
