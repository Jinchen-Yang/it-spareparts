# DEV-05C1 确定性金额疑点检测器——验证记录

## 结论

DEV-05C1 已完成开发分支验证，可以进入独立 Standards/Spec 双轴复审和 PR 阶段；本分支不建 PR、不合并、不部署。

本切片只把 ETL 已有的 `amount_mismatch` 确定性提示转换为正式数据疑点。疑点默认继续参与全部经营统计；没有新增相邻价倍数、数量单位或 SN 规则，没有历史写入、自动排除、利润/库存/池分析改动或员工评价。

## 实现范围

- 采购、销售导入成功写事实行后，在同一事务调用金额疑点检测器。
- 唯一规则复用 `app.etl.anomaly.line_flags` 与 `AMOUNT_TOL=0.05`。
- 命中后复用 DEV-05A 的 `create_or_refresh_issue` 唯一写入口。
- `detected_by` 记录真实上传账号；无登录上下文的受控内部导入记录 `system:etl-import`。
- 稳定源指纹不含批次 ID；相同业务内容 upsert 不增加疑点、version 或审计。
- 已核实源发生变化时旧结论转为 `source_changed`：新值仍命中与已不命中两条路径都覆盖。
- 导入尚未提交时检测器也不提前提交；外层 rollback 后事实、批次、疑点和审计同时为零。
- 事实行 ID 使用单个 PostgreSQL 数组绑定，不展开超长 `IN` 参数；事实只加载规则/追溯所需列并按 1,000 行流式分区，每分区只读预取一次既有疑点。
- 两类源变化共用同一状态转换和 `source_changed` 审计动作。
- 批量既有疑点预取不再加 `FOR UPDATE`；创建/刷新/源变化统一进入唯一写入口，锁序固定为 advisory → issue row。写入口返回锁后 `mutation`，并发统计不再用锁前 `existing is None` 猜测。
- 历史回扫仅有 `--dry-run`；数据库事务显式 `READ ONLY`，没有 apply 或定时入口。

### 大批导入查询预算

- 70,000 个 raw line ID：单一数组参数查询通过，不触发 PostgreSQL 65,535 参数上限。
- 1,000 条均不命中：2 条 SQL（批量取事实 + 批量取已有疑点）。
- 1,000 条中 10 条新疑点：42 条 SQL，即固定读取 2 条 + 每条实际写入最多 4 条。
- 第 2 条疑点 INSERT 人为失败：外层 rollback 后批次、事实、疑点和审计均为 0。
- 5,000 条真实采购事实：1 条轻量流式事实查询 + 5 条分区疑点快照；identity map 峰值不超过 1,100，`tracemalloc` 峰值低于 16 MB；重复 100 个 raw ID 仍只扫描 5,000 行。
- 生产等价快照 `spareparts_dev05_stage` 选取 70,000 条当前不命中事实实测：71 条 SELECT、0 写入，`tracemalloc` 峰值 **21.1 MB**（旧完整 ORM 方案约 236 MB）；调用后显式 rollback。

### 并发锁序与统计

- 旧实现被确定性复现为真实 PostgreSQL deadlock：会话 A 批量 `FOR UPDATE` 后等待 advisory，会话 B 持 advisory 后等待同一疑点行。
- 修复后同一交错下，批量快照不持行锁；唯一写入口完成后检测器继续，无 deadlock、无 lock timeout。
- 两个会话同时在锁前看到“疑点不存在”并发检测同一事实行，最终只保留一条疑点；报告恰好一个 `created`、一个 `unchanged`，均取自锁后 mutation。

## 经营数字与权限保护

- dry-run 前后疑点、审计、采购/销售事实摘要和经营 KPI 均保持不变。
- 正式疑点的创建、刷新、失效只写 `fact_data_quality_issue` 与 `sys_audit_log`，不写采购、销售、利润、库存或互通池表。
- 有治理页面但无采购成本权限账号：清单与详情无法看到数量、单价、金额、证据、源指纹或审计证据。
- 无治理页面账号：疑点接口返回 403。
- 本切片没有新增 HTTP 写入口；历史命令只能由有服务器命令权限的运维人员运行，且只有 dry-run。

## 已知风险与边界

1. 快照中预计有 10,619 条存量命中，实际历史写入会形成较大人工核实工作量；本切片刻意不开放 apply，必须另做分批、失败恢复和甲方承载量评审。
2. 实时事实读取为单个数组参数流式查询，既有疑点按每 1,000 个实际事实行分区预取；固定读取预算为 `1 + ceil(scanned/1000)`，实际写入仍按疑点逐条并发保护、每条最多增加 4 条 SQL。候选很多的超大采购/销售文件仍需在 staging 用真实文件测量；库存 20 万行不经过本检测器。
3. `source_changed` 只表示旧结论失效，不自动判定新数据正确，也不自动从任何统计排除。
4. dry-run 要求数据库已包含 DEV-05A 的 `fact_data_quality_issue` 表；部署前必须先确认目标 main 已迁移到当前 head。
5. 独立 Standards/Spec 双轴复审由主会话在空闲 agent slot 中执行；发现 blocker/P1 必须返修后才能建 PR。
