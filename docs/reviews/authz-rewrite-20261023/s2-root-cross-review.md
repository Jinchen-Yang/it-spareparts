## 发现与处理

| 编号 | 触发与影响 | 处理及当前证据 |
|---|---|---|
| S2-R1 | 批量规范化新路径把原逐行提交改成整批事务；与原业务契约不符，且无法在行间撤权 | 恢复逐行锁、重验、提交；两行之间修改 epoch 后首行保留、次行拒绝。组合 69 passed |
| S2-R2 | 别名审核在总写锁之前解析当前 part_id，等待时对象可能变化，后续锁集合可能过期 | 初始解析移到主数据锁内并刷新；真实第二连接改变映射，以 pg_blocking_pids 确认等待期间未查询别名，释放后锁住新目标。组合 89 passed |
| S2-R3 | 疑点 direct-ID 先取整条事实再判断 side，未在 SQL 内限制当前允许侧 | 按允许侧过滤查询；真实跨侧 SQL 反例通过，禁止未授权侧的完整事实加载 |
| S2-R4 | 可拆卸的库存、订单事实、价格策略等块仍依赖复合父接口的总 read；合法独立授权不可使用 | 复合入口改为任一实际块准入，拒绝块不查询/不返回数据；全部拒绝仍 403。列表与详情同时适配，独立块和 SQL 非干扰反例通过；前端最终回归仍待完成 |
| S2-R5 | 旧授权开始的文件下载使用 FileResponse，途中切换新授权后仍可继续传输 | 所有下载均逐块重检；旧文件处理与视觉返回、元信息发布同样检查跨切换。4 条独立反例加入真实 PG 测试；与原来源和 hub 组合 32 passed |
| S2-R6 | 新会话已按稳定用户 ID 校验，随后仍校验历史 owner_sub；同一身份变更用户名后误拒绝 | 新权威只按稳定 ID 和当前实名状态校验，旧兼容保留 owner_sub；独立回归通过 |
| S2-R7 | 升级时没有变化的旧规范空拒绝未记录 receipt，回退时误判为新规范授权 | 对不变但已存在的规范 Grant/模板包记录基线 receipt，不递增升级版本；真实升降级回归验证拒绝和版本单调性 |
| S2-R8 | 消息写入先持有 actor 共享锁，再等待独立事务记录协议使用；与回退先锁 receipt 后锁 actor 的顺序冲突 | 协议标记移至领域和 actor 锁之前；第二连接 FOR UPDATE NOWAIT 证明标记阶段未持 actor 锁，发布前仍重验来源。Agent 组合 41 passed；跨模型静态复查完成 |
| S2-R9 | policy-only 的 GET 已正确隐藏目录字段，但策略保存回执仍返回成员计数、创建人等 | 独立 HTTP 反例先失败；同一锁内批次读取可选 catalog.read，在提交前按同一最小定位合同投影。修复后与原池目录组合 45 passed |
| S2-R10 | 公司池分析用价格策略资源的同名字段开关决定越线展示，混淆两个独立 Grant | 分开 analysis 治理字段与 policy coverage 字段；双向允许/拒绝组合通过真实 Provider 测试 |
| S2-R11 | TaxBasis 的快照已切换但 policyOwner 未更新，首帧把默认税口径当作已验证值 | 跨模型 layout effect 测试先红；同步 owner mismatch 进入 loading 后原样转绿，禁止暂用默认值解释金额 |
| S2-R12 | PartSearch/Master 在 effect 中清理旧查询结果，URL 切换首帧仍可能显示上一对象；定价 OR 展示面误把响应 block 当成动作授权 | 同步 query-owner 投影、独立 AbortController/shared query；财务/询价块另 AND 其动作。跨对象、首帧、取消及伪允许响应反例通过 |
| S2-R13 | 税口径边界包住整个应用，无 display_policy.read 时连权限中心也无法打开；数量块也不应依赖税口径 | 按真实金额消费者定位共享依赖，非金额控制页独立；真实 App 缺共享权限访问账号页与金额页失败关闭通过。库存、型号库存、健康、无成本采购和治理非金额块的独立场景通过；金额区域仍失败关闭 |
| S2-R14 | 直接进入账号页时，快照未 ready 使路由暂时未注册；其他 legacy 页已允许，于是通配重定向提前跳到导入页 | 根代理真实浏览器复现；控制页保留 pending/deny 路由，真实 Provider 的延迟允许/拒绝两例均保持原地址。根代理浏览器再次进入账号页并成功读取列表 |

最小定位信息合同：池列表/详情在任一实际块授权后可返回 `group_id/name/version/status`，它们是已授权信息块所需的对象定位信息。未授予目录或分析时不返回成员、描述、自动签名、分析统计和派生金额；只按已可见的名称/主键排序，不借隐藏事实筛选。型号基础信息被拒绝时 `part=null`，不带描述、分类、品牌；独立事实块仍可使用。此合同需前后端共同测试，不能只删除总门而继续执行原全部查询。
