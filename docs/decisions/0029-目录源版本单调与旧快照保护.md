# D-0049 目录源版本单调与旧快照保护

- 日期：2026-10-30。
- 依据：杨金臣本轮要求保留已拍板口径、对问题采用推荐保守选择并全权完成发布；承接 D-0048 第 7 条与 D-36 目录同步边界。
- 状态：本轮授权内的技术一致性修复，不改变 PN 业务资料、商城人工处理边界或既有业务单据。

## 已验证问题

jinchen-dev 使用实际 PN 建档、人工编辑和主数据锁，复现了先开始的事务在后开始事务提交之后合法更新同一 PN：两项不相交修改均保留，但 `func.now()` 取得事务开始时间，令最终 `updated_at` 倒退。商城按源版本拒绝旧快照时会误拒绝这个合法最终状态。仅修改商城规模测试的旧预期不能解决该问题。

## 决定

1. `dim_part.updated_at` 继续表示本系统目录资料的技术更新时间。对同一 PN 的实际更新，数据库统一保证它严格前进；不把它当作跨 PN 的全局提交序列，也不改变 D-36 活读分页及周期全量对账的边界。
2. 采用数据库行级更新约束覆盖 ORM、Core upsert、治理和规格 touch 等入口。比较非生成列；真实变化时以数据库真实时钟、旧值加一微秒及必要的新值取大。INSERT 保持原语义，完全无变化的幂等导入不得推进版本。
3. 不回填任何现有 PN，不改描述、身份、库存、价格或业务状态。无标记历史版本不能推断为新版本；启用前必须只读比对商城实际用于防旧判断的版本与同一稳定 partId 的源版本。无法解释的源版本落后、身份不一致或采集漂移均阻断，另行复核，不自动改写生产记录。
4. 保留商城所有既有防旧快照、同源锁、人工冲突和 UUID 回执保护。相同版本下既有合法聚合信息更新仍按原契约处理；不得删保护换取 CI 通过。
5. 新增独立 Alembic 迁移，位于本轮 `f1a3c5e7b9d2` 之后，保持唯一 head；迁移只创建/删除技术约束，不修改现存数据。验证真实双事务顺序、时间精度、回滚、ORM/Core/规格入口、导入幂等、迁移往返及旧快照拒绝。
6. 发布期间须先停止旧源端写入，避免新消费端保护遇到尚无单调约束的旧源写入。停写身份、阶段回执、备份恢复、失败恢复边界及两套控制器的保护快照须单独复审；未经完成的源版本门禁不得启用新链路。

## 验证与上线

仅在 jinchen-dev/CI 验证。精确最终提交重新完成独立跨模型复审及必需完整 CI，正常合并，以 release 标签和实际运行镜像、数据库版本及发布回执判断上线。保留用户本地改动，禁止管理员绕过、强推、生产合成业务写入及旧备份覆盖已暴露的新业务。
