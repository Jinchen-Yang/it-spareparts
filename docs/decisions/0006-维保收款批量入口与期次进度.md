# D-28 维保收款批量入口与期次进度

- 日期：2026-10-12。
- 来源：杨金臣提供全公司收款单原件，要求筛选维保部分、跨项目自动归属并批量导入，不必进入每个项目子页。已明确选择“按累计到账计算各期进度”。
- 状态：已确认；复用 D-16 的财务导入与冲突规则，不另建一套收款事实。

## 归属与期次

1. 销售订单号匹配唯一、有效、已映射且纳入总额的维保合同，再归属项目。不按客户名或项目名猜测，不因收款导入创建项目；文件业务类型只用于提示分类，不能代替合同关系。
2. 实际收款日期用于月度累计；期次进度按同一合同的累计实收依次覆盖累计计划计算。一期可分多笔到账，一笔可覆盖多期；不把某月或某笔 SKD 硬绑定到第几期。
3. 预览显示所选可提交行对各期进度的影响；未选择的覆盖行不能计入“导入后”。没有计划时允许正常记收款，但显示未配置计划；没有已确认实收时显示未报，不当成 0 元。
4. 仍使用收款台账、月度快照、来源归档、冻结预览、权限、并发校验和 D-16 去重/裁决机制。只有用户确认后才记账；本次研发不向生产自动导入这份附件。

## 文件及入口

在数据导入及维保主页提供明确的“维保收款单导入”入口，复用既有批量导入接口。默认展示可归属的维保收款与待处理项，非维保部分给出跳过数量及有界样例。

用户原件约 23 MB、约 9.8 万行，包含错误的 A1 维度和大量纵向合并。不能只提高文件上限：需流式读取、保留合并单元格及逐行金额校验，扫描源文件的行数与实际维保业务候选数分开限制，保持 ZIP 安全和有界预览。

收款单完整性校验先于展示筛选：同一张 SKD 中的负数/平账腿不能因属于其他业务而被隐藏后，让维保正数单边入账。备注出现坏账/红冲等文字沿用 D-16 第18条，只标注，不据文字否定已到账金额；真实负数、无效状态及金额矛盾仍按既定规则处理。
