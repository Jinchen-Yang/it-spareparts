# D-0045 售前 PN 就地建档与操作诊断

- 状态：已确认（杨金臣在本轮对话提出）。
- 日期：2026-10-27（America/Los_Angeles）。
- 范围：PR #491 的售前 PN 输入、待建档处理与操作错误反馈。

## 决定

1. PN 输入继续使用现有实时联想，候选展示 PN、描述/简介、品牌、类别和参数；选中已有档案沿用其稳定 part_id。
2. 无匹配档案时，具备主数据建档权限的实名用户可从售前输入处显式打开建档表单，填写 PN、描述、简介、品牌、制造商、主数据两级类别及可增删的参数键值对。类别使用主数据字典，不另造 CPU/GPU 分类。
3. 建档成功后将返回的主数据身份加入当前编辑内容。未保存的询价/主动报价通过现有主数据建档接口操作；已提交询价的待建档行继续通过原子“新建并绑定”接口，沿用处理人、权限、版本、审计及查重约束。单纯输入、检索或选中候选不创建主数据。
4. 保留仅按原文加入待建档行的路径；不扩大现有角色权限，不自动提交询价、发布报价或调用 AI。参数写入主数据规格，与建档在同一事务内完成，并标为人工维护。
   标准参数沿用现有键和规范单位；其他参数存入 `custom:<名称>` 文本命名空间（名称 1–25 字符、值 1–128 字符），不假定其数值单位，不参与标准数值规格计算。普通未知规格键仍拒绝。
5. 售前点按失败提供中文原因和恢复建议，以及可复制的诊断信息（错误码、HTTP 状态、请求方法/路径、服务端请求标识）。区分版本冲突、重复 PN、权限不足、字段校验、网络和服务端故障；不把所有 409 一律说成“被他人修改”。
6. 失败保留当前输入；诊断信息不包含凭据、请求体或完整业务响应。写入成功但后续刷新失败必须明确区分，避免用户误以为写入失败而重复操作。

## 验证

覆盖新建与绑定的资料/参数持久化和失败回滚、权限与查重、候选选择与表单键值对、错误分类与诊断信息，以及售前既有流程回归。无数据库迁移。完成本地回归后待用户点按验收；本决定不授权生产部署。
