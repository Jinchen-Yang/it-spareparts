# D-0067 维修任务单正式接入维保返还

用户在三页原型评审后授权接入真实前后端，要求主管建单时在左侧使用维保备件返还。办理流程依据 [#549](https://github.com/Jinchen-Yang/it-spareparts/issues/549) 和 [D-0070](0050-维修任务池三页原型.md)。

- 主管建单左侧的联动来源限定为维保返还台账，使用返还行 ID 与版本，并按主管的维保项目范围提供可送修明细。氚云《返库单》留在原仓储流程。右侧填写任务条及维修方式。已确认坏件、有效 PN、正整数件数才可送修。组件明细随整机登记，避免独立件数重复选取。
- 建单后，所选数量在维修任务条占用。新任务与 D-0058 已生效结果共同扣减同一返还行的容量。创建、主管更正和旧维修扣数仍守同一 PN 锁及返还数量约束。退回主管保留原单及占用。主管删除未办理的任务条或下调数量时释放相应占用。返还原单维持自身业务状态。
- 三页使用实名登录、按账号授予销售、维修主管、维修人员、去向管理员能力。销售查看自己的单，维修人员查看公共池与本人任务，主管管理维修单。主管的返还来源读取及挂靠受现有维保项目范围约束。多人操作以服务端版本及事务判断，负责人记录由服务端追加。
- 电商和主公司登记去向及数量，二次维修建立关联单。电商去向、结果标签和导出以 [D-0071](0051-维修结果去向标签与导出.md) 为准。历史循环记录保留。
- 本地验收可使用独立的生产快照副本。写入和并发回归使用隔离的测试库。
