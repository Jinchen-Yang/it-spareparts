## 决定

1. **价值保留比例缺省 50%（Sunny 01:20 修正，覆盖早期「无默认」段）**：
   `value_retention_ratio` 是请求级试算参数，[0,1] 有限小数；**未提供/空白 =
   0.5**，20%/30% 仅作为可选项（快捷入口 0.5/0.3/0.2，0.5 即默认）；显式 `0`
   合法且必须保留为 0——解析禁止 `ratio or 0.5` 写法（会把显式 0 吞成默认）。
   非法/非有限/越界一律 422 `invalid_retention_ratio`，对所有角色一致校验。
   **参数接收面 = summary/projects/parts/valuation/receipts/export 六处**（/projects
   起初漏接、致行级恒 `awaiting_ratio` 且与导出同屏分裂，root 裁决后端补传，
   2026-10-22 修正轮补齐并有红→绿钉住）。有利润门权限者不带参数首查/刷新/导出
   即按 0.5 试算并回显（`policy.retention_ratio` 与 `cards.valuation.retention_ratio`
   回显 `"0.5"`）；数量账号不因缺省泄露金额或政策键，也不得被要求提供该参数。
2. **试算不落账**：比例只作用本次请求与伴随导出；不写全局政策、历史成本、
   成本链或任何业务事实（估价只是经营试算，非变卖收入）。
3. **窗口与旧口径废除**：参考样本窗口 = 含统计结束日的 7 个上海日历日；
   R33 旧预设系数（坏件 20%/废品 5%/成品折算 100% 预设）与 30 天窗口废除；
   商城 30 天参考价政策（D-43 等）不受影响。
4. **三域独立（R34-05）**：采购优先、销售回退构成主展示参考；领用已计成本
   只作独立并列视角，不暗替市场首选；三域估值不相加、不混均价。某域缺样本
   只是该域不出值，不得抹掉其它域（含 PN 行、总览卡、导出三处一致）。
   成本域必须先证明主单位（`DimPart.unit` 规范化有效）才给参考；缺主单位 /
   缺样本单位 / 混用单位一律待估（`unit_missing_master` / `unit_missing_sample`
   / `unit_mixed_samples`），不按名称猜单位。成品返件按参考全值另列
   （`finished_estimated_value_*`），不混入坏件主卡与三域聚合。
5. **状态机与「待估不填 0」**：行/PN/总览三级状态 ready（有可估行）→
   pending（缺样本待估）。`awaiting_ratio`（缺比例待试算）是服务层 ratio=None
   直调时的保留态；HTTP 层缺省恒 0.5，该态经 API 不可达，`awaiting_ratio_bad_qty`
   键保留、恒 `"0.000"`（形状兼容）。全部待估时不出 0 元金额卡/金额键（键不存在，
   不是 0）；未知件况（未填/其他/任意文本）不估价。
6. **权限模型（延续 R33 D-0022）**：全部端点 = 登录 + `page_maintenance` +
   项目范围交集（空交集保持空，绝不回退全量）；金额可见 = admin 或运行时
   `data_profit`；`/valuation` 额外挂利润门；无金额权时金额/参考/覆盖/政策键
   **整个不存在**（不是 0/null），导出不出金额列头，金额排序 `bad_value_desc`
   强行请求 422 `sort_requires_profit_permission` 并记审计。
7. **M01 期间下单**（独立模块 `maintenance_dashboard_consumption.period_orders`）：
   制单日期入期 + `已生效` + 未墓碑（沿 T4 无条件语义）+ 活跃挂靠的有效需求单行，
   Σcoalesce(qty,0) 原始数量（**不扣退货、不扣免返**）+ 去重单数；纯数量域，
   任何角色无金额列；无关键词参数。
8. **M03 每日每项目已计消耗**（同模块 `daily_consumption` / `consumption_issue_rows`）：
   mapped + confirmed/corrected + 行有效的领用数量全计；金额**只读**既有
   `cost_amount` 双税已知小计，另报未计成本量/覆盖率/成本来源；未计成本行
   `cost_source=null` 且无金额键；只读不回算、不减返件估值、不覆盖成本链
   （原取价证据可能晚于领用日，响应 note 明示）。明细下钻支持 `issue_date` /
   `project_id`（与授权范围取交集），API 与导出可核对日表。
9. **生产隔离红线**：看板 API **不得** import 生产巨型 `app.api.maintenance`
   （无 `_safe_formula_only`，且会拖入无关业务）；CSV 防公式净化放独立模块
   `services/maintenance_dashboard_export_text`（`safe_formula_only` 只对
   `=`/`@` 一律、`+/-` 公式形态加撇号，控制字符清理与 32767 上限转 413）；
   不引用 `resale_price_reference` 私有 helper。流式导出自持（BOM、spool、
   64MiB/512MiB/100 万行/50000 行导出上限 413）。
10. **兼容**：R33 四视图（summary/projects/parts/receipts/quantity-checks）
    数量键形状不变；金额键按上列新增/更名（估算→试算列名）；`policy_version
    = "mdv-2026-10-22-r34"`；跨系统消费者（商城）不消费本路由，无兼容影响。
