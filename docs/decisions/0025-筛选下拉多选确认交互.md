# D-0025 筛选下拉多选：独立搜索与确认提交

- 来源：杨金臣在本次会话要求“方框点选，下拉一个面板，然后可以重置，搜索，然后确定”，并固定为可复用多选框。
- 状态：已确认交互方向，候选实现待点按验收。
- 首批范围：销售分析与采购分析的销售人员筛选。

## 交互契约

1. 通用组件使用下拉面板和复选框；搜索输入与已选结果摘要分离，不再把搜索光标挤进姓名标签。
2. 面板内维护选择草稿；勾选与搜索不更新页面筛选、URL或查询，点击“确定”才一次性提交。
3. “重置”清空面板草稿及搜索词，点击“确定”后才清空已应用筛选。点击外部或Escape关闭时放弃未确认草稿。
4. 再次打开从受控value恢复已应用选择；父页面重置/前后导航或会话失效改变受控状态时，不允许旧草稿覆盖新状态。
5. 未选显示选择提示；单选显示姓名，多选显示“已选N项”及可核对摘要；面板支持查看完整已选列表，包括不在当前候选中的已选值。候选辅助计数不进入关闭态姓名。
6. 组件不认识销售业务或URL，不触发网络请求。选项value支持string/number；由调用页转换各自数据与提交方法。
7. 两页保留现有URL/API参数：销售salesperson_name、采购salesperson，确定时使用既有patch并归一分页。其他筛选交互与权限策略不在本次范围。

## 验收

真实浏览器验证单人、多人、长名、窄屏、搜索与复选状态、滚动、键盘开关面板、取消、重置后确定。组件测试覆盖草稿与已应用隔离、跨搜索保留、外部value变化、禁用项及未知已选值；页面集成测试验证确定前无筛选请求/URL变更，确定与重置确认后参数正确。
