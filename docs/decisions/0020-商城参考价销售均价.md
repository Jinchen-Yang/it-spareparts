# D-42 商城参考价：销售均价（30 天窗口 + 时间衰减）

- 日期：2026-10-19。
- 来源：杨金臣 2026-10-19 09:33Z 口径（经 PM 转述），替代同日实施计划中所有“最近 12 个月”默认；其余默认沿用计划并经本轮实现固化。
- 状态：**窗口与时间衰减已拍板**；订单状态、业务范围、零价、加权方式、数据质量、金额来源、币种精度、最低样本门槛等细项仍按本文件默认/待确认说明执行，不冒充已确认业务决策。
- 范围：itsp 新增只读 GET `/api/integrations/resale/parts/price-reference`，供商城详情页点击查询。不进入目录 `/list`、`/snapshots`、catalog v2 发布或人工资料命令；不写任何业务状态；无 Alembic 迁移。

## 决定

1. **窗口**：`end = business_today()`（Asia/Shanghai，注入式可测）；`start = end - (window_days - 1)` 天，闭区间，含今天共 `window_days` 个日历日。默认 `RESALE_PRICE_REFERENCE_WINDOW_DAYS=30`，允许 1..366。不使用自然月平移，删除“12 个月”默认。
2. **时间衰减**：每行 `age_days = (end - order_date).days`（0..window_days-1），权重 `d = 0.5 ** (age_days / half_life_days)`。默认 `RESALE_PRICE_REFERENCE_HALF_LIFE_DAYS=7`（Decimal，>0 且 ≤3650）。
3. **加权**：配置值 `RESALE_PRICE_REFERENCE_WEIGHTING=qty_weighted`（默认）时每行 `w=qty*d`；`line_mean` 时每行 `w=d`。响应 `calculation.method` 分别为 `time_decay_qty_weighted` / `time_decay_line_weighted`，并声明 `decay="exponential_half_life"`。
   - 含税均价 `Σ(w×unit_price)/Σw`；未税均价 `Σ(w×unit_price/(1+r))/Σw`。
   - 在 SQL 按 `(order_date, 有效税率)` 分组取精确 Decimal 聚合值，Python 用 Decimal 完成衰减加权，避免浮点漂移；最终按 HALF_UP 保留两位。
4. **税率与税基**：销售 `unit_price` 恒含税；有效税率 `r = 票面非零税率，否则 13%`（复用 D-39 `_rate_expr`）。同时返回含税、不含税两条 `kind=sale` 价格，不返回采购价。**2026-10-20 更正**：按 [D-43](0021-商城参考价采购均价.md) 在销售条目后追加采购含税、不含税均价；销售口径及顶层 `calculation` 的销售样本语义不变。
5. **名义样本**：票面税率为 NULL/0 时，未税侧是按 13% 推算的名义值；价格条目的 `nominal_sample_count` 在含税侧恒为 0，未税侧为该类参与行数。
6. **样本与日期**：`sample_count` 为参与明细行数，`order_count` 为 distinct `FSalesOrder.id`，都不是销量。每条价格和 `calculation` 都带 `window`、`latest_sale_date`、`oldest_sale_date`；空样本时后两者为 null、计数字段为 0。`occurred_at` 为最近合格销售日的上海零点，不是抓取时点或真实成交时刻。
7. **默认过滤**（均只作用于本 GET）：
   - 只计 `data_status` ∈ `RESALE_PRICE_REFERENCE_ORDER_STATUSES`（默认 `["已生效"]`，非空、去重、只允许既有四种状态）；不依赖全局开关。
   - `RESALE_PRICE_REFERENCE_COUNTS_REVENUE_ONLY=true`：消费已落库的 `counts_revenue` 布尔值。
   - `RESALE_PRICE_REFERENCE_INCLUDE_ZERO_PRICES=false`：false 取 `unit_price>0`，true 取 `>=0`；负价与 NULL 始终排除。
   - `qty>0` 恒固定；`RESALE_PRICE_REFERENCE_EXCLUDE_CONFIRMED_SOURCE_ERROR=true` 时用 NOT EXISTS 排除已确认源错误，不排除未确认疑点/普通异常，不做离群裁剪。
   - 无合格样本仍返回完整 `pn/reference_only/calculation` 且 `prices=[]`，不返回伪零价格。
8. **PN 身份**：复用既有 `/resolve` 的标准化、规范名精确、active 别名与 `_canonical` 合并链规则；对每个候选先 canonical 再按最终 id 去重。pending 别名、不同最终目标、循环、断链或超过 10 跳一律 409；同一最终身份可用。原 POST `/resolve` 行为不变。
9. **错误**：未配置服务凭据 404；缺失/错误 Bearer 401；参数非法 422；身份歧义 409；数据库、聚合结果、坏税率或超出商城金额上限 503（固定文案，无 SQL/参数）。成功（含空样本）与手工 409/503 均带 `Cache-Control: no-store`。
10. **隐私**：响应只经白名单 DTO；不返回客户、单号、人员、销售行/订单 ID、原始证据、原始税率明细或内部错误。

## 待确认细项（不阻塞本实现）

- 30 天是否含今天：本实现含今天共 30 个日历日。
- 半衰期 7 天为 PM 默认值；qty 是否参与权重：默认参与。
- 订单状态是否只“已生效”、是否只计 `counts_revenue`、零价是否纳入、是否沿用“仅排除已确认源错误”、是否需要最低样本门槛、是否需 4 位单价精度——均按上文默认，业务确认后只改配置，不改公式。
