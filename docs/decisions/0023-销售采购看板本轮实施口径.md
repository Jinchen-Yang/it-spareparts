## 决定

1. **角色硬界**：销售分析与采购分析仅 `admin`/`boss` 可访问（`ENABLE_RBAC` 开启时
   API 层硬校验 403）。页面键控制菜单，角色硬界控制数据面——`purchaser`/`readonly`
   即便被显式授予 `page_sales_analysis`/`page_purchase_analytics` 也 403；
   PHASE1 旁路（ENABLE_RBAC=False）不受影响。受限销售（own_customers_only）403。
2. **金额信息整体走成本权限（Q-A-03/A-AC03）**：无 `data_purchase_cost` 时，三口径
   （含 revenue）的金额区间 / 正负 / 空值开关筛选与金额分布直方图一律 403，options
   金额上限全 null——区间结果的单数本身泄漏金额分布，营收无例外。
3. **金额区间恒比整单口径（Q-A-02，预审线索 2 修复）**：不含税/含税比原单头事实列；
   营收无单头列，用**整单营收相关标量子查询**（`header_revenue`，与行级 join 无关）。
   行级筛选（大类/品牌）只决定展示金额=匹配行合计（「整单入选、匹配行计额」）。
   options 金额上限与直方图同一整单比较域。
4. **许可开关∩有限区间（Q-A-06，预审线索 3 修复）**：`include_negative=false` 时
   负区间内的负单同样排除（区间不绕过开关）；无金额单无法与有限区间比较自然不入；
   开关单独（不限区间）语义不变。
5. **对账列排序经 DISTINCT ON 最新快照子查询（预审线索 1 修复）**：uv.lock 锁定
   SQLAlchemy 2.0.49 无 `Select.distinct_on`（旧写法组 SQL 前抛 AttributeError），
   用 `Select.distinct(*expr)`（PG 方言 DISTINCT ON）。快照排序序与
   `latest_snapshots_by_raw_order_id` 一致：修改时间 DESC NULLS LAST → 批次 → id。
6. **趋势无日期单守恒（A-AC05/DL-019，预审线索 4 修复）**：「全部」口径追加显式
   无日期桶（`bucket=null, no_date=true`，单数+金额同口径），桶合计（含无日期桶）
   = KPI 合计的订单数**与金额**；有日期区间时 `no_date_orders` 计数 +
   `no_date_amount_*` 金额提示，不只靠说明文字。
7. **排序回退（Q-A-04，预审线索 5 修复）**：被遮蔽的金额/毛利/客户/对账排序键
   静默回退——订单列表/导出回**公开口径 order_date + id**（不退回 revenue，营收
   行序同样是排名信息），分组排行回 `orders` 单数。API 层 `effective_sort` 与
   服务层 `orders()` 双保险。
8. **客户派生聚合收敛（预审线索 6 修复）**：`data_customer` 不可见时
   `customers/new_customers/returning_customers/undetermined` 结构化置 null（递归，
   含 summary/compare/groups/trend）——聚合计数本身是客户情报。只动标量计数：
   options 的 `customers` 候选**列表**已被 customer 门控成 `[]`（防存在性探测），
   不覆盖成 null。与 revenue_costed/cost_coverage 同理不做全局键登记（老板看板
   同名键公开，全局登记会改变既有契约）。
9. **明细行营收组合遮蔽（A-AC01/DL-006）**：无 `data_purchase_cost` 时订单详情
   每行 `qty/unit_price/line_amount/revenue` 全 null（阻断 营收÷数量×1.13 精确
   重建成交单价，反例 2000×1.13÷2=1130）；单头聚合营收沿公开口径。
10. **叶子舍入守恒（A-AC04/DL-018）**：行级口径每条明细先各自舍入到分（含税=行
    金额或 数量×单价；不含税=含税÷1.13 名义）再求和，订单/分组/趋势/KPI 对同一批
    叶子值逐分守恒（56.55×2 反例：整单舍入差 8 分）。
11. **缺失语义（A-AC06/DL-020）**：所有维度 NULL/空串/全空白（含全角空格）统一归
    缺失（`nullif(btrim(col, ' \t\r\n　'), '')`）；分组键 NULL+`is_empty`，与真实
    名叫「未填」的对象不碰撞；筛选缺失传哨兵 `__empty__`。GROUP BY 用原始列
    （SELECT 表达式与 GROUP BY 各自渲染 `_norm_dim` 会产生不同绑定参数 → PG
    GroupingError）。
12. **直方图守恒（A-AC09）**：右端闭（8000 落 [8000,9000)），段宽 1k 整数倍、
    段数 ≤ bins，负单/无金额单单独计数，`sum(bins)+negative+empty == total`。
13. **极值日期不 500（A-AC10）**：月平移越界抛 `DashboardValidationError` → API
    422 或对比期不可得；趋势序列触日历尽头正常收尾。
14. **KPI 边界（Q-A-05/Q-A-07/Q-A-10）**：营收>0 且全未配成本→覆盖率 0%（毛利
    null 显示「待配成本」）；无订单合计 null 不伪造 0；分母≤0（含负）占比/毛利率/
    增长 null；全范围不拆新老客。
15. **CSV 导出（D-33）**：防公式纯函数提取为 `services/sales_export_text.py`
    （生产基线 api.maintenance 无 `_safe_formula_only`，不可从该巨大 API 模块
    import）；`= /@ /+/-` 公式形态转义、负数负 PN 不误伤、控制字符剔除、32,767
    上限 413、超深括号按公式转义、长度闸门在启发式之前（ReDoS）。被遮蔽列整列
    不导出；≤10,000 行。
16. **采购分析（D-39）**：仅加角色硬界（同 1），其余口径与 main 一致；图表由前端
    基于既有四端点数据实现，不新增后端、不新增前端依赖包。
17. **CI**：`.github/workflows/ci.yml` 仅在 `on:` 下新增 `workflow_dispatch:`——
    发布 runbook 要求按确切 release 提交 SHA 验证 CI（徽章只反映 main），手动触发
    提供该入口；其余 CI 定义/保护不动。
18. **第四对账列排序（本轮返工，反馈§2）**：`return_reconciled_amount` 加入
    `RECON_SORTS`——按最新快照（修改时间空值末→批次→id，与展示同源）的退货已
    对账原值排序，不随 `include_returns`；无对账权限回退 `order_date`；NULLS LAST
    两向 + id 同向破并列；导出同键。
19. **分组排序补齐（本轮返工，反馈§3 / A-AC07）**：`GROUP_SORTS` 增 `lines` /
    `avg_order` / `basis_change`。`lines` 只对行级维度（category/brand/pn）合法，
    单头维度无该列 → `DashboardValidationError` → 422（groups 端点补 trend 同款
    转换）；按当前匹配行集合。`avg_order` 按响应 `amount_basis`（被遮已强制
    revenue）÷ 组内去重单数，排序与展示同口径。
20. **真实同期变化排序（本轮返工，反馈§3）**：`basis_change` = (当期−上期)/上期
    （响应 `amount_basis` 口径），与前端 `changeRatio` 同式；基期未知 / ≤0 或本期
    未知 → 不可比较（Q-A-07，禁 abs(基期) 造增长），两向空值末尾，同率并列组键
    升序；**不得以金额排序冒充**（金额降序头部 ≠ 变化降序头部，测试有数学反例）。
    对比期行只取一次（排序先于 TopN，compare 附值复用）。未开 compare/对比期不可
    用 → 全部不可比较 → 组键序（静默，不报错）。
21. **CI 追加（本轮返工）**：`on.push.branches` 增 `release/**`（保留 main/test、
    pull_request、workflow_dispatch 与全部 job/step）——P 派生 R 自身 push 即可跑
    精确 SHA CI，不依赖手动触发。
22. **客户数排序防侧信道 + 派生排序同源口径（permissionfix 轮，反馈§4A / Q-A-04）**：
    无 `data_customer` 时非客户维度的 `sort=customers` 退回公开单数并如实回显
    `orders`——计数置 null 之外，**行序按真实客户数同样泄漏相对规模**（冻结反例：
    A 销售 3 单 1 客户 vs B 销售 2 单 2 客户，两向都反序，可被逐向抓住）；客户类属
    分组本身仍 403，回退不放宽硬界；有权账号照常真实客户数排序。`avg_order` /
    `basis_change` 两个派生金融排序金额全遮时按 `_public_basis` 强制后的公开
    `revenue` 口径（排序值 = 展示值，revenue 是未登记公开键）。服务层
    `sales_dashboard.groups` 新增可选 `user_ctx`，与 API 同判据双保险（被遮
    金额/毛利/客户数排序退 `orders`、被遮口径退 `revenue`）；不带 ctx 的内部取数
    行为不变。
23. **行级归一分组唯一键（normalizedfix 轮，A1 独立审查阻断）**：category/brand/pn
    的 SELECT 归一与 GROUP BY 必须同一表达式——旧写法 GROUP BY 原始列，NULL/空串/
    半角或全角空白归一成同一 key 却各成一行（三缺失变体返回 3 个重复 null 组；
    top=1 时「其他」按 rest_keys 匹配把头部同 key 行再计一遍：Top1 1000 + 其他
    3000 = 4000 ≠ KPI 3000，含税 3390→4520、营收 2700→3600）。返工在**命名子
    查询**里先算好唯一归一 key（规避带绑定参数表达式不能直接放 GROUP BY 的 PG
    限制），外层对子查询列分组；过滤聚合（FILTER）改内层 CASE 预备列、外层
    SUM（跳 NULL，全空 → NULL，语义等价）。禁止前端去重或 Python 盲加已聚合
    的 orders/customers（同单多行 distinct 会重计）——去重在 SQL `count(distinct
    order_id/customer)` 内完成（同单 3 行同组 → orders=1/lines=3）。对比期、
    行级筛选与分组同用同一归一；首尾空白（含全角）同名归同组；同规范 PN 配不同
    raw 别名合并（pn_std 优先、NULL 落 pn_raw 同样归一）；「未填」真实名不与缺失
    null 碰撞；叶子舍入不变。
