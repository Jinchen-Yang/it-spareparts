# D-44 销售看板：分组、趋势、订单金额区间与毛利

- 日期：2026-10-21。
- 来源：杨金臣对《[销售看板（销售分析 v2）编码前设计方案](../销售看板_编码前设计方案_2026-10-21.md)》§六 的答复（2026-10-21）。
- 状态：已拍板口径（第 1–6 条 2026-10-21 首答，第 7–13 条同日追加）。实现按方案 §七 分批进行。

## 背景

D-41 的销售分析页只有区间 KPI 与按金额倒序的大单列表。甲方要按客户、按销售、按时间看销售数据，可以升序和降序，可以看金额区间。

## 决定

1. **扩展现有「销售分析」页（Q1）**：`/sales/analytics` 改为公共筛选栏（含金额区间拖动条）加四个视图（概览、分组排行、趋势、订单明细），沿用页面键 `page_sales_analysis`（admin/boss），不新增页面或权限键。D-41 §1–§6 的口径（已生效单、三金额并存、业务类型原值、日期预设默认今天）全部继续适用。
2. **“按客户分类”两种都做（Q2）**：分组维度同时提供「客户」（单个客户）和「客户类型」（`dim_customer.customer_type`，原列「客户类型」原值，空值显示「未填」）；两者也都可作为多选筛选。
3. **“价格区间” = 订单金额区间（Q3）**：按单头订单金额的下限 / 上限筛选订单（形式见第 7 条）。**金额区间默认不限（全部金额）。** 本轮不做明细单价区间。
4. **任意列升序 / 降序（Q4）**：放开 D-41 §2 的“倒序”限制——订单明细、分组排行、金额区间表的任一列都可升序或降序；空值无论升降都排在最后，再按键 / id 破并列。金额被遮蔽的账号按金额排序时退回按单数排序（防行序泄漏，沿用现有 `sort` 回退）。
5. **加入毛利（Q7）**：看板展示毛利、毛利率与成本覆盖率，口径与老板看板 KPI（`services/dashboard.kpi`）一致，本模块只消费不重算：
   - 已配成本营收 = 计营收行中 `cost_moving_avg` 非空行的 `revenue_amount` 之和；
   - 毛利 = 已配成本营收 − 对应成本；毛利率 = 毛利 ÷ 已配成本营收；成本覆盖率 = 已配成本营收 ÷ 营收；
   - 未配成本的营收不计入毛利，页面同时显示成本覆盖率，不用推算成本补齐；
   - 可见性随 `data_profit`（`config.FIELD_GROUPS["profit_amount"]` 等既有组），新增键逐字登记；无权限时不能按毛利排序（沿用 `ranking_restricted`）。
6. **本轮不做回款视角（Q8）**：不展示已对账 / 待对账 / 回款率卡片。金臣 2026-10-21 说明：销售订单的回款导入在实际使用中尚未适配，等适配后另行决策。订单明细里现有的 D-40 对账块保持不变。

7. **金额区间 = 双端拖动条（Q3 补充，2026-10-21 追加）**：不设固定档位。用一根两端可拖动的滑块选订单金额下限 / 上限，两端也可直接输入数字；**最小步长 1,000 元（1k）**，输入值按 1k 取整。滑块范围为当前其他筛选条件下订单金额的 0 至最大值（向上取整到 1k）。默认不限（第 3 条）；拖到两端极值等同不限。区间比较的金额口径在拖动条旁单独选择（三金额之一，默认不含税金额，因其 100% 有值）。金额被遮蔽（无 `data_purchase_cost`）的账号不能使用金额区间（后端 403、范围返回 null），防止用筛选结果反推金额。
8. **行级口径（Q5）**：按商品大类 / 品牌筛选或分组时，订单拆成明细行、只计匹配行（与 D-39 §5 同一范式）。行级含税 = 行金额（为空时 数量 × 含税单价）；行级不含税 = 含税 ÷ 1.13，页面标注「名义（按 13% 推算）」；营收与毛利只计匹配的计营收行。行级分组的单数之和可以大于总单数，表头注明。
9. **对比期 = 上个月（Q6）**：不做去年同期（硬件市场逐年变化大，同比无参考意义）。对比期 = 所选区间整体前移一个自然月（如 10-01–10-21 对比 09-01–09-21；昨天对比上月同日）；日期落在不存在的日子（如 3-31 前移）时取该月最后一天。所选区间长于一个月（半年、一年、全部）时与对比期重叠，不提供对比。
10. **负金额单与无金额单（Q9）**：都计入合计，另加两个筛选开关「含负金额单」「含无金额单」，默认都开。无金额指金额区间所选口径为空（如含税订单金额缺失）。
11. **客户权限（Q10）**：没有客户信息权限（`data_customer`）的账号，不能按客户、客户类型、客户城市、客户来源筛选或分组（403），与按客户筛选的现有规则一致。
12. **客户按规范名合并（Q11）**：客户筛选、客户排行、新老客都按 `dim_customer.name_normalized` 合并，同一规范名下的多个 `customer_id` 算一个客户；规范名为空的单显示「未填客户」。
13. **新客 / 老客（Q12）**：做。新客 = 首单日期落在所选区间内的客户；老客 = 区间内有成交、但首单早于区间的客户。首单 = 该客户（按规范名）全历史已生效销售单的最早 `order_date`，不受业务类型等其他筛选影响。「未填客户」不参与新老客划分。

## 影响与验证

- 只读；不改老板看板 `/dashboard/*`、`REVENUE_BUSINESS_TYPES` 与利润计算链路；不需要数据库迁移。
- 验收：同一筛选下 KPI 合计 = 分组排行各组合计（含“其他”）= 趋势各桶合计 = 订单明细合计（金额区间筛选下同样成立）；毛利合计与 `/dashboard/kpi` 同区间结果一致（±0.01）；升序 / 降序翻页不丢行、不重行；权限矩阵 admin/boss 可见，其他角色 403，关闭 `data_profit` 时毛利为「—」且不能按毛利排序。
