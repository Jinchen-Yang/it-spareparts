# D-0054 需求单导入改挂已归属销售单

- 日期：2026-11-04。
- 状态：已确认。拍板人：金臣。合并不等于上线。
- 背景：修复模式重导需求单时，若某张已挂项目的需求单把销售单（XSDD）改成另一项目已经拥有的销售单，`trg_maintenance_order_claim_xsdd` 会替旧项目认领新销售单，触发 `ck_maintenance_project_xsdd_single_owner`（SQLSTATE 23514）。整文件回滚，上传人只看到「系统处理异常」。

## 已确认

1. **上传的需求单是这次改挂的准绳。** 修复模式（upsert）里，一张已挂项目的需求单如果把销售单改成另一个项目已经唯一拥有的销售单，就把这张需求单的项目挂载改到该销售单所属项目，并继续导入本文件的其他行。跳过模式不改已有销售单，因此不改挂。
2. **一个销售单仍然只属于一个项目。** 不删除、不放宽 `maintenance_claim_project_xsdd` 和 `ck_maintenance_project_xsdd_single_owner`。改挂是先把需求单从旧项目摘下，再挂到已经拥有新销售单的项目；旧销售单的归属保持不变。
3. **每次改挂都要让上传人看见。** 导入结果记下需求单号、原销售单、原项目、新销售单、新项目。批量作业的说明里给出同样的摘要。
4. **无法唯一确定归属的行只丢本行。** 新销售单已经同时落在多个项目上时，本行（该需求单及其明细）不写入，库内原销售单和原挂载保持原样，并用可读的中文逐行说明。销售单号与库内相同，只要该销售单仍同时落在多个项目上，同样拒绝本行，不能借同号重导继续写入。同文件其他行继续导入，不因这一行回滚整个文件。被拒绝的需求单不进入缺行作废候选，也不再被本批自动挂靠。
5. **仍因该约束失败的文件不再显示「系统处理异常」。** 若 23514 / `ck_maintenance_project_xsdd_single_owner` 仍然冒出并导致整文件回滚，作业说明和上传接口改成说明销售单归属冲突的中文，不把数据库异常原文返回给上传人。
6. **其他写入错误只丢本行。** 修复模式写入某一张需求单时，如果失败不是上述单归属约束，回滚这一张单，中文说明本行未导入，其余行继续。客户、商品、别名和事实行在同一保存点里，这类失败（例如 23502）不把整文件打成 HTTP 500。旧项目上还有其他需求单时，不归档该项目，也不摘掉那些需求单的挂载。

## 不在本决定内

不合并历史多项目销售单，不改人工改派的权限和乐观锁，不改跳过模式，不自动重放已经失败的生产导入作业。
