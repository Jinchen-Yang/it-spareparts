# D-40 销售单已对账快照

- 日期：2026-10-17。
- 来源：杨金臣对《itsp 客户需求 Round1 开发计划》的答复（2026-10-17，含当日追加）。
- 状态：已拍板口径；实现分 PR 进行（迁移 PR-1、导入与回填 PR-2、接口 PR-3b、前端 PR-4b）。生产回填只在门控发布中执行。

## 背景

氚云销售订单导出含「已对账金额 / 待对账金额 / 退货已对账金额」，现有导入丢弃这些列。只读核查（76 份原件、10,591 单）显示：值是订单级累计快照，同一订单多次上传取最新；退货已对账与已对账是并列的两块（有退货已对账的 181 单中 174 单满足 订单金额 = 已对账 + 待对账 + 退货已对账）。

## 决定

1. **已对账金额 = 实际回款。**
2. **导入改造**：销售导入识别上述三列及「修改时间」，每次导入为每个订单追加一条快照；skip 与 upsert 模式都写；文件没有对账列则不写；空单元格存 NULL，不当 0。快照不覆盖、只追加。
3. **快照表**：新表 `f_sales_reconciliation_snapshot`，按 (氚云数据ID, 导入批次) 唯一；“最新值”按氚云「修改时间」较新者，其次批次号较大者。
4. **每单展示**：已对账、待对账、退货已对账、数据截至时间；无快照显示“无对账数据”，不显示 0。
5. **含/不含已退货开关**：含 = 已对账 + 退货已对账（退货已对账不扣除）；不含 = 只看已对账（退回的钱去掉）。**默认 = 不含。** 不写死扣减。
6. **可见范围**：老板、管理员。新增数据权限组（实现时命名，暂名 `data_reconciliation`），角色模板仅 `boss` 开，admin 恒全开。
7. **回填**：从已归档的历史原件回放。06-30 之前的销售单也用已有历史 Excel 重导（并入同一回填作业）。回填脚本默认 dry-run，执行需实名操作人与清单校验码；生产执行只在门控发布中进行，先备份。
   - 事实说明：截至 2026-10-17 只有 2026-06-30 起的 76 份原件带对账列；更早的原件没有，重导不会产生 06-30 前的已对账值（含税订单金额仍可回填，见 D-41）。

## 影响与验证

- 不改 `f_sales_order` 既有列语义与 skip 模式对既有列的“不覆盖”行为。
- 与维保项目合同级收款（`maintenance_collection_snapshot`）相互独立，本轮不打通。
- 验收：回填 dry-run 得到 76 文件 / 10,591 单 / 已对账合计 255,011,389.07 / 退货已对账合计 1,439,441.60（±0.01）。
