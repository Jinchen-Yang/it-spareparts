## 已确定需求

1. 全部业务集中在 ITSP 一个模块、一个主菜单下，菜单名为“检测与维修”。本期不实现检测流程。
2. 从维保返件取得坏件和好件，统一进入池子；以 PN、数量、主数据描述列出物品。
   好件入池后允许不经维修，直接分流到电商系统或主公司（用户后续回复“1”，按第一个问题的选项 1 记录）。
3. 专门人员按 PN + 数量分配送修，支持委外维修和内部维修。
4. 委外维修可设置追踪人，负责跟进该批维修件。
5. 维修返回后记录“修好了 / 没修好”以及备注。“没修好”不自动视为报废。
6. 返回后的去向由人选择：电商系统、主公司、二次维修。二次维修回到待分配池，并明确标注“二次维修”。修好不再自动决定送电商。
7. 支持公共池和人员指派；被指派人员可看到自己的任务及公共池任务。
8. 送电商本期包含实际入库对接（用户对“完成实际入库对接 / 仅记录去向”回复“1”）。人工选择电商去向后触发入库对接，不能只登记去向即当作入库完成。
9. 依据补充会议纪要，电商上架由内部人员手动决定。实际入库与上架分开记录，入库成功不自动变为可售。
10. 依据补充会议纪要，维修由内部人员筛选并分配，维修人员不自行选择送修物品；公共池可见不等于可自行领取。旧纪要“仅见被分配任务”由本轮“自己的任务 + 公共池”取代。
11. 用户审阅流程图后确认“公共池分配”“我的任务”“维修管理”三个板块。
12. “去向与交接”只记录去向，不管理实际交接，不增加实物交接、签收或主公司收货确认流程；只有去电商的数量对接进入电商库存。去主公司只记去向及数量，不对接主公司库存或收货系统。二次维修仍按既定规则回待分配池，不增加外部库存。
13. “历史记录”改为“分析”板块。底层仍保留返件、分配、维修结果、去向和历次维修记录供分析及追溯；具体分析指标与呈现方式尚未冻结。

## 菜单内板块（流程图审阅后）

| 板块 | 范围 |
| --- | --- |
| 公共池分配 | 按 PN、数量、主数据描述查看池内物品，分配内部维修或委外维修，好件可直接分流 |
| 我的任务 | 指派给我的内部维修任务、由我追踪的委外批次，并可查看公共池 |
| 维修管理 | 管理内部维修、委外维修、人员指派、追踪人及返回结果 |
| 去向与交接 | 记录去向及数量；只有去电商才触发电商库存入库，不管理实际交接 |
| 分析 | 基于保留的业务记录提供分析，具体指标待细化 |

## 流程

维保返件（好件、坏件） → 待分配公共池（PN + 数量 + 主数据描述） → 按数量分配 → 内部维修 / 委外维修（可指定追踪人） → 登记返回结果和备注 → 选择去向。

选择二次维修 → 回待分配池并标注二次维修 → 再次分配。维修人员具有“我的任务”和“公共池”两个视图，均归属同一主菜单。

好件直接分流：维保好件 → 公共池 → 电商系统 / 主公司，无需先分配送修。

电商出口：人工选择送电商 → 对接电商实际入库 → 返回入库结果 → 电商内部人员手动上架。好件直送和维修后送电商遵循同一出口规则。

主公司出口：选择主公司 → 记录去向及数量。到此完成本模块的去向登记，无实际交接、签收或收货系统对接环节。

## 实现时必须验证的边界

以下是技术验收约束，不增加新的业务去向：

- 同一返件不可重复入池；同 PN 汇总后仍应能追溯返件来源。
- 分配不得超出可分配数量；分配出去的数量不能被重复分配。
- 部分返回、不同维修结果和不同去向需保留数量对应关系，不能把整批默认处理成同一结果。
- 二次维修回池不能重复增加物品总量，并应保留上次维修记录。
- 我的任务及公共池范围须由服务端验证；查看公共池不自动意味着可以分配或修改他人的任务。
- 电商出口不得重复入库；已有历史维修结果、已投递记录和在途记录须制定迁移映射，不能重新投递历史库存。
- 对接失败或等待回执时不得显示“已入库”；重试必须复用该次电商去向记录的投递身份，避免重复增加电商库存。入库与手动上架分别验收；此回执是系统入库结果，不是实物交接签收。

## 补充拍板（2026-11-16，五页签原型评审后用户裁定）

1. “没修好”的物品**允许送电商或主公司**（用户原话：“没修好也可以送”）。
2. **好件不能分配送修**，只能直送电商或主公司（用户原话：“好件不能送修”）。
3. **“修好件不能进入二次维修”转正为正式口径**（用户答复“好的”）：二次维修仅用于没修好的部分。
4. **撤销分配**：管理员（分配/管理人员）可撤销分配，数量回池；改派按“撤销后重新分配”执行。
   实现约束（原型与正式实现一致）：仅限尚未登记维修结果的批次；已登记结果的批次不可撤销，须按结果与去向流程处理。撤销保留批次记录并标注已撤销，不删除追溯链。
5. 委外批次增加**可选“预计返回日期”**字段（用户原话：“可以选择”），用于跟进与超期提示，不强制。
