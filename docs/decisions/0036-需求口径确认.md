## 背景

需求侧在 2026-11-08 对账（`team/reports/req/2026-11-08-需求现状与下一轮候选.md`）中确认：需求 0.0.0.1 的 R4–R17 已有实现（R4–R14 随 v1.45.0 上线，R15–R17 已合入 main 待随 v1.46.0 上线），剩余开口集中在 R6/R8/R9/R10 的处置方式、R19/R20 两个决策门、需求00004-R2 的收窄确认、需求00005 的 D-32 §5 缺口，以及 #136 E4 源端取消口径。用户已授权按需求侧推荐执行，本决定把上述口径一次性收口，避免再以会话记忆为依据。

> 口径真值仍以本文件与既有决策为准；实现与发布状态不等于本文件合入。

## 决定

### 1. R19 离职销售清洗：暂不做，登记为已知限制

1. 在获得**权威离职名单**前，销售分析与维保看板/排名**不隐藏**离职销售人员；不得用「长期无业务」「最近无成交」等推断代替离职事实。
2. 本项登记为**已知限制**：相关页面与导出如实呈现人员事实，不对外宣称「已清洗离职人员」。
3. 待 issue #136 C2（角色×可见性）与权威名单（人事/氚云字段或人工维护清单，须明确维护人与生效口径）确定后，**另立需求编号**出 PRD，不在本决定下开发。
4. 不做期间，既有行级权限口径（如 `own_customers_only`）与人员排名/筛选不变。

### 2. R20 采购类型改名：维持 D-39，不改名

1. 采购分析的「采购类型」保持 `f_purchase_order.source_type_raw` **原值展示**，不改名、不映射、不分组；D-39 继续有效。
2. 「采购产品」列**已存在**（PN+描述，见 `backend/app/api/purchases.py`），不得把「采购类型」改名成「采购产品」，避免同一页面两列语义冲突。
3. 若未来用户仍要求「按采购产品维度分析」，须新决策 supersede D-39，并重写筛选/导出/历史报表口径，单独立项，不在本决定下扩大范围。

### 3. R6/R8/R9/R10 变相满足项：不二次开发，仅入口/文案引导

1. 按 D-0051 已实现能力处理，不按原文做口径级二次开发：
   - R6（作废/删除后重导「覆盖」）：维持 D-27/D-34 的源取消、缺项、人工保护分流，**不提供静默覆盖开关**；
   - R8（维保主页「删除」项目）：维持可恢复归档，**不提供物理删除**；
   - R9（排名旁「待返数量」）：维持 D-31 的同期实收与需求单 N/R 差额核对，**不把差额当待返义务**；
   - R10（总表收货台账可编辑）：维持独立签名收货工作簿可写、项目总表收货快照**只读**。
2. 允许（且仅允许）做**入口、文案、引导**层面的体验改进，作为后续小任务；不得借「引导」改变上述口径或放开写入口。
3. 验收以「用户能在正确入口完成对应操作、理解分流/归档/核对的含义」为标准，不以与原文功能清单逐字对齐为标准。

### 4. 需求00004-R2 返还状态：接受 D-31 §8 方案 A 收窄

1. 需求00004 R2「返还状态反写」按 **D-31 第 8 款（2026-10-15 方案 A）**收窄：只交付品类筛选、原始下单量 N、实收 R 与差额 `max(N-R,0)`，以及需求单核对入口；**不发布已返/未返、收齐/未收齐等状态**。
2. 不再按原文「返还状态反写」开发；已交付实现见 #370/#422/#507（随 v1.45.0 上线）。
3. 需求侧在 `docs/requirements/需求00004.md` 与台账登记该收窄，作为后续验收依据。

### 5. 需求00005 免返标注：补 D-32 §5「01_项目概览」只读显示（后续小任务）

1. 经实测，D-32 第 5 款中「项目工作簿 `01_项目概览` 只读显示免返标注」**仍未实现**：`backend/app/services/maintenance_project_master_workbook.py` 的 `_v2_build_overview` 字段清单只有「项目备注」，无「免返标注」；项目列表导出列已由 #507 实现。
2. 确认**要补**该只读显示，作为**后续小开发任务**（不在本文件与本次文档 PR 实现）。实现边界：只加只读展示，不增加 Excel 回写入口；`01` 其他部分、签名与版本契约不变；不改变免返判定。
3. D-32 第 3 款「历史按批准清单更正工具」**暂不开发**，另立需求时再排期。

### 6. issue #136 E4：维持现状（失效保留 + 人工确认）

1. 月度全量同步遇到源端取消/删除时，维持 D-27/D-34 口径：**失效保留 + 人工确认**，不自动作废、不静默覆盖。
2. E4 的最终答案（是否改为自动作废）仍待用户确认；确认前研发按现状执行，不猜测。
3. 需求00008 的「删行/作废/改值」处理据此收口，不再要求「上传即自动作废」。
