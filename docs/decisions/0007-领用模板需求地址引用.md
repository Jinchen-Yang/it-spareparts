# D-29 领用下载模板引用需求单地址

- 日期：2026-10-12（上海）。
- 来源：杨金臣要求在下载领用模板的最后一列之后新增一列，自动按PN引用对应维保需求单地址。
- 已确认范围：下载模板末尾的地址引用与PN匹配。是否直接带入实际领用地址已提问，尚待明确；本次先实现独立引用列，沿用D-26实际地址的写入规则。

## 下载引用

1. 当前项目总表与领用Tab共用的 `06_领用返还` 末尾新增“需求单收货地址（参考）”，来源是需求单头 `receiver_address`。下载时系统为已有领用行填写匹配结果；不是本地Excel输入新PN后自动查找的公式。
2. PN关联使用既有稳定备件身份 `part_id`，先限制当前项目、有效需求单及有效明细。已有明确需求单关联时按它核对；没有关联时，同项目同备件只有一个不同非空地址才引用。多地址、关联不匹配或缺地址明确提示，不选第一条或最新地址，不跨项目取地址。
3. 仓库来源的 `source_line_id` 可能是CKD明细，不能据同名字段直接认成WBDD明细。需求单号与原始头ID都必须在当前项目核对后使用。
4. 地址引用沿用客户信息权限；没有权限的导出不加载或展示来源地址。

## 往返兼容

新增列作为下载参考，不用作单据身份、删除哈希、自动编号、数量、成本或地址写入意图。回传参考列不修改实际领用地址；旧模板没有该列仍可正常上传。实际领用地址继续使用D-26的领用地址、地址操作、签名基线与冲突规则。

这是当前已授权下载引用范围的实现边界；后续如果用户明确选择直接带入实际领用地址，应追加确认并更新本决策对应规则，再实现该行为。没有生产历史地址补录或其他业务状态写入。
