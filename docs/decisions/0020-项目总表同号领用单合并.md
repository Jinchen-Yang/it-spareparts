# D-0042 项目总表同号领用单合并

- 来源：金臣 2026-10-19 11:01Z 对 PR #417 的明确规格修订。
- 状态：已批准实施；同 worktree / 分支 / PR 继续，不授权合并或部署。
- 取代：本 PR 初版 `3c72466` 对“不同既有领用单最终同号一律拒绝”的处理。项目内唯一约束、整本原子应用、D-02 作废优先、D-28 展示号和 D-38 原回执规则继续有效。

## 规则

1. 同一项目工作簿中，不同既有 `issue_id` 的最终 `issue_no` 相同，自动合并为一张领用单；包括改到另一张未改名单正在使用的号码。
2. 保留单优先选择数据库中已持有最终号且本批未改走的单；没有时按 `created_at`、`issue_id` 升序选择。预检列明全部参与单的稳定 ID、原单号、保留单、目标号、各单明细数、总数及 Excel 行号，并显示可读中文计划。
3. 合并全部明细（含非活跃明细），保留明细 ID；被吸收单的明细按来源稳定顺序、原行号、明细 ID 接到保留单最大行号之后。全部现行引用及投影随稳定身份迁移；历史审计和不可变命令/事件内容保留原文，通过新增合并审计追溯，不伪改历史。
4. 被吸收单保留软作废单头，改为不冲突的技术墓碑号，保留原展示号、来源与幂等证据；不回收展示号。合并审计保存保留单、全部来源 ID/原号、移动明细 ID/数量、引用处理与单头冲突决议。现行版本、审计、返还义务、取价与工作簿 revision 协议继续生效。
5. 单头业务值默认取保留单；本工作簿对目标单头显式修改的字段优先。每个不同值都在预检列出字段、保留单原值、被舍弃值及来源和最终值。日期、地址等多个显式意图不一致时，不能用保留单顺序覆盖用户意图，应中文 4xx 拒绝。来源、创建/幂等信息与展示号属于各单历史身份，不转成另一单的来源。
6. 任一来源/目标已作废、跨项目、状态不能兼容、身份/引用无法无损合并时，整本拒绝，指出单号与行号。已确认与已更正属于有效事实可共存；其他状态只允许相同状态，未知映射不合并。自动生成（空单号/WBDD 输入）的 LY-AUTO 新头保持独立，若与改名目标相撞继续 `duplicate_issue_no` 拒绝，不合并。
7. 预检→应用使用绑定文件、项目、操作者和完整合并计划的签名确认凭据；出现合并的 apply 必须提交预检凭据，非合并保持原协议。应用在原锁序内重新读取所有参与单及明细/引用，重新计算；计划不同则提示重新校验，不静默扩大或替换合并集合。
8. 保留互换/链式改名的事务内两阶段改号；临时号不出现在成功审计或业务回执中。所有数据库约束异常回滚并转中文 4xx，不留下不可用会话或部分写入。

## 身份与引用边界

- 原生 `site_issue_v2` 保留单不能接收其他来源的明细：其后续发货身份编辑流程要求原生明细，不能为合单伪造来源，也不能同文件追加无发货身份的新明细。纯草稿之间可合并，但不得已有确认返还义务；原生单号还须满足现有跨项目唯一约束。
- 返还义务保留自身 ID，改挂保留单，坏件返还行的义务外键不变；追加最终纠正/作废事件及版本水位，防止迟到旧事件复活被吸收单义务。历史命令、已消费事件、审计和冻结回执保留原关联及原文，由墓碑单和合并审计连接历史。
- 仓库关联按既有不可改写约束将旧关联标为 superseded，并追加指向保留单的新关联。未决仓库候选不能原地改候选 JSON：旧项按允许的 open→resolved 转换关闭，追加含新目标的新 open 项，双向记录接替关系；已解决候选不改。没有修改数据库触发器。
- 展示号终身保留在各自单头；成本、返还要求等按稳定明细 ID 关联，随明细归属迁移并触发原有重算。当前业务附件模型没有领用单附件外键，不创建虚构附件映射。

## 边界与验证

无 schema 变更、无迁移，不修改库存与真实收货事实。同文件成功重放返回首次完整回执；重新下载后的新文件可以干净回传。引用清单、冲突字段、实现和测试证据记录在本 PR 交接文档；开发验证不代表用户点按验收或生产发布。
