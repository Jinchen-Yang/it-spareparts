## 已确认规则

1. **领用地址复用现场位置。** 复用 `maintenance_site_issue.site_location`，表示实际领用地址。需求单 `receiver_address` 表示收货地址，两者分别保存；不根据需求单收货地址自动覆盖领用地址。现有普通页面手填的必填及 256 字符限制继续保留，不静默截断。
2. **缺列或空白保留原值。** 旧模板没有地址列，或地址列存在但留空，更新既有单据时保留原地址；新建且未填写时，按对应入口的既有必填/选填规则处理。清空只能由明确的清空操作触发。需求单原件现支持可选「地址操作」（别名「收货地址操作」）列填写「清空」，单元格中的地址文本「清空」本身不触发操作；领用清空入口随第 2 步实施。
3. **本文件同单地址矛盾，保留原地址。** 同一张单出现两个不同的非空地址时，指出单号与数据行号，保留该单原地址，其他单据的合法地址继续处理。相同地址重复、首行填写而续行空白不构成矛盾。新建单没有旧地址时保持未填并提示冲突，不从其他单据继承。

需求单实施细则：地址表头仅明确识别「收货地址」「地址」及选填注解，不把「选择收货地址」当地址；操作列允许「保留」「设置」「清空」。同单不同非空地址、不同操作或非法操作均提示并保留地址，即使其中一行填了清空。无冲突时明确操作优先于地址单元格的普通填写规则。通用入口 skip 模式仍跳过已有单据，upsert 与专用入口才更新已有地址；回执中的地址数量描述已解析单据的处理意图，不宣称每个同值重复上传都造成实际变更。

## 与现有工作簿规则的关系

- 第 3 条处理同一份文件自身的地址矛盾，不替代 D-02 的并发三路合并与覆盖回执。
- 签名往返工作簿中的单头地址应与现有单号/领用日期一样规范化：只改一行，未修改的同行沿用基线，不因此报告矛盾；若两行分别修改成不同的新地址，按第 3 条保留原地址。
- 旧工作簿没有地址列或地址基线，不代表用户请求清空。新增字段不得使原本未修改的行变成地址写入。
- 地址不参与来源单据身份、领用自动编号、项目归属、数量及成本口径。地址变更的审计与版本更新沿用各入口现有规则。

## 实施边界

- 需求单复用已有 Text 字段 `receiver_address`；「选择收货地址」继续独立保存到 `delivery_address_option`，不得模糊匹配为地址。
- 领用页面、接口与项目总表 `06_领用返还` 读写同一 `site_location`；兼容原有字段名和旧模板。
- 两类 Excel 地址字段按明确表头名称识别，不依赖位置。具体别名限定在对应文件类型，不影响采购、销售和入库等其他导入。
- 地址的查看和修改沿用对应入口既有项目范围、客户信息及动作权限；不因补地址放开领用、成本、删除等权限。导出和签名基线也须验证权限。
- 删除、作废、恢复及级联由另一台电脑负责；本任务不新增这些业务规则，集成时保留已确认实现。供货分类暂缓。
- 历史原件、数据库与当前页面的只读核查不是历史补录。生产补录、合并 main 和部署均不在本次授权内。
