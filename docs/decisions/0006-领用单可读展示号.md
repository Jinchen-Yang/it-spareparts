# D-28 领用单人类可读展示号（LY-YYYYMMDD-NNNN）

- 日期：2026-10-15。
- 来源：用户要求 06 维保项目总表上传的自动领用单号对外不可读（LY-AUTO-<sha256[:20]>-<sha256[:24]>），
  列表/详情/导出/回执需要一个人类可读编号；hash 形式继续充当内部身份。
- 状态：已确认（范围仅此一项；同批提议的「是否应返还空值默认/列头改名」「作废重建警告」
  均被用户明确放弃，返库/no_return 逻辑、列头、导入解析保持完全不变）。

## 口径

1. `issue_no`（含 LY-AUTO hash 形式）仍是唯一身份：去重、replay、
   `uq_maintenance_site_issue_project_no` / `uq_maintenance_site_issue_v2_no`、
   4072/6546 处前缀判断全部原样，不改名、不迁移、不复用。
2. 新增可空列 `maintenance_site_issue.display_no`，格式
   `LY-YYYYMMDD-NNNN`（NNNN 四位起、按日溢出自然加位），全局唯一
   （部分唯一索引 `ux_maintenance_site_issue_display_no`，仅覆盖非空行），
   CHECK 约束校验格式。
3. 分配时机：**仅首次创建 LY-AUTO 单时**在 apply 事务内按单头 `issue_date`
   通过按日计数器表（`maintenance_site_issue_display_counter`，
   `INSERT … ON CONFLICT DO UPDATE … RETURNING` 原子递增）分配；
   与领用单 INSERT 同事务，整本回滚一并撤销；apply 全程持有全局数据咨询锁，
   计数器行锁兜底其他未来分配路径。replay 按 hash 身份查回，**绝不重新分配**。
   用户手填单号（含 page_manual/site_issue_v2/workbook 手工行）不分配。
   display_no 分配后永不变更、永不改写。
4. 展示口径 `display_no_effective`：LY-AUTO 单且有 display_no 时展示 display_no，
   否则展示 issue_no。用户后来把自动单改号为自定义号后（issue_no 前缀不再是
   LY-AUTO），以用户号为准展示。UI 列表/详情、V1/V2/v3 导出、作废回执、
   返还义务台账「来源单号」一律用展示口径；关联需求单号（用户填写的 WBDD）
   照旧单独展示。写操作（作废/编辑/地址补丁）仍以 issue_no/issue_id 定位。
5. **导出/回读兼容（关键不变量）**：V2 下载件单号列写展示号，但
   replay 比对、99_元数据 `site_base_hashes` 与删行守卫全部钉在
   `issue_no` 身份口径（`_v2_site_identity_values`），旧版导出（hash 列）的
   在途文件删行/重放不被展示列变化误判；回读时单元格值等于该单 display_no
   不视为改号（等价身份），真实改号照常走改名校验。V1 下载件同样写展示号，
   回读把展示号映射回身份后再做只读校验。行级签名基线令牌按导出时刻的
   展示口径签名（新旧文件各自与自身基线比较，不受影响）。
6. 存量回填：迁移内按 `issue_date` 分组、组内 `created_at` 再 `issue_id`
   排序确定性回填 LY-AUTO-% 行；用户手填号（即使形如 LY-YYYYMMDD-NNNN）
   不回填、不修改。计数器对齐到各日回填最大值，后续分配不复用回填号。
   仅新增列与计数器表，`alembic downgrade` 可完整回退且不动既有值。
7. 解析期（validate）零副作用：展示号只在 apply 事务内分配；自动编号解析
   警告不再打印 hash 单号。
