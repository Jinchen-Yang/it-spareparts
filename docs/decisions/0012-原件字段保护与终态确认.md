# D-34 原件字段保护与终态确认

- 日期：2026-10-15。
- 来源：杨金臣确认 Q30=B、Q31=B；依据 `R/01-开工计划.md`、P2 边界、需求00006/00008调研和 `R/金臣答复-2026-10-15.md` 第17节（R 为本批调研目录）。
- 状态：已确认；本条规定后续实现，未执行历史转换、级联作废或生产操作。

## 背景

[D-27](0005-维保原件同步与缺项差集.md)要求原件更新保留人工保护。现有总表任一有效修改可能扩大为整行保护，导致只改备注或人工价后，未手改的需求数量也无法接受原件更新；源单头非生效与最终作废又需要区别处理。

## 决定

1. **只保护人工实际改过的字段（Q30=B）。** 网页与工作簿在归一化后记录实际变化字段，未改字段继续接受合法原件 upsert。PN 文本及 part_id 作为身份组保护；人工价独立保护，不冻结未改数量；备注纳入保护及有权撤销链。原样回传不产生保护。撤销保护不冒称“采用最新上传值”，需要采用新原件时明确重传。
2. **历史证据不足继续保护。** 只有审计完整证明来源及改动字段的历史记录，才可按受控清单转换为字段保护并留痕；无法证明改过什么的继续旧整行保护并列待核对。真正人工新建行不因本条被当作来源行放开，不批量清空 `workbook_manual` 或人工账本。
3. **当前唯一最终作废状态为“已取消”（Q31=B）。** 2026-10-15 既有生产只读聚合：已生效 **23,242**／进行中 **142**／已取消 **76**／草稿 **14**。这是来源材料的当日分布，本次未再访问生产。“草稿”“进行中”和空值仅为未生效：退出项目有效需求视图，不连带作废领用。未来兼容提示：答复将以后可能出现的“已作废”视为同义状态并要求告警；本次执行白名单仍只有“已取消”，不得据此把未来文字或任意未知非生效值自动纳入连带作废。
4. **源终态单独列影响，人工确认后才连带作废。** 上传合法单头状态后，需求读侧先排除未生效单，现场实际领用仍独立保留。以成功 upsert 批次的不可变状态证据和当前实体摘要形成“明确终态”候选，列出需求及精确关联领用影响；不把取消伪装为文件缺项。skip 上传即使归档了取消原文，也不据此生成可执行终态候选，须显式 upsert。
5. **确认受身份、权限、版本和幂等约束。** 有权实名用户选择具体候选、填写原因后，锁内复验批次、摘要、当前终态及项目范围；任何漂移整次零写并要求刷新。只通过原始明细 ID 等可靠证据精确关联领用，无法精确关联者保留并提示，不按 PN、单号相似或数量猜测。重复确认返回原结果，不作废后来新增或已恢复的数据。
6. **真实事实保留。** 需求软作废及其精确关联领用软作废后，已登记返还、库存、采购、报销、回款和历史成本证据保留，不自动删除或冲减；需求数量变更也不自动改实际领用量。未被逻辑作废的单头重新已生效可按源状态恢复可见，已有系统作废行及墓碑不因重传复活。

## 影响

- 项目共用读侧统一检查单头已生效，保留管理历史查询；不以开启生产 cutover、清空旧成本或仅在页面藏行替代有效性修复。
- 上传回执区分 skip、实际变更、无变化、人工保护、缺单／缺行及源状态，不能以同键匹配数声称全部字段已覆盖。
- 网页／总表／loader 共用字段保护；确认沿既有全局数据锁→项目状态→单头→归属→需求明细→领用协议，保留审计和事务原子性。实现须与 [领用事实原语](../integrations/maintenance-site-issue-facts-v1.md)的编辑协议兼容。
- [D-31](0009-返还数量上限与需求单核对.md)负责需求减量后保留实收及禁止增加；本条不截断返还，不新增迁移或在部署时自动处理那 76 张单。

## 取代关系

仅部分取代 D-27“已确定的输入和比较规则”第 6 项中“沿用现有人工修改保护”的实现说明：由整行升格改为本条可证明的字段级保护；人工值优先及历史保守保护原则继续有效。新增明确源终态的独立人工确认，不改变 D-27 原件／工作簿分离、不可变身份集合、每日序号范围、坏行存在保护、缺项先列差异后确认、精确级联及返还不删规则。D-01 项目工作簿删行语义和 D-12 现有作废／恢复权限不由本条改写。
