# D-32 免返标注与免返标准

- 日期：2026-10-15。
- 来源：杨金臣确认需求00005及 Q20～Q25 推荐默认（Q23=B）；依据 `R/01-开工计划.md`、P3 边界、需求00005调研和 `R/金臣答复-2026-10-15.md` 第17节（R 为本批调研目录）。
- 状态：已确认；本条归档业务口径，标注字段及工具尚待实现和验收。

## 背景

项目间免返设置存在差异，需由小郭按合同核对。生产只读聚合中的“28 个项目硬盘全部被标必须返”是核对线索，不能证明这些行录错，更不能据此自动更正。提醒文本、行级返还要求和实际收货是三个不同概念。

## 决定

1. **免返标注只作提醒，不是事实（Q21=A）。** 项目概览基础信息提供可人工维护的多行纯文本；空值为“未标注”，不解释成必须返或免返。不解析文字，不驱动 `no_return_default`、行级要求、义务、数量、成本、收货或返还率，不开放项目默认免返开关。
2. **维持现行标准（Q22=A）。** 标准硬盘默认免返，逐行明确设置优先。行级 `no_return=True/False/None` 分别表示免返／必须返／继承；界面“是否应返还”的是／否与该布尔方向相反。项目默认 false 表示继续采用行级及品类规则，不等于全项目必须返。当前实时行缺标准品类但明确必须返时继续应返；旧义务保留冻结分类和既有约束，不因显示归一重建旧义务。
3. **历史只按批准清单更正（Q23=B）。** 小郭依据合同核实项目和行，工具先干跑展示稳定身份、旧值、新值、凭据、原因及版本，只更正批准项并逐项留痕；有漂移重新核对。证据不足不改，不把所有 NULL 固化，不全量把硬盘改免返，不覆盖未批准的合同例外。撤销同样以新版本更正并留历史。
4. **沿现有主档编辑权限（Q24=A）。** 标注与项目主档使用相同实名、项目范围、乐观锁、审计和工作簿 revision 链；可看项目不自动获得编辑权，不新增职位或“仅备注”权限。
5. **网页编辑、01 只读、导出可选（Q25=B）。** 基础信息提供清楚的编辑入口；项目工作簿 `01_项目概览` 只读显示这一字段，项目列表导出可选此列，不增加 Excel 回写标注入口，也不把整张 01 表改为只读。旧模板缺列或原样回传不清空标注。
6. **按下单量核对（Q20=A）。** 收满才为已返，统一遵守 [D-31](0009-返还数量上限与需求单核对.md)。批量应返／免返及恢复继承同由 D-31 规定，不由文本框生成批量命令。**2026-10-15 修订：**免返硬盘不计入返还核对（金臣 2026-10-15 裁定）：领用单、返还单和手工录入备件中，按现行免返判定（与 `maintenance_bad_returns` 的 `exemption_source` 一致：项目默认免返 `project_default_no_return` 或硬盘品类默认免返 `category_disk`；行级显式“必须返”优先，仍计入）判为免返的硬盘，从需求单核对的下单量 N 与已收量 R 中同时剔除，不参与已返／未返判断与差额。项目免返提醒文本仍只作提醒，不驱动剔除。详见 D-31 第 8 款。

## 影响

- 标注与布尔要求分开保存、显示和审计；页面提示“仅作提醒，返还要求以明细标记和规则为准”。文本变更前后经营事实保持不变。
- V3 无义务行使用统一实时读模型；V2 分清可编辑事实与派生展示；来源码兼容整理不得改变本条已确认分类，也不得破坏旧工作簿签名、基线和身份。
- 标注持久化迁移与批准清单工具由后续指定会话实施，本次不新增迁移或执行任何数据更正。
