# D-0026 模块权限引擎与客户归属

- 日期：2026-10-23。
- 来源：杨金臣要求比较难度、成本、收益、代码量及体量后选择最佳方案并实施；随后明确服务销售读取「本人负责客户的全部订单（需要维护客户归属）」。
- 选择：自托管 Cerbos，保留 FastAPI、SQLAlchemy、React/AntD。固定发布版 PDP 0.57.0、Python SDK 0.16.1、SQLAlchemy adapter 0.4.0 已完成独立可运行验证。
- 本决策覆盖 D-41 / D-44 中**销售分析**仅 admin/boss 的限制；采购分析及其他未迁移模块原政策不随此变更。

## 权限主干

身份（实时实名账号）→ 授权记录（资源、动作、数据范围、字段成组绑定）→ Cerbos 决定/查询计划 → SQL 范围 → 领域字段投影 → 页面及导出。

1. 权限引擎是迁移模块的唯一权威；未知能力/字段、无实名账号、无授权、引擎不可用均不放行，不能在新引擎拒绝后回退旧允许。
2. 销售分析先完整迁移：菜单、候选、汇总、比较、分组、趋势、直方图、详情、导出同一数据范围。其余模块列在目录并标记 legacy，逐模块迁移，不宣称全系统完成。
3. 新授权独立于角色名称：`sales_analysis` 资源支持 `read`、`export`，范围 `all` 或 `assigned_customers`。字段组沿用已验证的六类 `data_*` 字段政策；一个用户在一个资源的一条授权中保存动作、范围与字段，禁止把不同授权的范围与字段做交叉乘积。
4. 迁移为有旧页面资格的存量实名账号生成显式授权：管理员/老板为 all，其他身份为 assigned_customers；旧 own_customers_only 为 true 时始终收紧为 assigned_customers。不额外开通旧页面拒绝的账号。新用户默认无授权，权限中心显式赋予。
5. 客户归属用 `SysUser.id → DimCustomer.id` 的受控多对多关系。每位销售可负责多位客户，每位客户可显式共同分配给多位销售；界面明示共享归属。无归属的范围为空，不能依据成交销售名、手机号或历史订单猜测，不退回全公司。
6. 归属变动影响这些客户的全部历史及后续订单；不会改变订单的成交销售、事实数据或导入行为。未匹配客户 ID 的订单不属于 assigned_customers 范围。
7. 新权限及归属配置首期仅实名管理员可维护，记录审计、版本冲突及 token_version 撤销；一般账号管理权限不能隐式获得授权提升能力。后续委派管理另立能力。
8. 页面快照只描述可见能力；API 始终独立鉴权。字段过滤、排序、分组、聚合和响应投影一起受控，延续现有销售分析已验证的派生信息保护。
9. 模块切换开关是部署控制，默认关闭；一旦启用不允许逐请求 fallback。停用模块时停止其新链路，不用宽松旧政策替代新政策。生产启用需遵循正式发布与验收流程。

## 本批交付边界

权限核心、显式销售分析授权与客户归属、管理界面、服务端快照、完整销售分析 SQL 接入及真实 PDP/PostgreSQL 测试。全系统库存、采购、维保、附件和 Agent 等其他模块仍按审计清单分批迁移；本批不改写这些业务的口径或工作流。

该拆分用于控制可审查变更体量，不将首批交付称为所有权限已统一。完整覆盖仍以每个面板/数据/API/SQL/导出/工具与测试的对应清单为准。

新版字段组合补充：销售对账快照包含原订单金额，因此 data_reconciliation 与 data_profit 都依赖 data_purchase_cost。新授权保存拒绝缺少金额权限的组合；迁移时删除该非法组合中的对账权限，不自动扩大金额权限。此收紧仅限新销售分析授权，旧模块口径不变。
