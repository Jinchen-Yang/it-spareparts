# D-0052 售前询价报价共享池

- 状态：已确认。杨金臣 2026-11-01 提出「询价然后报价，全体人员共享一个池子，不再做归属，谁更新价格谁记录」，并在同日逐项选定下列第 1、2、4、5 条。
- 日期：2026-11-01（Asia/Shanghai）。
- 范围：售前询价、报价的归属、可见性、状态流转和页面。**覆盖** D-0046 第 3、4 条中有关报价人的限制、D-0047 第 3 条催办、D-0048 第 2、5 条有关本人报价和待办的部分；其余长期有效、含税默认、价格性质、优先级、PN 建档口径不变。

## 决定

1. **每个询价行只有一个当前价。** 任何能进售前菜单的账号都可以填写或覆盖，保存立即生效。系统记录最后更新人和全部历史修订。不按 PN 合并：同 PN 的新询价显示最新价，可一键沿用（复制成本行自己的价，之后互不影响）。
2. **全部公开，客户名看权限。** 能进售前菜单（`page_presales`）的账号都能询价、报价，能看到全部询价和报价，包括历史上设为私密的记录、成本价、供应商和备注，售前范围内的供应商不再受 `data_supplier` 限制。客户名只给有 `data_customer` 权限的账号看。受众规则在售前不再生效，也不再提供设置入口；规则数据保留，仅为回滚。草稿仍只有本人和主管可见。
3. **取消领取、指派、整单回复和催办。** 提交询价不再产生待办；存量进行中的询价待办由迁移取消，且可由回滚迁移恢复。优先级保留，紧急行排在待报价最前。
4. **询价条件可在行内直接修改，不再撤回后重新提交。** 任何人都可以修改数量、坏件返回、PN 一致和备注。改数量、坏件返回或 PN 一致时，若该行已有答复，先确认；确认后旧价作废并留在历史中，该行回到待报价。只改备注不影响价格。
5. **询价、报价合并为一个页面。** 菜单只保留「询价报价」：顶部新建询价，下方按行显示同一张总表，可按待报价、已报价、不报、我发起的、全部筛选，并在行内直接填价。

## 并发

- 写入只锁单个询价行，不锁整张询价单，同一单的不同行可同时报价。
- 每次写入都带行版本。两人同时改同一行时，后保存者收到冲突和最新价，由其决定是否覆盖，不静默丢失。
- 列表接口在 SQL 内过滤和分页，一次读取当前页，查询数不随页面行数和历史数据量增长。

## 存量数据

- 迁移为每个询价行计算一次当前答复：取该行可用的最新有效价；没有时取不报原因；都没有时为待报价。
- 「已回复，当前无有效报价」的行回到待报价。同一行有多个有效价时，最新的成为当前价，其余留在库中，在该行下次更新时标为失效。
- 尚未发布的报价草稿不自动发布，也不显示给他人；相应的行显示为待报价。

## 不变

- 询价行、报价、修订历史和成交快照的数据结构继续使用，历史修订不改写。
- Excel 询价和报价继续可用，报价上传后立即生效（不再存草稿等回复）。不新增跨行数据库事务承诺。

## 验证

- 后端：任意账号可报价和覆盖；并发同行只有一人成功；条件修改使旧价作废；客户名按权限隐藏；他人草稿不可见；列表查询数恒定；迁移可升可降。
- 前端：单页完成询价、填价、改价、不报、改坏件和查看历史；旧路由跳转到新页面。
- 本决定不授权生产部署。
