# D-0050 Excel导入字段保真与销售原值保护

- 日期：2026-10-31（America/Los_Angeles）。
- 来源：用户在Excel核查后授权“派发任务修复，由Codex验收、CI后合并”；随后明确选择“按建议实施”前四条口径。就金额非法值与跨行冲突提供具体样例后，用户再次选择“采用上述处理”，确认第五条。
- 状态：已确认；分批实现。合并不等于上线，历史数据补录不随代码实施自动执行。

## 已确认

1. **维保可选源列缺失保留已有值。** 缺列不同于源列存在但空白；转换结果应携带实际提供字段集合。现有D-26地址保留/设置/清空、D-34人工字段与历史整行保护优先。普通显式空白沿用既有规则，本条不将全部空白改成保留，也不以COALESCE吞掉合法清空。
2. **“个别调整发货仓”新增原文文本保存。** 保存源单元格文本，不再以只能接受是/否的布尔字段承载全部原值。既有布尔列保留兼容，只有明确的受控布尔值才填该列；不从仓库名猜布尔、不把该文本自动当仓库主数据或业务状态。历史值不自动回填。
3. **销售票面原值不被合同派生结果覆盖。** 通用销售导入原样写入的未税金额、订单金额、税金及显式税率属于销售源事实；合同适配器可按既定规则生成合同金额，但不得再次将合同派生未税/税率写回既有销售原值。系统确需创建销售锚点的合法路径必须保持其来源与字段身份，不得伪造原件值。保留显式维保业务建项资格、XSDD身份与原有事务完整性。
4. **销售现有upsert空白覆盖规则维持D-41。** skip只补空、upsert以本次解析值覆盖及快照追加规则保持。跨批次快照补旧单头、利润引擎税算法、库存快照全量/增量语义均不在本决策内。
5. **采购/销售单头金额或税率非法、同字段跨行冲突时，拒绝该单据。** 校验同一单据的全部源行观测；非空值无法解析，或者同一金额/税率字段出现不同的有效值时，该单据本次不更新，保留库内旧事实，其他合法单据仍可继续导入。回执报告源行、字段及原因；被拒单据不写入单头、明细、对账快照或合同派生结果。原本合法空白仍按第四条处理，D-40对账金额/修改时间软警告规则不变。此条取代相关测试中“问题金额静默变空/后续好值补位”和“同字段冲突取首值”的旧行为，但不新增未税×税率=税金等算术等式或舍入阈值的整单拒绝规则。

## 配套技术修复边界

按文档类型识别受控别名，关键身份缺失或同字段多列歧义必须明确反馈；合法无明细单头、完全重复跳过不应被错误地视为全失败。全数据行被拒绝且无可接受事实时不可显示成功。

源文本和往返可编辑文本不得静默裁剪，限额应明确报错或按经过验证的模型容量保留。保留原文不意味着扩大业务写权限。工作簿错列、日期金额错配、超限静默截行和未编辑回传产生覆盖属于技术缺陷，应以契约测试修复。

## 验证与存量边界

回归必须覆盖缺列/空白/合法/非法值、同义列冲突、同单/明细身份冲突、人工保护、地址显式清空、幂等和批次回执。loader与项目总表相关改动保留锁序/revision bump契约。使用合成夹具和独占测试数据库，不连接生产业务库。

历史修复需另行形成带file_hash、批次、稳定ID、字段、旧值/候选值及冲突的dry-run清单；本次不执行生产补录、不重放整单upsert、不改变墓碑或人工确认事实。
