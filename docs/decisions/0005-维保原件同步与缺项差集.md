# D-27 维保原件同步与缺项差集

- 日期：2026-10-12。
- 来源：杨金臣要求将维保需求单缺项差集、原件修改覆盖和同步作废纳入当前发布，与地址和三种分析视图一起交付。
- 状态：已确认。杨金臣选择“先列差异，一键确认后同步作废”，与地址、三种分析视图一起发布。

## 已确定的输入和比较规则

1. 原始需求单与系统导出的项目工作簿是两条协议。工作簿沿用 D-01、D-02 的签名基线和行级同步；不得把原件缺行功能写成早已具备。
2. 每次原件上传保存不可变的原始单头 ID、明细 ID、单号及数据行号集合。提取发生在业务字段校验之前；坏数量、空 PN 不能被当成源文件删除了该行。后续导入不得改变旧文件成员。
3. 整单候选按合法 `WBDD-YYYYMMDD-NNNN` 的日期前缀分别比较本文件出现的最小、最大序号；不跨日期连接。序号用于限定比较范围，实体仍按原始 ID 匹配，不能以可重排的明细序号覆盖记录。
4. 例如文件同时有 6 月 9 日旧单和 8 月 9 日新单，只比较这两天各自的序号区间，不把中间两个月没上传的订单算成删除。边界之外或文件完全没有出现的日期，不能据此发现删除。
5. 同单明细按原始明细 ID 比较；仅对本文件实际出现、身份无冲突的父单列出缺项。局部裁剪导出与源端删行无法仅凭文件区分，必须明确呈现比较范围及确认含义。
6. 数量等字段沿用 upsert 和现有人工修改保护；需求数量不自动改写实际领用数量。地址继续遵循 D-26。
   - **已废除（保护粒度部分）**：其中“沿用现有人工修改保护”（整行保护）的实现说明已被 [D-34](0012-原件字段保护与终态确认.md)（2026-10-15）部分取代，改为可证明的字段级保护；人工值优先及历史保守保护原则继续有效。
7. 全部修改保持审计、幂等、并发检查和作废优先。不得因缺项检查自动开启生产 cutover 总闸，不做生产历史补录。

## 确认与同步作废

1. 上传成功先更新本文件出现的合法字段，再展示缺失整单、缺失明细及关联领用数量。上传本身不自动作废缺项。
2. 用户选择具体缺项并填写原因，一键确认。请求绑定来源批次、候选摘要和明确选择；确认前候选、原行或关联领用发生变化，整次确认不写入，要求刷新差异。
3. 明细作废与现有项目工作簿同义：软作废来源需求行，并软作废通过原始明细 ID 精确关联的现场领用行。整单确认除既有墓碑、归属停用外，同样处理其有效需求明细及精确关联领用。所有领用行失效时同步该领用单为作废；保留实名、原因和前后审计。
4. 已登记返还、库存、采购、报销、回款不因需求缺项被当作从未发生，不自动删除。无法精确关联的下游只提示，不模糊匹配。
5. 行级失效必须在生产现有 `maintenance_cutover_enabled=false` 下退出旧统计与导出，不通过开启全局开关实现。用户确认执行，不包含本次部署中自动对历史数据批量作废。
6. 并发锁顺序沿用全局数据锁、项目状态、单头、归属、需求明细、领用；一次确认中的选择全部成功或全部回滚。重复确认按原结果返回，不重复作废后续数据。
