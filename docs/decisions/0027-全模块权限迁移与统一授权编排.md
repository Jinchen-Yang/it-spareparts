# D-0027 全模块权限迁移与统一授权编排

- 日期：2026-10-23（Asia/Shanghai）。
- 来源：杨金臣要求继续按 Cerbos 方案迁完其余模块，补齐已覆盖与未覆盖的权限；每阶段完成多智能体不同角度对抗审查、测试和 CI 后再推进，全部完成后统一验收，暂不上生产。
- 本决策扩展 D-0026 的实施范围，替代 `0001-维保整改八条口径.md` 中 **D-07** 的「旧权限键继续作底层真值、守卫层零改动」约定。D-06 是订单编号规则，不在替代范围。
- 业务计算、事实、工作流及既有对象关系口径不随权限框架改写；D-03、D-12、D-13、D-25、商城服务合同等继续适用。

## 唯一授权权威

统一主干为：实时主体 → 资源授权与受控关系 → Cerbos 决定/查询计划 → 领域数据范围及字段用途 → API、面板、导出、工具、任务和文件。

1. 所有业务模块、数据面板、现有读写动作、数据出口和延迟执行入口均需登记。菜单只是其中一种入口。纯布局操作可具名登记为展示行为，不伪造业务授权数量；已退役动作不重新开放。
2. 采用具名、闭合的资源/动作/范围/字段目录。未知项、缺授权、身份失效、非法组合和引擎故障均拒绝，不能用旧角色或旧权限键补一个 allow。
3. 资源按数据合同拆分。同一资源的一条 Grant 将动作、范围和信息组绑定保存；不同范围下的字段不能分别取并集。存在「全项目普通信息、本项目完整财务信息」时，采用不同资源合同，不把本项目权限扩到全部项目。
4. 角色仅作账号分类与旧授权迁移来源。新业务模块的动作由显式 Grant 授予。授权管理自身继续遵循 D-0026：首期只允许有效实名管理员维护；一般账号资料管理能力不自动包含改权。
5. 后端执行授权，前端消费同一权威的能力快照及对象决定。前端隐藏不替代后端保护；不允许隐藏面板仍挂载其无权查询。详情、子对象及复合文件必须检查实际对象关系。
6. 权限暂停保持新权威并失败关闭，不恢复旧允许。分阶段切换只适用于尚未切换的资源；每阶段标明实现状态与运行状态，不能将未迁移项展示为已保护。
   已切换状态按资源持久记录，不能只凭环境变量或 Grant 是否存在推断。显式启用配置在服务启动的独立事务内幂等写入切换标记；普通读取不产生切换写入。已有标记后撤去启用配置只会暂停/拒绝启动，不恢复旧权限。控制面协议兼容模式不删除该标记。

## 保守迁移及业务例外

- 除 D-0026 已明确变更的销售分析外，存量授权按旧**实际允许的动作、对象和字段**生成；不是仅复制 page=true。新框架增加配置能力不代表自动给存量人员扩大权限。旧拒绝条件涉及身份、动作、字段、项目关系及发布状态时须逐项核对。
- 销售分析仍采用明确维护的负责客户关系，覆盖负责客户全部历史及未来订单；不按成交销售猜归属。其他域不自动套此范围。
- 普通采购记录与采购经营分析分别建资源：前者原有全公司采购读取语义保留；后者存量种子仍按原 admin/boss、页面和非受限条件生成。管理员以后通过新授权配置明确委派时，才改变该账号实际能力。
- 池价格分析的价格治理合同独立于采购成本合同。保留其既有价格、经办人及交易证据语义；不能把其他页面的逐单禁读规则机械套入池分析。
- D-03 的项目负责人本人项目完整工作簿权益，以及销售本人项目金额资格分别建模。D-25 的汇总范围与项目详情范围分别判定。现有稳定项目、有效负责人挂靠及 canonical 销售关系继续由领域适配提供，不凭展示姓名新建一套授权关系。
- 需求恢复、回款计划恢复、分类裁决、重算、全局回填、项目归属管理等独立登记，不从普通读取或一般管理能力自动推导。其余状态、版本、幂等、批量事务及实名检查继续保留。
- 已废弃的验收审批、池重建等不生成新授权。Beta/部署总闸与用户授权分开，迁移不会顺便打开功能发布开关。
- 商城等现有机器接口使用独立服务主体及既有 DTO 合同，不伪装成人类管理员，不由员工页面权限推导其服务授权。

## 模板、账号和关系

1. 模板保存的是规范 Grant 包；运行时只读账号当前规范授权。模板版本、来源和个人覆盖用于编排与审计，不成为第二个 allow 来源。
2. 保存模板不改变既有账号；同步必须预览差异，并在执行时复验指纹、账号/模板版本和目录版本。保留与清除个别调整明确区分，拒绝无提示扩大范围或字段。
3. 新账号默认不继承隐式新能力；需要显式选择模板或配置授权。模板不携带某员工客户 ID 或负责人关系；同步不覆盖客户/项目归属。
   后续阶段的旧权限种子资格须有独立、持久的来源记录，不能用空 Grant、空 profile 或空模板包推断。账号与模板的 `authorization_legacy_seed_eligible` 默认 false；尚未发布的 S1 迁移仅将当时已存在的行标为 true，仍受支持的旧创建入口明确记录 true，规范创建及复制入口明确记录 false。该标记不产生运行权限，不通过客户端编辑，也不随模板应用传播。后续 seed 仅补符合资格且没有规范来源/Grant 的资源；已有显式拒绝与账号保存的模板快照不得被覆盖或自动同步。
4. 改权、关系变化、审计和登录版本撤销须同事务完成，使用稳定锁序与版本冲突检查。普通账号资料编辑不能通过 role/template 字段获得权限提升。
5. 迁完的资源停用旧布尔编辑入口或将兼容请求交给同一规范写入口；不能成功保存到无效旧字段，也不能双写后依赖最终一致性。
6. 普通资料编辑不包含会改变范围的销售人员映射、角色资格、模板或客户关系。统一模块模式下这些变更及管理他人凭据均由实时实名授权管理员执行；本人自助改密保留既有协议。未迁域仍消费旧 role/base_role 时，不将这两个字段伪装成可自由编辑的纯职位分类。
7. 个人整资源覆盖具有独立存在性，值与模板恰好相等也保留覆盖；`actions=[]` 是显式拒绝，不是删除覆盖。清除覆盖恢复该账号保存的模板快照；追随最新模板必须另走同步预览。模板移除资源须显式产生撤销差异。

## 字段、文件与任务

- 字段权限同时约束输出、筛选、排序、分组、聚合、建议、颜色和导出；依赖关系按领域定义。只在响应末尾置空不算完成。
- 文件分用户原件、业务原件和生成产物。原件按整件内容的业务能力审查；生成产物保存来源资源、对象范围、信息合同及主体/版本，读取时重新判断。缺乏血缘的历史产物不得自动推断仍可读；保守拒绝后提供按当前权限重新生成路径。
- Agent 每次工具调用复用对应领域权限；聊天使用权不包含所有业务读取权，AI 继续不能写业务事实或状态。历史消息与附件不能仅凭旧会话 owner 永久绕过当前权限。
- 排队任务在执行、读取业务源数据和发布结果边界重新校验主体及版本；长任务不持有整个 LLM 会话的用户共享锁。已发送字节及用户已下载副本无法由服务端撤回，导出权限也不能阻止用户复制已合法读取的信息。

## 完成及推进标准

按依赖分阶段交付，每阶段可并行实施独立域。每个宣称已迁移的资源必须闭合页面/API/SQL/字段/导出/工具/任务/文件及撤权路径，不能把旁路留到最终验收才补。

每阶段必须有攻击面、架构一致性、业务不扩权三个独立角度的复审；包含跨模型复审、真实 Cerbos/PostgreSQL 测试、前端行为检查及精确提交的全量 CI。阻断项修复并重新验证后推进。统一用户点按在全部迁移完成后进行；是否可合并另据最终测试、覆盖、完成度和重构前后比较裁定。本决策不授权生产部署。
