# D-0059 商城在线发布与未执行迁移恢复

- 日期：2026-11-12（Asia/Shanghai）。
- 编号：D-0059。前一号为 D-0058（`0038-坏件循环待修池与结果记录.md`）。
- 来源：用户报告商城约北京时间 00:12 起返回 502：旧五个容器已停、已备份，升级命令被控制器把 `head` 误判为读密钥命令而拦截，数据库仍为 0027。用户明确要求“你负责修复一下这个问题。控制器。”并给出旧服务不停、在线备份、兼容迁移、旁起验证、Caddy 切流及保留旧栈的重发顺序。
- 状态：控制器修复的实施依据。事故现场状态以上述用户报告为来源，本决定不声称已经实测生产或恢复服务。
- 影响面：`.deploy/shop_cycle_ops.py` 的商城 0027 → 0028 → 0029 发布；不修改 itsp 的冻结迁移策略，不改历史 `shop_pn_ops.py`，不改变 D-0058 业务、经办人或出站口径。

## 1. 发布顺序

商城新发布依次为 `preflight` → `backup-old` → `migrate` → `backup-new` → `create` → `activate` → `verify`。不再先停旧五个容器，`freeze` 禁用。旧 backend/frontend 持续服务，旧 worker/agent 只在候选验证通过后的后台交接时停止；新旧 worker/agent 不同时消费。旧容器原名、id、镜像保留，NocoDB bridge 不参与重建。

在线备份使用 `pg_dump` 的一致 MVCC 快照，并在无网络、无发布端口的 PostgreSQL 15 中实际恢复。恢复快照的 schema、表与行数记录在回执中；并发业务下，不要求生产的稍后行数等于快照行数。迁移前重新核验 dump 摘要与实际恢复证明。

只有明确审查为旧代码兼容、循环写入仍关闭的精确候选才可走在线迁移。manifest 声明 `strategy=online-expand-v1`，并用 `online_migration_review_sha256` 固定 `online-migration-review.json`。审查绑定候选 release、源归档摘要、前后端镜像和 0027/0028/0029 链，显式声明 `old_app_compatible=true`、`cycle_writes_disabled=true`。本决定不把未来破坏性迁移纳入这一策略，也不把声明本身当成兼容性测试结果。

候选使用独立名称和专属网络。新前端的 `backend` 别名只指向新后端，候选不争抢旧服务别名或宿主机端口。候选 backend/frontend 的 Docker 健康检查和直接 HTTP 探测通过后才切流。

## 2. 入口切换与恢复

Caddy 只条件更新商城 route 的 upstream，保留 itsp 及其他站点配置，禁止整份 `POST /load`。持久 Caddyfile 同步核验内容和 inode 并取锁。文件与运行配置不能跨系统原子提交，发布窗口暂停其他配置写者；中断后依据保留的计划和现场状态显式恢复。

`recover-cutover` 核验原容器、迁移兼容性、计划及循环表零写入后，将入口与后台进程交回旧栈。保持升级后的 schema，不降级、不重写版本表、不用备份覆盖生产。循环业务已写入后拒绝回切。恢复开始即结束该次向前发布，后续另建发布。

## 3. 命令安全与未执行重试

安全检查按完整 argv 区分执行命令与参数，允许官方 `alembic upgrade head`，继续拒绝读取私有 env 的命令和改写升级命令的形态。

新迁移 intent 绑定 manifest，带 `dispatch_tracking=true`；发出子进程前持久化 `migration-dispatched-*.json`。仅当该协议可核验、没有 dispatch 记录、没有运行中的迁移容器/会话且 schema 为 0027 时，允许重试未发出的升级。dispatch 已记录、超时或启动结果不明，均不能以 schema 仍为 0027 当成“未执行”。0028/0029 续跑仍须先排除残留迁移进程和会话。

`recover-freeze` 保留为旧离线流程的恢复入口，覆盖 freeze 已完成但迁移可证明未发出的情况；它恢复原五个进程并验证健康与公网可用性，不恢复数据库。旧版本 intent 不含新的跟踪协议，因此缺少新 dispatch 日志不证明旧命令未执行。事故旧发布依靠独立现场证据和经审查的恢复步骤处理，保留原 manifest、owner、回执和日志；不得删除标记、补造字段或重算旧摘要绕过门禁。旧冻结发布不能原地转换成在线发布。

## 4. 授权与不变量

本次完成控制器代码、契约测试、审查材料和 runbook。没有执行生产恢复或迁移，没有切流或打开真实业务出口；后续生产动作按明确授权和精确候选执行。token 保持空，不配置经办人，不打开 `SHOP_CYCLE_SELL_ENABLED` 或商城 live，不改变 `CATALOG_*` / `PN_MASTER_*`。

详细阶段与证据见 [发布 runbook](../releases/2026-11-12-cycle-pool-cutover.md#商城按-d-0059-在线发布)。
