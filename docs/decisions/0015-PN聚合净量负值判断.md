# D-37 PN 聚合净量负值判断

- 日期：2026-10-16。
- 来源：杨金臣 2026-10-15 17:47Z 裁定（本次任务由 PM 转述）："Compact board: switch the has_negative check to per-aggregated-PN in a follow-up PR (approved)." 同日确认 NULL qty 按 0 处理，保持不变。
- 状态：口径与后续开发已批准；候选仍需用户验收，main 合并及部署另按分支政策审批。

## 决定

1. PN 紧凑双榜的 `pn_overview.has_negative` 与 PN 维度主榜的 `meta.has_negative`，仅当当前权限及筛选完整集内存在一个稳定 PN 身份的聚合需求净量小于 0 时为 true。先按 D-25 的 PN 身份合计，再判断正负；同 PN 跨项目、客户、销售或业务类型的正负量可以抵消，不同 PN 不互相抵消。
2. PN 排名的贡献率、累计占比及 Top 10 占比同步采用上述判断。判定不受分页、Top N、选中钻取项或成本可见性影响；即使负净量 PN 未进入返回的 Top，仍停用 PN 集中度。聚合为 0 不属于负值，全集总量为 0 时继续不计算占比。
3. 不扩大到项目、客户、销售、业务类型排名或项目分布的集中度规则：这些非 PN 排名保留既有负值保护，避免同 PN 跨项目抵消后对负项目绘制集中度。成本、实际领用、需求单数和缺价行数的规则不变。
4. 需求净量继续为 `coalesce(qty, 0) - coalesce(return_qty, 0)`；NULL qty 按 0，不改变缺价、未知成本、权限、有效性及事实日期规则。不增加迁移、导出、事实写入或生产动作。

## 取代关系与验证

补充 D-35 与 D-25 第 8 款中 PN 需求净量的负值判定粒度；其他约束不变。覆盖原始负行在同一 SQL 分组及跨分组抵消、聚合为零、独立负 PN、筛选与权限、分页与 Top N 外负值，以及前端提示和累计线。开发验证后标记待用户验收。
