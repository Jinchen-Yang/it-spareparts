# D-39 采购分析筛选与三口径

- 日期：2026-10-17。
- 来源：杨金臣对《itsp 客户需求 Round1 开发计划》的答复（2026-10-17，含当日追加）；数据依据为 2026-10-16/17 生产只读调研（仓库外报告）。
- 状态：已拍板口径（含分类筛选下的行级实付，2026-10-17 金臣拍板）。实现分 PR 进行（接口 PR-3a、前端 PR-4a），本文件不含代码。

## 背景

采购模块已有“采购分析”页（`/purchases/analysis`，逐型号频次），只有滚动天数窗口和少量筛选，金额口径跟随管理员全站税口径配置。甲方要求按日期区间、类型、采购员、销售、客户、分类看采购金额并可下钻，且能同时看含税、不含税、实付。

## 决定

1. **可见范围：老板（及管理员）。** 新的采购分析能力使用独立页面权限键（实现时命名，暂名 `page_purchase_analytics`），角色模板只给 `boss` 开；`sales`、`purchaser`、`readonly` 不开。现有权限模型中 `admin` 对常规页面恒放行（`permissions.page_permission_allowed`），即 admin ⊇ boss，因此管理员也可见。
2. **“周期”= 日期区间筛选**，不是订单周期分析。日期预设：全部、一年、半年、30 天、15 天、7 天、今天、昨天、前天，外加自定义日期（单日或区间）；**默认今天**。按采购单 `order_date` 闭区间筛选。
3. **筛选项**：日期、采购类型、采购员、销售人员、客户、分类；均可多选，结果合并显示。本轮不做项目筛选。
4. **采购类型 = 源字段原值。** 选项取 `f_purchase_order.source_type_raw`（原列「批量采购(必填)」）的去重值，照原文显示，不做映射、不做“维保/销售”分组或标注。截至 2026-10-17 生产原值为 销售订单、维保需求、指定采购、批量采购、其他采购、回收采购、委外维修、采购申请；**“批量采购”是原值，数据中没有“批量备库”**，筛选项按原值显示“批量采购”。
5. **分类 = 商品大类文本**（`dim_part.category_major`，约 35 个值），空值显示「未分类」。分类挂在明细行上；**按分类筛选时把订单拆成明细行，只汇总并展示匹配的明细行**（不是整单）。明细行没有税字段；含税/不含税按所属单头的标记与税率规则（第 6 条）从行金额换算。**分类筛选下“实付”= 匹配明细行 `line_amount` 之和**（2026-10-17 金臣拍板）。
6. **三种金额口径并存**：含税、不含税、实付。用一个多选控件选择显示其中一项或多项并排，是页面内的临时选择，不修改管理员全站税口径设置。
   - 实付 = 采购单原列「采购金额」原值（`amount_inc_tax` 入库原值）。
   - 税率规则：单据标了税率（13%、6%、0.6% 等）就用该税率；没标或税率为 0 视为未标，按 13%。是否含税标记不覆盖已标税率。由「是否含税」标记决定哪一侧是原始录入值：含税单的含税额为原值，不含税 = 含税 ÷ (1+税率)；非含税单的不含税额为原值，含税 = 不含税 × (1+税率)。0 税/不含税采购的“名义含税”= 不含税 × 1.13。
7. **下钻**：分组 → 订单列表 → 订单明细，筛选条件随层传递。采购模块提供自己的订单明细接口，不依赖老板看板权限。
8. **金额字段脱敏**：新增金额字段名必须登记到 `config.FIELD_GROUPS`，随 `data_purchase_cost` 遮蔽。
9. **异常大额单不处理**：采购单 id=149683（约 164 亿）及 ≥1000 万的单本轮保留原样、不过滤，验收时单独说明。

## 补充决策（原待确认项）

- **分类筛选下“实付”的行级口径（已拍板 2026-10-17）**：取匹配明细行 `line_amount` 之和。事实：`line_amount` 合计等于单头「采购金额」的已生效单为 81,711 / 81,722；其余 11 单行合计与单头不等，分类筛选下按行合计计，单头差额不分摊到行（不按分类筛选时实付仍取单头「采购金额」）。这 11 单在验收时单独列示。
- **行级统计只计单头所属批次的明细行（金臣 2026-10-17 拍板，随 PR-3a 落地）**。事实：库里 11 张已生效采购单（清单见仓库外报告 `purchase-line-mismatch-11.md`）的 `f_purchase_line` 残留旧导入批次的明细行——9 单表现为同一 `line_no` 新旧批次各一条、2 单是旧批次多出一个 `line_no`（新批次已删），导致全部行求和比单头「采购金额」多 41,187.00；只取 `f_purchase_line.import_batch_id = f_purchase_order.import_batch_id` 的行后 11 单全部与单头一致（“按行号取最新批次”修不了后 2 单，只有按单头批次能全部对上）。规则：采购分析里所有**行级**汇总与展示（分类筛选下的三口径、行数、分类分组、订单明细里的行）只计单头所属批次的行。本轮**只做读侧过滤**：不动数据、不改 `etl/loader.py`；根因修复（采购导入重导时整单替换明细行）与存量残留行清理属生产写操作，另行决策后走带门控的发布。

## 影响与验证

- 不改变现有“型号分析”口径与 `TaxBasis` 管理员配置；不写任何业务状态。
- 验收：2025、2026 YTD 按采购类型的实付合计与只读 SQL 一致；权限矩阵覆盖 admin/boss/sales/purchaser/readonly。
