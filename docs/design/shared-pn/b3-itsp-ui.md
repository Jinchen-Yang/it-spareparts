# B3：ITSP 维护入口和业务读取边界

本候选仅在隔离环境实施，没有切换生产。沿用已有授权运行态 `legacy / enabled / suspended`；不新增并行权限中心或前端启用开关。默认没有资源激活记录时保留旧入口。启用后，撤去配置只会暂停，不会退回旧角色放行。

## 已实现的入口

- 主数据导航和型号全景的编辑入口使用 `/api/authz/me` 的当前资源决策；每个编辑面板再读取 `/pn-catalog/v1/parts/{id}/access`，将操作与字段权限取交集。配置能力 `/capabilities` 只表示外部服务能否运行，不授予权限。
- 主资料按字段版本提交实际改动；保留描述、品牌、厂商、品类、整机/备件、单位和规格维护。近似建档必须使用服务端确认令牌及理由。冲突保留草稿，用户明确更新基线后才能重新提交；PN 身份变化要求重新打开。
- 自定义参数按键维护 JSON 类型，明确区分 `null` 与删除墓碑；每个键独立版本检查，冲突保留结构化草稿并要求人工更新基线。权限词表由后端实际注册表导出，`--check` 校验漂移。
- 好件和坏件各一份通用商品文案；字段权限独立投影。资料候选先展示当前值和提案，再人工选择采用或拒绝；审计入口分页显示实际操作者、执行器和来源。
- PN 图库提供正式/候选/删除视图、主图、排序、用途、候选采用、删除恢复和缩略图任务。上传直接送 OSS，应用 bearer 与 cookies 不发送到存储；图片验证完成后才能加入图库。读取链接短期签发，失败可以刷新。分页未读完不能提交全组排序，分页期间版本变化要求刷新。
- 旧 `/parts/master*` 的单项建档、基线读取、字段更新转入同一事务门面。旧裸 `force` 不能跳过确认；旧批量规范化和历史日志入口在切换后明确返回迁移提示，不制造新鲜版本替旧客户端绕过冲突。

## 独立图库和收件箱工作台

`/pn-gallery` 和 `/pn-inbox` 分别以当前 `gallery.read` / `inbox.read` 决策准入，没有旧入口的页面在 `legacy` 下不向旧管理员放行。图库页面先选择 PN 身份，再加载该 PN 的字段与动作能力；不需要通过主资料页面间接访问。

收件箱支持本人/共享范围、分页、状态筛选、图片预览、认领/接手理由/释放、明确选择 PN 后归档、删除恢复、同组人工排序。批次上传保留 `client_order`，通过 upload→inbox 精确查询恢复已入组状态，不重复写回人工位置；校验响应丢失后先读取票据再决定是否传图。每批最多20张、每张最多20MiB，当前 ITSP 使用整图直传重试。上传可以取消，已结束批次可开始下一批。

归档提交前读取目标 PN 当前权限与身份版本；响应未知时冻结完整命令、目标和请求号，不让修改表单悄悄覆盖原意图。组排序读取全部可见成员后再复核版本，有不可见成员或分页期间变更时停止，保存冲突保留排序草稿。预览按当前授权签发短期链接，刷新失败清除旧链接，到期移除预览。

研究、识图和 ZIP 均需人工触发，与实际权限及外部服务配置能力取交集。研究先核对资料、好/坏件文案、图库版本，再由用户确认；结果只进入候选。ZIP 先读取同一图库版本的完整选择范围，好件不含缺陷图，再确认最多1000张/1GiB。本人任务支持分页、状态刷新、取消与失败/取消重试；任务刷新不会启动外部工作。成功 ZIP 每次下载重新鉴权并签发短期地址，撤权后清除旧地址。共享收件箱可见严格识图提示，但不会因此得到他人的任务管理权限。

## 经营查询的字段边界

`/parts/search` 和 `/parts/overview` 仍允许按原业务权限读取型号身份和经营事实；其中当前 `DimPart` / profile 的描述、品牌、厂商、品类、规格、字段保护信息，必须与当前 `part_master.read` 字段授权相交。无授权的标量清为 `null`，规格和保护字段列表过滤。搜索结果的描述命中副本及替代型号的当前描述也过滤。

投影只处理已确认来自主数据的 `items / similar_items / part / substitutes`，不递归重写历史采购、销售、库存记录。因此历史单据原始描述、数量、价格继续遵守原业务规则。响应增加 `shared_master`：`runtime_state`、`status` 和 `readable_fields`。暂停或授权服务不可用时清空当前资料，返回 `unavailable` 并由页面明确提示；没有新读授权时返回 `restricted`。旧缓存和旧 admin 角色都不是回退来源。共享资料响应禁止缓存。

## 收件箱和拍照顺序

收件箱投影提供文件名、大小、类型、上传者稳定主体、实际上传时间、来源、尺寸、当前操作者的 `uploaded_by_me / claimed_by_me`。尚无持久化更新时间的旧记录返回 `updated_at: null`，不伪造时间或用户名。最新成功识图只展示严格类型化提示；共享接手者可见提示，但不能读取、取消或重试他人的任务。当前 generation 不匹配或异常结果不展示。

`client_order` 是可选且不可变的设备拍摄序号，`position` 是可人工调整的组内顺序。第二张先完成时可先入组，第一张后来按序插入；同一个上传重复恢复不覆盖人工排序。多设备修改仍使用组版本冲突检查。g9 迁移不从历史位置猜拍摄序号，降级遇到已使用的新序号会拒绝丢失数据。

## 验证及待验收范围

B3 基础候选的真实 PostgreSQL + Cerbos 旧 URL 和业务字段投影、收件箱投影、拍摄顺序并发、图库原有领域与 HTTP 共53项通过。另有实际分片读取与精确上传查询5项、前后端权限词表1项通过。后续分组 GET 的拥有者门和当前顺序连同原拍摄并发共5项通过。

加入工作台后的前端聚合17个文件106项通过，涵盖旧主数据/型号查询、导航运行态、JSON空值/删除/CAS、账户切换、OSS凭据隔离、上传未知结果恢复、组分页变化、排序冲突、归档冻结重试和任务版本守卫。之后图片短链到期清理与撤权增量回归3项通过；TypeScript、Vite构建、权限导出校验及ruff通过。最终完整回归由集成阶段按固定提交汇总，不将重叠局部测试相加。

当前 ITSP 尚未复制 Shop 的持久化分片续传交互；这里提供整图直传与当前票据恢复，后端分片能力仍可用。图片复用接口尚未暴露为按钮；内容隐藏与恢复显示已补齐，边界与验证见 `b3-suppression-maintenance.md`。候选构建的浏览器实际点按、完整迁移/恢复演练、双仓统一验收和生产切换仍须单独完成；本地测试不能替代实际点按验收。
