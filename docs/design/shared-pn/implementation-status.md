## 当前可验证范围

- itsp `app.pn_catalog.api` 是事务内应用入口；HTTP 只负责协议和最终提交。历史写路径过渡期也推进同一版本与审计，不能绕过并发检查。
- `openapi.json` 只登记本阶段实际实现的端点，由 `backend/scripts/export_pn_catalog_openapi.py` 生成；概念设计表中其余接口不冒充可用能力。
- shop 客户端和 BFF 默认不启用；原页面及业务数据留在原路径，尚未切换共享维护。
- HTTP 授权 resolver 未安装时返回 `auth.unavailable`，不能凭旧 admin 角色、共享密钥或自报用户名放行。
- 权限依赖会话正在实现 `VerifiedIdentity` 与 `resource_access`。本阶段可注入授权端口做领域/传输测试，不能将这些测试当成真实 Cerbos 与跨站委托验收。

## 测试隔离

仅使用专属本地 PostgreSQL 容器，监听 loopback，限制 2 CPU / 1 GiB 内存。itsp 每个 pytest 进程新建独占数据库；shop 每个用例使用随机 schema。不读取或写入生产，也不复用权限会话的测试数据库。

阶段测试结果按最终精确提交汇总；过程中的局部通过不等于阶段完成。每阶段需核对并发反例、迁移、旧功能回归和独立审查。schema 回滚不得静默丢弃新模块已经接管的审计、字段保护或主数据。

## B1 本地阶段门

- itsp 扩展回归 57 个文件：978 passed、1 条既有 skip。随后边界修复定向复测：核心 27、HTTP/页面准入 34、旧写入口与身份保护 29、主数据 10 项通过；各批存在重叠，不相加冒充独立覆盖数。
- itsp 前端：相关交互 59 项、TypeScript、构建通过；编辑基线在冲突后保留草稿并完整传递单调版本。
- shop 后端相关回归 117 项通过；随后协议与错误边界补充用例通过。前端全量 483 项、随后共享客户端 5 项、类型检查和构建通过。
- 两仓按实际 OpenAPI 对拍；8 类真实 itsp HTTP/PG 响应经过 shop 客户端和生成 DTO 校验。这是录制响应重放，尚不是实际网络委托验证。
- 独立交叉复核复现并修复新旧建档竞态、派生规格越权、读请求编号不一致、入站体积无界和小版本读字段兼容问题，均有针对性回归。详见 [B1 复核](b1-review.md)。

没有将本地通过当作 CI、用户验收或生产证据。B2 开始前固定此阶段提交；真实授权、共享 UI 切换、图库和数据迁移按后续阶段分别交付。
