## 当前可验证范围

- itsp `app.pn_catalog.api` 是事务内应用入口；HTTP 只负责协议和最终提交。历史写路径过渡期也推进同一版本与审计，不能绕过并发检查。
- `openapi.json` 只登记本阶段实际实现的端点，由 `backend/scripts/export_pn_catalog_openapi.py` 生成；概念设计表中其余接口不冒充可用能力。
- shop 客户端和 BFF 默认不启用；候选按持久切换状态选择新旧维护路径。两站尚未在实际环境切换共享维护。
- HTTP 授权 resolver 未安装时返回 `auth.unavailable`，不能凭旧 admin 角色、共享密钥或自报用户名放行。
- B3 已接入权限会话的 `VerifiedIdentity` → Grant → Cerbos、持久切换和暂停状态。使用固定真实 Cerbos 二进制及独占 PostgreSQL 验证 native / Shop 请求级短期委托、账号版本与撤权；两应用实际联网 13 项检查及开发期浏览器双向保存已通过；最终用户点按尚未验收。

## 测试隔离

仅使用专属本地 PostgreSQL 容器，监听 loopback，限制 2 CPU / 1 GiB 内存。itsp 每个 pytest 进程新建独占数据库；shop 各测试进程使用不同数据库，每个用例再用随机 schema，避免旧迁移的全库 advisory lock 互相干扰。不读取或写入生产，也不复用权限会话的测试数据库。

阶段测试结果按最终精确提交汇总；过程中的局部通过不等于阶段完成。每阶段需核对并发反例、迁移、旧功能回归和独立审查。schema 回滚不得静默丢弃新模块已经接管的审计、字段保护或主数据。

## 隔离验收：图库状态读取授权修复

首张图片建立图组后，`candidate`、`processing`、`deleted` 查询会进入原有状态授权检查；此前对应动作未在宿主权限目录注册，导致 Shop 详情页并行读取候选图时整页 403。现将 `gallery.candidate.read`、`gallery.processing.read`、`gallery.deleted.read` 注册为独立只读动作，均依赖 `gallery.read`，并同步 Cerbos、权限目录及前端词表；空图组也必须先通过状态授权。ITSP 只展示有权读取的候选/删除筛选入口。

没有数据库 schema 迁移，也不会自动扩充已有授权。部署须一起更新 Cerbos 策略与应用，并由授权管理明确给需要的账号添加新动作、推进 grant 版本；Shop 客户端能力上限必须显式包含所需动作。已有普通 `gallery.read` 不自动获得候选、处理中或删除区读取权限。新权限目录版本需要页面刷新后重新读取快照；旧客户端委托需重新签发。回归使用独占 PostgreSQL、真实 Cerbos，以及 native / Shop 委托 HTTP，覆盖非空图组、首次上传前、撤权、字段限制和客户端能力交集。

本次定向验证：后端 82 passed（含新增 9 个真实授权案例），前端图库及权限协议 10 passed，`npm run build` 和 Cerbos 策略编译通过。未修改验收数据库或自动迁移已有真实账号的 grant。

**未验收边界：非空候选图预览签名链。** 当前 `get_entry` / `entry_links` 的 `assert_visible` 仅接受 `status=gallery`，真正候选条目在 Shop 的 `projectImage` 请求签名链接时仍会得到 409。隔离环境关闭 AI / 搜图，本次检查的候选列表为空；候选列表可按权限读取不等于候选图片可预览。本次不改签名资源可见性语义，也不将非空候选预览列为通过，需另行复验和确定该资源的显示边界。
