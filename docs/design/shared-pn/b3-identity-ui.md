# B3 共享身份维护入口

ITSP 的 `/pn-identity` 使用当前 `part_identity.read` 准入，分别检查合并、回滚、别名审核与事实归属治理权限。旧数据治理页在身份资源切换后，将旧合并候选、合并历史与别名页导向新维护面板；旧模式仍保留原页面。主资料切换后旧自动分类和整库刷新按钮停用，不再把用户引向已经退役的写入口。

身份操作统一先读取 `/identity/preview`，显示涉及的全部 PN 与身份/资料版本，再由用户确认。提交原始完整版本向量，不读取新鲜版本替用户绕过冲突；确定冲突要求重新预览，网络失败或 5xx 结果未知时冻结完整命令及请求号。身份保存与派生重算分别显示，不能把已入队说成已重算完成。

`GET /identity/merge-logs` 与 `GET /identity/aliases` 是两站共用的选择口，使用当前身份读取权限与 `identity` / `aliases` 字段交集，仅支持实际授权的 all 范围。查询按主键游标分页，每页最多100条，游标绑定主体、授权和查询；不返回 `affected_records`、历史主资料快照、金额或凭据。

合并日志没有持久化的“已撤销”标记，因此 `relationship_active` 表示此记录仍是来源 PN 的最新周期，且源当前直接并入有效目标。后续链式合并或重新合并会令旧记录失效，不能把它笼统解释为已撤销。回滚命令在拓扑锁内再次验证最新周期，防止 L1→回滚L1→L2 后旧L1恢复旧快照；历史成功请求回执仍可重放，绝不再次执行回滚。

Shop 在 shared 模式保留来源/目标 PN 选择与预览确认交互，改用相同 authority 命令；旧库存合并任务不再用于共享身份变更。Shop 的库存仍保留本地 SKU 和数量，身份合并不会转移这些库存。当前 Shop 页面提供共享合并，ITSP 页面另提供回滚及别名重新归属。

验证：真实 PostgreSQL 的身份协调、选择口和旧合并服务25项通过，其中 ABA 反例先确认旧实现误放行，再验证 preview、command、旧事务服务拒绝旧周期且最新周期正常回滚。ITSP 新身份面板、旧治理页、客户端13项通过，TypeScript与构建通过。Shop 原合并与 shared 页面10项通过；后续请求作用域保护的 shared 增量2项通过。实际双应用授权联调与浏览器点按由集成阶段统一验收，未操作生产。
