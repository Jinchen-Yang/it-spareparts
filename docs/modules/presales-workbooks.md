# 售前工作簿接入

依赖方向：售前 `inquiry_workbook` / `quote_workbook` 声明 schema 和回调 → M4 导出、预览、应用 → 现有询价和报价服务。销售汇总是独立只读导出，不生成令牌或 `_meta`。

## 下载和导入

| 接口 | 用途 | 权限与范围 |
|---|---|---|
| `GET /presales/workbooks/inquiry-template` | 空销售模板 | 实名、有销售询价权限 |
| `GET /presales/workbooks/inquiry/{id}` | 现有询价模板 | 本人或主管可编辑的草稿、撤回中销售询价 |
| `POST /presales/workbooks/quote-sheet` | 单张或多张采购报价表 | 本人有未暂停且待处理的待办；公共池须先领取 |
| `POST /presales/workbooks/sales-summary` | 按 PN 汇总只读报表 | 仅本人发起的销售询价，主管也不能汇总别人的单据 |

POST 请求体为 `{"inquiry_ids": [1, 2], "visible_columns": {"lines": ["mode", "unit_price"]}}`。销售汇总工作表键为 `summary`，其余为 `lines`；GET 的 `visible_columns` 传相同对象的 JSON 字符串。身份列始终保留。全部下载记录固定字面量访问审计。

导入使用 M4 两步接口：

- 空模板：`POST /workbooks/presales_inquiry_lines/preview`，不传业务对象，应用后创建草稿。
- 现有单：同一接口增加 `subject_type=presales_inquiry&subject_id={id}`，应用只更新这张单。
- 采购：`POST /workbooks/presales_quote_sheet/preview`，来源行由签名实体身份携带，不传业务对象。
- 确认：`POST /workbooks/operations/{operation_id}/apply`，提交 `expected_plan_digest` 和逐行 `confirm_deletes`。

前端 `presalesWorkbooks` 提供三种 schema 读取、四种下载及两种预览封装；确认复用 `applyWorkbook`。销售汇总 schema 注册为只读，仅供列选择，拒绝导入与应用。

页面入口：询价列表「从 Excel 新建」在弹窗中下载空模板、上传、预览并确认，成功或回执重放后进入草稿编辑页；「我的询价」仅可选择 `is_owner=true` 的销售询价，选列合并下载只读汇总。草稿和撤回中的编辑页可下载已保存的本单内容、上传往返；追加行模式不开放整单导入。

采购工作台右侧按当前单下载报价表；左侧选择本人可处理、未暂停的待办合并下载，未领公共池不能选择。单张及合并表都在弹窗中复用 `WorkbookImport`，文件签名决定实际来源单；应用后重读当前页面、刷新队列，显示「已保存为草稿，请在页面确认后回复」，不会自动发布或完成待办。导入提示会说明尚未保存的页面编辑将被替换。报价通知和主动报价不开放采购往返模板。

## 业务边界

销售模板新增行以 PN 原文精确匹配活跃主数据；无匹配时保留待建档原文，多匹配拒绝。已绑定行的 PN 原文不能改，换型号需删除后新增。数量、交期、备注、字段值通过现有草稿服务保存；重新提交才执行原有版本 diff 和 stale 规则。未选列保留旧值。自定义字段经 M7 保存，已绑定行记录 `part:{id}` 使用锚点。

M7 内部也使用保存点，而 M4 的提交保护会拦截嵌套保存点的释放。销售应用在 M4 已开启保存点后使用局部 Session 适配，仅复用该保存点；全部实际查询和写入仍委托原 Session，真实提交仍被 M4 拦截。任一字段或后续行失败由 M4 回滚全部业务写入。

采购按 `part_id` 聚合，待建档行按 PN 原文聚合，并按“要求 PN 一致”拆组。签名身份包含全部来源行；版本摘要覆盖来源单、行、待办、草稿报价和行处理结果。预览和应用重新锁定、检查每个来源。

采购应用只保存草稿报价或草稿行处理，不发布、不完成待办。草稿沿用和不报对销售隐藏、不计入已回复进度。正式回复时复查有效期、可见性和版本；报价更新选择也保存原报价版本，避免回复时覆盖后续更新。供应商按名称精确且唯一匹配；新增报价默认采用既有供应商私密规则。

参考价复用 M3，不换算税基；报价摘要及行备注经 M8 过滤。采购有效报价摘要只包含当前采购和全部来源单所有人都能看到的报价。销售汇总不输出客户字段，采纳价使用钉住的历史版本。

售前自有 `presales_workbook_export` 记录每次往返导出的授权范围，与文件同时生成、同事务持久化。范围只保存来源行、实际导出的字段定义及作者、备注对象、报价 ID 和字段组，不保存字段原值或价格。上传授权先复查这些范围，因此导出后 M8 收窄再首次上传（包括删行错误计划），以及历史回执重放，都不能返回已失权的签名基线。字段定义使用 ID 定位，改名不绕过授权检查。销售字段 ID 和作者来自生成文件的同一锁定快照；作者清空自己的值后仍可查看首次回执。该表随账号外键清理，不使用访问日志承载授权依据。

M4 不验证导出人与上传人相同，因此来源校验也检查其他账号对相关来源导出的范围。采购只检查与来源相交的 scope 行，销售按询价单检查；另一账号导出的私密字段不能经转交文件或删除行绕过输出权限。跨账号采购草稿还按实际导出的字段键检查当前报价可见性。

## 保守限制

- 现有单头没有统一有效天数字段，因此新报价采用现有服务默认的 1 个自然日；可逐行填写。
- 合并来源草稿值不同的单元格显示为空，未修改时逐来源保留原值；填入后统一分发。单行有多个货源草稿时要求回页面处理，避免猜测应覆盖哪条。
- 同一批次不能多次更新同一旧报价：第一张单回复后会改变旧报价版本，其他来源单必然冲突。因此应用时整份拒绝这类选择，要求逐单处理或选择另报。
- M4 授权回调不接收当前文件或导出编号。采购保守检查同账号所有历史导出及操作；任一来源失去待办归属、曾导出的受控字段失权，拒绝该账号的采购 schema 读取、预览和重放，也会阻止其他新文件。仅重新导出或删除新文件受控列不能解除旧范围限制，须恢复权限；后续需另行约定按导出编号传递授权上下文。
- 销售在有业务对象时只检查该单历史导出和计划；无业务对象的空模板入口检查本账号全部导出、操作来源及已创建草稿回执。曾导出的自定义值失去可见权限或无法证明移除后的历史可见性，恢复前保守拒绝；历史计划未保存字段 ID，存在隐藏字段的行会保守拦截任何非空历史自定义字段。只导出数量、未导出相应值的文件不会新增该字段的授权义务。
- 同一来源的其他账号曾导出的敏感字段，也可能阻止当前账号导入自己不带敏感列的文件；这来自授权回调缺少当前导出编号的保守约束，不把猜测的文件归属当作权限依据。
- 两种往返模板均注册 `validate_fn`，在 M4 SAVEPOINT 内复用应用路径试运行。先整份试运行检查业务约束，出错时各行分别回滚以收集供应商匹配、沿用可见性、PN 等业务错误；不会留下草稿、字段、事件、审计或版本写入。跨行约束不能唯一归责时标出全部参与行。应用前重检，失败回执带逐行错误；预览与失败回执沿用同一红框展示。
