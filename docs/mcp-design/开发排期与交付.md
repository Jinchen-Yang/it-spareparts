按你们两人、工作日各2h、周末各4h：每周总28人时（此处解释为周六周日均翻倍），理想全投入约3.2–4.8周；考虑其他客户交付，建议按4–6周安排首发。如果你所说周末翻倍仅指一天，应按更低容量重排，不改变验收要求。

工作可分两条开发线（任务分工建议，不表示本次已启动子代理）：A 负责身份/MCP/审计/worker；B 负责单据 adapters/网页确认/导出/Skills。共同评审权限与事务；M2 接口冻结后 M3/M4 的无依赖部分可并行。上线窗口由现有项目流程决定，不因为文档完成就部署。

## 首发裁剪规则

必须保留：独立身份、文件真实上传、至少一个稳定项目单据族、一个通用预检族、一个导出族、网页确认和可靠审计，能端到端完成。

可以后移：PN 历史价格扩展、全套缺项面板、Beta工作簿、仓库直接动作、OAuth、连接器市场上架、Open API 远程调度。审计全局检索可先用现有账号页面扩展，不先建设独立大后台。

WBDD 原生导入没有独立预览的部分先保持“识别后转现有网页”，明确这是受限能力；如果纳入首发自动链路，必须在 M4 增加 dry-run/收据任务并重估人时，不能假装已获得统一预览。

## 开发完成定义

不仅 tools/list 能看到工具：从员工真实客户端上传一批文件，系统产生真实预览，员工只确认一次，成功写入一次，错误逐件可见，下载文件可核验，全部操作可追溯。服务重启与员工撤权不会造成重复入账或越权。

交付时提供版本与变更、迁移脚本、环境变量说明（无凭据）、角色测试样例、脱敏样本集、自动测试结果、WorkBuddy平台/版本记录、回退步骤。测试必须包括审计持久性故障和失去响应后的结果恢复。
