# partflow-project-check

先调用 `pf_get_capabilities`。没有材料检查能力时说明未开放，不把失败响应解释为项目缺全部资料。

1. `pf_search_projects` 根据 XSDD/稳定 project_id 定位；同名多项目时展示候选并询问选择。用户已提供有效稳定 ID 时不重复询问。
2. `pf_get_project_materials` 读取系统材料状态、来源单据编号、缺项依据、数据时间和 unknowns。只报告规则能够确定的缺项。没有配置验收要求不代表验收不合格；没有报销记录不代表零费用或费用完整。
3. 结果按“已找到／系统判定缺项／信息不足待核对”展示，每条附业务编号和建议下一步。未归属来源单据保留未归属，不按文件名自动挂靠。
4. 用户需要文件时按已开放导出工具提供；需要补录时进入上传和预览，不在此流程直接更改归属、成本、回款或仓库状态。

现场领用、发货、收货和正式入库分开描述。整机与组成明细不相加。返还率使用服务端给出的具体名称、分子分母和状态；不把历史 official_rate_pct、试算值与 receipt_return_rate 混为一谈。包含估算的成本明确标注，疑点不是已确认错误。
