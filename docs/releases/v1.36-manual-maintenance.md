# v1.36.0 维保人工维护与页面批量

> 本文记录 2026-09-20 的发布能力、发布前验收与回滚方案。
> 最终 CI 见 [PR #333](https://github.com/Jinchen-Yang/it-spareparts/pull/333)；正式上线 SHA、时间、最新备份与公网验收，以生产验收完成后发布的 [v1.36.0 Release](https://github.com/Jinchen-Yang/it-spareparts/releases/tag/v1.36.0) 为准。本文不提前宣称上线完成。

## 一、发布主干

v1.36 把维保事实维护拆成四条彼此诚实的通道：

1. **需求**：维护需求单及需求明细；页面人工值用字段级 override 保护，不让后续 WBDD 导入静默覆盖。
2. **回款**：维护项目合同下的月度累计实收快照；合同从当前项目关系中选择。
3. **领用**：页面登记明确的人工领用事实，来源为 `page_manual`；它不是仓库发货，也不改变库存。
4. **返还 / 坏件**：维护实际收到的返件台账；件况可为成品、坏品、废品或留空，全部有效收货按既有返还台账口径计数。

页面批量只是对既有单行命令的**逐行编排**，不是一个跨行数据库事务。Excel 仍是独立的文件导入 / 回传通道，不能把 Excel 能力写成“页面批量”。

- 人工领用：一张单最多 200 条明细的新增、更正及作废。
- 返还：16384 字符凭据、逐件 SN、页面单条及批量登记/修改/作废。

## 四、输入与并发契约

### 4.1 返还来源单号、凭据与 SN

- 返还台账 `evidence_ref` 前端、API、service 与数据库统一为最大 **16384** 字符；数据库类型为 `Text`。
- SN 使用多行输入，每行一个；单条返还最多 **1000** 个 SN，去空白后不允许重复。
- 有 SN 时，数量必须等于 SN 个数。
- 页面批量粘贴中，无 SN 的数量必须写成 `qty:<数量>`；纯数字永远按 SN 文本处理，不猜成数量。
- 整机返还沿用整机数量规则，不为组成项虚构逐件 SN。

### 4.2 幂等、冲突与部分成功

- 需求、返还和人工领用新增冻结请求与幂等键，重试复用原 key。回款新增沿用合同/月唯一约束，没有伪造幂等键；未知后冲突会分页读回并核对全部业务字段，不能自动修改既有记录。成功行不重发。
- 修改 / 作废类命令冻结读时 `version` 或 canonical digest；发生冲突后不自动升级 token 覆盖他人结果。
- 无响应、超时或 5xx 记为“结果未知”，不得伪称成功或失败；须用原请求重试或刷新核对。
- 4xx 明确拒绝只说明该次请求未接受；如果同一行此前已经是“结果未知”，后续 4xx 不能反推首次一定未落库。
- 所有页面批量都是逐行执行，可出现部分成功；**不承诺跨行原子事务或整批回滚**。

### 4.3 需求字段保护

- 页面只允许维护白名单字段：数量、退货数量、SN、描述、PN。
- override 保存人工值、导入源值及操作者；WBDD 重导跳过仍受保护的字段。
- 撤销恢复首次人工修改前的 `source_value`。WBDD 与项目总表保留各自导入规则；总表通过字段三路合并及提交前行摘要复核处理冲突，最新总表中明确发起的人工更正仍可执行。
- PN 是一个身份组；修改或撤销必须同步校验 canonical PN 与 `part_id`，禁止留下字符串与型号身份错位。
- canonical JSON 的 SHA-256 digest 是页面 GET、PATCH 和撤销操作共用的 OCC token。

### 4.4 人工领用与仓库闸门

- 页面人工领用只记录用户明确提交的领用事实，来源固定为 `page_manual`，不冒充 `direct_api` 或仓库交付。
- 成本仍走 06 人工领用既有瀑布；缺价保持空值并提示，不编造 0 成本。
- 返还义务及更正审计复用既有 06 规则。
- `direct_api` / `production_ready` 等仓库适配器原闸门保持关闭条件不变；不得为了页面领用绕开仓库生产就绪校验。
- 页面领用不改变库存，也不得把需求单伪造成仓库发货记录。
