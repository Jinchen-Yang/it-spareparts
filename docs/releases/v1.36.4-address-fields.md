## 发布与回滚

本次须仅替换 `it-spareparts-app-1` 和 `it-spareparts-frontend-1`。保留数据库、Caddy、商城容器、原工作树、全部环境值、上传挂载、端口及外部网络。当前线上 app 来自商城只读接口发布目录，不能直接执行 `/opt/it-spareparts` 旧 compose。

已基于实际容器 inspect 生成候选/回滚两服务 Compose；本地 config 校验及环境逐值比对通过。含凭据文件只存私有证据目录，不提交到 Git。完整操作稿位于当前操作者私有证据 `release-preflight.md`，另一台机器操作时必须重新获取实际运行配置，不能照抄旧凭据或假定目录仍存在。

批准后的顺序：

1. 锁定批准后的 main 精确 SHA，归档源码，先构建两张带 revision 标签的新镜像。
2. 再次核对旧容器镜像 ID 和运行配置，保存旧镜像、inspect、网络及可读回滚配置。
3. 只停两应用容器；备份数据库和上传文件并校验摘要，在无网络的临时 Postgres 做恢复演练。
4. 用新镜像执行 `alembic upgrade head` 和结构核查，预期迁移头仍为 `e7c1f9a3b5d2`。
5. 只启动新 app/frontend，不使用 `down`、`prune`、`--remove-orphans`，核对其余容器 ID 不变。
6. 验证健康、正常登录、需求单/领用地址只读展示及商城9项只读链路；记录 URL、源码 SHA、镜像 ID、备份与结果，打 `release-` 标签。

任一关键验证失败，保存诊断后按回滚 Compose 启回原 app/frontend。无迁移时不恢复旧数据库、不删除新上传文件、不执行 downgrade，避免覆盖上线后的真实业务。
