# v1.34.0 维保数据分析「开支统计」：时间粒度 / 业务类型拆分 / 销售查询

> 状态：方案已定稿，实现与验证见本文件后续章节（2026-09-16 夜由 agent 完成并部署）。

## 一、需求背景（甲方原话）

> 「维保订单里面 数据分析能不能按照每天 每周 每月 每年 能选择 而且也能区分备件外包 拆改配服务 整体运维 算力运维这几类的开支 这个能不能按照销售的名称查询」

拆解为三条：

| 编号 | 需求 | 口语对应系统口径 |
|---|---|---|
| R1 | 按天 / 周 / 月 / 年可选 | 时间**统计粒度**（把开支按周期分桶），不是简单的起止日期筛选 |
| R2 | 区分各类开支 | 业务类型开支**拆分**：备件外包=备件维保、整体运维=整体维保，另有拆改配服务、算力运维（沿用现有六档 + 未归属） |
| R3 | 按销售名称查询 | 按销售**筛选与汇总**（现有 `sp` 包含筛选已支持查询；缺按销售的开支汇总视图） |

需求类型：**统计口径扩展**（时间维度 × 业务分类 × 人员维度），与 v1.33 已交付的「全字段筛选」互补——筛选解决「看哪一单」，本次解决「看哪一类、哪一期、哪个人」。

## 二、现状（v1.33.0 已部署）

- `/maintenance/analytics` 只有 **PN 排名**一个视图：按 PN 聚合的成本/数量/坏件排名；
  时间维度是**范围筛选**（本年/近 12 月/全部/自定义起止），没有周期分桶。
- 业务类型只能**筛选**（六档多选），没有「每类开支多少」的拆分展示。
- 销售只能**筛选**（`sp` 包含匹配），没有按销售的汇总。
- 数据基础已齐备：行成本经 `maintenance_cost_quality.sql_normalized_line_cost` 归一
  （缺价不计 0、单列计数）；业务类型按**需求单当前活跃挂靠项目**分类；行键范围
  （`own_maintenance_projects_only`）收敛逻辑现成可复用。

## 三、目标（达成后是什么样）

1. 数据分析页新增「开支统计」页签，与「PN 排名」并列；顶部筛选栏（时间范围、业务类型、
   项目、客户、销售、单号、需求类型、仓库、成本来源）对两个页签**共同生效**。
2. 页签内可选 **按天/按周/按月/按年**（默认按月），整页数据按该粒度分桶。
3. 展示：**堆叠柱状图**（每期各业务类型开支）+ **按业务类型汇总表** + **按销售汇总表**
   + **按期明细表**（时间 × 各分类金额）。四种视图口径一致、可互相核对。
4. 销售下拉/输入框可按名称查询，并直接看到该销售的开支汇总与占比。
5. 全部状态写入 URL（view / granularity + 既有筛选），刷新与分享不丢。

## 四、验收指标

| # | 指标 | 判定 |
|---|---|---|
| A1 | 粒度正确性 | 同一批数据分别按日/周/月/年分桶，各桶合计与总额一致；周桶从周一开始；跨年跨月边界不重不漏 |
| A2 | 分类正确性 | 六档 + 未归属（无项目）拆分之和 == 总额；未标注仅指「有项目但类型为空」；未归属单独一行显式展示，不混入未标注 |
| A3 | 筛选一致性 | 业务类型/项目/客户/销售/单号/需求类型/仓库/成本来源/时间窗与 PN 排名页口径完全一致（同参数同结果） |
| A4 | 权限 | 无成本权限：金额列 restricted 信封、数量与单数正常；无行键范围账号看不到范围外数据（含未归属） |
| A5 | 成本口径 | 已知成本合计（缺价行单列计数，不按 0 计）；与 PN 排名页同口径 |
| A6 | 销售查询 | `sp` 筛选收窄销售汇总表；无销售值的单归「未标注」 |
| A7 | 交互 | 切粒度/切页签/改筛选不串数据（旧响应不覆盖新结果）；重置一键清空；URL 可恢复 |
| A8 | 回归 | 既有 PN 排名功能与测试全绿；后端相关回归、前端全量、构建、CI 通过 |
| A9 | 上线 | 生产迁移头一致、健康、`hbzgc.icu` 版本号 v1.34.0 |

## 五、约束

1. **无数据库迁移**：只读聚合，不新增表/列。
2. **口径冻结**：成本只认 `sql_normalized_line_cost`；业务类型分类复用
   `business_type_code` / `BUSINESS_TYPE_*` 常量与 btrim 语义；行键范围复用
   `maintenance_scope_project_ids`；筛选参数复用 `parse_csv_items` 与既有 422 语义。
3. **权限不放松**：成本三态信封（ready/restricted/not_imported）；审计只记布尔标志，
   不落客户/销售/单号等自由文本。
4. **图表规范**（charts/README）：option 必须 useMemo、null≠0、颜色只取 CHART_COLORS、
   金额文案写「金额合计」。
5. **最小侵入**：不重构既有 PN 排名逻辑；筛选栏共用；默认页签仍是 PN 排名，
   既有前端测试不改语义即可通过。
6. **发布纪律**：分支 → PR → CI 全绿 → squash 合并 → 生产部署（数据备份、迁移头核对、
   健康检查、版本核验、tag、版本日志）。

## 六、实现方案

### 6.1 后端（新增只读接口）

`GET /api/maintenance/analytics/spend-trend`，参数与校验与 `pn-ranking` 对齐：

- `range`(ytd|12m|all|custom，默认 ytd) / `date_from` / `date_to`
- `granularity`(day|week|month|year，默认 month)
- `business_type`（同 `BUSINESS_TYPE_FILTER_PATTERN`，默认 all）
- `project`(≤50)/`customer`(≤128)/`sp`(≤128)/`order_no`(≤128)/`demand_type`/`warehouse`(≤10，原值)/`cost_source`

聚合：

- 分桶 `date_trunc(granularity, order_date)::date`；周桶为周一。
- 分类 CASE（与 `business_type_code` 同语义）：无活跃挂靠项目→`unassigned`；
  项目类型空/空白→`unlabeled`；四类标准字面量→对应码；其余非空→`other`。
- 单次查询按 (bucket, 分类) 分组；销售汇总单独一次 group by；返回前在 Python 侧透视。
- 成本 = 已知成本合计（含税/未税），`missing_lines` 单列；数量 = Σqty、有效数量 = Σ(qty−return_qty)。
- 权限/范围/审计与 `pn-ranking` 完全一致；未导入 WBDD 时成本返回 not_imported 信封。

响应：`buckets[]`（含每分类金额与合计）/`by_business_type[]`/`by_salesperson[]`/`summary`/`window`/`granularity`。

### 6.2 前端

- 页签：`view=pn|spend`（默认 pn）；既有内容整体进 PN 页签（DOM 与默认行为不变）。
- Spend 页签：粒度 Segmented（日/周/月/年）→ 堆叠柱状图（`SpendTrendBar`，
  超 40 期只画最近 40 期并注明，完整数据在明细表）→ 按业务类型表 → 按销售表 → 按期明细表。
- 成本列走既有 `statMoney` 三态渲染；无权限显示「—/需要权限」。
- 独立性：spend 数据独立请求与代次守卫；刷新/重置对当前页签生效。
