# P1-1 返还只读筛选与需求单核对候选

决策: D-31

本文件说明本地候选的范围与验收方法，不表示用户已验收、已合入 main 或已部署。
批次 0 的 D-31 及 `maintenance-return-request-summary-v1` 须先进入集成基线。

## 范围与口径

- 领用、返还列表使用主数据库当前 `category_major/category_minor`，在数据库分页前筛选。
  `category_state=unclassified` 表示已关联主数据但任一级品类为空；`unlinked` 表示未关联主数据。
  不根据 PN 文本猜品类，不改变返还要求的标准分类或冻结义务。
- 领用仍按单头分页，`total` 是匹配单数；返回明细只含命中有效行。
  筛选后的 `total_line_count` 表示整单有效行数，原有整单作废仍影响整单。
- 返还收货按行分页，列表与总数使用同一组筛选条件；更换筛选清理选择，刷新保留已执行条件。
- 需求单摘要只读计算：N 是有效明细需求数量之和，R 是精确关联整单的全部有效收货。
  按 D-31 第 8 款 / 汇总契约 v1.1-draft，从 N、R 同时剔除规则免返硬盘；
  不扣退货、不取自报汇总；部分返还仍未返，超收保留原数。
  判定直接复用 `maintenance_bad_returns.classify_return_obligation`，只使用标准品类证据，
  剔除来源限 `project_default_no_return` / `category_disk`，行级显式必须返仍计入；
  非硬盘、只有品类文字而无标准品类的备件不剔除。
  `line_no_return` 不在本次枚举的两个来源内，仍计入；后续若扩展须先更新契约。
  项目免返提醒是纯文本，不驱动剔除。分别输出
  `excluded_exempt_disk_demand_qty` / `excluded_exempt_disk_received_qty`，三位小数字符串或 null。
  数量缺失、负值、零量、无有效明细、失效或归属异常时不伪造确定进度。
  全部剔除后 N=0 仍为待核对，不自动已返；跨项目冲突同时遮蔽剔除收货量。
  领用覆盖优先使用同单同备件的需求原始行身份；仓库明细身份不等于需求行身份，
  无需求行身份时使用同单同备件的覆盖证据，显式必须返优先。
  人工录入的单号参考仅在同项目、单号唯一且没有冲突稳定单 ID 时采用。
  同单同备件需求行同时存在应返和免返、且收货无法逐行区分时，收货及其衍生量标待核对，
  不按数量或比例分摊；已知 N 与需求剔除量仍展示。
- P4 消费同一汇总 Module；列表只传本页 ID，完整快照由调用方建立只读 REPEATABLE READ 事务。
  单批仍一条 SELECT，需求、收货与领用覆盖证据独立聚合后汇合，数量按文本取回再以 Decimal 计算。
  `unknown_order_count` 只计数量不完整或归属异常；失效、停用和无归属单另计 `inactive_order_count`。
  `over_received_qty` 仅在当前单完整有效时发布，不能把失效单差额当成确定超收。
  原卡墙及 PN 分析仍用同期实际返还／同期实际领用，摘要不进入删除或明细 OCC digest。
- 项目内需求单 `project_orders` 现已对授权后的当前页批量富化 `return_summary`，
  API 每页上限 200（小于汇总上限 500），前端 `BoardOrderRow` 共享相同类型。
- 汇总始终检查未恢复墓碑；稳定需求单列表的墓碑过滤仅在 cutover 开启时生效。
  因此 cutover 关闭时，列表可能保留某行，而该行摘要显示失效／待核对；本 PR 不改变列表集合或开关。
- 全局需求单列表现在向非编辑者提供只读明细入口；后端原已允许有读权者读取，未扩展写权限。

本批不实施新增容量限制、满额候选、领用页内更正、批量应返／免返、导出排序或待返分析页签。

## 既有返还指标的保留与收敛

`maintenance_boss_board._pending_return_item` 仍使用项目有效需求明细 `return_qty` 合计减 RKD `returned_bad`，
允许负差额且受 RKD 导入就绪状态影响；它与新服务的逐单 `max(N-R,0)` 不同。
本 PR 保留旧行为，后续由 S-B / S-C 将该待返入口收敛到新服务，不能宣称本次已统一所有待返数字。

`maintenance_return_receipts.receipt_summary` 是实收事实总计，不是另一套待返公式。
它保留所有 active 实收（含规则免返硬盘），保证“关联各单量之和＋未关联量＝项目实收总量”。
不能直接用剔除后的 R 替换这些字段；后续如新增核对差额／状态，应调用新服务并保留实收事实字段。
卡墙／PN 同期返还率及旧冻结义务的判定、数量、审计均保持现行行为。

尚需 S-B API owner 代接 `ReturnSummaryError` → 503 / code 的异常映射补丁，
见 `R/logs/S-A-370fix-to-S-B-summary-error-mapping.patch`；本次未改 owner 的 API 文件。
该异常分支尚不具备契约规定的 503 响应，候选发布前需补齐。

## 本地检查与用户验收

自动检查使用本机随机隔离 PostgreSQL 库和合成数据，默认基库位于 :5433。
共享实例 I/O 拥堵时，可用 `PYTEST_DATABASE_BASE_URL` 指向本会话独享的同版本本机临时实例；
保留 conftest 的随机库 / 所有权保护和 PostgreSQL 默认持久化设置，不修改共享服务。
实际端口、命令、退出码及临时资源清理记录见 S-A 报告。
完成后端 pytest 全量、Alembic 单头检查及前端 tsc、Vitest 全量、Vite 构建；既有失败须在干净
origin/main 快照复现，不删除或跳过测试。高负载时只限制测试 worker，不减少用例。

待用户在候选构建实际点按：

1. 一单含硬盘、内存，多页领用与返还：分别选择大类、小类、未分类和未关联；核对总数、分页、
   清空及刷新条件。筛选后点击整单作废时确认提示仍准确说明整单范围。
2. 需求单 N=5，先收 2 再收 3：列表／明细显示未返 2/5、已返 5/5；只读用户能看摘要。
3. A 单 N=2/R=3、B 单 N=4/R=0：A 原数及超额保留，B 差额仍为 4；项目免返提醒不驱动剔除。
   混合硬盘和内存单据中，核对默认免返硬盘同时退出 N/R，行级必须返仍计入；
   全硬盘被剔除后 N=0 显示待核对，同型号应返／免返混合收货显示无法逐行核对。
4. 缺量、零量、取消、跨项目旧收货：显示待核对及原因，不出现伪零或无权项目数量。
5. 切换项目、快速改筛选和旧请求迟到时，页面不串数据；保存其他事实后摘要参与必要读回。
