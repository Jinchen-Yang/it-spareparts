# P1-1 返还只读筛选与需求单核对候选

决策: D-31

本文件说明本地候选的范围与验收方法，不表示用户已验收、已合入 main 或已部署。
批次 0 的 D-31 及 `maintenance-return-request-summary-v1` 须先进入集成基线。

## 范围与口径

- 领用、返还列表使用主数据库当前 `category_major/category_minor`，在数据库分页前筛选。
  `category_state=unclassified` 表示已关联主数据但任一级品类为空；`unlinked` 表示未关联主数据。
  不根据 PN 文本猜品类，不改变返还要求的标准分类或冻结义务。
- 领用仍按单头分页，`total` 是匹配单数；返回明细只含命中有效行。
  筛选后的 `total_line_count` 表示整单有效行数，原有整单作废仍影响整单。
- 返还收货按行分页，列表与总数使用同一组筛选条件；更换筛选清理选择，刷新保留已执行条件。
- 需求单摘要只读计算：N 是有效明细需求数量之和，R 是精确关联整单的全部有效收货。
  不扣退货或免返，不取自报汇总；部分返还仍未返，超收保留原数。
  数量缺失、负值、零量、无有效明细、失效或归属异常时不伪造确定进度。
- P4 消费同一汇总 Module；列表只传本页 ID，完整快照由调用方建立只读 REPEATABLE READ 事务。
  原卡墙及 PN 分析仍用同期实际返还／同期实际领用，摘要不进入删除或明细 OCC digest。

本批不实施新增容量限制、满额候选、领用页内更正、批量应返／免返、导出排序或待返分析页签。
项目需求单数据源由 S-B 接线；未合入其后端富化前，独立状态组件不能替代实际摘要数据。

## 本地检查与用户验收

自动检查使用本机随机隔离 PostgreSQL 库和合成数据，默认基库位于 :5433。
共享实例 I/O 拥堵时，可用 `PYTEST_DATABASE_BASE_URL` 指向本会话独享的同版本本机临时实例；
保留 conftest 的随机库 / 所有权保护和 PostgreSQL 默认持久化设置，不修改共享服务。
实际端口、命令、退出码及临时资源清理记录见 S-A 报告。
完成后端 pytest 全量、Alembic 单头检查及前端 tsc、Vitest 全量、Vite 构建；既有失败须在干净
origin/main 快照复现，不删除或跳过测试。高负载时只限制测试 worker，不减少用例。

待用户在候选构建实际点按：

1. 一单含硬盘、内存，多页领用与返还：分别选择大类、小类、未分类和未关联；核对总数、分页、
   清空及刷新条件。筛选后点击整单作废时确认提示仍准确说明整单范围。
2. 需求单 N=5，先收 2 再收 3：列表／明细显示未返 2/5、已返 5/5；只读用户能看摘要。
3. A 单 N=2/R=3、B 单 N=4/R=0：A 原数及超额保留，B 差额仍为 4；免返提醒不扣差额。
4. 缺量、零量、取消、跨项目旧收货：显示待核对及原因，不出现伪零或无权项目数量。
5. 切换项目、快速改筛选和旧请求迟到时，页面不串数据；保存其他事实后摘要参与必要读回。

## 迁移与回退

本候选无 Alembic 迁移、无历史回填，不改变收货、领用、库存或业务状态。
回退前后端同一候选的展示与富化适配；若 S-B / P4 已消费汇总接口，保留兼容服务或协同撤回消费者。
保留实际收货及审计。
不得降级历史收货台账结构，也不能在回退后声称已有本批之外的容量保护。
