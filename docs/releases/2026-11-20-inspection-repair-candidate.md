# 检测与维修候选验收及回退

关联 [Issue #549](https://github.com/Jinchen-Yang/it-spareparts/issues/549)，业务口径见 [D-0067](../decisions/0047-维修任务单正式接入维保返还.md) 与 [D-0071](../decisions/0051-维修结果去向标签与导出.md)。候选 SHA 与执行结果随 PR 更新。

## 点按验收

- 在隔离副本中，用具备维修主管和维保项目范围的实名账号，进入「维保 → 检测与维修」。创建维修单，在左侧搜索并选中已实收的坏件，核对右侧来源和可送修数。保存后再次查询，核对已占用的数量从可用数中扣除。
- 切到销售账号，建单后放入公共池。用维修人员账号领取，登记部分修好及没修好数量，再退回主管。主管在「我的任务 → 退回待处理」查看原单及负责人记录，按需更正、改派。确认其他维修人员无法办理该单。
- 用去向管理员账号为修好件登记电商或主公司去向。维修主管可查看「修好 · 已登记去向」标签和对应件数，并在任务总池导出 Excel。核对部分登记时标签与 Excel 仅计已登记数量，按去向逐行列示。
- 未授维修岗位的账号没有入口。维修主管只能引用有维保查看权限的项目返还行。电商去向仅在 ITSP 登记。

## 迁移和回退

两条迁移新增维修单、任务条、幂等请求记录和共享返还容量防护。旧维修结果留在原表，旧待修池仍通过共享扣数反映可用数量。现有账号按既有权限中心流程显式授维修岗位。

验收前在隔离数据库确认 Alembic 单头、升级及 ORM 无漂移。若并行功能先进入 main，先同步并复核首条维修迁移的父 revision。升级失败或旧待修容量异常时停止候选切换。

如后续版本经授权发布，按当前生产 runbook 备份并校验可恢复性，用同一候选 SHA 构建前后端，先执行迁移再启应用。出现越权、重复占用或结果导出不一致时，按 runbook 停止扩大授权。回退优先撤回维修岗位及恢复前端入口，保留数据库及共享容量保护。已经产生维修单后，数据库降级会拒绝删除维修事实；需要回退后端时，先验证目标版本的旧维修写入与共享容量保护兼容，并保留两条业务线的新事实。
