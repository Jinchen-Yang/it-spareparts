# v1.12.x 发布 Runbook（PR #89 看板 + PR #90 后续修复）

本文是**本次版本专用**的发布手册；通用部署流程见 [docs/DEPLOY.md](../DEPLOY.md)（保持不动）。
本次发布包含：数据库迁移（部件池 + 序列对齐）、**利润税口径统一 13% → 必须利润重算**、池初始化。
生产发布前必须先在 staging 用生产快照完整演练本文全流程。

约定：服务名 `db` / `app` / `frontend`，数据库名 `spareparts`，项目目录 `~/apps/it-spareparts`；
`BACKUP` 指向本次唯一备份文件，不要用 `backup-*.dump` 之类模糊 glob。

**失败即停**：全流程在同一个 bash 会话里执行，开头先：

```bash
bash            # 进入子 shell 执行发布（检查失败 exit 1 只退出子 shell，不关运维终端）
set -euo pipefail
```

`set -e` 下任何命令非零即中止。下文所有语义检查都写成**失败时非零退出**的形式
（`grep -q PASS`、`[ "$(…)" = "0" ]`、python `assert`），只打印不拦截的检查一律无效。

## 0. 部署目标（先决条件）

**生产只部署已合并进 `main` 的精确 squash SHA，绝不部署功能分支**——功能分支会被删除，
且 squash 后 main 上的正式提交 SHA 与分支 SHA 不同。

PR #90 批准合并后，在本地确认目标 SHA 并填入下方（示例）：

```bash
git fetch origin main
git log origin/main --oneline -3     # 找到 "…（v1.12.x）(#90)" 的 squash 提交
# 把它的完整 SHA 写进 TARGET_COMMIT，此值贯穿全文
```

## 1. 服务器上检出目标 SHA，记录回滚基线

```bash
cd ~/apps/it-spareparts
OLD_COMMIT=$(git rev-parse HEAD)
TARGET_COMMIT=<粘贴已批准的 main squash SHA>
git fetch origin main
# 目标 SHA 必须真实属于 origin/main（防止误填功能分支/本地提交）
git merge-base --is-ancestor "$TARGET_COMMIT" origin/main \
  || { echo "FATAL: TARGET_COMMIT 不在 origin/main 上"; exit 1; }
git checkout "$TARGET_COMMIT"
test "$(git rev-parse HEAD)" = "$TARGET_COMMIT" || { echo "FATAL: 不在目标 SHA"; exit 1; }

# 记下当前运行版本，回滚时恢复这两个镜像和这个 commit。
OLD_APP_IMAGE_ID=$(sudo docker compose images -q app)
OLD_FRONTEND_IMAGE_ID=$(sudo docker compose images -q frontend)
echo "OLD_COMMIT=$OLD_COMMIT OLD_APP=$OLD_APP_IMAGE_ID OLD_FE=$OLD_FRONTEND_IMAGE_ID"
```

## 2. 备份并由 db 容器校验

```bash
mkdir -p backups

export BACKUP

sudo docker compose exec -T db pg_dump -U spareparts -Fc spareparts > "$BACKUP"
```

备份为空或 `pg_restore --list` 失败：**立即中止**，不得进入迁移或重算。

## 3. 重算前锁定固定 40 单 + 导出旧值基线（版本无关 SQL）

> 本节只用 **db 容器 psql**，不依赖任何 app 镜像里的 Python 模块——旧生产镜像没有
> `app.services.dashboard`，新镜像此时也尚未构建。
> 旧值基线**只用于解释差异**：本次发布本来就在改 13% 税价口径，正确重算的结果与旧值
> 出现明显差异是预期行为，**绝不能**要求"重算前后差 ≤0.01"。

```bash
PSQL='sudo docker compose exec -T db psql -U spareparts -d spareparts -v ON_ERROR_STOP=1'

# 3a. 锁定 40 个**互不相同**的单：营收最高 20 + md5 稳定伪随机 20（随机组显式排除
#     high 组，两组无交集）。生产已生效销售单远超 40，若这里凑不齐 40 个唯一单号说明
#     连库/口径错了——直接停，不做小样本降级。
$PSQL -At -c "
WITH rev AS (
  SELECT o.id, o.order_no, sum(l.revenue_amount) AS revenue
  FROM f_sales_order o JOIN f_sales_line l ON l.order_id = o.id
  WHERE o.data_status = '已生效'
  GROUP BY o.id, o.order_no),
high AS (SELECT 'high' g, order_no FROM rev ORDER BY revenue DESC NULLS LAST, id DESC LIMIT 20),
rnd  AS (SELECT 'random' g, order_no FROM rev
         WHERE order_no NOT IN (SELECT order_no FROM high)
         ORDER BY md5(order_no), id LIMIT 20)
SELECT g || ',' || order_no FROM high UNION ALL SELECT g || ',' || order_no FROM rnd;
" > backups/orders40-${TARGET_COMMIT}.csv
# 硬校验：恰好 40 行且单号全唯一，否则非零退出中止发布
test "$(wc -l < backups/orders40-${TARGET_COMMIT}.csv)" = "40" \
  || { echo "FATAL: 锁定单数 != 40"; exit 1; }
test "$(cut -d, -f2 backups/orders40-${TARGET_COMMIT}.csv | sort -u | wc -l)" = "40" \
  || { echo "FATAL: 单号有重复"; exit 1; }

# 3b. 旧值基线（仅解释用）：导出全量订单聚合（与第 6 节同构；解释差异时用 3a 的
#     40 单文件过滤即可，避免向 SQL 注入单号列表的脆弱拼接）
$PSQL -A -F, -c "
SELECT o.order_no, sum(l.revenue_amount), sum(l.gross_profit)
FROM f_sales_order o JOIN f_sales_line l ON l.order_id = o.id
GROUP BY o.order_no ORDER BY o.order_no;" > backups/before-${TARGET_COMMIT}.csv
test -s backups/before-${TARGET_COMMIT}.csv
```

序列核对（打印存活最大 ID、序列水位与结论；**FAIL 即非零退出中止**）：

```bash
$PSQL -c '
WITH live AS (SELECT max(group_id) AS max_group_id FROM part_pool),
seq AS (SELECT last_value, is_called FROM part_pool_group_id_seq)
SELECT live.max_group_id, seq.last_value, seq.is_called,
       CASE WHEN seq.is_called THEN seq.last_value + 1 ELSE seq.last_value END AS next_value,
       CASE WHEN (CASE WHEN seq.is_called THEN seq.last_value + 1 ELSE seq.last_value END)
                  > coalesce(live.max_group_id, 0)
            THEN $q$PASS: next_value > max(group_id)$q$
            ELSE $q$FAIL: sequence may collide$q$ END AS conclusion
FROM live CROSS JOIN seq;' | tee /tmp/seq-check.txt
grep -q 'PASS: next_value' /tmp/seq-check.txt \
  || { echo "FATAL: 序列未对齐，按第 8 节回滚"; exit 1; }
```

## 6. 对账：按新 13% 公式独立验证 + 幂等复算（通过标准，非旧值比对）

**判定口径**：不比"新旧值相等"（口径变更下必然不等），而是——
① 40 单的行级数值**独立满足新公式**；② **第二次重算幂等**（差 ≤0.01）；
③ 旧值 vs 新值差异仅用于书面解释（应能全部归因于 ÷1.13 口径与成本重放）。

```bash
# 6a. 行级独立复核（新公式，**只覆盖利润引擎的正式重算范围 = 已生效订单**；取消/作废/
#     历史非生效行引擎不重算、允许保留旧值，混进来会把正确部署误判为失败）：
#     计营收行 revenue_amount = round(qty*unit_price/1.13, 2)；
#     有成本行 gross_profit = revenue_amount - cost_amount。两计数必须为 0，否则中止。
BAD_REV=$($PSQL -At -c "
SELECT count(*) FROM f_sales_line l JOIN f_sales_order o ON l.order_id=o.id
WHERE o.data_status = '已生效'
  AND l.counts_revenue AND l.qty IS NOT NULL AND l.unit_price IS NOT NULL
  AND abs(l.revenue_amount - round(l.qty*l.unit_price/1.13, 2)) > 0.01;")
BAD_GP=$($PSQL -At -c "
SELECT count(*) FROM f_sales_line l JOIN f_sales_order o ON l.order_id=o.id
WHERE o.data_status = '已生效' AND l.gross_profit IS NOT NULL
  AND abs(l.gross_profit - (l.revenue_amount - l.cost_amount)) > 0.01;")
echo "bad_revenue=$BAD_REV bad_gross=$BAD_GP"
[ "$BAD_REV" = "0" ] && [ "$BAD_GP" = "0" ] \
  || { echo "FATAL: 新公式复核不通过，按第 8 节回滚"; exit 1; }

# 6b. 第一次重算后导出 40 单聚合
AFTER1="backups/after1-${TARGET_COMMIT}.csv"
$PSQL -A -F, -c "
SELECT o.order_no, sum(l.revenue_amount), sum(l.gross_profit)
FROM f_sales_order o JOIN f_sales_line l ON l.order_id=o.id
GROUP BY o.order_no ORDER BY o.order_no;" > "$AFTER1"

# 6c. 幂等复算：第二次 recompute 后再导出，与第一次逐行比（40 单集合内差 ≤0.01）
sudo docker compose run --rm --no-deps app python -c \
  'from app.db import SessionLocal; from app.services import profit; db=SessionLocal(); print(profit.recompute(db)); db.close()'
AFTER2="backups/after2-${TARGET_COMMIT}.csv"
$PSQL -A -F, -c "
SELECT o.order_no, sum(l.revenue_amount), sum(l.gross_profit)
FROM f_sales_order o JOIN f_sales_line l ON l.order_id=o.id
GROUP BY o.order_no ORDER BY o.order_no;" > "$AFTER2"

python3 - backups/orders40-${TARGET_COMMIT}.csv "$AFTER1" "$AFTER2" <<'PY'
import csv, sys
orders = {line.split(",", 1)[1].strip() for line in open(sys.argv[1]) if "," in line}
assert len(orders) >= 20, f"锁定单号过少: {len(orders)}"
def load(p):
    out = {}
    for row in csv.reader(open(p)):
        if len(row) == 3 and row[0] in orders:
            out[row[0]] = (float(row[1] or 0), float(row[2] or 0))
    return out
a1, a2 = load(sys.argv[2]), load(sys.argv[3])
missing = orders - set(a1)
assert not missing, f"锁定单号缺失于导出: {sorted(missing)[:5]}"
assert set(a1) == set(a2), "两次导出的订单集合不一致"
bad = [(k, x, y) for k in a1 for x, y in [(abs(a1[k][0]-a2[k][0]), abs(a1[k][1]-a2[k][1]))] if x > 0.01 or y > 0.01]
assert not bad, f"幂等失败: {bad[:5]}"
print(f"PASS: {len(a1)} 单两次重算幂等（差 ≤ ¥0.01）")
PY

# 6d.（解释用）新旧对照：backups/before-*.csv vs AFTER1，逐单差异书面归因到 13% 口径，
#     出现无法解释的差额 → 按第 8 节回滚。

# 6e. KPI 独立对账：新镜像 one-off 直调 dashboard.kpi()，与独立 SQL 重算的六项逐一比对
#     （销售额/已配成本营收/毛利/采购额/未配成本营收/成本覆盖率 + 未来单排除）。
#     任何一项不符 → python assert 非零退出 → set -e 中止发布。
sudo docker compose run --rm --no-deps -T app python - <<'PY'
from sqlalchemy import text
from app.db import SessionLocal
from app.services import dashboard
db = SessionLocal()
k = dashboard.kpi(db, None, None)
sql = db.execute(text("""
WITH s AS (
  SELECT sum(l.revenue_amount) FILTER (WHERE l.counts_revenue) AS sales,
         sum(l.revenue_amount) FILTER (WHERE l.counts_revenue AND l.cost_moving_avg IS NOT NULL) AS costed,
         sum(l.gross_profit)   FILTER (WHERE l.counts_revenue AND l.cost_moving_avg IS NOT NULL) AS gp
  FROM f_sales_line l JOIN f_sales_order o ON l.order_id=o.id
  WHERE o.data_status='已生效' AND o.order_date <= current_date),
p AS (
  SELECT sum(CASE WHEN po.is_tax_inclusive IS FALSE THEN pl.qty*pl.unit_price
                  ELSE pl.qty*pl.unit_price/1.13 END) AS pur
  FROM f_purchase_line pl JOIN f_purchase_order po ON pl.order_id=po.id
  WHERE po.data_status='已生效' AND po.order_date <= current_date)
SELECT s.sales, s.costed, s.gp, p.pur FROM s, p""")).one()
def close(a, b, name, tol=0.01):
    a = float(a or 0); b = float(b or 0)
    assert abs(a - b) <= tol, f"KPI 对账失败 {name}: api={a} sql={b}"
close(k["sales_ex_tax"], sql.sales, "销售额")
close(k["sales_costed_ex_tax"], sql.costed, "已配成本营收")
close(k["gross_profit"], sql.gp, "毛利")
close(k["purchase_ex_tax"], sql.pur, "采购额")
close(k["sales_uncosted_ex_tax"], float(sql.sales or 0) - float(sql.costed or 0), "未配成本营收")
cov = (float(sql.costed or 0) / float(sql.sales)) if sql.sales else None
if cov is not None:
    assert abs((k["cost_coverage"] or 0) - round(cov, 4)) <= 0.0001, "成本覆盖率不符"
# 未来单排除：库里存在未来日期已生效单时，无日期上限的销售额必须严格大于 KPI 销售额
fut, uncapped = db.execute(text("""
SELECT count(DISTINCT o.id) FILTER (WHERE o.order_date > current_date),
       sum(l.revenue_amount) FILTER (WHERE l.counts_revenue)
FROM f_sales_order o JOIN f_sales_line l ON l.order_id=o.id
WHERE o.data_status='已生效'""")).one()
if fut:
    assert float(uncapped or 0) > float(k["sales_ex_tax"] or 0), "未来单未被 KPI 排除"
print(f"PASS: KPI 六项独立对账一致（未来已生效单 {fut} 张，已排除）")
db.close()
PY

sudo docker compose up -d app frontend
sudo docker compose ps
```

## 8. 回滚：重建干净库恢复备份 + 旧镜像（联合回滚）

利润重算和迁移已改库时，不能只回滚镜像，也不能对现存库直接 `pg_restore --clean`
（不会删除备份中不存在的新对象）。必须停写、重建库、恢复旧镜像/commit：

```bash
sudo docker compose stop app frontend

sudo docker compose exec -T db psql -U spareparts -d postgres -v ON_ERROR_STOP=1 -c \
  "SELECT pg_terminate_backend(pid) FROM pg_stat_activity
   WHERE datname='spareparts' AND pid <> pg_backend_pid();"
sudo docker compose exec -T db psql -U spareparts -d postgres -v ON_ERROR_STOP=1 -c \
  'DROP DATABASE spareparts;'
sudo docker compose exec -T db psql -U spareparts -d postgres -v ON_ERROR_STOP=1 -c \
  'CREATE DATABASE spareparts OWNER spareparts;'
sudo docker compose exec -T db pg_restore -U spareparts -d spareparts --no-owner < "$BACKUP"

git checkout "$OLD_COMMIT"
APP_IMAGE_REF=$(sudo docker compose config --images | awk '/app/ {print; exit}')
FRONTEND_IMAGE_REF=$(sudo docker compose config --images | awk '/frontend/ {print; exit}')
sudo docker tag "$OLD_APP_IMAGE_ID" "$APP_IMAGE_REF"
sudo docker tag "$OLD_FRONTEND_IMAGE_ID" "$FRONTEND_IMAGE_REF"
sudo docker compose up -d app frontend
sudo docker compose ps
```

恢复后重跑健康检查、`alembic current` 与关键页面验收；恢复失败保持 app/frontend 停止并升级处理。
