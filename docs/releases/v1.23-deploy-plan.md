## 2. 发布包构建（合并后）

```bash
python3 .deploy/v123_maintenance_boss_manifest.py build \
  --source-dir .deploy --target-sha <新main SHA> \
  --parent-sha ab42005b5b94bf98b3db0e4bff87e5df9da2f7ca --out <package-dir>
```

> `--source-dir` 必须是 `.deploy/`（清单按 `source_dir / 工件名` 定位，包目录扁平），
> 不是仓库根；填仓库根会以「缺少发布工件」失败。

2. **代码切换**：`git fetch origin main && git checkout -B deploy-v123 origin/main`（先确认工作树改动只有那 4 个文件）
3. **恢复现场配置**：把备份的 `backup.sh`／`monitor.sh`／`docker-compose.secure.yml` 盖回（compose.yml 经比对与新 main 一致，无需恢复；见发现 10）

5. **构建新镜像**（发现 7 补充，不可省）：`docker compose build app frontend`
6. **预检**：`./v123_maintenance_boss_release.sh preflight <state> <package-dir>`
7. **备份**：`backup <state> <backup-dir>`（pg_dump -Fc）
8. **迁移**：`migrate <state>`（强制总闸 false；c8e2a4f6b1d3 → d6e1f4a8c3b5，读回核验）
9. **部署**：`deploy <state>`（重建 app/frontend，总闸仍 false，读回核验）
10. **灰度**：`canary <state>`（翻总闸 true，容器读回核验；失败自动紧急复位）
11. **观察**：`observe <state> 30`（30 分钟观察期，抽查 404/500 日志与看板页面）
12. **收尾**：`commit-release <state>`

回滚口径：**只关 flag**（`rollback <state>`），永不 downgrade。
