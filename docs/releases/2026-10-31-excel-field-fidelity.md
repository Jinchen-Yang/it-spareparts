本轮授权为代码修复、独立验收、CI 和正常合并；没有生产部署或历史补录授权。

## 数据库迁移

迁移 `c7e1a3b5d9f2`，前驱 `a3c5e7f9b2d4`。新增 nullable Text 原文列并将注册展示列从 varchar 扩到 Text；无业务值回填。具体列集合以迁移中的 `_ORDER_TEXT_WIDEN` / `_LINE_TEXT_WIDEN` 为准，ORM 同步。

迁移设置 5 秒锁等待上限。若锁等待失败，应确认事务回滚并排查占锁来源，按既有发布程序重试；不得擅自终止其他连接或提高限额掩盖占锁问题。

## 候选验收

精确提交使用独占 Linux/PostgreSQL 环境和原仓库 pytest 隔离，不连接生产业务库。至少执行：

1. `uv run --extra dev alembic upgrade head`、`alembic check`、`alembic heads`，确认零漂移和单头。
2. 缺列/空白/长原文、人工保护、地址清空、revision 失效、合同事实所有权、销售问题单据保留旧值及其他合法单据继续。
3. `tests/test_expense_source_text_length.py`：边界值保留、超长 skip/upsert 整批拒绝且旧费用不作废。
4. `tests/test_excel_field_fidelity_migration.py`：空/短数据降级再升级，以及长单头、长明细、新原文非空三类拒绝降级；失败后 revision/schema/原值不变。
5. main 分支保护的两项完整 CI 全绿，跨模型复审记录在 PR；同步 main 后正常 merge commit，不绕过保护。

实际通过数、失败修复、精确 SHA 与日志在 PR/验收证据中记录。测试文件存在不等于已经执行通过。

## 获得生产部署授权后

按 `docs/BRANCH_POLICY.md` 选择明确发布范围及精确提交，备份数据库、归档原件和镜像回退点；前后端使用同一提交。先完成 `alembic upgrade head`，再启用候选应用镜像并做导入回执/只读证据冒烟；按仓库程序记录 `release-` 标签、镜像 revision 和迁移 revision。main 合并不代表上线，不从功能分支直接发布。

## 回退边界

优先回退应用镜像并保留扩容后的 schema。旧代码可读取新增兼容列之外的既有字段；须注意旧导入缺陷会随旧代码恢复，回退期间停止相关新导入并核对已接收批次。

需要结构回退时，先停相关写入并备份/导出受影响字段，再对本次前驱执行降级。迁移在检查与收窄的同一事务持有表锁：任何文本超过旧列宽，或 `adjust_warehouse_raw` 存在任何非 NULL 值，均明确拒绝降级，不截断、不删原文。不得为通过降级而自动清空这些字段；人工核对保留方案后才可另行处理。

历史丢值和快照补旧单头仍需带 file_hash、批次、稳定身份、字段旧值/候选值、人工保护和冲突信息的只读差异清单。此迁移与合并都不授权整单 upsert 重放或生产补写。
