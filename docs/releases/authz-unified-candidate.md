# 统一模块授权候选运行说明

决策：D-0027。本地开发候选，未部署；S1 阶段回归和独立审查进行中，后续全域迁移尚未完成。统一验收及最终合并判断在 S4 完成后进行。

运行配置由 `app.authz.runtime` 统一解释：

| 配置 | 含义 |
|---|---|
| `AUTHORIZATION_MODE=legacy_compat`（默认） | 使用未迁模块的原管理协议；不能恢复已经切换资源的旧允许 |
| `AUTHORIZATION_MODE=unified_modules` | 使用规范资源配置、来源快照、CAS 与批量预览协议 |
| `AUTHZ_ENABLED_RESOURCES` | JSON 字符串数组；只能包含当前执行目录已实施的资源，S1 只有 `sales_analysis` |
| `AUTHZ_SUSPENDED_RESOURCES` | JSON 字符串数组；暂停已经切换的资源。初次以暂停态切换时，该资源也须在 enabled 集合 |
| 原销售 enabled / suspended 两项 | 与相应新集合取并集，由同一个运行态解析器处理；不是前后端各自的开关 |

应用先完成 Alembic 迁移，再由 lifespan 在独立连接事务幂等写入 `sys_authorization_cutover`，提交后才进入 ready。`compose.authz.yml` 同时明确统一模式和销售启用，默认栈仍保持原模式；此说明没有执行任何环境切换。业务请求、`/me`、模板或账号保存都不写切换标记。

已存在 marker 后，移除启用配置或改回兼容模式只会暂停新资源，不恢复旧权限。配置声明启用但初始化未完成时请求返回 503；未知、计划中或退役资源无法启用。每次请求读取当前 marker，避免另一实例已切换但本实例仍缓存旧状态。暂停时业务拒绝，统一模式的实名管理员仍可修正配置。

S0 的旧授权 PUT 永久退役。单账号、模板、批量和同步都走规范来源与 Grant 同事务编排；已切换环境不得使用旧 bool 写体，空旧字段也会拒绝。用户来源变化与客户归属变化推进 token_version，旧会话失效；模板保存只推进模板版本，必须显式同步才影响已套账号。

旧版本不识别 marker，因此不能把回滚应用到旧代码、删除 marker 或切回 bool 配置视为安全暂停。S1 migration 的 downgrade 在已有任一 marker 时明确拒绝；未激活的候选仍可正常进行迁移往返测试。当前候选的可逆操作是暂停资源并保留新授权执行链；未来若确需恢复切换前整套版本与数据，必须停止入口并按经核验的完整备份恢复方案处理，不能在运行中重开旧权限。最终发布回执、备份与恢复演练、真实账号点按均尚未产生。
