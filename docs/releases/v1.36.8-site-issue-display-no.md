# v1.36.8 领用单人类可读展示号（LY-YYYYMMDD-NNNN）

日期：2026-10-15（上海）。决策：0006。

## 背景与范围

06 维保项目总表上传的自动领用单号是 hash 形式
`LY-AUTO-<sha256[:20]>-<sha256[:24]>`，对用户完全不可读。本次仅落地
**人类可读展示号**：hash 形式继续充当内部身份（去重/replay/唯一约束/前缀
判断全部原样），列表、详情、导出与回执展示 `LY-YYYYMMDD-NNNN`。
同批提议的「是否应返还空值默认/列头改名」与「作废重建警告」被用户明确放弃，
本次 diff 不含任何返库/no_return 逻辑、列头或导入解析变化。

## 改动

1. **schema（迁移 `c8f3d1a7e2b9`，down_revision `e7c1f9a3b5d2`）**：
   `maintenance_site_issue.display_no`（String(32) 可空、
   CHECK 格式 `^LY-[0-9]{8}-[0-9]{4,}$`、部分唯一索引
   `ux_maintenance_site_issue_display_no`）+ 按日计数器表
   `maintenance_site_issue_display_counter`；存量 LY-AUTO-% 行按
   `issue_date` 分组、组内 `created_at` 再 `issue_id` 确定性回填，计数器
   对齐各日最大值。downgrade 顺序完整回退（索引→CHECK→列→计数器表），
   不动既有值。
2. **分配（仅 apply 事务内）**：首次创建 LY-AUTO 单头时按其 `issue_date`
   原子递增计数器分配；与单头 INSERT 同事务，整本回滚一并撤销；replay
   按 hash 身份查回、绝不重新分配；用户手填号不分配。分配后永不变更。
3. **展示口径 `display_no_effective`**：`site_issue_dict`/搜索、V1/V2/v3
   导出、作废回执、返还义务台账「来源单号」统一展示可读号（用户改号后
   以用户号为准）；搜索 q 增加可读号匹配。写操作仍用 issue_no/issue_id。
4. **导出/回读兼容**：V2/V1 下载件单号列写展示号；replay 比对、
   `site_base_hashes` 与删行守卫钉在 issue_no 身份口径——旧版（hash 列）
   在途文件删行/重放不受影响；回读时单元格值等于 display_no 不算改号。
5. 前端：SiteReturnTab / SiteIssueWorkflowPanel 展示 `display_no || issue_no`
   （作废等 API 调用仍用身份字段）；BadReturnPanel 来源单号随接口自动变可读。
6. 版本号 1.36.8 + 更新日志；CONTEXT.md 增补「领用展示号」术语。
