# v1.33.0 数据分析全字段筛选与「拆改配服务」业务类型

## 范围

1. 维保数据分析（`/maintenance/analytics`）新增七个筛选：项目、客户、销售、需求单号、需求类型、仓库、成本来源。
2. 业务类型新增第六档「拆改配服务」（`refit`）：维保主页筛选、项目面板「编辑基本信息」与数据分析筛选同步。

## 已确认口径

- 所有新筛选在 PN 聚合前落到 `WHERE`：行集、`total`、汇总 KPI、成本占比、排序与分页随之收敛。
- 筛选与既有条件（时间范围、业务类型、PN/描述关键词）**叠加**，全部写入 URL，刷新/分享保留；`重置筛选` 一键清空并回到默认查询。
- 分类依据：
  - 项目筛选：需求单当前活跃挂靠项目（`maintenance_source_order_assignment`），与行键可见范围取**交集**，只收不放。
  - 客户/销售/需求单号：单据级 `end_customer` / `salesperson` / `order_no` 的大小写不敏感包含匹配，`%`、`_`、`\` 按字面转义。
  - 需求类型：`报修供货`（repair）/ `补库供货`（stock）多选，URL 用 ASCII 码。
  - 仓库：单据 `warehouse` 精确 IN；候选项来自实际有效出库数据（`/filter-options`），带空格的历史原值原样保留（不 trim），保证「候选 = 可筛选值」。
  - 成本来源：行级四分类，与项目面板同口径——系统关联（direct）/ 估算（其余非空来源）/ 人工回填（manual）/ 缺失（NULL、`none`、空串）。
- 坏件返还佐证（RKD）只随**项目级**条件收敛（业务类型 + 项目筛选），单据级筛选不改变其项目范围；页面提示已注明「按项目范围」。
- 未归属需求单只出现在「全部」中；任何具体业务类型（含历史五档）都要求真实挂靠项目，不混入「未标注」。
- 历史五档 URL（`overall,spare,computing,other,unlabeled`）是**显式子集**：不再等同于「全部」，会排除拆改配服务；六档全选或 `all` 才是不过滤。

## 接口

`GET /api/maintenance/analytics/pn-ranking` 新增可选参数（省略即不过滤）：

| 参数 | 说明 | 上限 |
|---|---|---|
| `project` | 项目 id CSV | 50 项 × 64 字符 |
| `customer` / `sp` / `order_no` | 包含匹配文本 | 128 字符 |
| `demand_type` | `repair` / `stock` CSV（正则校验） | 128 字符 |
| `warehouse` | 仓库原值 CSV | 10 项 × 64 字符 |
| `cost_source` | `linked` / `estimated` / `manual` / `missing` CSV（正则校验） | 128 字符 |

新增 `GET /api/maintenance/analytics/filter-options`：返回 `{"warehouses": [...]}`（去重排序、最多 200、随行键范围收敛、`no-store`）。

非法码/超限返回 422；审计日志只记录筛选是否启用的布尔标志，不落自由文本。
