# v1.36.6 按 PN 建议维保需求单（返还/领用）发布候选

决策：D-26 补记（0004 附录「页面表单地址建议预填」）。日期：2026-10-12。

## 交付内容

基于已上线 v1.36.5 / main `d6a9802`，PR #361（`feat/pn-demand-suggestion`）：

1. **登记返还（按 PN 建议需求单）**：选定返件 PN 后，维保需求单下拉出现「含此 PN」
   置顶分组（其余归入「其他需求单」）；唯一匹配且用户未选择时预选该单；无匹配显示
   禁用提示「本项目无含此 PN 的需求单」；未选 PN 行为与旧版一致。
2. **人工登记领用（按 PN 建议关联 + 地址预填）**：行内「关联需求单」升级为
   AutoComplete，按行内已选 PN 拉本项目活跃需求单候选；手输仍允许，服务端按归属表
   校验兜底。新建表单、领用地址为空、用户未手动编辑、且各行已选需求单唯一指向同一张
   单时，预填该单收货地址并标注「已按需求单〈单号〉收货地址预填，可修改」；无
   customer_info 权限显示中性提示；用户手动编辑后本会话建议永久退位。
3. **后端**：`demand_candidates` 可选 `part_id`（EXISTS 相关子查询，排序与分页口径
   不变）；返还候选端点加 `part_id` Query；新增领用侧候选端点
   `GET /maintenance/site-issues/projects/{id}/demand-candidates`（脱敏联系人
   fail-closed + sys_access_log 审计）。
4. 无 DB 迁移（head 仍为 `e7c1f9a3b5d2`）；统计口径、Σ 恒等式、导入导出、权限模型
   不变。

  如需开放地址建议，管理员须显式授予 data_customer。
