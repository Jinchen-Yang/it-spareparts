## AB-2｜attention 注册 kind ①③（M0-A 拍板） — **已实现**

- **已确认候选**：①超预算/预算余量；③待返件多。
- **口径**（业务 2026-08-16）：
  - ①超预算：台账合同金额(含税) − 已知申请估算成本；余量 ≤20% 提醒。
    红黄绿语义沿用 `maintenance_cost_quality.budget_decision`，与工作簿一致。
  - ③待返件：报数量（待返/已返/坏件），并带**返件率 = 返件类数量 ÷ 需求单「需求」数量**
    （分母=需求单需求列，业务指定；不是领用列）。
- **改法**：`backend/app/services/maintenance_boss_board.py: attention()` 注册两个 kind
  （每条 `{kind, project_id?, evidence_link, value}`），移除 `pending_decision: "M0-A"` 回传；
  `sort=attention` 应用注册权重，`sort_applied` 如实回传。
- **事实源**：合同金额=台账导入；成本五件套=既有；返件类=返库单成品＋入库单坏品返件类；
  需求数量=WBDD 明细。
- **测试**：attention 返回注册 kind；无成本权限账号金额受限（沿用既有看守测试）；
  `sort=attention` 不再回 `sort_pending_decision`。
- 无迁移。

## AB-4｜补库购物车解冻 — **已实现（后端三查+导出）**

- **已确认**：这期从冻结清单解冻「补库购物车 Beta」。
- **流程**（业务 2026-08-16 复述 + business-handbook §3.4）：
  销售经理选 PN＋数量 → 系统三查（通用池归属 / 半年内购销记录 / 是否小众 PN）→
  系统审批通过 → 导出 Excel（PN、数量、产品描述、每 PN 最近销售历史、池内最低价对比）
  交人工复核。
- **现状**：代码已有 Beta（导航隐藏），生产无数据。
- **已确认（2026-08-16 业务）**：
  1. 审批分两段：**系统侧**（三查自动通过）+ 导出后**人工再过一遍**。
     系统只做系统侧：不建模人工审批流程、不记录人工审结果。
  2. 审批结果**不作为 WBDD**：WBDD 仍走氚云导入，与购物车无关。
     购物车申请是**独立记录**——记下这一条、挂在所选项目下、
     与项目其他内容（需求/发货/成本事实）**隔离**，只作记录展示，
     不进入任何计算与对账。
  3. 池内最低价：有则显示；无则显示「—」（铁律 5：不知道≠否定）。
- **验收**：三查逻辑单测（池归属沿用主档双线查，同 `maintenance_boss_facts`）；
  导出 Excel 列与内容核对；权限与动作键（仅授权账号可导出）。
