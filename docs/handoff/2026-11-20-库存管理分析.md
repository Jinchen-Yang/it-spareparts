# 库存管理分析候选

需求 #554，实际出库统计依据见 D-0066。入口为「库存管理 → 库存管理分析」。代码包含独立的仓单分析投影与离线增量接入，操作及回退见[候选验收](../releases/warehouse-analytics.md)。采购与销售分析维持原有口径。

## 核数与读取

在隔离 PostgreSQL 上接入用户提供的入库、返库、直采直退三个来源。逐源比对有效单头与明细数，并对账销售退货 PN 总数、跨单重复型号数、前十型号明细行占比。矩阵单元格、单据及单内匹配行使用同一组筛选。取消单保留在来源投影，默认报表只统计已生效记录。

经登录账号请求本机回环 HTTP，每项连续 7 次，包含鉴权、数据库聚合和序列化。样本共数万行。以下是本次开发机观察值，生产并发与公网时延尚待验收。

| 查询 | 中位耗时 |
| --- | ---: |
| 全期销售退货 PN × 中心，前 10 × 8 | 122 ms |
| 全期销售退货 PN 排行 | 153 ms |
| 交叉格匹配单据分页 | 57 ms |
| 单内匹配货品分页 | 33 ms |

浏览器已实测默认区间、日柱和周折线悬浮、矩阵到单据再到货品的两级下钻与返回、六个看板切换、移动宽度的水平布局。独立审查发现明细维度的总计下钻可能包含空单头、单型号周轴可能遗漏最后一次退货之后的周。候选为这两个条件补了范围约束和回归场景。

## 仍需业务输入

- 全仓实际 CKD 的完整导出或等价来源，以及覆盖哪些仓、哪些日期。现有维保 CKD 暂存按专项业务接入。
- 实际出库拣货或发货人的身份字段、岗位与多人归属。缺该字段时无法给个人归集出库工作量。
- 目前沿用公司级经营看板的访问范围。面向库房岗位开放还需要授权范围及账号到仓库的归属依据。
