# 采购分析实量验收 · 2026-11-19

候选基线为 main 的 `3cbb72a4`，需求 #550，口径 D-0064、D-0065。正式入口为「采购管理 → 采购分析」。实体、字段与每张看板的用途见[字段与接口对照](../plans/purchase-analytics-prototype/正式字段与接口.md)。本次改动只涉及已有数据的读取，未新增数据库迁移。验收使用具备 D-0063 可见性字段的主线 schema 隔离副本。

## 数据核对

使用只读快照在独立 PostgreSQL 15 核对万级采购订单与明细。检查了单位缺失、目录描述缺失、单据原行描述及所有非空计量单位。采购员 × 类型的全集单数、行数与独立 SQL 一致；校验了头部交叉格的可见单数、各页订单 ID 不重叠，以及 PN × 供应商交叉格只展开匹配的 PN 行。

另以直接 SQL 独立复核了近 30 天每种采购类型的三种金额、各采购员的工作量和供应商数、上期金额、共同供货的双边成交行，以及同单位 PN 与池的未税加权均价。这些核对均使用隔离副本中的真实记录。

## 读取耗时

正式构建、本机回环 HTTP、有权限的验收账号。以下为 3 次连续真实请求的中位数，包括鉴权、后端计算和返回 JSON。数据库已预热；浏览器缓存未参与这组接口计时。

| 查询 | 中位数 | JSON 大小 |
| --- | ---: | ---: |
| 30 天 · 人员 × 采购类型，前 5 × 5 | 169 ms | 5.6 KB |
| 全历史 · 人员 × 采购类型，前 5 × 5 | 1,123 ms | 8.0 KB |
| 全历史 · PN × 供应商，前 5 × 5 | 1,868 ms | 5.8 KB |
| 全历史 · PN 前五 | 1,124 ms | 1.9 KB |
| 30 天 · 采购类型期间变化 | 310 ms | 1.8 KB |
| 全历史 · PN 互通池首页 20 项 | 1,344 ms | 8.6 KB |
| 头部交叉格 · 前 50 单 / 第二页 50 单 | 243 / 243 ms | 34.6 / 35.3 KB |
| PN 交叉格 · 匹配订单列表 / 单笔明细 | 160 / 78 ms | 1.7 / 1.3 KB |
| 单号浮窗 · 采购单 / 关联销售单 | 69 / 72 ms | 0.2 / 0.4 KB |

另在同一隔离实例同时发起四种读取，连续三轮共 12 次全部成功。并发下的中位数为全历史 PN × 供应商 1,891 毫秒、近 30 天人员 × 类型 269 毫秒、全历史 PN 前五 1,207 毫秒、热区 50 单 330 毫秒。这组计时使用同一验收账号，未经浏览器缓存。

矩阵以一次事实扫描计算格子、边际与全集，只向浏览器交付当前行列窗口。单头口径先对订单排序分页，再批量补当前页的产品、项目和数量。单据预览用精确单号、供应商与产品条件，同值查询合并。控件候选、图表、订单页和浮窗各自使用有上限的会话内存缓存。

## 人员工作量与图表读数复验

- 用独立 SQL 对照全历史、近 30 天、页面级限制计量单位三种情形。逐人核对单据、采购额、同单位数量、同批次明细行数、不同 PN 数和已知供应商数，全部相符。人员表的数值在切换排序时保持一致。相等值并列、缺量与零量、零行单头、空采购员、权限及跨页边界另有合成数据覆盖。
- 本机正式构建、预热数据库、绕过浏览器缓存，三次回环 HTTP 的中位数分别为全历史单数榜 693 毫秒、全历史实付额榜 721 毫秒、近 30 天单数榜 146 毫秒。近 30 天一位采购员的供应商前八为 120 毫秒、按日节奏为 140 毫秒，悬停指定采购员和日期所取的一行单据样本为 54 毫秒。全历史总榜响应约 3.3 KB。
- 浏览器从总榜切换采购额、数量单位、不同 PN 数，点姓名查看供应商与 PN 构成，从供应商和时间点分别下钻，核对范围后返回。柱、线的浮窗分别核对了同一天同一人的真实单号、PN、描述及数量。390 像素宽度下仅表格内部横向滚动。多框排行横条、销采关联的堆叠及散点、原汇总两组图的键盘读数均已点验。
- 触屏实际点按查出浮窗失焦后先关闭的问题。修正后在 320 和 390 像素宽度均完成轻触时间点、从浮窗进入该时段单据。键盘可在时点间移动、进入浮窗、用 Escape 返回图元或用回车下钻。
- 开发中启动的全量 Vitest 有 2,509 项通过，1 项报告柱/线浮窗未弹出；修复后以最终代码复跑全部采购页和图表容器共 136 项，全部通过。后端人员排行、cube 与预览 14 项通过，原采购接口、金额、权限迁移及等价性回归 160 项通过。最终 TypeScript 与 Vite 正式构建通过。
