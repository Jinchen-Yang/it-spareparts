# Issue 草稿：维保前端页面重设计（2 页定稿）

> 2026-08-16 业务定稿。此草稿可直接粘贴为 GitHub Issue 正文；口径记录见
> `docs/maintenance/REQUIREMENTS.md` #33–41。

## 标题

维保前端页面重设计：22 页 → 2 页（主页项目墙＋项目面板），一张总表改所有数据

## 正文

### 背景

代码里维保相关前端页面累计 22 个（展示板 5＋工作台 9＋数据维护 5＋旧版 3），三代页面叠加。
甲方定位是后事实展示板，页面应极简。2026-08-16 业务拍板重头设计，最终形态只有 2 个页面。

### 页面一：维保主页（项目卡墙）

- 顶部筛选：项目类型（进行中默认 / 已结束可筛出）、状态（正常 / 提醒 / 报警）＋模糊搜索框
  （搜项目名、项目单号等）。
- 一行 **5 张项目卡**，下滑无限加载（维保项目总量不多）。
- 每张卡：
  - 项目大标题；合同号如 `XSDD-20251230-0027`；
  - 基础信息：项目经理、合同总额；
  - 小字：备件成本（含税/未税）、缺失成本、维保备件采购数（＝需求单里已发货/已确认的数量，
    建议列映射：库房发货＋直采直发）、回款预览；
  - 进度条 v1 仅一条＝**成本÷合同额**：<80% 绿、80–100% 黄（低盈利提醒）、>100% 红（亏钱）；
    有多少数据算多少。二期加第二条＝坏件返还率（返库分两类：前置库未用件返库、坏件返还）。
  - 底部「进入面板」按钮。
- 主页全局下载：**所有项目**的备件行级表（系统自动回填后），时间预设 今天/昨天/本周/本月/自定义；
  改价/补价后上传覆盖＝真实源。

### 页面二：项目面板（点「进入面板」）

- 顶部：出库明细（保持当前生产版本内容，按时间筛选；一个项目多张合同时可并排显示或筛只看某一张）。
- 子顶栏 tab：项目基础信息（＝项目总表的 web 呈现）、备件成本、报销、回款……（表 6 所有内容）。
- tab 栏右侧：下载**本项目总表**（多 sheet 工作簿：01 基础信息/02 概览/03 备件订单/04 报销/05 回款/06 领用返还），回填后上传。
- 每个 tab 页内：单独下载对应 sheet（备件成本页→回填无成本；报销页→回填报销单），**在哪下载就在哪上传**。
- 项目名旁编辑入口：改项目基本信息（起止时间、负责人等），与总表 sheet 01 联通。

### 核心原则

**一张项目总表改所有数据**：缺价补录、报销、回款全部走「下载 Excel → 改 → 上传覆盖」，
系统内不再手工散改。下载/上传点共 3 处（主页全局 / 项目总表 / tab 单 sheet）。

### 已定

- 原始单据上传（需求单/发货/返库/入库/台账）：走 admin 既有「数据中心→数据导入」，不新建上传台。
- 卡片状态三态 = 进度条颜色：正常=绿、提醒=黄（成本≥80% 合同额）、报警=红（>100%）；「需关注」=提醒，并入卡片状态，不再单列。
- 旧页面（工作台 9 页、旧版 3 页、旧展示板 5 页）**直接删除代码**，新 2 页替换上线；实现顺序先建新后删旧。
- 归属挂靠：在项目面板「基础信息」tab 点确认挂靠，或选择独立成一个项目（罕见）。
  判定依据＝**XSDD 销售订单**：同一销售订单＝同一项目，不同销售订单＝不同项目。
  生产验证（2026-08-16）：312 个 XSDD 1:1 对应项目名；51 个跨多名全是期间/续签写法差异（同一项目）；
  唯一例外「兵装财务…整体维保」1 项目挂 2 合同（多合同项目，对应面板多合同并排/筛选）。
