# 前端首屏与失败恢复交接

决策: 无

基线：`origin/main` / `54efe9d55be2e908ce2a2f0182d1e4c57df8afad`。
候选分支：`fix/e2e-frontend-ux`。仅修改前端加载和读取失败恢复，无接口、业务口径、数据库或密钥变更。

## 问题与修改

- 路由已有 `React.lazy`，但 AppShell 首次空闲会预取所有可见页面。本地管理员冷启动三个目标路径均下载 73 个 JS、2,915,825 B，包含无关图表、Markdown 和账号页。改为当前路由与金额展示口径读取并行加载，仅悬停或键盘聚焦的菜单触发目标预取；金额展示仍经过原边界。切换路径等待代码时保留导航和加载提示。
- 项目详情的 7 个标签页分别懒加载，保留已访问标签的刷新注册和未访问标签首次取数行为。
- 稳定项目目录包含停用项目；展示板仅纳入活跃项目或仍挂有单据的停用项目。详情对停用项目用既有搜索接口查候选，使用项目编号缩小范围、遍历分页并按稳定 `project_id` 精确匹配。空集正常展示稳定详情，不盲调会返回 404 的单卡接口；归档但仍带单的聚合金额继续展示。
- 维保卡墙增加重试，续页失败保留已有卡片、重试原页；读取失败不再显示“没有项目”或“已到底”。库存沿用现有 AntD 提示，修正失败后重试旧成功页的问题，同时保留失败请求的查询条件。
- 项目基础详情、经营聚合和回款 workspace 分别显示持久错误和重试入口；迟到响应仍受原请求代次隔离。本次不包含其他标签页内部的历史错误处理整改。
