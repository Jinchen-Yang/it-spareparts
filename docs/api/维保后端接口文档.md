## 0. 三条渲染硬规则（先看这个）

这三条是后端契约的一部分，前端照着实现才不会把接口的意思渲染反：

1. **`state != "ready"` 时绝不渲染 0 或任何数字。** 六态信封里 `not_imported` /
   `restricted` / `error` 的 `value` 恒为 `null`，含义是「系统不知道」，不是「等于 0」。
   把它画成 0，老板会据此做决定。
2. **状态列只展示，不参与任何计算。** 单据明细里的 14 个流转状态列（已采/待供/待返/
   领用…）是氚云原样数据，前端不得相加、相减、算比例、打红黄标。
3. **自报与事实并排，不做差异提示。** `self_report`（本单头级自报）与 `facts`（项目口径
   三源事实）**口径不同、不可相减**，服务端也不产出任何 mismatch 字段。

## 1. 通用约定

### 1.1 鉴权

```
POST /api/auth/login   { "username": "...", "password": "..." }
  → 200 { "token": "...", ... }
其后所有请求带 Authorization: Bearer <token>
```

未登录 → `401`；登录但无权限 → `403`；越权 id 与不存在 id 一律 → `404`（不暴露存在性）。

### 1.2 权限模型

三类键，互相独立：

| 类别 | 含义 | 例 |
| --- | --- | --- |
| `page_*` | 能不能进这个页面 | `page_maintenance`、`page_maintenance_boss` |
| `action_*` | 能不能执行写操作 | `action_maintenance_wbdd_import` |
| `data_*` | 能不能看到某类数据 | `data_purchase_cost`（成本）、`data_profit`（金额/利润） |

前端拿权限图的入口：`GET /api/auth/beta-features`（Beta 组开关）与登录响应里的权限快照。
账号管理界面的键分组元数据：`GET /api/accounts/_meta`。

**成本权限没有「半开」**：无 `data_purchase_cost` 时，金额、取价来源、置信度整组返回
`restricted` 信封，且**响应键集合与有权限时完全一致**（防「字段存在性」侧信道）；按成本
排序会显式 `422`，不会静默降级成别的排序。

### 1.3 功能总闸（flag）

| flag | 影响 | 关闭时表现 |
| --- | --- | --- |
| `MAINTENANCE_BOSS_DASHBOARD_ENABLED` | 展示板七端点 + WBDD 专用上传 + relink | 整组 `404`（与未发布不可区分） |
| `MAINTENANCE_BETA_ENABLED` | 维保 Beta 工作台 | 整组 `404` |
| `REPLENISHMENT_BETA_ENABLED` | 补库购物车（AB-4 已解冻，但仍受此闸） | 整组 `404` |

回滚 = 关 flag，永不 `alembic downgrade`。前端据此要能容忍「这组页面整体 404」。

### 1.4 分页与搜索

- 列表统一 `?page=1&page_size=20`（上限 200），响应恒含 `total / page / page_size`。
- **GET 不接自由文本搜索**：带 `q` 会返回 `422 use_search_endpoint`，改用同名 `POST .../search`
  （body `{ q, page, page_size, ... }`）。这是仓库既有约定。

### 1.5 错误体

```jsonc
{ "detail": { "code": "sort_requires_cost_permission", "message": "按成本排序需要成本数据权限" } }
```

常见 code：`use_search_endpoint`、`sort_requires_cost_permission`、`recompute_busy`(409)、
`duplicate_file`(409)、`layout_unknown`(422)、`invalid_file`(422)、`not_found`(404)。

### 1.6 其他

- 所有读端点带 `Cache-Control: no-store`。
- 上传类端点要求 `Idempotency-Key` 请求头（8–128 字符）；同 key 重放返回原报告并带
  `"replayed": true`。
- 金额与数量以**字符串**形式返回（`"200.00"`、`"3.000"`），避免浮点精度丢失；前端不要
  `parseFloat` 后再做金额运算。

## 2. 六态信封（所有 Stat 字段统一）

```ts
type StatState = "ready" | "partial" | "stale" | "not_imported" | "restricted" | "error";

interface Stat<T = unknown> {
  state: StatState;
  value: T | null;      // 非 ready/partial/stale 时恒为 null
  as_of: string | null; // YYYY-MM-DD
  unlinked?: number | null; // 三源事实位恒有此键；partial 时为未关联行数
}
```

| state | 含义 | 前端应该显示 |
| --- | --- | --- |
| `ready` | 就绪 | 数值 |
| `partial` | 部分关联，数字是**已知下限** | 数值 + 「不完整（未关联 N 行）」 |
| `stale` | 数据源 `as_of` 距今 > 45 天 | 数值 + 「数据较旧（截至 X）」 |
| `not_imported` | 该源没有已应用批次 | 「尚未导入」——**不显示 0** |
| `restricted` | 权限不可见 | 「无权限」——**不显示 0** |
| `error` | 上游计算失败 | 「暂不可用」——**不显示 0** |

成本字段的 `value` 是一个五元组，不是单个数字：

```ts
interface CostBundle {
  actual_amount: string;      // 实际价合计（含税）
  estimated_amount: string;   // 估算价合计（含税）
  known_amount: string;       // 已知合计 = 实际 + 估算
  missing_lines: number;      // 无价行数——缺价不按 0 计入
  coverage_pct: number | null;
  quality: "actual_only" | "contains_estimate" | "incomplete";
}
```

`quality === "incomplete"` 时前端必须显示「不完整／已知下限 ≥」前缀。

## 3. 维保展示板（7 个只读端点）

前缀 `/api/maintenance/boss-board`。查看权限：`page_maintenance_boss` 或 `page_maintenance`
（**M0-B 改判后两者都是全项目范围**）。成本字段另受 `data_purchase_cost` 控制。

### 3.1 `GET /health` — 四源健康

```jsonc
{
  "sources": {
    "wbdd":         { "readiness": "ready", "label": "维保备件需求单", "as_of": "2026-07-15",
                      "batch_id": null, "uploaded_at": null, "unlinked_rows": 0 },
    "ckd":          { "readiness": "not_imported", "label": "发货单（实发）", "as_of": null,
                      "batch_id": null, "uploaded_at": null, "unlinked_rows": null },
    "return_order": { "readiness": "not_imported", "label": "返库单（未用件收回·成品）", ... },
    "rkd_inbound":  { "readiness": "not_imported", "label": "入库单（坏件回收·返件类）", ... }
  },
  "stale_days": 45
}
```

`readiness ∈ ready | partial | stale | not_imported`。**四源各自独立**——某一源未导入不影响
其他源，页面必须能分别显示，不能合并成一个「数据就绪」灯。

### 3.2 `GET /summary?from=&to=` — 本期与环比

```jsonc
{
  "window": { "from": "2026-01-01", "to": "2026-08-16" },
  "orders_ytd": { "state": "ready", "value": 2, "as_of": null },
  "lines_ytd":  { "state": "ready", "value": 4, "as_of": null },
  "known_apply_cost_inc_tax": { "state": "ready", "value": { /* CostBundle */ }, "as_of": null },
  "prev_window": { "window": {...}, "orders_ytd": {...}, "lines_ytd": {...},
                   "known_apply_cost_inc_tax": {...} }
}
```

`from/to` 缺省 = 当年 1-1 至今；`prev_window` 是等长窗口紧邻前移。字段名带 `_ytd` 但**不写死
年份**，随窗口走。

### 3.3 `GET /attention?limit=10` — 需关注队列

```jsonc
{
  "items": [],
  "registered_kinds": ["budget_remaining", "pending_return"],
  "ranking": "budget_status_desc,pending_return_qty_desc",
  "threshold": null
}
```

**`threshold: null` 是刻意的**：业务给了口径没给分界线，所以这是「排序取前 N」，不是阈值
告警。前端不要写成「N 条告警」，写成「最需要关注的前 N 项」。

两个 kind 的 `value`：

```ts
// kind === "budget_remaining"（需 data_purchase_cost；无权限时整条不出现，不是 restricted）
{ status: "red" | "yellow" | "incomplete_cost",
  budget_inc_tax: string, known_spend_inc_tax: string,
  remaining: string | null, remaining_pct: string | null,
  cost_quality: "actual_only" | "contains_estimate" | "incomplete" }

// kind === "pending_return"
{ demand_return_qty: string,          // 应返（需求单退货列）
  recovered_return_qty: Stat<string>, // 已回收（返件类事实）
  pending_return_qty: Stat<string>,
  return_rate_pct: Stat<number> }     // 分母 = 需求单「需求」数量
```

每条另有 `kind / project_id / project_code / display_name / evidence_link`。
RKD 未导入时后三个字段是 `not_imported` 信封——**不能显示 0% 返件率**。

### 3.4 `GET /projects` / `POST /projects/search` — 全项目列表

参数：`page`、`page_size`、`lifecycle=ongoing|ended|missing|all`、
`sort=attention|orders|name|known_cost`、`has_activity`、`from`、`to`。

```jsonc
{
  "rows": [{
    "project_id": "unassigned",                 // 未归属桶恒为首行（见下）
    "project_code": "unassigned",
    "display_name": "未归属（待人工确认）",
    "lifecycle": "ongoing" | "ended" | "missing",
    "is_archived": false,                        // 已归档但仍带单 → true，标「已归档」
    // ↓ 项目卡字段（#34/#35/#41/#43）
    "contract_nos": ["XSDD-20251230-0027"],      // XSDD 销售订单号＝归属判定依据
    "project_manager": "李经理",
    "contract_amount_inc_tax": { "state": "ready", "value": "100000.00" },
    "known_apply_cost_ex_tax": { "state": "ready", "value": "70000.00" },
    "procured_qty": { "state": "ready", "value": "12.000" },   // 库房发货＋直采直发
    "collection_preview_inc_tax": { "state": "ready", "value": "30000.00" },
    "cost_ratio_pct": { "state": "ready", "value": "79.1" },
    "card_status": "normal",                     // normal|warning|alert；算不出＝null
    "has_activity_in_window": true,
    "pre_delivery_order_count": 0,               // >0 时打「预交付 N 单」徽标
    "orders_ytd": { "state": "ready", "value": 1, "as_of": null },
    "lines_ytd":  { "state": "ready", "value": 2, "as_of": null },
    "known_apply_cost_inc_tax": { "state": "ready", "value": { /* CostBundle */ } },
    "shipped_qty":       { "state": "not_imported", "value": null, "as_of": null, "unlinked": null },
    "returned_good_qty": { ... },
    "returned_bad_qty":  { ... }
  }],
  "total": 1, "page": 1, "page_size": 20,
  "sort": "name", "sort_applied": "name",
  "window": { "from": "2026-01-01", "to": "2026-08-16" }
}
```

**分页三个坑**（前端必须注意）：

1. 未归属桶（`project_id === "unassigned"`）是后端**额外置顶**的一行，**不计入 `total`**。
   分页器的 `pageSize` 必须用请求的 `page_size`，不能用 `rows.length` ——否则翻页会带着
   错误的 `page_size` 去请求，漏掉一个真实项目。
2. 桶只在「第 1 页 + 无搜索 + `lifecycle=all`」时注入。其余情况没有这一行，页面文案不要
   无条件承诺它在。
3. `sort=known_cost` 无成本权限 → `422 sort_requires_cost_permission`。

**卡片三态与权限**：`card_status` 只由成本率决定（<80% normal / 80–100% warning /
\>100% alert）。**无 `data_purchase_cost` 时 `card_status` 恒为 `null`**——三态是成本
派生物，给了颜色就等于泄露金额排名。合同额算不出时也是 `null`，前端显示「数据不足」，
**不要画一条 0% 的绿条**。筛选参数 `card_status=normal|warning|alert`。

## 4. 增补包新端点（AB-1~4）

### 4.1 WBDD 专用上传

| 端点 | 权限 |
| --- | --- |
| `POST /api/maintenance/wbdd-imports` | `page_maintenance` + `action_maintenance_wbdd_import` |
| `GET /api/maintenance/wbdd-imports/latest` | `page_maintenance` |

`multipart/form-data`，字段名 `file`，必带 `Idempotency-Key`。**不复用** `/api/import/upload`
（那是 page_import 全家桶）。非 WBDD 文件或布局不符 → `422` 且**零写入**。

```jsonc
// POST 200
{ "batch_id": 12, "file_hash": "...", "layout": "91-col",
  "snapshot_diff": { "missing_orders": 0, "sample_order_nos": [], "window": {...} },
  "recompute": { ... }, "replayed": false }

// GET /latest
{ "readiness": "ready", "as_of": "2026-07-15", "orders_total": 2,
  "batch_id": null, "uploaded_at": null, "layout": null }
```

`snapshot_diff.missing_orders` = 上批有、本批没有的单：**只报告，不删除不隐藏**。

`409 recompute_busy` 表示导入已提交、只是成本重算在忙——客户端用**同一个 Idempotency-Key**
整体重试即可，重放会把没跑完的重算补上。

### 4.2 单据项目重解析（上传顺序无关）

`POST /api/maintenance/doc-imports/relink-projects` —— `page_maintenance` +
`action_maintenance_doc_import` + `data_purchase_cost`，且受展示板总闸约束。

```jsonc
{ "relinked": 3, "still_unlinked": 1, "out_of_scope": 0 }
```

先传 RKD/返库、后建 WBDD 归属时，把停在 NULL 的 project_id 补齐。幂等，不覆盖既有归属。
确认归属时会自动调用，通常前端不必手动触发。

### 4.3 报销/回款往返工作簿（AB-3）

一个文件两张 sheet（`04_报销订单` + `05_项目经理回款单`），下载 → 本地改 → 上传覆盖。

| 端点 | 权限 |
| --- | --- |
| `GET  /api/maintenance/projects/stable/{project_id}/expense-collection-workbook.xlsx` | `page_maintenance` + `data_profit` |
| `POST .../expense-collection-workbook/validate` | 上述 + `action_maintenance_expense_collection_upload` |
| `POST .../expense-collection-workbook/apply` | 同上 |

```jsonc
// validate（无副作用预演）
{ "project_id": "...", "valid": true,
  "expense_updates": 1, "collection_creates": 1, "collection_voids": 0 }
// apply
{ "project_id": "...", "applied_by": "zhangsan", "import_batch_id": "uuid",
  "expense_updates": 1, "collection_creates": 1, "collection_voids": 0 }
```

前端要向用户讲清的三件事：

- **黄底列才可编辑**：报销只有「未税金额」，含税列是系统按 ×1.13 算的，改了也会被忽略；
- **回款是月度累计快照**，不是逐笔流水；同合同同月份重传 = 覆盖累计额；作废要显式写
  `VOID`，删掉一行不等于作废；
- **任何一行不合法整份 422**，不会部分写入——报错要把 `detail.message` 原样显示给用户。

> v1 裁剪：不做 BXD 逐条对账、不做凭证附件、不进老板看板三槽。
> 已知缺口：`04_报销订单` **没有可编辑的「备注」列**（底层表无该字段，加列需迁移，本期
> 约束零迁移）。

### 4.5 全项目备件行级表（主页全局下载/上传）

| 端点 | 权限 |
| --- | --- |
| `GET /api/maintenance/spare-part-lines.xlsx?range=&from=&to=` | `page_maintenance` + `data_profit` |
| `POST /api/maintenance/spare-part-lines/validate` | 上述 + `action_maintenance_expense_collection_upload` |
| `POST /api/maintenance/spare-part-lines/apply` | 同上 |

`range` ∈ `today` / `yesterday` / `this_week`（周一为周首）/ `this_month` / `custom`
（`custom` 必须同时给 `from` 与 `to`，否则 `422 invalid_range`）。

导出的是**系统自动回填价之后**的全项目行级表；黄底「未税单位成本」「变更原因」两列
可改，上传即覆盖＝真实源。含税单位成本由系统按 ×1.13 算，表里改了会被忽略。

```jsonc
{ "applied_by": "zhangsan", "import_batch_id": "uuid", "sheets": ["备件行级表"],
  "cost_refills": 1, "site_return_flags": 0,
  "expense_updates": 0, "collection_creates": 0, "collection_voids": 0 }
```

### 4.6 项目总表六 sheet / 各 tab 单 sheet

| 端点 | 权限 |
| --- | --- |
| `GET /api/maintenance/projects/stable/{id}/master-workbook.xlsx[?sheets=]` | `page_maintenance` + `data_profit` |
| `POST .../master-workbook/validate` | 上述 + `action_maintenance_expense_collection_upload` |
| `POST .../master-workbook/apply` | 同上 |

`sheets` 缺省＝六张全下；传逗号分隔的 sheet 名即**各 tab 单 sheet 下载**。
上传按文件里**实际存在**的 sheet 解析，所以单 sheet 与总表共用同一个 apply 入口。

| sheet | 可编辑列 | 落库 |
| --- | --- | --- |
| `01_项目基础信息` | 只读 | — |
| `02_概览数据` | 只读 | — |
| `03_备件订单` | 未税单位成本、变更原因 | `maintenance_manual_cost_override` |
| `04_报销订单` | 未税金额 | `f_project_expense` |
| `05_项目经理回款单` | 操作/报告月份/累计金额/凭证号/备注 | `maintenance_collection_snapshot` |
| `06_现场领用与返还` | 是否应返还(行级)、备注 | `site_issue_line.no_return` |

三类改动同一事务；**任何一行不合法整份 422，不部分写入**。未知 sheet 名 →
`422 unknown_sheet`；不存在的项目 → `404`。

> `04_报销订单` 目前**没有可编辑的「备注」列**——底层表无该字段，加列需迁移。

### 4.7 补库购物车系统三查（AB-4）

`GET /api/replenishment-beta/applications/{application_id}/exports/system-screening.xlsx`
—— `page_replenishment_beta` + `action_replenishment_create` + `data_pool_price_governance`，
受 `REPLENISHMENT_BETA_ENABLED` 闸。

导出列：PN / 产品描述 / 数量 / 最近销售日期 / 最近销售未税单价 / 池内最低价(未税) /
与池内最低价对比 / ①通用池归属 / ②半年内购销记录 / ③是否小众PN / 系统三查。

- **没有「审核结论 / 打回原因」列**：系统只做系统侧，不建模也不记录人工审批。
- 池内最低价或最近销售价缺任一 → 该格显示 `—`，差额也显示 `—`，不显示 0。
- 「是否小众」采用**零样本边界**（半年内采购与销售样本都为 0 才算小众），样本数随行给出。
- 购物车申请是独立记录：**不进 WBDD**，不参与项目成本与对账。
