## 结论

- 合并结论：满足合并门槛。
- 生产结论：暂不随本次开发自动部署。生产发布前需要先确认至少一批有效互通池已人工设置采购最高价或销售最低价；否则摘要会正确显示“约束价未设置”，但不会产生越线记录。

## 合并门槛

以下条件全部满足即可合并：

1. 前后端全量测试、类型检查与构建全绿；合并时 GitHub CI 也必须全绿；
2. 独立 SQL 与接口的越线行数、订单数、池数、差额和经办人聚合一致；
3. 全权限与受限权限账号均完成真实浏览器验收，受限账号无侧信道；
4. 日期、池、PN、订单下钻和移动端布局可用；
5. 无迁移漂移，代码复审无 blocker/P1。

## 生产门槛

合并不等于立即生产。生产发布前还需要：

1. 备份数据库并记录回滚代码 SHA；
2. 由老板或管理员为真实互通池人工设置一批约束价，确认含税/未税口径；
3. 在 staging 或生产只读抽样中，用独立 SQL 对至少 5 个池、10 张订单复核越线判断；
4. 用老板账号和受限账号分别验证权限、下钻与空状态；
5. 部署后观察接口错误率和响应时间至少 30 分钟。
