# PARTFLOW MCP 首版

本次实现是可运行的员工业务接口与文件确认工作台。入口为 `/mcp`（Streamable HTTP）和 `/mcp-office`（登录、个人令牌、上传、审阅、导出、本人审计）。默认不启用，不改变生产发布状态。

## 交付范围

| 能力 | 首版行为 | 限制 |
|---|---|---|
| 身份 | 每人独立业务账号与30天以内个人令牌 | 服务端仅存令牌SHA-256；不接受共享回退账号 |
| 文件 | 创建会话、登录上传、结构识别、哈希检查 | 10文件/批、单件20MiB、合计100MiB；每人每日最多10个活跃会话 |
| 验收清单 | 预览、整表替换、保存历史、当前条目导出 | 最多2000条、8MiB；无当前数据时导出模板 |
| 费用/回款 | 原生完整工作簿导出、校验、事务内提交 | 单项目；保留原模板与版本规则，变更最多2000条 |
| 通用采购销售单据 | 复用原生识别与重复检查 | 仅预检，不开放通过MCP正式入账 |
| PN/库存 | PN描述、规格、品类与分仓数量 | 不返回历史价格、供应商、库存单位成本或库存金额 |
| 项目材料 | 当前验收清单及未完成项 | 不能推断全部合同/发票/附件齐套 |
| 任务 | 数据库存储、后台worker、租约恢复 | 只有预览/导出任务；不在后台自动提交业务 |
| 审计 | 发起、完成、失败、确认、下载事件 | 本人检索；管理员可指定其他员工；北京时间，31天/次 |

实际16个工具及输入输出契约以 [tools.json](../../backend/app/mcp/tools.json) 为准。19个工具的原始设计保留在 `docs/mcp-design/`，其中直接提交、主动重试、价格参考没有启用。

## 员工流程

1. 管理员分配独立业务账号及实际页面/项目/金额权限。
2. 员工登录公司地址的 `/mcp-office`，生成个人连接令牌，在 WorkBuddy 的连接配置内填写，不放进对话。
3. WorkBuddy调用工具建立上传会话；员工在登录网页选择原件上传。文件工具不接收任意本地路径、SQL、Shell或文件Base64。
4. AI查询结构、定位项目、创建预览任务。网页显示实际清单或费用回款变更，员工核实后点击确认。
5. 服务端检查预览哈希、原件哈希、账号版本、原连接授权和当前业务版本；提交、回执和审计在同一事务内写入。重复确认返回同一回执。
6. AI查询预览的 `status=applied` 和 `receipt` 才报告入账。预检任务完成不代表业务完成。下载页面核验SHA-256后发起保存。

[WorkBuddy配置和5个Skills](../../connectors/workbuddy/README.md)。首版尚未内置跨平台静默上传下载，员工仍使用网页文件通道。WorkBuddy自身的模型读取、员工本地文件操作不在服务端审计范围。

## 数据与审计

- `mcp_credential`：个人授权及撤销状态。业务账户停用、权限版本变化、令牌过期/撤销在每次访问与后台执行时重验。
- `mcp_record`：upload/file/preview/job/artifact/receipt，各记录绑定所有者。幂等键由所有者+记录类型+请求键组成，同键不同输入拒绝。
- `mcp_audit_event`：事务内追加日志。确认事件包含预览哈希、项目、回执；文件事件包含文件ID、大小和SHA-256。工具查询保留参数哈希、目标ID、返回的稳定记录ID及结果摘要哈希，不记录原始检索词、令牌、密码、整份工作簿或完整业务结果。
- 当前没有异步审计outbox：直接在业务事务中落库，审计失败则业务回滚。发起日志先提交，以便追踪中途失败；无响应时仍应查询原预览/任务。
- PostgreSQL触发器拒绝更新、删除审计行；这是应用级不可变保护，不声称防御数据库所有者/超级管理员。备份应同时覆盖业务库和文件卷。
- 下载开始事件在发送前写入；完成事件表示服务端完成流迭代，不证明员工电脑最终保存。网页校验另验证收到的字节。
- 预览有效30分钟；原件、导出字节保存7天；回执元数据保留至少一年（当前无自动删除）。worker每小时清理过期字节及超过24小时的孤立文件，保留数据库元数据与审计。
- 费用数据仍要求 `data_profit`；费用回传还要求原有上传动作权限。项目范围使用原生行级约束，不按项目名称猜测身份。

## 部署

遵循仓库原有分支→PR→合并→发布流程。迁移版本 `a16b7c8d9e01`，父版本 `e3a7b9c2d4f6`。不自动迁移，不做生产数据测试。

1. 备份当前业务库及上传文件卷，确认当前版本和可用空间。
2. 设置 `MCP_ENABLED=false`、`MCP_CONFIRM_ENABLED=false`，构建后显式执行 `docker compose run --rm app alembic upgrade head`；再执行 `alembic check`。原有密钥、数据库密码和维保签名配置按既有生产部署保留。
3. `MCP_PUBLIC_BASE_URL` 必须是公司业务系统的HTTPS根地址，不含路径、查询串或用户名。不要复用营销演示域名指向生产数据。
4. 启用 `MCP_ENABLED=true`；初次先保留 `MCP_CONFIRM_ENABLED=false`。`docker compose --profile mcp up -d --build app mcp-worker frontend` 启动API、独立worker和前端代理。worker复用app配置、数据库和原件卷，不对公网开放端口。
5. Nginx新增 `/mcp`、`/mcp-office`、`/mcp-office.js` 反代；现有 `/api` 继续提供受保护文件通道。Cloudflare或外层代理保持这些地址不缓存，不添加会修改响应体的网页挑战；保留HTTPS与Authorization请求头。无需透传数据库端口。
6. 在专用测试项目验收：独立员工登录、列出能力、上传、预览、导出、下载、撤销授权。确认版本与项目范围后再启用 `MCP_CONFIRM_ENABLED=true`，做一份已核对清单的具名验收，检查回执与审计。
7. 监控worker进程、queued/running任务年龄、failed任务、文件卷剩余空间和数据库备份。任务超过10分钟未变化应调查worker；不要反复创建同一导入。

回滚：关闭两个MCP开关并重启app/worker；原业务系统继续使用。保留MCP表和文件，禁止通过降级抹掉证据；迁移降级在新表非空时会拒绝。

配置默认：文件上限20MiB（允许下调），任务恢复租约600秒（允许60–3600秒），队列最多20个未完成任务。生产部署建议先运行一个worker，无业务写入型后台任务。

## 验证

`backend/tests/test_mcp.py` 覆盖协议、完整往返、权限与撤销、幂等、过期预览、审计失败回滚、任务恢复、过期清理、迁移及连接器契约。使用仓库隔离测试库与临时文件目录。

`backend/tests/test_mcp_browser.py` 是可选真实浏览器验收，同时使用官方Python MCP客户端连接真实HTTP端口。设置 `MCP_BROWSER_PYTHON` 为安装Playwright的Python路径；可选 `MCP_BROWSER_EXECUTABLE` 指定Chromium、`MCP_BROWSER_OUTPUT` 指定截图目录。合成数据走登录→上传→审阅→提交→导出→下载→审计，检查桌面/手机布局与脚本错误。

运行记录见 [验收记录](acceptance.md)。浏览器/官方SDK通过不等于员工WorkBuddy客户端实测通过；生产发布、客户端联调分别记录。
