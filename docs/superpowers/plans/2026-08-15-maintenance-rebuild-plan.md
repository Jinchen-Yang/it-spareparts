## 2.1 十二问答复后的模型修正（v2，2026-08-15 晚）

| 决策 | 内容 |
|---|---|
| **无现场收货环节** | 发货单（维保供货）→ **直接入前置库**（`front_stock` += 数量）；不建在途/收货状态 |
| **前置库维度** | 以 Excel 写法为准（前置库名一般 = 项目名），不强建仓库字典；front_stock 存仓库名自由文本 + project_id |
| **领用单** | IT_data 系统表单（人工录入，非导入）：登记消耗事实 + 应返义务，**不写账本** |
| **坏件返还** | = 氚云**收货入库单 RKD**；返还率分子来自入库单 |
| **SN** | 不记录/不强制，只统计 PN+数量（SN 字段降级为可选） |
| **返还率公式** | 已返还件数（入库单）/（领用件数 − 不返还件数）；不返还由**系统自动审批**（项目级默认+规则） |
| **补库购物车边界** | 只审 PN 合理性；通过后一键导出 Excel（**PN+数量+采购金额+销售金额**），后续人工渠道，系统不接采购执行 |
| **回款提醒关闭** | 上传凭证（巡检报告/图片/PDF）为关闭依据；DB 只记 **md5**，文件存独立目录，每文件一个 **yml 元信息** |
| **验收/巡检/结项** | 不做独立流程，只展示台账 Excel 状态；结项=软提示；**期限从项目名解析**（名称内嵌起止日期） |
| **台账权限** | 项目经理 + 指定成员账号（需在账号体系配置） |
| **氚云关系** | 只读，零回写 |

## 7. 方向纠偏（2026-08-16 业务沟通，以本节为准）

**本质定位**：这套系统是**老板决策用的后事实展示板（post-fact dashboard）**——
业务发生时数据已在氚云/台账里，系统只做「导入 → 归集 → 回填 → 展示」，
不做业务流程闭环（不需要购物车审批、凭证上传、变卖登记等重功能）。

**v1 核心（按业务口述）**：
1. 上传「维保备件需求单」独立文件（氚云导出），按项目更新需求单清单；
2. 每条需求单明细用备件系统回填成本：**采购价优先，无采购用销售价，时间就近**
   （离需求单制单日期越近的价格越优先）；
3. 项目主数据可维护：改名、改期限；**预交付项目并入真实合同项目**展示
   （不叫合并——预交付单归到真实合同下）；
4. 需求单可更改：改行/改单、作废、补录、改项目归属（展示板层面的数据修正）；
5. 老板看板：每项目 备件申请成本/发货/消耗/现场剩余/报销/回款/坏件回收/应返还，
   每周或每月看一次；
6. 权限：勾选名单制——被勾选的人（老板+项目经理）整套都能看，不分细粒度。

**明确不做/冻结**：销售采购模块与采购分析（已完美，不动）；AI 兜底、补库购物车审批、
回款凭证上传、坏件变卖登记、工作簿回填（D3）等重闭环功能全部冻结，代码保留不上界面。

**待业务提供**：维保备件需求单（WBDD）导出样例文件 → 才能写 adapter。
