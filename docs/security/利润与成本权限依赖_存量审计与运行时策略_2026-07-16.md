# 利润与成本权限依赖：存量审计与运行时策略

## 结论

`data_profit=true` 必须同时满足 `data_purchase_cost=true`。

原因不是岗位偏好，而是数学上的数据泄漏：经营报表会展示营收，若再展示毛利，使用
`营收 - 毛利` 就能精确还原采购成本。因此“看利润、隐藏成本”是假脱敏；反向的
“看成本、不看利润”合法，采购职位模板即采用此口径。

## 新写入如何阻断

`permissions.combo_errors()` 是单一校验源，以下四类权限中心 v2 写路径都按最终生效
权限图校验并返回 400，不静默改管理员的选择：

1. 单账号新建、修改；
2. 职位模板新建、修改；
3. 账号批量增加、取消、套模板、恢复模板；
4. 模板同步账号（保留个别调整和清除个别调整两种模式）。

前端权限矩阵读取 `/api/accounts/_meta.dependencies.data_data`，开启利润时自动补齐采购
成本；若手工关闭成本，会在保存前显示“营收减毛利可反推出采购成本”。后端仍是最终
裁判，不能靠绕过前端写入非法组合。

## 存量数据如何审计

系统不直接修改历史 JSONB。账号与模板列表新增 `permission_combo_errors`；账号另返回
`runtime_permissions`。权限中心会给异常账号/模板显示“权限组合需修复”，管理员可选择：

- 该岗位确实需要利润：同时开启采购成本；
- 不应看到采购成本：关闭利润。

上线前也可用以下只读 SQL 统计存量异常。

```sql
-- 职位模板
SELECT code, name
FROM sys_role_template
WHERE COALESCE((permissions->>'data_profit')::boolean, false)
  AND NOT COALESCE((permissions->>'data_purchase_cost')::boolean, false);

-- 账号：精确复刻 effective_for_user 的两条路径。
-- 有模板快照：缺键按 false，不回退旧 permissions；无快照：旧 permissions 覆盖角色默认值。
WITH effective AS (
  SELECT username,
         CASE WHEN template_perms IS NOT NULL THEN
           COALESCE((perm_overrides->>'data_profit')::boolean,
                    (template_perms->>'data_profit')::boolean, false)
         ELSE
           COALESCE((permissions->>'data_profit')::boolean,
                    role IN ('boss', 'sales'))
         END AS data_profit,
         CASE WHEN template_perms IS NOT NULL THEN
           COALESCE((perm_overrides->>'data_purchase_cost')::boolean,
                    (template_perms->>'data_purchase_cost')::boolean, false)
         ELSE
           COALESCE((permissions->>'data_purchase_cost')::boolean,
                    role IN ('boss', 'sales', 'purchaser'))
         END AS data_purchase_cost
  FROM sys_user
  WHERE role <> 'admin'
)
SELECT username
FROM effective
WHERE data_profit AND NOT data_purchase_cost;
```

## 历史账号和旧 token 如何失败关闭

为避免等待管理员逐个修复期间继续泄漏，运行时有两层保护：

1. 登录和 `verify_token_db()` 把非法图收紧成 `data_profit=false`；已经签发的旧 token
   也在每次验签后收紧，不能等到下次登录才安全。
2. `permissions.hidden_groups()` 再按安全图计算字段组。即使测试、内部调用或遗漏调用方
   手工构造了非法 `UserContext`，采购成本、毛利额、毛利率仍一起置空。

运行时只收紧返回与 token，不自动回写数据库；原始异常仍保留在权限中心供审计，管理员
修复保存后会递增 `token_version`，旧登录立即失效。

## 合并与生产门槛

- 内置五模板全部通过依赖校验；
- 四类保存路径均有 400 + 零部分写入测试；
- 历史脏账号的列表告警、登录收紧、旧 token 收紧、字段脱敏均有测试；
- 上述 SQL 在生产只读执行并记录异常账号数；
- 使用异常账号快照验证成本和毛利字段均为空，修复权限后重新登录符合预期；
- 无数据库迁移。回滚代码不会回滚管理员已通过权限中心完成的显式修复。
