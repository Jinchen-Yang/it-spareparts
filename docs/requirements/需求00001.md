# 需求00001 —— 商城目录同步的上游支撑：备件主数据整目录只读接口

- **编号**：00001（itsp 侧流水号）

- **提出日期**：2026-10-14
- **最后更新**：2026-10-14
- **来源**：柳朝红需求（经商城侧转来），主档见 **shop#需求00001**（`spareparts-shop/docs/requirements/需求00001.md`）之 R1.6
- **性质**：关联条目——只登记落在本仓库（it-spareparts）的范围，不复制主档全文

## 1. 原始需求（转述自主档原话）

> "第一是维保智能体的数据中心——备件主数据的数据同步到电商系统的商品里，这样我们只需要补充数据就行，不需要再新建PN了。""数据同步过去先都是0库存就行。"

商城侧主档将其中落在本仓库的部分拆为 R1.6：**新增"整目录列举／增量拉取"只读接口**，供电商系统把备件主数据目录同步成商品（初始 0 库存）。

## 2. 背景与动机

现有对外只读接口（`backend/app/api/resale_catalog_export.py`：`/resolve`、`/snapshots`、`/price-evidence`；`resale_catalog_search.py`：`/search`）只支持"按已知 PN 精确查＋模糊搜索"，**没有整目录列举／增量拉取能力**。商城侧现有同步（`itsp_catalog.py`）因此只能更新已有商品资料、无法建商品。详见主档 §3.3。

## 3. 本仓库范围（建议实现口径，立项后细化）

- 新增只读接口：按 `dim_part.updated_at` 游标分页列举备件主数据目录（含墓碑／合并状态，供下游处理合并与下架）。
- 复用现有 Bearer 凭据与 schemaVersion 约定；默认未配置凭据时保持 404 现状。
- 字段口径沿用现有快照导出（PN、描述、品牌、品类两级、specs；"类型"列是否输出待主档确认）。
- **只读**：不接收任何写回；不暴露除商品字段以外的数据（人员、合同、SN 等不入接口）。

## 5. 验收标准（立项后按确认口径细化）

- [ ] 携有效 Bearer 凭据可按游标分页拉取全量主数据目录，无凭据／未配置时 404；
- [ ] 增量拉取以 `updated_at` 为准，重复拉取幂等；
- [ ] 墓碑／合并记录有明确标记，下游可据此处理；
- [ ] 不输出商品字段以外的数据；接口只读，无任何写路径；
- [ ] 商城侧按主档 R1 验收标准完成端到端联调（库存守恒等以主档为准）。
