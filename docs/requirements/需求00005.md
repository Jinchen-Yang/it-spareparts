## 2. 背景与动机

硬盘等品类按口径默认免返（D-14 拍板"项目级默认值＋行级覆盖"），但业务发现"部分项目的免返条件未统一设置"，收货人员无法在项目入口直接看到该项目备件要不要返——先要查清系统里免返逻辑有几处来源、哪里不一致，再给项目概览一个能手动标注、能提醒收货人的入口。

## 3. 现状事实（2026-10-14 六路只读调查；标注 ★ 的已由主 Agent 抽查复核原文）

### 3.1 免返的数据模型与判定（来源排查结果）

免返/需返在系统里共**三层表达＋两套载体**：

- **三层**：①项目级 `maintenance_project.no_return_default`（Boolean，NOT NULL，默认 false）；②行级 `maintenance_site_issue_line.no_return`（nullable 三态：True 免返/False 必须返/NULL 继承）；③义务冻结结果 `maintenance_return_obligation.classification`＋`exemption_source`（DB check 约束枚举 none/category_disk/line_no_return/project_default_no_return）——`backend/alembic/versions/c3b5d9e1f7a2_maintenance_no_return_rules.py:16-73`
- **判定核心只有一个函数** `classify_return_obligation`，固定顺序：行级 no_return → 项目级 no_return_default → 品类规则（标准大类"硬盘"豁免）→ pending_category——`backend/app/services/maintenance_bad_returns.py:58-123`
- **两套载体**：原生发货链行在确认时把判定**冻结**进义务表（当时的项目默认不随后续设置变化）；06 表/页面登记行**永不形成义务**（D-15），免返状态由 `line_details` 每次实时现算（随项目默认与品类主数据变化）——`docs/decisions/0001-维保整改八条口径.md:141`、`backend/app/services/maintenance_site_return_requirements.py:70-93`

### 3.2 "未统一设置"的结构性根因（本排查最重要发现）

- ★ **项目级 `no_return_default` 是断头路：全仓没有任何写入入口**——建档/编辑 API 的 StableProjectCreate/StableProjectPatch 均不含该字段（主 Agent 已读 :43-60 白名单复核，grep 零命中）、工作簿 01 表只渲染不解析、前端零引用；唯一设置手段是直接改数据库（测试里就是裸 SQL UPDATE）——`backend/app/api/maintenance_projects.py:32-60`、`backend/app/services/maintenance_project_master_workbook.py:530,542,677,5491-5497`
- 该字段 NOT NULL 默认 false，**false 无法区分"从未设置"与"明确需返"**——即使查库也看不出哪些项目"没设置"
- 行级 no_return 的写入入口有五处（原生 API／页面人工登记／V1 06 表／V2 06 表／V2 删行置 None），语义统一"是=应返、否=免返、空=继承"——`backend/app/services/maintenance_project_master_workbook.py:1101-1107` 等
- 无免返覆盖度报表/脚本（scripts/ 与 docs/reports/ 均无）；可行的排查途径：查 no_return_default 分布、行级 no_return NULL 率、exemption_source 分布（后两者可 SQL 统计，第一个因断头路意义有限）

### 3.3 消费路径的三处不一致（统一标准要一并处理的清单）

1. **V3 工作簿 06 表**对无义务行一律兜底显示"无需返还"，忽略行级/项目默认/硬盘规则——与其余口径直接矛盾（该端点仍在线但前端已无调用方）——`backend/app/services/maintenance_project_workbook_v3.py:234-245`
2. **V2 上传合并路径** `_v2_site_row_values` 不带 details 调用时把 no_return=None 兜底为 pending_category、忽略项目默认与品类规则，与导出路径（带 line_details，口径正确）不一致——`backend/app/services/maintenance_project_master_workbook.py:2803-2821 vs 2892-2896`
3. **展示层自造枚举** `exemption_source="line_return_required"`（行级"必须返还"时），不在义务表 DB check 枚举内，审计口径不统一——`backend/app/services/maintenance_site_return_requirements.py:79-93`

### 3.4 相关既有口径（方案不得破坏，或需显式修订）

- **D-14**（2026-08-15，REQUIREMENTS #32）：不返还标记＝项目级默认＋行级覆盖；**三项至今未拍板**：返还率分母口径、官方字段能否业务确认前发布、pending_category 由谁处理（GitHub #208 open）——`docs/decisions/0001-维保整改八条口径.md:116-127`
- **D-17**：免返不改变收货事实、卡墙返还率不扣免返——免返只影响"要求"，不减少"事实"——`docs/decisions/0001-维保整改八条口径.md:216-217`
- 项目默认变更不回溯已冻结的义务快照（只在下次事件重算）——"改了项目默认后存量行怎么办"无统一处理路径——`backend/app/services/maintenance_bad_returns.py:661-704`

### 3.5 项目概览与可编辑字段（R2 落点）

- 项目概览＝项目面板「概览」tab（OverviewTab），基础信息为只读 Descriptions（8 字段：项目名称/编号/合同号/负责人账号/来源负责人/合同总额/维保期限/生命周期）；编辑走页头「编辑基本信息」Modal——`frontend/src/pages/maintenance/panel/OverviewTab.tsx:131-180`、`frontend/src/pages/maintenance/MaintenanceProjectPanelPage.tsx:432-436,571-743`
- 保存走 `PATCH /maintenance/projects/stable/{id}`，字段白名单 5 项（display_name/salesperson/project_manager_id/period_from/period_to）；全链路含实名门禁、乐观锁 version、审计日志、workbook revision bump——`backend/app/api/maintenance_projects.py:43-60,137-167`、`backend/app/services/maintenance_project_catalog.py:194-227`
- 权限：整个编辑弹窗由单键 `action_maintenance_project_manage`（＋data_profit＋实名）控制，无字段级区分——`backend/app/permissions.py:68,143`
