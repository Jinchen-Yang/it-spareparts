## 2. 背景与动机

让技术人员按对接关系查看项目。先后否决两个方案后收敛到本方案：

1. **销售名映射**（账号"对应销售名"+行键）：新项目自动跟随，但行级谓词无排除语义，
   客户例外（除福建联通/中兴）表达不了；账号销售名单值，一人多销售装不下。
2. **全员挂负责人**：负责人每项目一名、顶替制（原负责人失权），且 D-03 授予
   成本/合同额全字段编辑权，与"只看"诉求不符；新项目也不自动跟随。
3. **本方案**：新增"技术人员"职位，项目级可见（viewer 挂靠承接 11 条名单），
   可见面收窄到需求单/返还件/备件信息，一切价格不可见。

生产底账已核（2026-10-14，只读审计）：705 项目（644 活跃）、664 有销售名、41 空；
逐人命中——李呈辉 114、郭鸿广线 118、李冰冰线 52、司珂梓线 56、涂丹琴 62；
廖晓娟客户线：电信云 1 + 仁科 6 + 福建联通/中兴若干。

## 4. 方案（已成案；`决策: 无`——Phase 2 开发前须先落 `docs/decisions/` 新编号）

**探查结论（2026-10-14 三路代码调查）：**

- 内置 `maintenance_manager` 模板（permissions.py:183-196）≈ 画像 90%：
  `page_maintenance + own_maintenance_projects_only + acceptance_submit`，data_* 全 false；
  管理员可在权限中心 UI 零代码建自定义模板（快照式，带版本/审计/停用回滚）。
- 需求单 API/页面**零价格字段**（services/maintenance_demands.py:189-228）；返还/坏件
  模型纯数量；`/substitutes` 写有独立门禁 `require_sub_editor`。
- **缺口①销售参考价泄漏**：`/parts/search|overview|purchases|sales` 仅登录即可调
  （api/parts.py:27-131），`avg_sale_price`/`sale_price_ref`/`inquiry_ref`/AI quick_pricing
  不在任何字段组（config.py:562 注释表明有意为之）→ 无 data 键账号仍见销售参考价；
  前端无条件渲染（PartSearchPage.tsx:456-499）。
- **缺口②主数据页写裸奔**：`/parts/master*` 增删改仅挂页键（api/parts.py:218-319）
  → 给技术员该页=能改主数据，故不给。

**Phase 1：纯配置（零代码）**

1a. 建职位模板 technician（copy_from maintenance_manager，base_role=maintenance_manager）：

| 键 | 值 |
| --- | --- |
| page_maintenance | true |
| own_maintenance_projects_only | true |
| action_maintenance_bad_return_manage | true |
| action_maintenance_acceptance_submit | true（跟随基线，可去） |
| 其余全部（含 page_parts/master_data/inventory/pool、全部 data_*、领用写权） | false |

1b. 建技术员账号（UI/批量，套模板）。
1c. viewer 挂靠脚本 `backend/scripts/apply_technician_viewers.py`：roster JSON 输入
（复用审计脚本 DEFAULT_ROSTER 结构）→ 逐项目 `sync_project_viewers`
（maintenance_project_assignments.py:629，整组差量=幂等）；--dry-run、执行前备份
当前名单 JSON；配套 `rollback_technician_viewers.py` 按备份恢复。本地栈演练后再上生产。

**Phase 2：堵销售参考价泄漏（小代码改动，需决策编号先行）**

2a. 决策记录（拟 `docs/decisions/0006-*.md`）：新数据键 `data_sales_reference`（销售
参考价），未持键账号服务端置空。
2b. 后端：permissions.py 增键+元数据（**全部内置模板默认 true，既有账号零漂移**，
technician 显式 false）；config.py FIELD_GROUPS 注册组键 `avg_sale_price`/
`ref_sale_price`/`ref_sale_samples`/`avg_sale_price_90d`/`min_money`/`max_money`/
`last_money`（apply_field_visibility 递归置空，/parts 四端点已包裹，注册即生效）；
核查 agent quick_pricing（agent/tools.py）是否同样过包裹；契约测试。
2c. 前端：PartSearchPage.tsx 三处卡片（:456-499）改按 `canSee("data_sales_reference")`
条件渲染（沿用 :27-31 既有模式）。
2d. Phase 2 上线后 technician 模板同步加 `page_parts: true`，技术员获得型号查询页。

**过渡期已知残留**（Phase 1→2 间）：技术员无备件查询页（主数据页因缺口②不给）；
API 直调 `/parts/search` 仍见参考价（页键只藏菜单）。低风险（内部受信员工），决策
记录中如实记载。
