# DEV-07 互通池约束价覆盖率 — 实施规格

## 1. 目标

让管理层一眼知道有效互通池中还有多少池未设置采购最高价、销售最低价，并能从老板经营看板或池管理页一键筛出这些池，进入现有池编辑抽屉补录。

本功能只统计、展示和导航，不自动生成价格，不提交价格，不审批，不拦截交易，也不评价员工。

## 2. 业务口径

- 分母只包含 `status=active` 的人工池；归档池不参与覆盖率。
- 当前有效约束记录为 `part_pool_price_policy.valid_to IS NULL`。
- `purchase_ceiling_ex_tax IS NULL` 表示未设采购上限。
- `sales_floor_ex_tax IS NULL` 表示未设销售下限。
- 两侧分别统计，不能把“未设约束”显示成“未越线”。
- 覆盖统计是全局有效池口径，不受列表关键字、分页或当前筛选影响。
- 无 `data_pool_price_governance` 权限时，不返回覆盖数字，也不允许用缺失筛选反推哪些池设置过约束。

## 3. 后端契约

扩展 `GET /api/pools`：

- 新增可选查询参数 `policy_missing=purchase|sales|either|both`。
- 响应新增：

```json
{
  "coverage_restricted": false,
  "coverage": {
    "active_pool_count": 40,
    "purchase_set_count": 26,
    "purchase_missing_count": 14,
    "sales_set_count": 21,
    "sales_missing_count": 19,
    "both_set_count": 18
  }
}
```

- 无治理可见权限：`coverage_restricted=true`、`coverage=null`；显式传 `policy_missing` 返回 403。
- 不新增表、不改迁移；查询次数不随池数增长。

## 4. 前端交互

### 池管理页

- 列表上方显示：有效池总数、未设采购上限、未设销售下限。
- 点击缺失卡片更新 URL 查询参数并筛选列表；刷新、前进、后退保持状态。
- 当前筛选有明确高亮与“清除缺失筛选”。
- 每条记录沿用现有编辑入口，直接打开编辑抽屉设置约束价。
- 无治理可见权限时不显示覆盖数字或缺失筛选。

### 老板经营看板

- 互通池板块显示与管理页同源的覆盖数字。
- 明确标注这是全局有效池口径，不受经营看板当前时间范围影响。
- 账号具备池维护或约束价设置能力时，点击缺失项跳到池管理页对应筛选；只有看板权限但没有池管理入口能力时只读显示数字并提示联系管理员，不跳入未注册路由。
- 不复制统计逻辑。
- 390px、768px、1440px 不产生页面级横向滚动。

## 5. 验收与发布门

1. 独立 SQL 与 API 的有效池总数、两侧缺失数完全一致。
2. 归档、历史已失效策略不计入当前覆盖。
3. 关键字、分页和列表状态切换不改变全局覆盖数字。
4. 治理受限账号拿不到数字，也不能用筛选结果反推。
5. 看板与管理页数字同源且一致，卡片导航可用。
6. 筛选请求失败时清空旧列表并保留可重试错态，不能让新 URL/筛选标签搭配旧数据。
7. 前端权限测试、URL 历史测试、390/768/1440 浏览器验收通过。
8. 后端全量 pytest、前端 vitest、TypeScript、Vite build、GitHub CI 全绿。
9. 合并后仍不可自动生产；需单独授权并完成生产前备份、账号冒烟和部署后观察。
