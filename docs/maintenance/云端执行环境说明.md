# 云端 Claude 执行环境说明（WSL 测试机）

> 供在 Claude Code 云上执行 `docs/maintenance/plan-v1.3-fullstack.md` 的实现者使用。
> 本文件不含任何密钥；密钥由负责人通过环境变量/文件单独下发。

## 1. 连接参数（WSL Linux 测试机）

| 项 | 值 |
|---|---|
| 主机 | `wsl.cloudlay.cn` |
| 端口 | `2222` |
| 用户 | `cloudlay-3080` |
| 认证 | 专用 SSH 密钥（负责人下发的 `CLOUD_WSL_KEY`） |
| 测试数据库 | PostgreSQL 容器 `spareparts-test-db`，`127.0.0.1:5433/spareparts_test`（已在运行，只供测试，勿碰生产） |

环境变量约定（在 Claude Code 云设置；**云上无法保存文件时用 base64 模式**）：

```
CLOUD_WSL_HOST=wsl.cloudlay.cn
CLOUD_WSL_PORT=2222
CLOUD_WSL_USER=cloudlay-3080
# 二选一：
CLOUD_WSL_KEY_B64=LS0tLS1CRUdJTiBPUEVOU1NIIFBSSVZBVEUgS0VZLS0tLS0K...   # base64 单行（推荐，云环境）
# 或 CLOUD_WSL_KEY_FILE=/path/to/cloud_claude_wsl                              # 私钥文件路径（本机模式）
```

SSH 命令模板（base64 模式：先把环境变量还原成临时密钥文件再连，用完即删；
必须带 `-o IdentitiesOnly=yes`）：

```bash
KEY_TMP=$(mktemp) && chmod 600 "$KEY_TMP" && \
echo "$CLOUD_WSL_KEY_B64" | base64 -d > "$KEY_TMP" && \
ssh -i "$KEY_TMP" -o IdentitiesOnly=yes -o BatchMode=yes \
    -p "$CLOUD_WSL_PORT" "$CLOUD_WSL_USER@$CLOUD_WSL_HOST" '<远程命令>'; \
rm -f "$KEY_TMP"
```

本机模式命令模板：

```bash
ssh -i "$CLOUD_WSL_KEY_FILE" -o IdentitiesOnly=yes -o BatchMode=yes \
    -p "$CLOUD_WSL_PORT" "$CLOUD_WSL_USER@$CLOUD_WSL_HOST" '<远程命令>'
```

## 2. 首次初始化（一次性）

```bash
ssh ... 'mkdir -p ~/Workspaces && cd ~/Workspaces && \
  git clone https://github.com/Jinchen-Yang/it-spareparts.git it-spareparts-cloud && \
  cd it-spareparts-cloud && git checkout feat/maintenance-ledger-import && \
  cd backend && uv sync --extra dev'
```

> 注意：不要用 `~/Workspaces/it-data-pm/it-spareparts-b2`（那是本机的 rsync 镜像，非 git 仓库）。
> 自己在 `it-spareparts-cloud` 下维护一份 git 克隆。

## 3. 每次开发循环

1. 在云上写代码 → `git add`/`commit`/`push`（推 `feat/maintenance-ledger-import` 或自己的
   子分支）；
2. WSL 拉取并跑测试：

```bash
ssh ... 'cd ~/Workspaces/it-spareparts-cloud && git fetch origin && \
  git reset --hard origin/<你的分支> && cd backend && \
  .venv/bin/python -m pytest tests/<相关文件> -q'
```

3. 里程碑收尾跑全量（约 24 分钟，一次只跑一个进程，测试库是共享的）：

```bash
ssh ... 'cd ~/Workspaces/it-spareparts-cloud/backend && .venv/bin/python -m pytest -q 2>&1 | tail -12'
```

## 5. 硬规则

1. pytest 要求 Linux：一切测试只在这台 WSL 上跑；
2. 单进程测试：同一时刻只允许一个 pytest（测试库共享，并发会互相 truncate）；
3. **禁止访问生产**（生产凭据不下发；本环境只有测试库）；
4. 冻结清单（plan §0）功能零实现、零改动；
5. 真实业务数据文件不得提交进仓库（`import-field-contract.md` §9.2，测试只用合成数据）。
