# DEV-12 先行切片：维保项目生命周期状态

## 1. 目标与边界

在现有「项目成本」页增加维保期限状态，让用户默认只看仍在维保期内的项目，并可切换查看已结束或缺少维保终止日期的数据。

本切片只落地已确认口径：**项目是否结束由维保终止日期判断**。不新增负责人、截止时间、采购/入库/返件节点，不回填价格，不改变成本或利润算法。

## 2. 统一业务口径

- 统一状态：`ongoing`（进行中）、`ended`（已结束）、`missing`（期限缺失）。
- 判定基准为后端请求时的北京时间业务日，响应必须返回 `as_of` 供页面解释；不得依赖容器本地时区。
- `maint_end < as_of`：已结束；`maint_end >= as_of`：进行中（终止日当天仍算进行中）。
- 一个项目或合同包含多张维保单时：只要任一底层维保单缺少 `maint_end`，聚合状态就是期限缺失；全部有日期时取最晚 `maint_end` 判定。
- 日期范围仍筛选出库单日期，项目搜索同时作用于项目表和合同看板；生命周期判定始终相对北京时间当天，三个口径必须在页面说明中分开。
- 合同看板的项目搜索只用于召回命中的合同；命中后仍展示并计算该合同在当前日期范围内的全部项目与成本，不能裁掉共用合同的其他项目后重算盈亏。
- 默认筛选 `ongoing`；期限缺失计数必须常驻可见并可一键切换，不能因默认筛选而静默消失。

## 3. 后端契约

扩展：

- `GET /api/maintenance/projects?lifecycle=ongoing|ended|missing|all`，默认 ongoing。
- `GET /api/maintenance/board?lifecycle=ongoing|ended|missing|all`，默认 ongoing；既有 `status=red|yellow|green|no_budget` 含义不变。
- `GET /api/maintenance/export` 接收同一 lifecycle，导出与页面可见项目一致，并新增「期限状态、维保终止日期」列。

projects/board 响应每行新增：

```json
{
  "maint_end": "2026-12-31",
  "lifecycle_status": "ongoing"
}
```

顶层新增：

```json
{
  "as_of": "2026-07-16",
  "lifecycle_filter": "ongoing",
  "lifecycle_counts": {"ongoing": 12, "ended": 8, "missing": 3}
}
```

`lifecycle_counts` 是应用 lifecycle 过滤前的同级聚合计数；仍受原有日期、项目搜索等业务筛选影响。无数据库迁移，SQL 查询次数不得随项目数增长。

## 4. 前端交互

- 页面顶部增加「维保期限」分段筛选：进行中（默认）/ 已结束 / 期限缺失 / 全部，并显示 projects 响应计数。
- 期限缺失使用橙色明确提醒；不是已结束，也不是进行中。
- 项目表新增「期限状态」「维保终止日期」列。
- 盈亏卡同时显示期限状态；红黄绿仍只代表预算/盈亏，不能与期限状态混成一个标签。
- 页面说明明确：日期选择器筛出库日期；期限状态按响应中的 `as_of` 判断。
- 快速切换筛选时旧请求不得覆盖新筛选；失败时不保留上一个筛选的旧项目/卡片。
- 390/768/1440 三档无页面级横向滚动；宽表只允许容器内滚动。

## 5. 验收门

1. 昨天终止=已结束、今天终止=进行中、未来终止=进行中、空日期=期限缺失。
2. 聚合内任一空日期必须为期限缺失；不能被另一张有日期的单掩盖。
3. projects、board、export 三处口径一致；默认请求只返回进行中。
4. 生命周期筛选不改变既有成本、预算、盈亏金额与权限脱敏。
5. 日期筛选与生命周期筛选可以同时使用且页面解释清楚。
6. 快速 A→B 切换采用确定性延迟测试，A 最后返回也不能覆盖 B。
7. 后端全量 pytest、前端 vitest、TypeScript、Vite build、独立 SQL 抽样、真浏览器与 GitHub CI 全绿后才可合并。
8. 合并后不可自动生产；需单独部署授权与生产冒烟。
