# DEV-15 维保双税毛利与可往返工作簿规格

状态：甲方口径已确认，进入实现与验收
协议：`ITDATA_MAINT_ROUNDTRIP/1.0`
统一税率：13%

> 适用边界：本规格服务于既有合同级双税毛利与九表往返协议。稳定项目经营工作台的
> 四表全量工作簿、现场实际领用和项目成本进度采用
> [ADR-0002 稳定项目成本证据与已计成本语义](../adr/0002-stable-project-cost-evidence.md)，
> 不使用本规格第 3 节的三个月互通池瀑布。

## 1. 目标与边界

本增量解决三件事：

1. 合同级维保贡献毛利同时保留含税、未税两套结果，并扣除备件成本和维保报销；
2. 采购、销售、项目维保的展示口径由管理员统一设置，普通用户不能形成个人口径；
3. 提供固定、可读、可机器回填的维保工作簿，使订单、报销和缺失成本能够安全往返。

项目毛利只做到合同级。没有可靠分摊依据时，不把合同收入伪分摊到单个维保项目。

日期选择器只定义导出闭区间，不改变项目页、看板或明细页的在线查询范围。

## 2. 财务口径

### 2.1 双税计算

采购与销售的业务计算统一使用 13%：

```text
含税金额 = 未税金额 × 1.13
未税金额 = 含税金额 ÷ 1.13
```

来源表中的原始税率、含税标记和原始金额继续保留作审计，不被 13% 业务计算覆盖。

报销表存在明确税口径时按该口径读入；只有单一“报销金额”且没有口径字段时：

- 原始金额保留；
- 权威口径记为“未税（系统默认）”；
- 未税金额取原始金额；
- 含税金额按未税金额乘 1.13 生成。

该判断来自上传工作簿的实际表头和同行字段，不能从数据库中的单一历史金额反推。生产
切换前必须审计旧表事实数和原始归档；本次 2026-07-29 只读预检确认生产
`f_project_expense=0`，且没有成功的报销导入归档。迁移仍会在发现任一旧报销行时失败
关闭，避免把显式含税的历史金额盲目当成未税。若切换前数据发生漂移，必须先停止发布，
逐本检查归档并用本版本解析器重放，不能放宽迁移门禁。

### 2.2 合同级毛利

```text
含税备件毛利 = 含税合同收入 - 含税备件成本
未税备件毛利 = 未税合同收入 - 未税备件成本

含税贡献毛利 = 含税合同收入 - 含税备件成本 - 含税维保报销
未税贡献毛利 = 未税合同收入 - 未税备件成本 - 未税维保报销
```

只有合同的报销完整快照已经由往返工作簿声明并成功导入，贡献毛利才可发布。仅发现若干报销行不等于费用完整。

同一销售订单号存在多版本时，只在已成功导入且订单状态为已生效的记录中选择最新版本；排序依次为导入时间、事实创建时间、导入批次 ID、事实行 ID。看板、工作簿和导出必须共用同一解析器。

## 3. 缺失成本瀑布

本节仅适用于既有维保出库成本与合同级毛利流程，不适用于稳定项目经营工作台。

自动取价顺序保持：

```text
直接关联采购
→ ±7 天采购
→ 当月采购均价
→ 3 个月内有效互通池采购均价
→ 3 个月内有效互通池销售均价
→ 3 个月内本 PN 采购
→ 3 个月内本 PN 销售
→ 人工成本回填
→ 无成本
```

全部 `status=active` 的互通 PN 池均可作为参考，不再按池来源限制；同一 PN 同时落入多个
有效池时只对该 PN 的池级参考失败关闭，不选择任一池，继续尝试本 PN 历史采购、历史销售，
不得因此中断整批重算。

所有历史采购、销售参考必须位于出库日当日或之前，且不早于出库日前三个自然月。边界日可用，超出边界即不可用。

人工成本只覆盖自动瀑布仍未命中的维保明细。人工输入未税单位成本、依据和原因；系统生成含税单位成本并保留操作者、版本和更新时间。重算结果标记 `cost_source=manual`，不得直接篡改派生成本列。

## 4. 管理员展示策略

服务端维护三个独立口径：

- `purchase_display_basis`：采购；
- `sales_display_basis`：销售，默认 `ex`；
- `maintenance_display_basis`：项目维保。

每个值只能是 `inc | ex | both`。只有管理员能修改，更新必须使用乐观锁并写审计日志。普通用户只读取当前统一策略，不得通过本地存储、页面控件或换账号继承个人选择。

这是一项统一展示策略，不是删除另一套业务事实。双税字段仍同时落库并可由有权限的导出流程使用。

## 5. 往返工作簿协议

### 5.1 固定工作表

| 顺序 | Sheet | 用途 |
|---|---|---|
| 00 | `00_使用说明` | 操作步骤、颜色图例、校验规则 |
| 01 | `01_项目` | 合同和项目摘要，只读 |
| 02 | `02_维保订单` | 维保订单更新 |
| 03 | `03_订单明细` | 订单明细更新 |
| 04 | `04_报销明细` | 报销新增、更新、作废 |
| 05 | `05_人工成本回填` | 自动缺失成本的人工回填 |
| 07 | `98_字典` | 枚举和数据验证，隐藏 |
| 08 | `99_合同版本` | 合同 revision 快照，逐行保存并参与签名，`veryHidden` |
| 09 | `99_元数据` | 协议、导出 ID、范围、版本和签名，`veryHidden` |

五个数据页使用固定 Excel Table 名；禁止依赖员工可修改的 Sheet 名猜测数据类型。表头冻结并启用筛选。蓝灰列为系统只读，浅黄列可填，必填项有明确标识。工作簿不含宏、外链或易变公式。合同版本采用逐行表，避免将大批合同 revision 压入单个 Excel 单元格并触发 32,767 字符上限。

### 5.2 行操作

每个可写表包含以下技术列：

```text
操作
__entity_id
__base_version
__row_token
__client_row_id
```

各工作表允许的操作如下，导出模板的下拉选项必须与服务端规则一致：

| 工作表 | `KEEP` / 空白 | `CREATE` | `UPDATE` | `VOID` |
|---|---:|---:|---:|---:|
| `02_维保订单` | 允许 | 禁止 | 允许 | 禁止 |
| `03_订单明细` | 允许 | 禁止 | 允许 | 禁止 |
| `04_报销明细` | 允许 | 允许 | 允许 | 允许 |
| `05_人工成本回填` | 允许 | 允许 | 允许 | 允许 |

- 空白或 `KEEP`：不写；
- `CREATE`：新增，`__client_row_id` 必填；
- `UPDATE`：更新，实体 ID、基础版本和行签名必填；
- `VOID`：业务作废，不物理删除事实。

删除 Excel 行不代表删除系统数据。任何删除或作废必须显式填写操作和原因。

### 5.3 幂等、冲突和事务

- 现有实体以实体 ID 定位；
- 新增实体以 `export_id + sheet_code + client_row_id` 保证幂等；
- 行签名使用服务端 HMAC，导入时验证；
- 当前版本与 `__base_version` 不同返回 409；
- 重复上传同一已成功文件返回原结果或无变更，不重复写入；
- 整本工作簿先完整预检，再在单事务内应用；
- 任一签名、版本、跨页引用、金额或结构错误均使整本零写入；
- 导入成功后，同事务重算维保成本并更新合同工作簿 revision；
- 只有 `date_from`、`date_to` 都为空的全量模板成功导入，才可把合同报销标记为完整快照；
- 带日期范围的工作簿只更新范围内显式操作，不能建立或延续“费用已完整”的声明。

没有审批流。预检、版本检查和审计属于数据安全机制，不构成业务审批。

往返工作簿采用独立写入权限。默认只有管理员和老板角色具备；管理员可把该权限授予指定
工作人员，但不能借此扩大采购成本或利润数据可见范围。导入账号还必须具备模板中数据所需
的可见权限。

### 5.4 资源上限

- 每个可编辑 Table 最多 10,000 行；
- 超限导出必须在 ORM 全量物化和 openpyxl 构建前失败；
- XLSX 总解压量最多 64 MiB，压缩炸弹在解析工作簿前拒绝；
- 单进程同一时刻只构建一份往返模板；
- 批量写入按集合预取和批量 flush，数据库查询次数不得随编辑行数线性增长。

全局“全部”模板超过上限时，工作人员改用合同卡上的单合同回填模板；合同筛选属于签名
scope，导回时不能越过该合同修改其他数据。

## 6. 导出范围

预设支持：全部、今天、近 7 天、近 14 天、近 21 天、近 30 天、当月和自定义闭区间。

所选日期只传给导出 API。范围导出的订单、订单明细和报销内容必须全部落在闭区间内；不能只用日期选中合同后又导出合同的范围外明细。

## 7. 发布验收门

### 7.1 计算

- 来源税率为 0%、6%、13% 或空值，业务双税结果都按 13%；
- 原始税率不被改写；
- 无税口径报销按未税默认并生成双值；
- 贡献毛利逐分等于收入减备件成本减报销；
- 最新有效销售版本在页面、CSV 和工作簿一致。

### 7.2 成本

- 历史生成但仍 active 的池可用，archived 池不可用；
- 三个月边界可用，边界外一天不可用；
- 销售参考仍无数据后进入人工回填；
- 人工价只接管自动 `none` 行，重算后仍可审计。

### 7.3 权限与日期

- 普通账号在桌面和移动端均无切换控件；
- 本地存储无法覆盖服务端口径；
- 销售默认显示未税；
- 切换导出日期不触发项目、看板或明细请求；
- 所有导出请求携带正确闭区间。

### 7.4 往返

- 导出后原样导入为零业务事实变更；允许写入导入批次、原始归档、全量费用完整性声明和
  合同工作簿 revision 等协议证据；
- 新增、更新、作废均可重放且不重复；
- 两份旧工作簿并发时，后一份冲突且不覆盖新数据；
- 篡改元数据、行签名、表结构、公式、重复 ID 或超限输入均失败关闭；
- 失败后业务表、成本结果、合同水位和审计日志全部不变；
- 成功导入后再次导出与数据库一致。
