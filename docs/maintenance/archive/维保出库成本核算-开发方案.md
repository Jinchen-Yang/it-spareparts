## 1. 总体设计原则

1. **旁路新增，零侵入现有成本路径**：维保成本是独立管线（新表、新 service、新 API、新页面），不改 `cost.replay`、`profit.recompute`、`COST_METHOD` 等任何现有语义。现有利润测试必须全绿（回归红线）。
2. **复用导入框架全链路**：reader（双表头/F 码识别、列名容差、ffill）→ mapping → transform → loader（`_upsert_facts` 幂等）→ 批次/作业/报告，全部按采购/销售的既有套路扩一类文件。
3. **注意与销售成本口径的刻意差异**：销售毛利用移动加权/FIFO + `ex_tax`；维保成本按客户确认的"当月加权 + 原值税口径标注"。两者并存、互不影响，文档与代码注释必须写明这是客户拍板的差异而非疏漏。
4. 所有新成本字段**必须登记 `config.FIELD_GROUPS`** 脱敏组，防止对无权限角色泄漏。

## 4. 成本引擎 `services/maintenance_cost.py`

新建独立 service（**不改 cost.py**）。入口 `recompute(db) -> dict`（返回各来源计数报告，风格同 `profit.recompute`）。

### 4.1 价格池构建（一次性内存构建，量级：半年 1.2 万采购行，无性能问题）

全部只取 `query_filters.active_orders`（已生效）、`unit_price > 0`、`pn_std NOT IN MAINT_POOL_EXCLUDE_PNS` 的行；按 `part_id` 分组（与 profit 同约定，pn_std 仅展示）：

1. **直配池**：`{(linked_maintenance_order_no, part_id): (加权单价, tax_basis, 采购单号)}`——来自 `f_purchase_order.linked_maintenance_order_no IS NOT NULL` 的采购明细；同单同 PN 多行按数量加权。`tax_basis = 'inc' if order.is_tax_inclusive else 'ex'`。
2. **采购月度池**：`{(part_id, 'YYYY-MM', basis): (Σ qty×unit_price, Σ qty)}`——采购类型限 `COST_PURCHASE_TYPES`（现值含维保需求，直接复用）。**金额用 `qty×unit_price` 而非 line_amount**（其他款项/运费不摊入，§0）。
3. **销售参考池**：同结构——来自 `f_sales_line` join `f_sales_order.business_type IN MAINT_SALES_REF_BUSINESS_TYPES`；`basis = 'inc' if order.tax_rate > 0 else 'ex'`（销售单价字段即含税口径）。

### 4.2 取价瀑布（对每条有效出库行；月份 = 头表 order_date 所在月）

```
D = 出库日（需求单日期，时间锚——绝不用"今天"）, M = 出库月
1. A0 直配    : 直配池[(order_no, part_id)] 命中
               → cost_source='direct', 记 linked_purchase_order_no        [置信:高]
2. A1 ±7天窗口: |采购日 − D| ≤ MAINT_PRICE_WINDOW_DAYS(=7) 内时间距离最近
               的同 part 采购价（同距离取更早那天；同日多行按数量加权）
               → cost_source='window', 记 price_distance_days(带正负号)   [置信:高]
3. A2 当月均价: 采购月度池[(part_id, M, 'inc')] 优先，无则 ('ex')
               → cost_source='month_avg', trace_months=0                 [置信:中]
4. B  追溯均价: for k in 1..MAINT_TRACE_MAX_MONTHS(=3):
                 采购月度池[(part_id, M−k, inc优先)] 命中
               → cost_source='trace_avg', trace_months=k                 [置信:中]
5. C  销售参考: 销售参考池按 当月→追溯≤3月 规则
               → cost_source='sales_ref'                                 [置信:低]
6. 无成本     : cost_source='none', unit_cost/cost_amount=NULL, flag 'no_cost'
```

置信度依据 §16.1 校准：direct/window 命中时中位偏差 0%（<10% 占 95.5%/65.7%）；month_avg/trace_avg 中位 6.9%/9.1%；既无直配又无近期采购的部分任何规则中位偏差 25%+，属数据极限——`confidence` 字段（high/medium/low）落库并在前端展示，**低置信估价不伪装成精确数**。

- 每步取价含税优先（Q4）；`cost_tax_basis` 记实际采用的口径；`price_month` 记实际取价月。
- 金额量化沿用 `cost.py` 的 `_CENT=0.01`。
- **每层语义（前端标签文案）**：direct=「实际·专属采购」(green)；month_avg=「实际·当月均价」(blue)；trace_avg=「预估·追溯N月」(orange，N=trace_months)；sales_ref=「没有采购有销售」(purple，客户指定原话)；none=「无成本」(red)。
- 有效行定义：头表 `data_status = ACTIVE_STATUS`、`order_date ≥ MAINT_COST_START_DATE`、pn 非空、qty 非空。起算日前的行 `cost_source=NULL`（不计价、不进报表，与 `'none'`「算了但没算出来」区分）。`(qty − return_qty) ≤ 0` 的行 cost_amount=0 并 flag `has_return`。

### 4.3 config.py 新增开关（§8 区域，附中文注释）


## 10. 边界情况（实测数据得出，实现时必须处理）

1. **草稿/取消单**：按 `data_status = ACTIVE_STATUS` 过滤（2026 数据：已取消 8 单、草稿 5 单、进行中 7 单）；草稿单存在全空明细行（如 WBDD-20260702-0004），空 PN 走 `empty_pn_inactive` 软错误。
2. **退货/退库**：明细有「需求明细.退货数量」列；`cost_amount = (qty − return_qty) × unit_cost`，`return_qty > 0` 时 flag `has_return`。（联通 2023 人工账中有 52 张负成本退库冲抵单——该底稿周期在起算日前不作验收基准，但**退库冲抵口径仍以它为参照与财务核对一次**。）
3. **打包采购占位 PN「一批备件」**：13 行 / 2,333 万，进池会严重扭曲均价，必须按 `MAINT_POOL_EXCLUDE_PNS` 排除（已向客户提出在氚云拆明细）。
4. **PN 质量**：V 码后缀（约 9% 行）`standardize_pn` 已截断，两侧一致，实测不影响匹配率；多段空格 PN（约 5%）`needs_review=True` 原样匹配。
5. **共用合同**：13 张 XSDD 挂多项目，`contract_shared` 标记，绝不据此算毛利（Q5）。
6. **未来日期**：销售数据见 1 单 2026-12-02 录错；维保 transform 对 `order_date > today + 30d` 记 anomaly flag（不拦截）。
7. **产品成本列**：维保导出 90 列无任何成本列——不要试图从维保文件本身取成本。

### 17.1 理念：工作簿即表单，导入格式 = 导出格式

员工把一本「项目追踪工作簿」托付给系统 → 系统吃走人填区（报销费用）→ 日常从氚云导出（维保需求单 WBDD，**样式不变**）导入出库并回填成本 → 导出时把**同一形态**的工作簿还给员工：人填的部分原样返还，系统区已填满（备件成本、盈亏、月度汇总）。新合同导出即空白表单——**模板不再单独维护，模板=系统导出的空表**。

### 17.2 页结构与所有权

| 页 | 所有权 | 导入时 | 导出时 |
|---|---|---|---|
| 项目预算 | 系统区 | 忽略 | 抬头 + 盈亏色块 + 月度×分类汇总 |
| 备件明细-氚云 | 系统区 | **忽略**（权威源=氚云 WBDD 导出；防回环污染） | 出库行 + 成本回填（单据级总额首行 + 行级明细列） |
| 报销明细 | **人填区** | → `f_project_expense` | 已入库行原样返还 + 合计行 |
| 填写说明 | 系统区 | 忽略 | 人填区/系统区图例与规则 |

### 17.3 报销明细页 canonical 格式

- **第 1 行 = 归集锚**：`A1="销售订单"，B1=XSDD 单号`（导出自动写入；行级若有「销售订单/维保销售订单」列则行级优先，锚兜底；两者皆无的行 → 错误行）。
- **第 2 行 = 表头**：`报销日期 | 报销人员 | 报销类别 | 费用分类 | 支出事由 | 报销金额 | 流程状态 | 单号 | 序号`。
- **必需列仅 报销日期 + 报销金额**（+归集键），且**每行日期必填**——报销页全字段不 ffill（v3 修订：ffill 会让只填日期+金额的新行继承上一行的流程状态/人员/事由，状态=流程中时新报销静默不计已花；「留空=同上」的头明细语义随氚云导出一并废止）。列名容差归一复用 `canonicalize_columns`。
- **流程状态为空 → 默认 `已结束`（生效）**：表单心智——员工写上来的就是要计入的账；带审批流状态的导出（若有）则尊重原值。
- 行分拣（v3 修订）：无金额的行跳过（计数进报告）；**有金额但缺日期 → `missing_date` 错误行**（半截行必须响，不许静默丢账），唯一豁免=任一文本格含「合计」（导出件合计行天然跳过）。手填自由文本入库前按列宽钳制，防单行超长炸整批。

**识别签名（sheet 级）**：列含「报销金额」且含（「费用分类」或「报销日期」）→ expense。采购/销售/WBDD/库存导出均无「报销金额」列，零误伤。

### 17.4 幂等键：内容派生（替代"文件hash+行号"）

- 有单号+序号 → `单号#序号@sha1(XSDD)[:8]`（v3 修订：生产 f_project_expense 实为空表，无历史键包袱；单号自 v1.7.0 起是员工手填自由文本，**必须带合同域后缀**，否则合同 A/B 都填"1#1"时 skip 静默互吞、upsert 把 A 的行改挂到 B）。同一文件内 单号+序号 重复 → `duplicate_key` 错误行（否则 upsert 同语句撞键 CardinalityViolation 炸整批）。
- 否则 `EXP:sha1(xsdd|日期|金额|norm(事由)|norm(人员))[:36]#文件内重复序`——同一本工作簿**每月更新再上传是常态**，文件hash+行号会导致每次全量重插；内容键天然幂等（parse_money 量化 0.01，float 往返不漂键）。
- 代价：财务改了某行金额 → 新键入库、旧行残留。承接：两种导入模式语义映射——
  - `skip`（增量）：ON CONFLICT DO NOTHING，只进新行；
  - `upsert`（修复/**以本表为准**）：对本次文件出现的每个 XSDD，**先删该合同全部 expense 行再插入**（表单=该合同费用的全量真值），被删行 before 快照进 SysAuditLog（超量记总数），删除计数进导入报告。**前置条件：报销页零错误行**——半截行/撞键行意味着"本表"不完整，整表替换会静默丢账，先修再导（skip 模式不受此限）。

### 17.5 多 sheet 导入（reader/pipeline 改造）

- 新增 `reader.read_workbook(path) → list[SheetData]`：逐 sheet 探测（复用表头探测+列归一+类型识别；expense 页额外做锚行探测）。重复列名只记录（`dup_cols`）不抛错——仅对**实际取用**的页校验（v3 修订：被跳过的副本页不该拖垮整个文件）。
- `pipeline.run_import` 调度（v3 修订——判据是"有没有报销页"，不是"页数"）：
  - 可识别 sheet=0 → 报错；
  - **含报销页 → 项目追踪工作簿**：全部报销页合并为**单次装载**（多报销页时跨页同键去重；单次合同级替换，计数不虚高），其余可识别页跳过并报告；`batch.file_type`=多页时 `workbook`、单页时 `expense`；
  - **不含报销页 → 老语义**：导第一个可识别页（隐藏备份页/副本页不再整批失败），其余页进报告 `ignored_sheets` 提示。
  - 报告为扁平结构（值只有标量/字符串数组），前端 Descriptions 泛化渲染零改动。
- `peek_columns`（导入预检）与上述调度同判据，预检类型=实际入库类型。
- 文件级 hash 去重、导入锁、归档逻辑不变。行数上限改为全 sheet 合计（多页会全量物化）。

### 17.6 Round-trip 验收（核心不变量）

`export-workbook → 原样再导入` 必须：0 错误、0 新增（锚行/合计行/预算页/备件页/说明页全部被正确跳过或幂等命中）。以集成测试固化。

## §18 DEV-14：双税成本与缺失成本参考（历史基线，2026-07-28）

本节是对旧成本引擎的**后置增量**。既有
`direct → window → month_avg → trace_avg → sales_ref`
五层的 `unit_cost / cost_amount / cost_source / cost_tax_basis` 选择结果必须逐行零漂移；只有原本会落 `none` 的行才继续：

```text
pool_purchase
→ pool_sales
→ purchase_history
→ sales_history
→ none
```

### 18.1 池和历史参考冻结口径

- 只读取人工维护且 `status=active` 的互通 PN 池，不使用采购最高价、销售最低价等人工约束。
- `pool_purchase` 优先于 `pool_sales`，不因销售样本日期更近而交换顺序。
- 每层只看出库日当日或以前的事实，取最近一个有有效样本的自然月，禁止未来前视。
- 池均价统计 active 池**全体成员，明确包含当前待补价的目标 PN 本身**；在同一参考月内按 `Σ(qty×price)÷Σqty` 加权，不做“成员均价的算术平均”。
- 池没有有效样本时继续本 PN 的 `purchase_history / sales_history`，最终仍无样本才保持 `none`。
- 只纳入已生效、正数量、正且有限价格、允许业务类型的事实；打包占位 PN、`counts_revenue=false` 销售行和 `confirmed_source_error` 行排除。
- 四个新增来源统一为 `estimated + low confidence`；最新样本距出库月超过 12 个月追加 `stale_cost_reference`。

### 18.2 每样本双税归一

来源事实必须先按自身 `tax_rate` 和含税标记换算，再分别按数量加权：

```text
unit_cost_inc_tax = Σ(qty × sample_price_inc) ÷ Σqty
unit_cost_ex_tax  = Σ(qty × sample_price_ex)  ÷ Σqty
```

- 销售 `unit_price` 是含税原值；采购按 `is_tax_inclusive` 判断原值口径。
- 税率 `0%` 原样保留；税率缺失时暂用 `PROFIT_VAT_RATE=13%`，并追加 `tax_rate_estimated`。
- 新参考 SQL 只接受 `tax_rate IS NULL OR 0 <= tax_rate < 1`；超出范围的事实整条排除。纯函数遇到脏税率时以 13% 防御性换算并标记估算，防止产生非有限金额。
- 严禁先混合含税、未税原值再统一乘除税率。

维保行新增并持久化：

```text
unit_cost_inc_tax / unit_cost_ex_tax
cost_amount_inc_tax / cost_amount_ex_tax
reference_side
reference_pool_group_id / reference_pool_version
reference_sample_count
reference_from_date / reference_to_date / reference_latest_date
```

`projects_aggregate` 与合同看板新增：

```text
parts_cost_inc_tax / parts_cost_ex_tax
parts_cost_{inc|ex}_tax_complete
parts_cost_{inc|ex}_tax_quality
parts_cost_{inc|ex}_tax_missing_lines
```

旧 `cost_inc / cost_ex / cost_total` 继续表达原始选中税口径的兼容汇总，**不得改名后冒充归一双税成本，也不得进入正式双口径毛利公式**。

### 18.3 迁移、权限与验收

- Alembic：`e5f9a2b3c4d5`，下游 `d4e8f1a2b3c4`；生成列 `cost_bucket` 同步识别四个新增估算来源。
- 新双税金额、质量、来源和 provenance 全部登记 `purchase_cost` 字段组；无成本权限时 API、CSV、XLSX 与 Agent 递归遮蔽。
- `backend/tests/test_maintenance_cost_reference.py` 固化四层瀑布、目标 PN 入池、最近非空月、无前视、6%/13%/0%/缺失税率、数据质量排除、退货、幂等和固定查询数。
- 发布前必须通过旧五层兼容字段零漂移、迁移 upgrade/downgrade/upgrade 单 head、全量维保回归和生产量级压测。
