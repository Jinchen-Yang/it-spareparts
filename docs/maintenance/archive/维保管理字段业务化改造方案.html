维保管理 — 字段业务化改造方案

当前维保管理模块（项目面板、项目主档、月度更新、成本回填、项目工作台）中的字段名称、按钮文案和提示语大量使用了数据库列名和技术术语，甲方运维/项目经理阅读困难。本方案逐页列出每个字段的当前名称、业务含义、以及建议的业务化新名称，供逐项确认后实施修改。

📋 影响范围：维保管理 5 个页面 + 项目工作台详情 📅 2026-08-12 🔖 基于 codex/maintenance-manager-combined
关于"技术化"问题的核心诊断

问题不在于用了英文缩写（PN、WBDD 等），而在于三件事：
① 数据库物理列名直接暴露给用户——例如 project_code、display_name、lifecycle_status、project_manager_id，它们不是中文世界里任何甲方人员会用的词汇；
② 状态值和技术标签直接用作界面文案——例如 mapped / unmapped、inc_tax、missing、restricted，业务人员看不懂这些词；
③ 菜单项和按钮命名偏开发视角——例如"项目面板"（实际是项目方块总览）、"项目主档"（实际是项目身份注册表）、"成本回填"（实际是缺失成本人工补充）。

改造原则：每次修改只改前端展示文案（nav.tsx 的 label、各页面组件的 title/subtitle/columns.title/placeholder/Button 文本）， 不改后端 API 字段名、不改数据库列名、不改路由路径。这是纯前端文案层的业务化翻译，风险极低，可分批实施。
