## 合并与生产门槛

### 可以合并到 main

同时满足：

1. PR 的前后端 GitHub CI 全绿；
2. PR HEAD 与本记录对应，未混入迁移、成本/利润算法或无关文件；
3. 对抗复审没有新增 blocker/P1；
4. 合并前确认 main 未出现需要重新对齐的冲突。

### 可以提交生产部署

必须另行获得部署授权，并按以下顺序执行：

1. 先备份数据库并校验备份可读；
2. 部署合并后的 main 精确 SHA，不部署功能分支；
3. 本版无迁移、无需利润或维保成本重算；需要重建前端镜像并重启后端；
4. 用管理员与维保查看账号分别验证：默认进行中、已结束切换、项目搜索、CSV 导出、受限金额脱敏；
5. 对照生产 SQL 复核项目/合同三类数量，并确认默认筛选不改变同一行金额；
6. 观察错误日志和健康检查至少 30 分钟，异常则按备份与旧镜像回滚。
