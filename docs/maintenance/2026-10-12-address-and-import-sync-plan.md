# 地址与需求单上传同步：共同实施方案

日期：2026-10-12。阶段：接手核查与编码前方案。业务选择见 [D-26](../decisions/0004-维保地址导入与旧模板兼容.md)；本文中的实现方式及预期效果尚未交付。

## 先看用户最终得到什么

两项任务共用“读懂 Excel → 按原始身份找到单据 → 更新明确提供的字段 → 页面与导出一致”的路径。地址作为单头字段接入；删除及级联由另一台电脑在共同输入集合上处理。

| 用户输入 | 当前情况 | 计划完成后的效果 | 可以看到的内容 |
| --- | --- | --- | --- |
| 氚云导出的维保备件需求单，带收货地址 | 标准列名已有读取、保存和展示；专用入口仍检查固定列段 | 地址列移动或插入任意位置后仍按表头读取；专用、通用入口识别同一份原件 | 单号、PN、数量、SN等原有内容，以及对应单据的收货地址、联系人、电话 |
| 更新某张旧需求单的原件，包含新地址 | 更新模式能保存地址；跳过模式不更新已有记录；旧规则把空白和缺列都转成空值 | 更新已有记录时保存新地址；缺列/空白保留旧地址；回执说明地址更新、保留或冲突 | 页面显示本次实际采用的地址，不串到别的单据 |
| 没有地址列的旧需求单文件 | 专用布局校验可能拒绝；覆盖时还可能清空原地址 | 仍可导入，已有地址保留，不要求补齐全部旧文件 | 原有业务内容继续可见；原来无地址的显示未填写 |
| 项目总表 `06_领用返还`，填写地址 | 工作簿不读取、保存或导出现场位置 | 新增可编辑地址列，读写现有 `site_location`；新建、修改及再次导出一致 | 领用单号、日期、PN、SN、数量、返还要求、备注和实际领用地址 |
| 领用页面手工填写地址 | 已有“现场位置”输入和 API | 继续使用同一字段，名称说明为领用地址/现场位置；与 Excel 的结果一致 | 详情与导出中的地址一致，不另造一份地址 |
| 地址单元格留空，或明确请求清空 | 当前原始覆盖导入会清空空值；往返工作簿没有地址列 | 留空保留；明确清空动作才清空。拟使用可选“地址操作”字段，值为“清空”；具体界面随实现交付 | 回执区分保留与清空，不把空白误当删除 |

“增加能看到的内容”不能理解为历史地址自动补齐：需求单已保存的大量地址现在就可见；历史领用地址全部为空，只有后续明确录入/修改才会有值。收货地址与实际领用地址不自动互相代填。

源字段更新继续区分当前“跳过已有记录”和“更新已有记录”协议，不能为了地址在用户明确选择跳过时偷偷覆盖数量。专用 WBDD 使用更新路径；通用入口的实际模式需在回执中说清。前面的数量/SN/状态不同步问题与地址共用这条更新路径，来源更新不得覆盖人工保护字段。

这不证明全部历史地址齐全。也不能把“表头有地址”理解为每张旧单都填写了地址。

已核实当前联系信息序列化：有客户信息权限时输出实际地址；无该权限时为 restricted 且地址为 null。通过真实生产前后端、正常登录和只读请求检查，需求单查询返回 200，页面当前 20 条地址与对应 API 内容逐条一致。选取已有领用的项目，其领用查询返回 200、15 张单，响应包含现场位置字段，但值为空。

当前现有需求单展示可以复用，主要修复点在识别、更新、旧模板保护，以及领用 Excel 的缺失链路。

### 专用入口发现的真实兼容问题

生产原件批次 393 原样运行专用布局校验即被拒绝：`segment_mismatch`，原因为头字段“需求数量”处于第 8 列，被固定列段规则判成明细段。将收货地址移动到 B 列同样被拒绝；删除地址列或增加“地址”列触发 `layout_unknown`。

这份原件已经通过通用 upsert 上传并正确保存 282 张单的地址。问题不仅是新地址别名缺失，更包括两个上传入口的布局约束不一致。因此不能只添加一个表头别名就宣称修复完成。

### 领用历史原件的核查限度

查询的 `sys_raw_file` 类型包括采购、销售、需求单、报销、收款批量及返还收货，没有找到项目总表/领用工作簿原件的独立归档。当前工作簿应用记录主要保留文件哈希与操作回执。该现状不能当成“历史领用 Excel 地址已丢失”的证据：没有读取到原件，就不能断言原件曾填过地址。

已读到运行代码的 `06_领用返还` 导出列和行构造，确实不含现场位置；当前领用记录也确实没有值。本次不通过调用带 FOR UPDATE 的生产导出服务伪装数据库纯只读验证。

## 两项任务怎样共同执行

### 本机负责输入识别、字段更新与地址链路

1. WBDD 先按核心身份、单号、PN、数量等表头识别；地址列及已约定扩展列可以移动或插入。保留重复表头、文件类型、必需身份和值类型校验，移除依赖固定列段的误判。
2. 地址别名只在相应文件类型中生效。WBDD 采用“收货地址”“地址”及明确的选填注解；“选择收货地址”始终独立。
3. 读取结果区分字段未提供、空白、有效新值、明确清空和字段冲突；将地址变化作为单头补丁写入已有字段，不通过 None 误清空。
4. 本次文件真实出现的父单 ID、明细 ID及解析失败信息应作为固定来源事实保存/读取，避免用可变化的业务表最后导入批次还原原文件。由删除任务消费共同来源集合；本机不据此增加作废动作。
5. 上传回执解释采用的新值、保留原因和冲突单号/行号。地址失败不因模板行顺序静默采用第一条或最后一条。

第 4 项属于此前上传差异清单问题的共同输入契约，具体持久化接入点需与删除实现一起核对；不是地址功能另起一套删除清单。

### 另一台电脑负责差集作废与级联

缺行判定、整单/行作废、恢复、下游级联和统计退出由对方实现。本机只提供可验证的源输入与字段存在性，不改其判定规则。

共同例子：增量文件同时有 6 月 9 日修改过的旧单和 8 月 9 日新单，字段更新以实际出现的单据为范围；不把两日期间的所有未上传单据自动视为缺失。地址不是判断是否删单、换项目或生成新身份的依据。

### 必须逐段协调的代码

| 模块 | 本机必要改动 | 集成关注点 |
| --- | --- | --- |
| etl mapping / reader / transform | 命名表头、别名、字段存在性、地址一致性 | 源存在集合不能因为地址错误或空白变成“缺行”；不得跨父单继承 |
| `etl/loader.py` | 单头地址的稀疏更新、审计与变更版本 | 保留既有人工覆盖、锁序、revision bump及作废优先；核对对方缺行执行位置 |

## 实施顺序与提交范围

1. **需求单地址和导入兼容**：命名列识别、地址字段存在性与补丁保存、D-26 空白和矛盾处理、通用/专用路径回执及契约测试。
2. **领用地址往返**：复用 site_location、06 地址导入/新建/修改/导出、同单单头传播、旧基线兼容、页面名称及展示、明确清空路径与测试。
3. **上传来源集合与删除分支集成**：核对对方共享的精确提交，合并共同来源快照改动和输入协议，跑跨模块回归；删除业务规则仍由对方负责。不要为了先交付地址合入整个未知开发分支。

目前未计划地址数据库迁移；复用已有字段，领用超长输入继续明确报错。已有领用普通页面手填必填契约不改变；旧 Excel 缺字段仍兼容。

## 契约测试与验收结果要求

- 原标准 90/91 列、单双表头及近期真实原件的表头形态；测试使用合成数据，不提交客户原行。
- 地址移动/插列后身份、PN、数量、SN仍对齐；采购/销售/入库解析不受 WBDD 别名影响。
- 无列/空白保留，有值更新，明确清空；同单地址冲突只保留该单原地址并给出准确提示，其他合法地址照常处理。
- 同单首行地址、续行空白、下一单空白、重复别名与多地址，不跨单串值。
- 06 新建、修改、同单单行改地址传播、两行不同新值的冲突；中文与换行保留；超长不截断。
- 旧工作簿无地址/无地址基线不会清空，不因升级生成重复单；地址不参与自动编号、原始 ID 或 PN/SN 身份。
- 重放幂等、并发地址修改、三路合并、实名审计、单头版本及工作簿版本更新。
- 查看和导出遵循原有客户信息、项目范围与动作权限；无权限不在隐藏令牌中绕过。
- 数量、成本、人工保护、归属、作废优先和既有删除实现保持其已确认口径；地址变更不产生额外领用、返还或库存事实。
- 按实现涉及的模块完成后端契约回归、前端测试、TypeScript 与构建；不得把原件只读核对当成功能已验收，也不以本轮未运行的全量测试作为通过证据。
