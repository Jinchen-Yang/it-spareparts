## 1. 契约范围

目前核对的五种导出结构对应四类业务对象：

| 业务对象 | 已核对的导出结构 | 表头宽度 | 表头/明细 | 主要作用 |
|---|---:|---:|---|---|
| 入库单 | 1 种 | 155 字段 | 单据表头 + 备件/整机明细 | 记录采购或返还件经检测后的正式入库 |
| 发货/出库单 | 1 种 | 166 字段 | 单据表头 + 备件/整机明细 | 记录仓库实际发出并进入在途的实物 |
| 费用报销支付单 | 1 种 | 43 字段 | 报销单表头 + 报销明细 | 归集备件以外的项目支出证据 |
| 退货返库单 | 2 种 | 49 / 120 字段 | 单据表头 + 备件/整机明细 | 记录项目或业务发起返还的动作 |

两种退货返库导出只是字段宽度不同，业务对象相同。导入器必须允许可选列缺失，不能仅因“49 列”或“120 列”决定业务语义，也不能要求窄表虚构宽表才有的字段。

## 2. 所有工作簿的统一解析规则

### 2.1 表头识别

1. 第 1 行是氚云内部字段编码，只保留为来源追踪信息；第 2 行是业务字段名，是本契约的匹配基础。
2. 导入按“规范业务字段名 + 受控别名”匹配，不按固定列序号。新增、删除或移动可选列不得造成错列导入。
3. 匹配前可以统一全半角标点、首尾空白，并移除字段名末尾的 `(必填)` 标记；不得改变字段的业务含义。
4. `备件明细.`、`报销明细.` 等前缀用于区分表头和子表，同名字段不得跨层自动合并。
5. 未识别列应记录字段名和数量后跳过；同一规范字段命中多个列、关键标识缺失或表头结构无法判定时必须失败关闭，不能选择“看起来最像”的列。

### 2.2 数据保真与去重

- 原始字段值与规范化结果分开保存。单号、PN、SN、记录 ID、订单关联等标识字段按文本读取，不把前导零、长编号或科学计数法当作数值改写。
- 表头是一张单据，明细是一对多子表。工作簿重复展示的表头字段要按业务单号去重后统计一次，不能随明细行重复累加。
- 表头业务主键优先使用单号；明细优先使用不可修改的明细记录 ID，缺失时使用“单号 + 明细序号”。不得只用 PN 或费用类别作为明细唯一键。
- 同一文件内同号且表头关键事实冲突、同一明细键内容冲突时必须报错；跨批次重导应幂等更新或忽略完全相同记录。
- 明细按 PN、SN 或费用类别汇总是统计行为，不改变原始明细主键和追溯关系。

### 2.3 空值、枚举和敏感字段

- 空列与列缺失是两种状态：可选列缺失记为 `not_provided`，存在但为空记为 `blank`；必需身份字段缺失或为空时拒绝该单据。
- 已验证枚举只接受本文列出的原值或经版本控制的别名；未知值进入异常清单，不能静默归到“其他”。
- 人员、客户、供应商、收款账户、附件和图片地址均为敏感字段。契约只定义字段，不在仓库保存真实值、样例行、附件、截图或导出的 Excel 文件。

### 2.4 库存与成本总原则

```text
项目实际成本 = 已确认备件成本 + 已确认项目费用
```

维保需求、采购、入库和出库是同一备件成本的关联证据，不能重复相加。出库只表示进入在途，退货返库只表示返还动作；只有现场收货确认才能增加项目前置库，只有返还件完成检测、仓库、库位登记并正式入库后才能恢复可用库存。具体成本计价、返还成本冲回、费用生效金额与状态尚未确认时，导入可以保存事实，但不得自动记账或生成确定利润。

## 3. 发货/出库单

### 3.1 最小字段

| 层级 | 用途 | 规范业务字段 | 必需性 |
|---|---|---|---|
| 表头 | 单据身份 | `出库单号`、`出库日期`、`出库类别`、`出库备件/整机`、`出库仓库` | 必需 |
| 表头 | 维保关联 | `维保需求单(备件)` 或 `维保需求单`；`销售订单(备件)` 或 `销售订单` | 维保供货至少命中一项需求关联；销售订单有值则保留，不强制虚填 |
| 表头 | 责任与范围 | `项目经理`、`维保需求人`、`客户名称`、`公司名称`、`数据状态` | 有值则保留；不得用姓名作主键 |
| 表头 | 物流证据 | `发货日期`、`快递单号`、`输入快递单号`、`关联收货入库单` | 可选 |
| 明细 | 明细身份 | `备件明细.数据ID(不可修改)`、`备件明细.序号` | 至少可组成稳定明细键 |
| 明细 | 实物身份 | `备件明细.备件PN(必填)`、`备件明细.备件SN号(必填)`、`备件明细.备件自贴码(必填)` | PN 必需；SN/自贴码按品类规则保留 |
| 明细 | 数量与位置 | `备件明细.出库数量`、`备件明细.所在仓库`、`备件明细.所在库位` | 数量必需；位置有值则保留 |
| 明细 | 成本证据 | `备件明细.成本单价(必填)`、`备件明细.成本金额` | 可为空并标记成本不完整，不得默认 0 |
| 明细 | 质量证据 | `备件明细.备件测试合格(必填)`、`备件明细.故障现象(必填)`、`备件明细.测试报告` | 有值则保留 |

### 3.2 主键、枚举与影响

- 表头业务主键：`出库单号`。
- 明细业务主键：`备件明细.数据ID(不可修改)`；缺失时为 `出库单号 + 备件明细.序号`。
- `出库类别` 已验证值：`销售出库`、`维保供货`、`委外出库`、`采购退货`、`其他出库`。
- `出库备件/整机` 已验证值：`备件`、`整机`；多个校验字段使用 `是` / `否`。
- 库存影响：仓库发出后从来源库存进入在途；在没有现场收货确认前，不增加项目前置库库存。
- 成本影响：成本单价和金额是备件成本证据，不与采购或入库金额再次相加；成本缺失时保持 `incomplete`。

## 4. 退货返库单

### 4.1 两种导出结构的兼容规则

49 字段窄表包含返库类别、类型、日期、项目/订单/需求关联、PN/SN、测试结果、数量和通知关联等核心事实。120 字段宽表在此基础上增加表头记录 ID、返库单号、明细记录 ID/序号、更多库存位置、对象 ID 和整机字段。

- 读取共同字段时使用同一规范名。
- 宽表专有字段均为条件可选；窄表不因缺少这些列而失败。
- 宽表存在 `返库单号` 时以它为表头业务主键；不存在时仅可使用来源系统不可修改的稳定记录 ID。两者都没有时必须进入异常清单，不能用客户、日期、PN 拼出伪主键。
- 明细优先使用 `备件明细.数据ID(不可修改)`；缺失时使用“稳定表头键 + `备件明细.序号`”。窄表无法形成稳定明细键时只能作为待治理事实，不得静默覆盖既有记录。

### 4.2 最小字段

| 层级 | 用途 | 规范业务字段 | 必需性 |
|---|---|---|---|
| 表头 | 单据身份 | `返库单号` 或 `数据ID(不可修改)`；`返库日期`、`返库类别`、`返库类型`、`返库备件/整机` | 稳定身份必需；其余缺失进入异常清单 |
| 表头 | 维保关联 | `维保销售订单`、`维保需求单(备件)` 或 `维保需求单`、`项目名称`、`项目经理`、`维保需求人` | 至少有可追溯的订单/需求关联 |
| 表头 | 后续交接 | `关联退货通知单`、`退返入库通知单`、`已生成返库子流程`、`返库单流程结束` | 有值则保留 |
| 明细 | 明细身份 | `备件明细.数据ID(不可修改)`、`备件明细.序号` | 可用时优先 |
| 明细 | 实物与数量 | `备件明细.备件PN`、`备件明细.备件SN号`、`备件明细.备件自贴码`、`备件明细.返库数量` | PN 和数量必需；SN/自贴码按品类规则 |
| 明细 | 检测与位置 | `备件明细.备件测试结果`、`备件明细.入库仓库`、`备件明细.入库库位` | 返还动作可为空，正式恢复库存不能为空 |

### 4.3 枚举与影响

- `返库类别` 已验证值：`销售退货`、`维保返件`、`委外返库`、`其他返库`。
- `返库类型` 已验证值：`租赁退回`、`其他退回`。
- `返库备件/整机` 已验证值：`备件`、`整机`。
- 备件/整机测试结果已验证值：`成品`、`坏品`、`废品`。
- 库存影响：退货返库单不恢复可用库存；它只触发退返入库通知和仓库检测交接。
- 成本影响：不得仅凭返库数量自动冲回项目成本；生效节点、检测条件和计价规则待财务与仓储确认。

### 6.3 费用生效边界

1. `报销金额`、`核销备用金`、`借款金额`、`待核销金额`、`核销金额`和`实付金额`描述不同资金事实，不能全部相加，也不能在没有财务确认时任选一列作为正式项目费用。
2. 表头金额按 `费用单号` 去重；费用类别分析按报销明细逐行汇总。不得把重复在每个明细行上的表头金额重复累加，也不得把表头总额和明细合计再次相加。
3. `流程状态`决定费用何时具备正式成本资格，但有效状态集合尚待财务确认。未知或未确认状态只能保存证据，不能进入已确认项目费用。
4. 当前明确的日期只有`报销日期`。若核算需要费用实际发生月份，必须新增或确认费用发生日期，不能静默用创建时间或报销日期替代。
5. `收款账户`、人员、客户、附件和图片地址是敏感信息；导入实现必须按权限和用途最小化暴露。

| 发货/出库单 | 出库单号 | 维保需求单、维保/销售订单 | PN/SN；原始明细键保留 | 来源库转在途；不直接增加前置库 | 提供已发出备件成本证据 |
| 退货返库单 | 返库单号；窄表用稳定来源记录 ID | 维保需求单、维保销售订单、退返通知 | PN/SN；原始明细键保留 | 不直接恢复可用库存 | 不直接冲回成本 |
| 入库单 | 入库单号 | 退返通知、维保需求、采购/销售订单 | PN/SN；原始明细键保留 | 合格且正式入库后恢复相应库存 | 提供入库及计价证据，避免重复相加 |
| 费用报销支付单 | 费用单号 | 维保销售订单或销售订单 | 费用类别；原始明细键保留 | 无 | 按财务确认金额、状态和日期计入项目费用 |

`维保需求单 → 发货/出库单 → 现场收货确认 → 领用/消耗 → 退货返库单 → 退返入库通知 → 入库单` 是实物流转链。采购、入库与出库金额是同一备件成本的多环节证据；费用报销是备件以外的独立成本来源。

## 8. 待确认及实现验收门

### 8.1 待确认

1. 项目主档稳定编号，以及销售订单、维保订单、补充/续签/变更单到项目的映射；
2. 项目现场收货确认的载体和差异处理规则；
3. PN 与 SN 管理边界，以及现场领用/消耗单的正式字段；
4. 备件成本计价来源、返还合格入库后的成本冲回时点和价格；
5. 费用报销正式计入金额、有效流程状态和费用归属日期；
6. 窄版退货返库导出缺少稳定单号/记录 ID 时的来源侧治理方式。

### 8.2 导入实现必须满足

- 通过业务字段名和受控别名识别，不依赖列序；两种退货返库宽度都可解析，可选列缺失不误拒。
- 单号重复导入幂等；冲突同号失败关闭；表头金额按单号去重，明细按 PN 或费用类别汇总且不放大。
- 未知枚举、缺失关键身份、金额口径未确认和关联不唯一均进入可审计异常，不自动补值或生成经营结论。
- 导入权限、文件大小、公式/外链、压缩包和敏感字段均有安全门；失败不会留下半导入数据。
- 测试只使用合成数据，不把真实业务行、客户、供应商、账户、人员、附件地址或工作簿提交到仓库。
