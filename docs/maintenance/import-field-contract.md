## 1. 契约范围

目前核对的五种导出结构对应四类业务对象：

| 业务对象 | 已核对的导出结构 | 表头宽度 | 表头/明细 | 主要作用 |
|---|---:|---:|---|---|
| 入库单 | 1 种 | 155 字段 | 单据表头 + 备件/整机明细 | 记录采购或返还件经检测后的正式入库 |
| 发货/出库单 | 1 种 | 166 字段 | 单据表头 + 备件/整机明细 | 记录仓库实际发出并进入在途的实物 |
| 费用报销支付单 | 1 种 | 43 字段 | 报销单表头 + 报销明细 | 归集备件以外的项目支出证据 |
| 退货返库单 | 2 种 | 49 / 120 字段 | 单据表头 + 备件/整机明细 | 记录项目或业务发起返还的动作 |

两种退货返库导出只是字段宽度不同，业务对象相同。导入器必须允许可选列缺失，不能仅因“49 列”或“120 列”决定业务语义，也不能要求窄表虚构宽表才有的字段。

## 2. 所有工作簿的统一解析规则

### 2.1 表头识别

1. 第 1 行是氚云内部字段编码，只保留为来源追踪信息；第 2 行是业务字段名，是本契约的匹配基础。
2. 导入按“规范业务字段名 + 受控别名”匹配，不按固定列序号。新增、删除或移动可选列不得造成错列导入。
3. 匹配前可以统一全半角标点、首尾空白，并移除字段名末尾的 `(必填)` 标记；不得改变字段的业务含义。
4. `备件明细.`、`报销明细.` 等前缀用于区分表头和子表，同名字段不得跨层自动合并。
5. 未识别列应记录字段名和数量后跳过；同一规范字段命中多个列、关键标识缺失或表头结构无法判定时必须失败关闭，不能选择“看起来最像”的列。

### 2.2 数据保真与去重

- 原始字段值与规范化结果分开保存。单号、PN、SN、记录 ID、订单关联等标识字段按文本读取，不把前导零、长编号或科学计数法当作数值改写。
- 表头是一张单据，明细是一对多子表。工作簿重复展示的表头字段要按业务单号去重后统计一次，不能随明细行重复累加。
- 表头业务主键优先使用单号；明细优先使用不可修改的明细记录 ID，缺失时使用“单号 + 明细序号”。不得只用 PN 或费用类别作为明细唯一键。
- 同一文件内同号且表头关键事实冲突、同一明细键内容冲突时必须报错；跨批次重导应幂等更新或忽略完全相同记录。
- 明细按 PN、SN 或费用类别汇总是统计行为，不改变原始明细主键和追溯关系。

### 2.3 空值、枚举和敏感字段

- 空列与列缺失是两种状态：可选列缺失记为 `not_provided`，存在但为空记为 `blank`；必需身份字段缺失或为空时拒绝该单据。
- 已验证枚举只接受本文列出的原值或经版本控制的别名；未知值进入异常清单，不能静默归到“其他”。
- 人员、客户、供应商、收款账户、附件和图片地址均为敏感字段。契约只定义字段，不在仓库保存真实值、样例行、附件、截图或导出的 Excel 文件。

### 2.4 库存与成本总原则

```text
项目合同总额 = 截至 as_of 当前项目关联且明确纳入统计的全部合同金额之和
项目当前成本 = 现场领用备件的已取价成本 + 审批完成报销的已确认计入金额
项目成本率 = 项目当前成本 / 项目合同总额
```

维保需求、采购、入库和出库是同一备件成本的关联证据，不能重复相加。出库只表示进入在途，退货返库只表示返还动作；只有现场收货确认才能增加项目前置库，只有返还件完成检测、仓库、库位登记并正式入库后才能恢复可用库存。首版退货和返还入库均不冲减项目成本；任何成本缺失保持空值并标注，不能按 0 处理。

- 表头业务主键：`出库单号`。

- `出库备件/整机` 已验证值：`备件`、`整机`；多个校验字段使用 `是` / `否`。
- 库存影响：仓库发出后从来源库存进入在途；在没有现场收货确认前，不增加项目前置库库存。
- 成本影响：成本单价和金额是备件成本证据，不与采购或入库金额再次相加；成本缺失时保持 `incomplete`。

## 4. 退货返库单

### 4.1 两种导出结构的兼容规则

49 字段窄表包含返库类别、类型、日期、项目/订单/需求关联、PN/SN、测试结果、数量和通知关联等核心事实。120 字段宽表在此基础上增加表头记录 ID、返库单号、明细记录 ID/序号、更多库存位置、对象 ID 和整机字段。

- 读取共同字段时使用同一规范名。
- 宽表专有字段均为条件可选；窄表不因缺少这些列而失败。
- 宽表存在 `返库单号` 时以它为表头业务主键；不存在时仅可使用来源系统不可修改的稳定记录 ID。两者都没有时必须进入异常清单，不能用客户、日期、PN 拼出伪主键。
- 明细优先使用 `备件明细.数据ID(不可修改)`；缺失时使用“稳定表头键 + `备件明细.序号`”。窄表无法形成稳定明细键时只能作为待治理事实，不得静默覆盖既有记录。

### 4.2 最小字段

| 层级 | 用途 | 规范业务字段 | 必需性 |
|---|---|---|---|
| 表头 | 单据身份 | `返库单号` 或 `数据ID(不可修改)`；`返库日期`、`返库类别`、`返库类型`、`返库备件/整机` | 稳定身份必需；其余缺失进入异常清单 |
| 表头 | 维保关联 | `维保销售订单`、`维保需求单(备件)` 或 `维保需求单`、`项目名称`、`项目经理`、`维保需求人` | 至少有可追溯的订单/需求关联 |
| 表头 | 后续交接 | `关联退货通知单`、`退返入库通知单`、`已生成返库子流程`、`返库单流程结束` | 有值则保留 |
| 明细 | 明细身份 | `备件明细.数据ID(不可修改)`、`备件明细.序号` | 可用时优先 |
| 明细 | 实物与数量 | `备件明细.备件PN`、`备件明细.备件SN号`、`备件明细.备件自贴码`、`备件明细.返库数量` | PN 和数量必需；SN/自贴码按品类规则 |
| 明细 | 检测与位置 | `备件明细.备件测试结果`、`备件明细.入库仓库`、`备件明细.入库库位` | 返还动作可为空，正式恢复库存不能为空 |

### 4.3 枚举与影响

- `返库类别` 已验证值：`销售退货`、`维保返件`、`委外返库`、`其他返库`。
- `返库类型` 已验证值：`租赁退回`、`其他退回`。
- `返库备件/整机` 已验证值：`备件`、`整机`。
- 备件/整机测试结果已验证值：`成品`、`坏品`、`废品`。
- 库存影响：退货返库单不恢复可用库存；它只触发退返入库通知和仓库检测交接。
- 成本影响：首版不因返库数量、检测结果或正式入库冲回项目成本；保留原始事实供未来规则使用。

### 6.3 费用生效边界

1. `报销金额`、`核销备用金`、`借款金额`、`待核销金额`、`核销金额`、`实付金额`和明细金额描述不同资金事实。用户只确认“审批完成”这一状态门，尚未确认正式计入金额列；在样板锁定前不得任选一列或互相相加。
2. 表头金额按 `费用单号` 去重；费用类别分析按报销明细逐行汇总。不得把重复在每个明细行上的表头金额重复累加，也不得把表头总额和明细合计再次相加。
3. `流程状态`决定费用何时具备正式成本资格，只有审批完成状态进入项目费用。实现前必须从真实样板锁定精确原值和受控别名；未知或近似状态只能保存证据，不能进入已确认项目费用。
4. 当前明确的日期只有`报销日期`。若核算需要费用实际发生月份，必须新增或确认费用发生日期，不能静默用创建时间或报销日期替代。
5. `收款账户`、人员、客户、附件和图片地址是敏感信息；导入实现必须按权限和用途最小化暴露。

## 7. 项目工作台新增数据契约

本节记录 2026-08-08 已确认的目标业务规则。由于尚未提供回款全量表和现场领用单的去敏样板，以下规范字段是系统契约，不声称已经核对来源侧真实表头；导入适配器只能在样板核对后添加受控别名。

### 7.1 项目、合同与回款全量表

| 对象 | 最小规范字段 | 主键与关联 | 业务影响 |
|---|---|---|---|
| 项目 | `project_id`、`project_code`、`project_name`、`project_manager_id`、`status` | `project_id` 是稳定主键；名称只用于展示和候选匹配 | 聚合合同、回款、领用、费用和系统待办 |
| 项目合同关系 | `project_contract_id`、`project_id`、`contract_id`、`contract_no`、`contract_amount`、`contract_status`、`included_in_total`、`effective_from`、`effective_to` | 关系行使用稳定 ID；同一合同重复关系幂等 | 截至 `as_of` 明确纳入统计且处于生效区间的合同金额求和，页面逐份标注 |
| 回款事实 | `collection_id`、`project_id`、`contract_id`、`collection_date`、`collection_amount`、`receipt_reference`、`status`、`remark` | 已有行以稳定 ID 定位；新行以 `export_id + client_row_id` 幂等创建 | 已确认累计回款进入回款进度；冲销、退款或未确认状态不计入 |

回款工作簿采用全量往返：项目经理下载当前全量表，在 `01_总览` Sheet 的固定 `tbl_collections` 回款明细表尾追加新记录后上传整本文件；同页固定 `tbl_project_contracts` 合同清单只读。下载范围可以是一个项目或有权限的全量范围，两个表必须使用同一 `scope + as_of`。

以下属于安全实现建议，需要在全量往返实现 Issue 中单独验收：每个可写行包含 `操作`、`__entity_id`、`__base_version`、`__row_token` 和 `__client_row_id`；隐藏元数据包含协议版本、`export_id`、范围、版本、导出时间、签名和 `as_of`。原样回填应为零业务事实变更；删除 Excel 行不得直接删除系统事实；上传前应返回差异预览；签名、版本、关键字段或金额错误应整本零写入并保留审计。

合同进入总额的规范判定为 `included_in_total = true` 且 `effective_from <= as_of < effective_to`；`effective_to` 为空表示持续生效。来源合同状态必须经版本化映射生成 `included_in_total`，不得从展示文本临时猜测。来源状态未映射、计入合同金额缺失、同合同重复关系冲突或同合同跨项目冲突时，项目合同总额为 `null` 并返回完整性原因。

### 7.2 现场领用单

| 层级 | 用途 | 最小规范字段 | 必需性 |
|---|---|---|---|
| 表头 | 单据身份 | `issue_no`、`issue_date`、`status` | 必需；只接受已确认且未作废的领用事实进入成本 |
| 表头 | 项目关联 | `project_id`；来源仅有项目名/订单时保留原值并进入待关联 | 正式计成本必须唯一关联项目 |
| 表头 | 责任与位置 | `issued_by`、`received_by`、`site_location` | 有值则保留；人员姓名不作主键 |
| 明细 | 明细身份 | `issue_line_id`；后备为 `issue_no + line_no` | 必须形成稳定明细键 |
| 明细 | 实物与数量 | `pn`、`sn`、`quantity` | PN 和正数量必需；SN 按品类规则 |
| 明细 | 关联证据 | `maintenance_demand_id`、`outbound_line_id`、`purchase_line_id` | 有值则保留；直接采购取价只接受稳定关联 |

有效现场领用明细的成本取价瀑布固定为：

```text
稳定关联采购单价
→ 同 PN、领用日前后 7 天有效采购的数量加权价
→ 同 PN、领用日前后 7 天有效销售的数量加权价（销售估算）
→ 成本留空并标记待补
```

加权公式为 `Σ(单价 × 数量) / Σ数量`。每次命中保存来源类型、来源行或样本集合、样本数、窗口起止日和计算版本。零价、负数、零数量、无效/作废订单、打包占位 PN 和已确认源错误不得成为样本。销售加权只能标记为估算；成本留空时下游显示 `已知成本率 ≥ X%`，不得把空值转成 0。

### 7.3 系统待办

已确认边界是待办只能由系统规则生成，用户不能手工创建业务待办。以下字段和生命周期属于实现建议，需在待办实现 Issue 中单独确认：`task_id`、`rule_code`、`project_id`、`source_type`、`source_id`、`reporting_period`、`severity`、`assignee_id`、`due_at`、`status`、`evidence`、`resolution_note`、`detected_at` 和 `resolved_at`。

- 建议唯一键为 `rule_code + project_id + source_id + reporting_period`，持续问题更新原任务而不重复生成。
- 建议首批规则覆盖月度全量表逾期、上传校验/版本冲突、项目关联失败、领用成本缺失、成本率黄色/红色阈值、关键字段缺失和已审批报销未关联项目。
- 接收、转派、处理说明、系统复核、自动关闭和忽略原因均未确认，不得提前写成已上线或已确认流程。

### 7.4 项目读模型与四表导出

项目总览、备件消耗、报销、待办和工作簿导出使用同一读模型。同一 `project_id + filter + as_of` 下，页面与工作簿的金额、行数、状态、缺失标记和预警必须一致。

四个可见 Sheet 固定为 `01_总览`、`02_备件消耗`、`03_报销单`、`04_项目经理追踪与提醒`；`01_总览` 固定包含只读 `tbl_project_contracts` 和可在表尾追加的 `tbl_collections`。可以额外包含隐藏字典、版本、行签名和元数据 Sheet。下载前必须预览项目范围、`as_of`、筛选条件、四表行数及成本缺失数量。

成本率小于 80% 为正常，达到 80% 且不超过 100% 为黄色，超过 100% 为红色报警。总览不使用成本构成扇形图；成本缺失行保持可见并提供带上下文的补录入口。

## 8. 关联链与影响矩阵

| 对象 | 首选单据主键 | 维保关联键 | 明细汇总键 | 库存影响 | 成本影响 |
|---|---|---|---|---|---|
| 发货/出库单 | 出库单号 | 维保需求单、维保/销售订单 | PN/SN；原始明细键保留 | 来源库转在途；不直接增加前置库 | 提供已发出备件成本证据 |
| 退货返库单 | 返库单号；窄表用稳定来源记录 ID | 维保需求单、维保销售订单、退返通知 | PN/SN；原始明细键保留 | 不直接恢复可用库存 | 不直接冲回成本 |
| 入库单 | 入库单号 | 退返通知、维保需求、采购/销售订单 | PN/SN；原始明细键保留 | 合格且正式入库后恢复相应库存 | 提供入库及计价证据，避免重复相加 |
| 费用报销支付单 | 费用单号 | 维保销售订单或销售订单 | 费用类别；原始明细键保留 | 无 | 审批完成后具备计入资格；正式金额列待样板确认 |
| 现场领用单 | 领用单号 | 稳定项目 ID；需求、出库、采购明细为证据 | PN/SN；原始明细键保留 | 项目前置库转实际消耗 | 逐行执行已确认取价瀑布 |
| 回款事实 | 回款稳定 ID | 合同 ID 与稳定项目 ID | 回款日期；原始行保留 | 无 | 进入已确认累计回款，不进入成本 |

`维保需求单 → 发货/出库单 → 现场收货确认 → 领用/消耗 → 退货返库单 → 退返入库通知 → 入库单` 是实物流转链。采购、入库与出库金额是同一备件成本的多环节证据；费用报销是备件以外的独立成本来源。

## 9. 待确认及实现验收门

### 9.1 待确认

1. 项目主档稳定编号，以及销售订单、维保订单、补充/续签/变更单到项目的映射；
2. 项目现场收货确认的载体和差异处理规则；
3. PN 与 SN 管理边界，以及现场领用单的真实表头、有效状态和稳定明细 ID；
4. 回款全量表的真实表头、确认状态、每月截止日和更正权限；
5. 费用报销审批完成的精确状态原值、正式计入金额列、项目关联键和费用归属日期；
6. 窄版退货返库导出缺少稳定单号/记录 ID 时的来源侧治理方式。

### 9.2 导入实现必须满足

- 通过业务字段名和受控别名识别，不依赖列序；两种退货返库宽度都可解析，可选列缺失不误拒。
- 单号重复导入幂等；冲突同号失败关闭；表头金额按单号去重，明细按 PN 或费用类别汇总且不放大。
- 未知枚举、缺失关键身份、金额口径未确认和关联不唯一均进入可审计异常，不自动补值或生成经营结论。
- 回款全量表实现前必须另建实现 Issue，确认稳定行 ID、版本、签名、删行、更正、冲突和事务边界；这些安全建议未确认前不得开放往返写入。
- 现场领用逐行取价可解释；前后 7 天边界、数量权重、采购优先、销售估算和无成本留空均有行为测试。
- 页面与四表导出按相同 `project_id + filter + as_of` 逐项对账；黄色/红色阈值和缺失成本下限语义一致。
- 导入权限、文件大小、公式/外链、压缩包和敏感字段均有安全门；失败不会留下半导入数据。
- 测试只使用合成数据，不把真实业务行、客户、供应商、账户、人员、附件地址或工作簿提交到仓库。
