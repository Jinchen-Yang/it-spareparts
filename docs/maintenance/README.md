# 维保业务文档

这里是 IT_data 维保业务的文档入口。业务目标是把合同履约、备件流转、项目费用和维保负责人待办串成可追溯闭环：维保负责人发起需求，仓库发货，现场确认收货和领用，返还件经检测入库后恢复库存；项目当前成本汇总现场领用备件的已取价成本，以及审批完成且金额口径已确认的项目费用。

> **权威规则**：合并到 GitHub `main` 的[维保业务运行手册](./business-handbook.md)是正式业务口径。会议原始记录、聊天记录和字段分析只作为来源，不是另一份可编辑真相。任何口径变更都必须经 Issue 和 PR 审查后进入 `main`。

## 一屏业务主干

| 维度 | 说明 |
|---|---|
| 主要角色 | 维保负责人、销售经理、现场人员、仓库、采购、财务、管理层；外部审核 Agent 回传补库逐条结论；坏件维修由独立维修子公司承接 |
| 库存范围 | 公司主库、地区共享库、项目客户现场前置库；其他项目前置库不作为日常可调资源 |
| 核心流转 | 维保备件需求 → 发货/出库 → 在途 → 项目收货确认 → 前置库 → 领用/消耗 → 返库 → 检测入库 |
| 成本原则 | `项目当前成本 = 现场领用备件的已取价成本 + 审批完成报销的已确认计入金额`；缺失成本留空，报销金额列未确认前失败关闭，需求、采购、入库、出库证据不重复相加 |
| 系统边界 | 本手册同时说明目标流程、当前能力与待确认项；目标流程不等于已经上线 |

## 下一阶段开发

维保前端业务化重构由 [#128](https://github.com/Jinchen-Yang/it-spareparts/issues/128) 统一规划，依赖图见 [业务工作台重构计划](../superpowers/plans/2026-08-12-maintenance-business-workbench.md)。主要包括：

- 可折叠导航与正式路由
- 维保需求单按项目负责人隔离
- 待办与项目工作流 UX 重构
- 采购链展示
- 氚云项目同步
- 全角色验收

补库 Beta 与稳定版共用同一后端和数据库，但使用独立表、独立 API、独立页面、独立权限和独立服务端总闸。稳定版仍为默认入口；关闭 Beta 只拒绝 Beta 业务访问，不删除 Beta 历史，也不改变稳定版库存、成本或维保逻辑。首批只允许稳定版、已绑定至少一个有效项目的只读维保 Beta 账号，以及角色为 `sales` 且经独立 canary 的补库创建账号；正式迁移与成本/库存切换明确排除。

## 同步与治理

1. 业务口径修改：先建或更新 GitHub Issue，再以文档 PR 修改本手册；未确认内容不得写成事实。
2. 实现规格：必须链接本手册的对应章节和 GitHub Issue，不能把聊天记录或旧会议纪要作为最终需求。
3. 图表维护：Mermaid 代码块是图的源文件，不并行维护手工 PNG；确需对外展示时再从 Mermaid 生成静态图。
4. 评审要求：业务一致性审查确认对象、状态和责任边界；文档工程审查确认链接、Markdown、隐私和可维护性。
5. 来源治理：原始记录可以留在受控资料区供追溯，但不得复制进仓库，也不得与 `main` 手册形成双份真相。
