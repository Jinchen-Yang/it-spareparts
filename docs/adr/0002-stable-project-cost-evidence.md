# ADR-0002：稳定项目成本证据与“项目已计成本”语义

- 状态：已接受
- 日期：2026-08-09
- 范围：稳定项目经营工作台、四表工作簿、项目提醒

## 背景

稳定项目需要把合同、回款、现场领用、审批报销和项目经理追踪放在同一个工作台中。现场实际消耗只能由已确认现场领用证明，但领用行的采购价格证据并不总是齐全。业务允许在采购证据缺失时使用销售记录估算价格，同时要求页面、接口、工作簿和提醒都不能把这种估算伪装成采购实际成本。

既有合同级毛利流程使用三个月互通池和历史价格瀑布。它解决的是另一类维保出库补价问题，不能直接成为稳定项目工作台的成本规则。

## 决策

### 1. 数量事实

只有同时满足以下条件的现场领用行才计入稳定项目的实际领用数量：

1. 来源维保单已经归属到稳定项目；
2. 单据状态已经明确映射为“已确认”；
3. 领用日期不晚于查询截止日。

需求、采购、入库、普通出库、状态未映射、待确认和已作废记录均不得替代现场实际领用数量。

### 2. 单价证据瀑布

每条符合条件的现场领用行按固定顺序取价：

```text
可明确关联的采购单价
→ 领用日前后 7 天采购记录按数量加权
→ 领用日前后 7 天销售记录按数量加权
→ 留空并进入人工回填
```

采购和销售样本都必须保留来源单据、样本窗口、样本数量、价格口径和算法版本。销售回退的证据类型固定为“销售估算”，不能降级显示为普通已取价。

### 3. 进度与预警

稳定项目页面使用“项目已计成本”，不使用会暗示全部价格均已核实的“项目实际成本”。计算口径为：

```text
项目已计成本 = 已确认现场实际领用的已计成本 + 审批完成报销
成本进度 = 项目已计成本（含税） ÷ 全部合同额（含税）
```

销售回退估算可以进入已计成本和成本进度，但接口必须返回估算金额、估算行数、是否包含估算及口径标识；页面、工作簿和提醒必须显示“销售回退估算”。成本进度超过 80% 且不超过 100% 标黄，超过 100% 标红；精确 80% 不预警。缺少价格的领用行不按零计价，继续单独提示补价。首版退货不冲减成本。

### 4. 重新取价与审计

后到的更强价格证据可以更新当前成本，同一证据层级的样本集合发生变化也可以重算。每次实际变化必须追加不可覆盖的审计记录，至少包含：

- 变化前的金额、来源和样本；
- 变化后的金额、来源和样本；
- 变更原因与操作者；
- 业务截止日（`as_of`）和算法版本。

较弱证据不得覆盖较强证据；没有实际变化时不新增审计。人工补价只接管当前缺价行，后续若出现瀑布中的可追溯证据，可以在完整审计下更新当前值。

“不可覆盖”同时由服务与数据库保证：业务服务只追加审计行；数据库拒绝对既有项目经营审计行执行 `UPDATE` 或 `DELETE`。运维清库使用的整表 `TRUNCATE` 不属于业务写路径，仍只允许在隔离测试库或经单独审批的数据销毁流程中执行。

### 5. 对外契约与兼容

- 项目目录与项目工作台返回同一份成本汇总语义；新增字段显式披露销售估算。
- 现场领用明细返回证据类型、是否估算和用户可读来源标签。
- 无成本权限时，估算金额、估算行数、是否含估算、证据类型和来源标签一并置空，避免侧信道泄露。
- 四表工作簿保持既有列顺序和签名协议，以保证原样导回仍为零业务变更；通过“成本完整性”和“成本来源”两列明确区分采购 / 人工确认与销售回退估算。
- 为兼容已经接入的客户端，旧成本金额字段暂时保留为别名；新页面和新文案以“已计成本”及显式估算字段为权威口径。

## 后果

好处是数量事实与价格证据被清楚分开：现场确实领用了多少不受价格缺失影响，价格是否为估算也不会被隐藏。成本预警可以覆盖更多项目，同时保留估算风险和审计追溯。

代价是销售样本或更强采购证据到达后，当前已计成本可能变化；使用方必须读取证据标识，不能只缓存单一金额。旧合同级毛利流程和稳定项目工作台仍保留两套明确边界，后续若要统一必须另立决策并完成数据迁移与验收。

## 不在本决策范围

- 真实项目映射与历史数据迁移；
- 生产部署和生产数据验收；
- 退货冲减、合同内收入分摊；
- 修改既有合同级九表往返协议。
