# ADR 0002：历史维保单只允许人工归属稳定项目

- 状态：Accepted
- 日期：2026-08-09

## 背景

历史维保单只保存上传时的项目文字。同一文字可能对应不同项目，同一项目也可能在不同时期改名，因此文字标准化只能帮助人工搜索，不能承担项目身份。

## 决策

1. 来源单以 `f_maintenance_order.raw_order_id` 识别，稳定项目以 `maintenance_project.project_id` 识别。
2. 两者之间使用独立、版本化的人工关系；每张来源单同一时刻最多一个 active 关系。
3. 首次归属、改派和撤销均要求实名高权限账号、显式原因和乐观版本。批量请求整体成功或整体回滚。
4. 已归属于目标项目的来源单按当前状态幂等返回：无期望值的首次请求重放，或携带当前归属 ID/版本的重试，都不新建关系、不追加审计；过期或不匹配的期望值仍整批冲突。
5. 改派和撤销归档旧关系并追加审计快照，不执行 `DELETE`；关系代次由数据库触发器限制为只可从 active 归档。
6. 名称搜索不触发自动归属。历史名称相同的来源单可以人工归到不同项目。
7. 重导相同 `raw_order_id` 继续按既有 ETL 规则同步来源事实，同时保留人工关系的 ID、版本和目标项目。
8. 项目详情只展示 active 人工归属数量及明细入口；该关系不进入合同、成本、报销或毛利计算。

## 结果

业务人员可以逐张消化历史单据，并能还原每次归属变化。系统同时避免把项目名漂移误判成项目合并，也避免归属操作暗中改变财务口径。
