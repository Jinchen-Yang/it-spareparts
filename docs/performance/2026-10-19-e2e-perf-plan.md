# 2026-10-19 e2e 性能与并发修复方案

决策: 无

基线：`origin/main@54efe9d55be2e908ce2a2f0182d1e4c57df8afad`。范围限定维保逐单导出、请求数据库超时、型号排名以及由测量确认的混合负载热点；不改产品日期默认值、业务事实、访问日志、前端或密钥配置。

## 编码前检查

- 用户/场景：误触全量导出与多人同时使用查询页面。既有导出已分批读库、write-only XLSX、临时文件和64 KiB响应块；仍需完整物化ZIP后才开始下载。优先减少CPU和读库开销，保留无筛选全量、显式宽范围、无日期订单、权限、稳定升序、源数据共享锁和既有容量保护。
- 业务/边界：D-33要求完整筛选集且不静默截断；排名金额、负值、未知成本、双榜、分页和权限口径保持。销售员/客户真实聚合在 `/api/profit?dimension=salesperson|customer`，`sales/analytics/orders`没有分组参数。
- 技术/假设：排名在分页前给所有PN计算价格分位数和Python金额字段；目标HTTP处理器都是同步def，由线程池执行，尚无事件循环阻塞证据。数据库池10+20、默认等待30秒、请求没有SQL超时；不能仅凭池参数认定需要扩池。将用HTTP、分段计时及pg_stat_activity核实。

## 实现与验证路径

1. 使用 `scripts/measure_e2e_performance.py`，同一副本、token文件、12并发、六类只读请求各4次；另测各端点单请求3次和全量导出，报告p50/p95/max、503/504和传输错误。原始响应与token不落报告。
2. 请求Session每个事务开始时 `SET LOCAL statement_timeout`；超时先rollback，返回504；连接池等待有界，返回503。不影响后台Session与已有更短的校准超时。
3. 排名先确定双榜/页内PN，再批量补充价格统计与池归属；用真实PG验证输出等价和SQL范围。
4. 导出分别测SQL、行渲染、ZIP压缩；仅减少ORM/Cell构造仍需78秒，因此采用XlsxWriter constant_memory写入器，缩窄查询列，并在单次导出内复用权限掩码、按值类型调用公开写入API。保留有界内存、空白金额格式、公式转义、临时文件清理及日期422、宽范围全量、权限、锁和异常清理契约。
5. 所有pytest连接任务专属容器，由conftest每进程再建独立数据库，不访问共享5433。第一台 `itsp-perf-pytest-20261019-01`（localhost:32862）的overlayfs并行清理遇到checkpoint等待，验证改用tmpfs的 `itsp-perf-pytest-20261019-02`（localhost:32863），最终增量再使用同配置的 `itsp-perf-pytest-20261019-03`（localhost:32864），启动时关闭fsync/synchronous_commit/full_page_writes；只用于一次性合成测试。
6. 仅替换e2e应用，保留停止的原应用容器；记录网络/IP和精确恢复步骤。e2e数据库只允许本分支必要迁移DDL。实现后独立审查、相关测试、相同HTTP脚本复测，中文提交并PR至main，不合并/部署生产。

## 决策记录

采用保留全量导出契约方案；拒绝在性能PR默认缩短日期或静默裁数据。暂不增加池容量或索引，除非测量证据支持。独立审查与最终观测记录见交接文档。
