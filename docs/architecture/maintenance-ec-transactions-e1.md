## 接口与调用链

- 独立 HTTP 上传 → 当前权限/项目范围 → `apply_and_commit` → EC 事实及审计 → 有变化时递增一次版本 → commit。
- 总表 V1/V2 → 既有锁序及当前权限 → `apply_in_transaction` → EC 事实及审计 → 总表统一版本、回执及 commit。
- 旧 `apply` 是兼容入口，保留已有参数组合与返回形状；业务实现唯一，实际生产调用迁移到上述两个入口。

两入口共享无提交的事实核心。嵌套入口必须传入调用方已锁定的同项目 state，返回命名结果（回执、事实是否变化），不再往回执塞内部布尔键。
嵌套入口不创建 savepoint、不 commit、不 rollback、不递增项目版本；失败由外层整本回滚。
独立入口保持既有异常契约，HTTP 的失败处理及 Session 生命周期仍负责回滚；不改变锁、审计或税率。
旧兼容入口允许原来四种 commit/bump_revision 组合，不将未迁移外部调用静默改变为某一种模式。

| 名称 | 类型 | 用途 / 定义原因 |
| --- | --- | --- |
| `WorkbookApplyResult` | frozen dataclass | 将内部变更信号和 HTTP 回执分开；不是深冻结承诺 |
| `receipt` | dict | 保留当前公开响应字段，含作废优先的行级回执 |
| `operating_fact_changed` | bool | 交给真实提交所有者决定是否递增版本 |
| `workbook_state` | MaintenanceProjectWorkbookState | 保持 state → project → facts 的既有锁序和单次版本递增 |

## 核验设计

真实 PostgreSQL 检查独立提交的跨 Session 可见性、嵌套未提交不可见及整本回滚、无变化不递增、兼容参数矩阵；保留 HTTP、总表 V1/V2、单调性、作废优先、重放、并发竞争既有契约。
