## 核验范围和判断方法

按用户 2026-10-23 最新更正，固定核验窗口为 **2026-10-08 12:02:46 UTC 至 2026-10-23 12:02:46 UTC**。这是本次研究快照；实施各批次前须重新核对滚动近 15 天及本次之后的新更正。

代码基线为 main `7a9fd2098acb6be0009a59a84e7d7330bb960d6b`；第一阶段候选 #451 为 `fa97e2490f480336e29f51c84bfdaac3ee4f12fe`。**main 确定代码现状，不独占最新业务口径**：已记录明确裁定但尚未合入的决策也要检查；同时区分已确认目标、设计建议、待决事项和暂停实施。

采用以下证据顺序：

1. 用户当前明确更正，以及近期同一事项更晚的明确修订。
2. 近 15 天决策文件、契约、协作规则的实质新增/修改及其明确承接的具体旧条款；按适用范围使用。
3. 当前代码和测试仅证明实现行为，供兼容比较，不自动成为业务授权。
4. 窗口前文件、memory、归档和旧 PR 仅作定位背景；未近期重申不等于已撤销，但不能压过新口径或成为新的永久约束。

检查使用提交 diff、关键条款 blame、分支可达关系及 PR 当前状态。文件新建、整份搬入、最近编辑或最近被引用，都不等于全文重新确认。以下“已确认”指决策文件明确记录的状态；未独立取得所有来源会话原文。PR 只用于定位文件和核对集成状态，不以 PR 描述反推业务裁定。

外部 GitHub/社群的一手工程资料用于设计方法，不能决定业务。较早发表的渐进重构方法不因本窗口而失效，也无权给旧业务规则续期。

## 对实施批次的具体影响

- **R0**：每批同时列“近期目标、当前实现、差距、待决事项”，包含与该批相关的未合分支；暂停状态是实施状态，不抹除已记录裁定，也不自动授予恢复施工的权限。
- **R1/R2**：先做不依赖争议的结构提取；测试分别标明近期有效契约和当前兼容观察。与新明确口径冲突的旧断言不能压过新口径，纠偏独立审查。
- **R3/W1/W2**：工作簿当前完整回执、合单、现有锁写者，以及尚未集成的 Q1/Q3 目标必须同时可表达；只搬现有类型可以单独推进，但不能因此宣称最终扩展协议已经完整。
- **F1**：D-25/35/37、D-33、D-0024、D-0025 各自范围清楚；不统一掉不同排序、单位、金额和登记人语义。
- **后续恢复能力**：完整恢复是一条有独立快照、权限、锁、幂等和反向审计的命令；不是通用 `restore` 布尔值，也不是导入时自动复活。待决细节解决后再安排实施批次。

本次后端、前端、Agent/工程规则三个代理分别追溯并由根代理交叉核对；复核导致三项实质修正：不按整份文件更新时间续认旧口径、纳入未合分支上的近期目标、区分 AI 业务写红线的近期重申与工具目录兼容事实。没有访问生产、执行历史转换或恢复暂停的实施队列。
