# F2：工作簿入口的下载与上传能力

决策: D-33、D-03。基线为已验收 F1 `6840c5a47cc3089e8cffba1011195818e6eb68aa`；依赖 F1 的已提交异步上下文，不修改后端权限或事务。根代理已核实当前 main 仍为 `7a9fd209`。

规则复核日期：2026-10-24，滚动窗口为 2026-10-09 至 2026-10-24。D-33 在窗口内明确续存 D-03 的金额资格；旧 zcode 文档对销售的宽泛表述不覆盖这项明确续存。窗口内未发现改变本批权限的后续决定。

## 本批边界

当前首页只看上传 action，下载无条件显示；项目面板把裸 action 与服务端编辑资格做 OR。两个入口因此可能显示服务端会拒绝的操作。六个实际 WorkbookRoundTrip 调用点共同需要独立的下载与上传能力。

D-33（2026-10-15）明确延续 D-03 金额资格。有效 `data_profit` 按后端 `permissions.runtime_safe` 同时要求 `data_purchase_cost`；采购成本可见本身不授予合同金额或工作簿权限。本人项目负责人的工作簿例外由服务端 `can_edit_master_workbook` 下发，不通过本地角色、姓名或负责人原文推算。销售仍要求有效利润键。

| 用途 | 下载 | 上传 |
| --- | --- | --- |
| 首页全项目备件行工作簿 | 页面权限 + 有效利润权限 | 下载资格 + EC 上传 action |
| 项目总表及四个 tab 的单 sheet | 已加载项目 + 页面权限 +（有效利润权限或服务端编辑资格） | 已加载项目 + 页面权限 + 服务端编辑资格 |
| 管理员 | 常规页面/数据/action 保留后端绕过 | 项目仍须加载成功；服务端明确拒绝不被本地 action 覆盖 |

项目稳定详情和展示板卡片使用同一个服务端编辑判定。任一显式 false 优先于 true，分歧时等待刷新收敛，不猜测哪份响应更晚代表业务权限；两者都缺字段才为旧载荷保留页面 + 有效利润 + 上传 action 的兼容。详情读取失败时不沿用旧资格，展示板 404 不丢失已成功取得的详情资格。项目面板 key 包含项目、token、角色及权限快照，变化后通过既有加载链重新取得资格；不会直接用本地 action=false 否定负责人例外。首页工作簿也按权限快照重建，范围变化而能力布尔值不变时，旧文件与弹窗仍失效。

## 实现

在现有 maintenancePermissions 模块增加用途明确的纯能力解析器和本地快照适配器，不复用旧 Roundtrip/Beta 权限，不引入通用 canViewMoney。首页和项目面板解析能力；四个单 sheet 组件只接收结果。WorkbookRoundTrip 显式接收 canDownload/canUpload，并在操作入口、异步落地及弹窗生命周期使用对应能力。

下载世代纳入 canDownload；权限撤销使在途 Blob、旧回调和错误反馈失效。上传同时要求下载资格；任一资格撤销关闭预检/冲突弹窗、清空文件草稿，旧确认回调不可写入。权限恢复创建新世代，不能复活撤销前的下载或预检。

组件在发请求和接收结果时还直接比对当前权限快照，覆盖 localStorage 已变化但父组件尚未重绘的间隙。单次挂载拥有初始权限快照；旧操作 finally 导致的子组件重绘不能拿旧能力 props 接管新权限。调用方按权限快照重建后才接受新的能力。
