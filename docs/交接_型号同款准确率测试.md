# 交接：型号「是否同款」AI 准确率测试

> 给本地 Claude Code 的接力说明。你不需要看过之前的对话——这份 + 脚本 + 设计文档就够了。
> 目标一句话：**在写整套 PN 治理 Agent 之前，先用几百对真实样本量出"AI 判同款准不准"，
> 尤其是错合率，用这个数决定自动化能放权到哪一步。**

## 背景（为什么先做这个）

我们在做一个「PN 标准化/合并 Agent」（设计见 `docs/PN标准化Agent设计方案.md`，PR #7）。
它要替人干的核心判断是：**两个写法相近的型号，是不是同一个实物商品？** 是 → 合并/标准化；
不是 → 放过。整套自动化能不能成立，全压在这个判断的准确率上。

现有的 `part_resolver` 只能算"文本像不像"，像 ≠ 是同一个（最典型：V100 16G 和 32G 型号
只差一点点，但是两个东西，错合会静默污染成本和报价）。所以**先别建大系统，先量准确率**：
让 AI 判几百对，人工核对，算出"AI 说同款其实不是"的比例（错合率）。这个数是后续给
Agent 设自动合并门槛（设计文档第四节 L1/L2）的依据。

本次交付的就是这个测试工具：`backend/scripts/pn_match_eval.py`（判定 prompt 在脚本顶部，
要调就改 `SYSTEM_PROMPT`）。**这份是这台云端机器写的，没在真库上跑过**（云端没有真数据/
DS 钥匙），所以由你在本地真库 + DS v4 上实测。

## 前置条件（你本地应已具备）

- `.env` 的 `DATABASE_URL` 指向**装好真实数据**的库（已导入两万多型号）。
- `.env` 配好 `LLM_API_KEY` / `LLM_BASE_URL`（DeepSeek）/ `LLM_MODEL`（v4）。
  思考模式由脚本强制开启（`extra_body={"thinking":{"type":"enabled"}}`），**不依赖** `.env`
  里的 `LLM_EXTRA_BODY`。
- 依赖已装（`openpyxl`/`openai`/`sqlalchemy`/`psycopg` 都在 backend 现有依赖里）。

## 怎么跑（都在 `backend/` 目录下）

```bash
# 1) 自测脚本本身有没有写坏（不连库、不花钱）
uv run python scripts/pn_match_eval.py selftest

# 2) 先空跑看采样质量（连库、但不调 AI、不花钱）：检查捞出来的候选对像不像样
uv run python scripts/pn_match_eval.py sample --dry-run --limit 300 --out pn_eval_pairs.xlsx

# 3) 真跑：调 DS v4 思考模式逐对判定（花 token，300 对约几分钟～十几分钟）
uv run python scripts/pn_match_eval.py sample --limit 300 --out pn_eval.xlsx

# 4) 人工核对：在 pn_eval.xlsx 的「★人工判定」列填
#    same / different / uncertain / not_a_single_part（有下拉）
#    —— 重点抽查 AI 判 same 的那些行，看是不是真同款 ——

# 5) 算分
uv run python scripts/pn_match_eval.py score --in pn_eval.xlsx
```

可调参数：`--source-kind all`（默认 `needs_review`，即只从待审型号取样；想覆盖全量改 all）、
`--min-score`（初筛相似度下限，默认 0.45）、`--per-source`（每个源最多取几个候选，默认 2）。
脚本会按相似度 high/mid/low 三档**均衡采样**，避免只测到容易的对、把准确率虚高。

## 输出看什么（最重要）

`score` 会打印一份指标，重点三个：

1. **★错合率（AI 判 same 却不是）**——命门。AI 说"同款"的里头，其实不是同款的比例。
   这个数高 → 绝不能让 AI 自动合并，只能出建议给人审；够低 → 才有资格谈自动合并。
2. **same 召回率**——真同款里 AI 抓出来多少。低说明 AI 太保守（漏合多，但漏合代价小）。
3. **AI 判 uncertain 占比**——它"拿不准"扔回人工的比例，反映人最终还要看多少。

## 跑完请回传

- `score` 打印的整段指标 JSON；
- 10～20 个 **AI 和人工判定不一致**的例子（直接从 xlsx 拷那几行）——尤其错合的（AI=same
  人工≠same）和漏判的（人工=same AI=different）。

我们据此定 Agent 的自动合并门槛、要不要加联网取证、以及哪些情形必须留人工
（对应设计文档第四节的 L0/L1/L2 分级）。

## 注意事项

- 这是**只靠记录字段 + 模型自身知识**的判定（DS 思考模式只推理、不联网）。这正是我们要先
  量的基线："光看这些信息 AI 判得多准"。联网取证是验证完这步之后的下一步。
- 脚本只读库、不写库（除 resolver 内部可能记一条 search_miss 审计日志），对真库安全。
- 想改判定逻辑就改脚本顶部的 `SYSTEM_PROMPT`，重跑即可对比。
