## 研究依据

PostgreSQL 默认 Read Committed 中，单条 SELECT 看到的是该语句开始时的快照；同一事务内的下一条查询仍可能看到其他事务新提交的数据。因此只把多次查询包在普通事务中并不能保证图表一致。新统计读模型将规范事实和分组汇总放在一条 SQL 内；权限查询不作为另一个业务总计来源。参见 [PostgreSQL 事务隔离文档](https://www.postgresql.org/docs/15/transaction-iso.html)。

图形事件需要携带业务实体身份，不能由屏幕标签反推；图形还需要文本、键盘入口和数值信息，颜色不能独自承担身份或数值表达。研究了 [ECharts 事件模型](https://echarts.apache.org/handbook/en/concepts/event/) 与 [无障碍指南](https://echarts.apache.org/handbook/en/best-practices/aria/)。本次正式组件可采用原生按钮、SVG 和表格实现同等交互，不新增可执行 HTML tooltip。

隔离的本地完整系统采用明确标注的构造验收数据，通过真实登录验证：三种视图可见，PN 条形 → 项目分析定位 → 原筛选返回；热力格点击另一 PN 时定位点击项且返回保持原项；无成本/无客户账号的指标和客户入口受限，仍能查看有权项目的实际领用定位，相关 API 全部 200，没有调用现场领用操作查询。390px 移动视口页面 scrollWidth=390，图表内部滚动不撑开页面。开发截图保留在本机 `output/playwright/`，不作为测试环境人工验收的替代。

新服务模块通过 stdin 在生产应用容器内临时加载到内存，数据库会话明确为 `REPEATABLE READ, READ ONLY`，语句超时 10 秒；没有替换运行文件、重启服务或写业务数据。与同一只读事务中的旧 PN 排名服务对照：

| 范围 | 领用 / 需求净量 / 含税成本 / 返还总量 | 新服务耗时 | 响应大小 |
| --- | --- | ---: | ---: |
| 全量 | 四项一致 | 2,063 ms | 38,734 bytes |
| 本年 | 四项一致 | 1,502 ms | 49,642 bytes |
| 近 12 月 | 四项一致 | 1,388 ms | 50,114 bytes |

全量 SQL `EXPLAIN ANALYZE`：规划 14.119 ms、执行 1,064.389 ms、内部聚合 15,959 组；命中缓存块 19,323、磁盘读取块 0。以上是当前数据量的一次只读抽样，不代表压力测试或延迟保证；数据量增长后需再次测量。内部去重订单 ID 不返回浏览器。

累计贡献由 Decimal 先求累计值再一次除以全集，避免逐行四舍五入后累加偏离 100%。Top 10 卡片固定表示前十项份额，与图形 Top N 控件分别标注；未知尾项不覆盖前面有效的累计份额。

保留的既有筛选语义：`cost_source=missing` 按明细记录的成本来源标记筛选，人工覆盖存在时不严格等同于「当前成本不可用」。新缺价明细指标使用规范化成本质量判定。页面明确说明两者区别，本次未重新定义旧来源分类。
