## 二、目标与非目标

**目标**：老板/管理员打开一个页面，就能回答：

1. 今天 / 昨天 / 任意区间卖了多少单、多少钱，比上一个同长区间多还是少？
2. 钱来自哪些客户、哪些客户类型、哪些销售、哪些业务类型、哪些商品大类？谁排第一、头部集中到什么程度？
3. 每天 / 每周 / 每月怎么走？哪天异常高或异常低？
4. 订单金额主要落在哪个区间？大单（例如 ≥10 万）有多少、是谁的？
5. 任一数字都能点进去，一路钻到订单和明细行；所有视图都能升序 / 降序，都能导出。

**非目标（本轮不做）**：

- 不改老板看板 `/dashboard/*` 与 `REVENUE_BUSINESS_TYPES` 口径（D-41 已定）。
- 不做预测、目标/配额完成率（没有目标数据源）、不做库存支撑判断（D-41 已排除）。
- 不新增导入列、不做任何写操作（AGENTS.md §6 红线）。
- 不对受限销售（`own_customers_only`）开放（沿用现有 403 硬界）。
- 采购、维保看板按同一底座后续再做，本文只覆盖销售。

## 三、页面设计

沿用 `/sales/analytics` 与页面键 `page_sales_analysis`（**待拍板 Q1**），把单页改成“公共筛选栏 + 五个 Tab”。所有状态继续写 URL（`analyticsUrlState` 规则），可分享、可刷新、可后退。

```
┌ 销售分析 ─────────────────────────────────────────────────────────┐
│ [今天|昨天|前天|7天|15天|30天|半年|一年|全部|自定义]  对比:[上期▾]   │
│ 业务类型▾ 客户▾ 客户类型▾ 销售▾ 商品大类▾ 品牌▾ 金额区间[  ~  ]      │
│ 金额口径:[不含税✓ 含税订单金额✓ 营收✓]          [重置] [导出]       │
├───────────────────────────────────────────────────────────────────┤
│ 概览 │ 分组排行 │ 趋势 │ 金额区间 │ 订单明细                        │
└───────────────────────────────────────────────────────────────────┘
```

### 3.1 公共筛选栏（所有 Tab 共享）

| 控件 | 说明 | 相对现状 |
|---|---|---|
| 日期预设 | 沿用 D-41 §5（默认今天）；“昨天”“前天”已有 | 不变 |
| 对比期 | 无 / 上一同长区间（默认）/ 去年同期 | **新增**（Q6） |
| 业务类型 | 多选，D-41 §4 原值 | 不变 |
| 客户 | 改为**多选**，带搜索（服务端 `options` 接口按关键字补全，返回 `customer_id`） | 单值模糊 → 多选精确（Q2/Q11） |
| 客户类型 | 多选，原值，空值显示「未填」 | **新增**（Q2） |
| 销售人员 | 改为**多选**，候选取已生效单去重值 | 单值模糊 → 多选精确 |
| 商品大类 / 品牌 | 多选；**一旦选中进入行级口径**（只计匹配明细行，见 §4.2） | **新增**（Q5） |
| 金额区间 | 订单金额下限 / 上限（闭区间，按当前排序口径） | **新增**（Q3） |
| 金额口径 | 三金额多选并排（D-41 §2） | 不变 |

点任一图表元素 = 把该值加进对应筛选（例：点“客户 A”柱 → 客户筛选 = A，并切到订单明细 Tab），面包屑显示已带入的下钻条件，可逐个撤销。

### 3.2 Tab「概览」

- **KPI 卡**：销售单数、三金额合计（随口径多选）、成交客户数、销售人数、单均金额（= 合计 ÷ 单数，按排序口径）、明细行数；`amount_inc_tax` 缺失单数照现有做法单独提示。
- 每张卡下方显示**对比期**数值与增减（↑12.3% / ↓5.0%，同时带正负号文字，不只靠红绿）；对比期无数据显示「—」，不显示 0% 或 ∞。
- **迷你趋势**：区间 ≤ 31 天按日、否则按月的小柱图。
- **三个 Top 5 小榜**：客户、销售、业务类型（点“更多”跳分组排行 Tab）。
- **毛利卡**（需 `data_profit`，D-44 §5）：毛利、毛利率、成本覆盖率，与老板看板 KPI 同口径。
- 回款卡本轮不做（D-44 §6：销售订单回款导入尚未适配）。

### 3.3 Tab「分组排行」（对应“按客户分类、按销售分类”）

- **分组维度**（单选）：客户、客户类型、客户城市、客户来源、销售人员、业务类型、仓库、商品大类、品牌、PN（后三项行级）。
- **二级拆分**（可选）：例如“销售人员 × 业务类型”，以堆叠横条展示，表格中可展开。
- **指标列**：单数、三金额合计、金额占比、累计占比（帕累托）、单均金额、毛利与毛利率（需 `data_profit`）、客户数（非客户维时）、明细行数、对比期增减。
- **排序**：任一指标列**升序 / 降序**切换；并列按分组键升序破并列（确定序，分页可复现）。
- **Top N**：10 / 20 / 50 / 全部；其余合并为“其他（N 组）”一行，合计 = 总计，不丢钱。
- **图**：横向条形图（复用 `HorizontalMetricBar` 的版式与约定：null 剔除并注明、柱端标签带金额）+ 下方完整表格。
- **集中度提示**：Top 1 / Top 5 / Top 10 金额占比，一行文字。
- 点某组 → 该组的订单明细（筛选带入）。

### 3.4 Tab「趋势」（对应“按时间”）

- **粒度**：日 / 周（周一起）/ 月，按所选区间自动推荐（≤31 天日、≤半年周、否则月），可手动切换。
- **指标**：三金额（柱）+ 单数（折线，右轴）；可切换“金额 / 单数 / 单均”。
- **按维度拆系列**（可选）：业务类型、客户类型、销售人员 Top 5 + 其他，堆叠柱。
- **对比期**：叠一条虚线（上期或去年同期，按相对位置对齐：第 1 天对第 1 天）。
- 空桶补零还是断开：**金额为 0 的桶显示 0（确实没成交）**，与“无数据 = null”区分；区间内每个桶都要出现，不能跳过没单的日子。
- **星期分布**（附图）：周一到周日各自的单数/金额，看哪天出单集中。
- 点某根柱 → 日期筛选收窄到该桶，切订单明细 Tab。

### 3.5 Tab「金额区间」（对应“能看价格区间”）

D-44 §3：价格区间 = **订单金额区间**，金额区间筛选默认不限（全部金额）；本轮不做明细单价区间。分档口径与默认档位待确认（D-44 待确认 Q3 补充）。

1. **订单金额分布**（单头）：按所选口径把每张单分档。默认档位
   `<1千 / 1千–5千 / 5千–1万 / 1万–5万 / 5万–10万 / 10万–50万 / 50万–100万 / ≥100万`，可自定义档位边界（URL 可分享）。每档显示：单数、单数占比、金额合计、金额占比——一眼看出“单子多的档”和“钱多的档”往往不是同一档。
2. ~~明细单价分布~~（D-44 §3：本轮不做）。

- 金额为空的单（例如含税订单金额缺失）单列“无金额”一档，不并入最低档。
- 负金额（退货/冲销类单）单列“负数”一档（Q9）。
- 点某档 → 订单明细按该档金额区间筛选。

### 3.6 Tab「订单明细」（现大单列表升级）

- 排序：三金额、订单日期、客户、销售人员任一列**升序 / 降序**（Q4）；空值无论升降都沉底。
- 订单抽屉增加**明细行**：PN、描述、大类、品牌、数量、含税单价、行金额、营收；毛利按 D-44 §5 随 `data_profit` 展示。
- 现有对账块、含/不含退货开关不变（D-40）。
- **导出 CSV**：按当前筛选与排序导出订单（上限 10,000 行，超出提示收窄区间）；导出走与页面同一接口与同一脱敏，写访问日志。

## 四、口径设计（建议值，拍板后入 D-44）

### 4.1 订单范围与日期

完全沿用 D-41：已生效（`query_filters.active_orders`）、`order_date` 闭区间、默认今天、不排除未来日期。**对比期**：上一同长区间 = `[from − 天数, from − 1]`；去年同期 = 两端各减一年（2-29 落到 2-28）。“全部”预设不提供对比期。

### 4.2 单头口径 vs 行级口径（与 D-39 §5 同一范式）

- **单头口径**（默认）：一张单一行；三金额取单头（`amount_ex_tax`、`amount_inc_tax`）与订单内营收合计——与现有 `summary`/`orders` 完全同源，保证“分组合计 = KPI 合计 = 列表合计”。
- **行级口径**（选了商品大类/品牌筛选，或按大类/品牌/PN 分组）：订单拆成明细行，只计匹配行。行级没有单头那三列，金额定义为：
  - 含税 = `line_amount`（为空时 `qty × unit_price`）；
  - 不含税 = 含税 ÷ 1.13（CONTEXT：销售 `unit_price` 恒含税，未税侧为名义值，页面标注「名义（按 13% 推算）」）；
  - 营收 = 匹配且 `counts_revenue` 行的 `revenue_amount` 之和（与单头口径的营收一致，可加）。
  - 单数 = 含匹配行的去重订单数；一张单可同时计入多个大类，因此**行级分组的单数之和可以大于总单数**，页面在表头注明。
- 页面上方用一个徽标显示当前处于「单头口径」还是「行级口径」，避免两种数混看。

### 4.3 分组键

- 客户按 `customer_id` 分组，显示 `name_normalized`（**Q11**：同一 `name_normalized` 对应多个 `customer_id` 时是否合并）。
- 客户类型、来源、城市、销售人员、业务类型、仓库、大类、品牌均取原值，不做映射；空值统一显示「未填」，作为一组参与排行，不丢弃。
- 销售人员是原文字符串，不做别名合并（拼写不一致会分成两组；如需合并另开主数据决策）。

### 4.4 排序

- 所有列表、排行、区间表都支持升 / 降序；`NULLS LAST` 固定（升降都沉底），再按键 / `id` 破并列。
- 金额被遮蔽（无 `data_purchase_cost`）时：按金额排序回退到按单数排序并在页面提示——沿用 `orders` 的 `sort` 回退与 D-39 组序保护，**防止用行序反推被遮蔽的金额排名**。

### 4.5 权限与脱敏（不新增权限键）

| 场景 | 处理（均沿用现有机制） |
|---|---|
| 页面准入 | `page_sales_analysis`；受限销售 403（`_guards`） |
| 不含税 / 含税金额 | `data_purchase_cost` 组遮蔽（现状如此，本方案不改分组）；新增的合计、占比、单均、区间金额键全部登记到 `config.FIELD_GROUPS` 同组 |
| 客户 | 无 `data_customer` 时：不能按客户筛选/分组（403，现有先例）；客户类型/城市/来源分组**是否同样禁止**（Q10） |
| 对账 | 订单明细现有对账块不变（D-40）；回款卡本轮不做（D-44 §6） |
| 毛利 | D-44 §5：走 `data_profit` 组，新增键登记 `FIELD_GROUPS`；无权限不能按毛利排序（`ranking_restricted`） |
| 金额区间分布 | 金额被遮蔽时档位表只给单数，金额与金额占比置 null；档位边界是用户输入，不泄漏 |

## 五、接口设计（全部只读，挂在 `/api/sales/analytics` 下）

公共筛选参数（所有端点同一套，后端抽一个 `SalesAnalyticsFilter` 依赖统一解析与校验）：
`date_from, date_to, business_type[], customer_id[], customer_type[], salesperson[], category[], brand[], amount_min, amount_max, amount_basis`。现有 `customer` / `salesperson` 模糊参数保留一个版本做兼容，前端切换后移除。

| 端点 | 说明 | 新/改 |
|---|---|---|
| `GET /options` | 增加客户类型、销售人员、大类、品牌候选；客户按 `customer_q` 关键字补全（最多 50 条） | 改 |
| `GET /summary` | 增加 `customers`、`salespeople`、`avg_order_*`、`lines`；`compare=prev|yoy` 时并返回 `compare_kpi` | 改 |
| `GET /groups` | `group_by`、`split_by?`、`sort`、`order=asc|desc`、`top`；返回 groups + `other` + `concentration` | 新 |
| `GET /trend` | `granularity=day|week|month`、`series_by?`、`compare?`；返回完整桶序列（无单的桶也出现） | 新 |
| `GET /amount-bands` | `basis`、`edges[]`（订单金额分档，D-44 §3）；返回各档 + 无金额档 + 负数档（后两档待 Q9） | 新 |
| `GET /orders` | `sort` 扩到 `order_date|customer|salesperson`，新增 `order=asc|desc` 与全部公共筛选 | 改 |
| `GET /orders/{id}` | 增加 `lines[]`（明细行） | 改 |
| `GET /orders/export` | CSV，同筛选同排序同脱敏，≤10,000 行 | 新 |

实现要点：

- 所有聚合复用 `_order_query` 的同一基查询（单头口径）或新增 `_line_query`（行级口径），**不另起 SQL 口径**；分组/趋势/区间都是在同一子查询上再 `GROUP BY`，用测试锁住“各分组合计 = summary 合计”。
- 趋势用 `generate_series` 生成完整日期桶再 LEFT JOIN，周按 ISO 周一。
- 性能：单头口径走现有 `ix_so_status_date` / `ix_so_status_btype`；行级口径走 `ix_sl_order`。区间“全部”在万级订单规模下预计百毫秒级，PR 内附 `EXPLAIN ANALYZE` 对拍（`docs/performance/` 格式）；如超 1s 再考虑物化日汇总表（另开决策，本轮不建表）。
- 前端图表一律走 `components/charts` 底座（ECharts 6.1.0 按需注册、`chartTheme` 取色、`EChartContainer` 壳、null ≠ 0 约定），新增 `SalesTrendChart`、`GroupRankBar`（基于 `HorizontalMetricBar`）、`AmountBandChart` 三个组件，各带 option builder 纯函数单测。

## 八、验收口径（拍板后写入 D-44）

1. 任一筛选组合下：KPI 合计 = 分组排行各组合计（含“其他”）= 趋势各桶合计 = 金额区间各档合计 = 订单明细合计（单头口径）。
2. 所选区间按客户 / 销售 / 业务类型的前 20 组与只读 SQL 一致（±0.01）。
3. 升序 / 降序翻页不丢行、不重行。
4. 权限矩阵：admin/boss 可见；sales/purchaser/readonly 403；关闭 `data_purchase_cost` 时金额全为“—”且排序退回单数；关闭 `data_reconciliation` 时无回款卡。
5. 今天 / 昨天 / 自定义三种区间在跨零点后不沿用旧日期（沿用现有 `todayKey` 机制）。
