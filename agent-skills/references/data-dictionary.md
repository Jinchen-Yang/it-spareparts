# 数据口径与术语字典

所有 skill 共用的口径定义。数值参数以主仓库 `backend/app/config.py` 为准，本文标注默认值。

## 价格口径

| 术语 | 定义 | 注意 |
|---|---|---|
| **近期成交参考价** `ref_sale_price` | 近 `REF_PRICE_MAX_N`（默认 5）条且 `REF_PRICE_DAYS`（默认 30）天内的成交价，按名次线性加权（最近权重最高），已削单笔异常价 | 销售出价的**主参考**。`ref_sale_samples` 很小时必须明说"近期成交少，仅供参考"。**系统不算"建议售价/底线价"，加价由销售自己把握** |
| **近 N 天采购价窗口** | 近 `RECENT_PURCHASE_DAYS`（默认 15）天采购的 均价/最低/最高/笔数 | 只取**计入成本的采购类型**（与成本口径一致，排除维保等）。窗口内无采购时用最近一次采购价，并标注"非15天内，最近 X 于 Y" |
| **近 90 天均售价** `avg_sale_price_90d` | 近 90 天销售单价简单平均 | 辅助参考，受批量/客户结构影响大 |
| **历史询价区间** | f_part_inquiry 的历史询价高低 | 是"问过的价"，不是成交价 |

## 成本与利润口径

- **两种成本法并行**：移动加权平均 与 FIFO，全景和利润排名都同时给出，回答时**必须标注口径**。
- **毛利率 = (售价 − 成本) / 售价**；销售单价为**含税**口径；金额一律人民币元，库内 NUMERIC 定点数。
- 成本为 null 或样本极少 → 明说"成本数据不全，仅供参考"，不要硬算毛利。
- 负毛利等异常数据如实说，并提醒可能是成本错配（如采购类型/口径问题），不要替数据圆谎。

## 商品身份与 PN（主数据整改后的关键口径）

- **商品身份 = `dim_part.id`（part_id）**。一切业务汇总（利润/库存/价格历史）按 part_id，
  事实行上的 `pn_std`/`pn_raw` 只是"导入时归一痕迹"，禁止作过滤/聚合键。
- **pn_std**：标准化型号文本（去氚云 V 码 token 等），dim_part 上唯一。
- **别名 `part_alias`**：同一商品的历史/变体写法 → part_id 映射；94% 的型号有恒等别名。
- **合并与重定向**：重复型号合并后，旧 PN 成"墓碑"（status=merged），查询沿 `merged_into`
  链自动重定向（链长恒 ≤1），工具返回 `redirected_from`。**凡见到 redirected_from 都要告诉用户**
  "你查的 X 已合并到 Y，以下数据属于 Y"。
- **候选标注**：
  - `PN待复核` = 录入不规范（含空格歧义 PN 等），价格可用但要提醒复核；
  - `已治理排除`（is_excluded）= 打包/非标型号，其价格**仅供参考**，必须提醒。

## 库存口径

- 库存 = PN × 仓库快照；**源系统数量 `source_qty` 每次导入覆盖**，人工修正在独立列
  `manual_qty + is_qty_overridden`，两者并存可追溯。
- 同一 part 在同仓可能多行（合并后保留源 pn 行），part 级库存 = SUM，行级带 `pn_std` 标注来源。
- **销售速率 `sales_velocity`**：近 90 天出货节奏，配合库存合计可算"还能卖多久"。

## 角色与可见性（详见 security-compliance skill）

| 角色 | 可见 |
|---|---|
| admin / 管理层 | 全量 |
| 采购 | 全量行情 + 采购数据 |
| 销售 | 匿名化行情 + **自己客户**的成交；同事客户显示为"（其他客户）"；禁用按销售员/客户的利润排名 |

## 常用术语

- **准系统**：barebone，不含 CPU/内存/盘的整机底座（如 超微 4029GP-TRT）。
- **整机拆解 / BOM**：把一台服务器配置拆成可询价的部件清单。
- **氚云**：上游业务系统，采购/销售/库存三类 Excel 的来源；"数据ID(不可修改)"是导入幂等键。
- **替代料 `part_substitute`**：可互替型号对，方向 both / a_to_b / b_to_a；采购谈判筹码、缺货替代依据。
