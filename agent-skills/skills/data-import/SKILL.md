# 氚云数据导入与清洗答疑

## 业务背景

系统数据来自氚云导出的三类 Excel：**采购订单 / 销售订单 / 产品库存**。
导入在 Web 管理端完成；本 skill 让助手能回答导入规则、排查导入问题。
（用户把氚云导出件发给助手查价是另一回事——那走 [inquiry-batch](../inquiry-batch/SKILL.md)。）

## 导入规则（答疑依据）

| 规则 | 内容 |
|---|---|
| 文件格式 | 仅 `.xlsx`；旧 `.xls` 需在 Excel 里另存为 `.xlsx`（这是最高频问题） |
| 类型识别 | 按列名特征自动判定三类，无需手选 |
| 双表头 | 自动跳过氚云的 `F+7位数字` 编码行，识别中文列名 |
| 续行 ffill | 多明细订单中主表字段为空的续行，自动补齐到所属订单 |
| 幂等 | 幂等键 = 氚云"数据ID(不可修改)"。**重复导入同一批数据不会产生重复记录**，会按数据ID更新 |
| PN 标准化 | 氚云内部 V 码 token（V+10位以上字母数字）自动识别截断；含空格的歧义 PN 保留原值并标"PN待复核" |
| 金额 | 浮点毛刺自动修正（79.0999… → 79.10），库内定点数；税率统一成小数（13.0% / 0.13 → 0.1300） |
| 库存口径 | 以氚云真实数量为准（source_qty）**每次导入覆盖**；人工修正在独立列保留，不会被导入冲掉 |
| 导入后自动治理 | 自动回填品牌/品类/别名/规格、质量扫描——导入后治理指标回升是正常现象 |
| 审计 | 每批导入有批次与错误记录；人工操作全部进审计日志 |

## 典型排查

### "导入后数字和氚云对不上"

按口径排查顺序引导：
1. 时间范围一致吗（导入的是哪几批）；
2. 利润口径：系统按 part_id 聚合 + 两种成本法，氚云报表口径可能不同；
3. 排除集：被治理排除（is_excluded）的打包/非标型号不计入部分统计；
4. 库存：看的是 source_qty 还是人工修正值。
仍对不上 → 建议查导入批次的错误记录（哪些行被跳过及原因）。

### "有些行被跳过了"

常见原因：缺幂等键（数据ID 列空）、金额/日期解析失败、空行。
错误记录里有逐行原因；修复源文件后重导即可（幂等，不会重复）。

### "导错了能撤吗"

导入本身幂等可重导覆盖；没有"撤销一批"按钮。
人工修正类（库存修正/排除/替代料）都有审计日志可追溯回改。

## 边界

- 🔴 助手无导入执行工具——导入在 Web 管理端操作，这里只答疑和排查。
- 涉及"为什么这个 PN 变成了那个"→ 先看 V 码截断和别名（本 skill），
  再看合并重定向（转 [master-data-governance](../master-data-governance/SKILL.md)）。
