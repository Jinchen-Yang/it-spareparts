# 经营分析

## 触发

- "谁卖得多 / 销售排名" → `get_profit_ranking(salesperson)`
- "哪个客户毛利高 / 大客户都有谁" → `get_profit_ranking(customer)`
- "哪个型号最赚钱 / 卖得最好" → `get_profit_ranking(part)`
- 带时间范围（"这个月""二季度"）→ `date_from`/`date_to`（YYYY-MM-DD，自己换算）

## 🔴 权限前置

销售角色调 salesperson/customer 维度会被服务端拒绝——这是防恶性竞争设计，
不解释技巧、不帮绕路，按 [security-compliance](../security-compliance/SKILL.md) 的模板回应，
可改为给型号级匿名行情。admin/管理层不受限。

## 流程

1. 选维度 + 时间范围调 `get_profit_ranking`（按营收降序，最多前 50 行；
   超过 50 行时工具会注明总行数，要转告"仅展示前 50"）。
2. 呈现，固定要求：
   - 表格 ≤10 行核心数据（名次/对象/营收/毛利/毛利率），更多的概括为"其余 N 项合计…"；
   - 🔴 **必须标注成本法口径**：两种成本法（移动加权/FIFO）毛利可能不一致，
     差异大的行要点出来（通常意味着进价波动剧烈）；
   - 给一两句洞察（头部集中度、毛利率异常者），但只基于返回数据，不外推编故事。
3. **异常数据如实说**：负毛利、毛利率 >90% 这类异常照实报告，
   并提醒"可能是成本错配/数据问题，建议核对该型号的采购记录"，不要替数据圆谎，也不要悄悄剔除。

## 常见组合问法

- "Q1 和 Q2 对比" → 两次调用（两个时间窗），对比表呈现，注明两期口径一致。
- "XX 客户都买了什么" → 排名工具不下钻到明细；客户维度只有汇总。
  如实说明，可建议按具体型号用 overview 看成交（其中该客户的单子能看到）。
- "毛利率怎么算的" → (售价 − 成本)/售价，售价含税口径、人民币；
  详见 [data-dictionary](../../references/data-dictionary.md)。
- 结果要带走 → `write_report` 出美化报表给 download_url。

## 边界

- 时间范围内无数据：如实说空，提示可能是该期间未导入数据（转 [data-import](../data-import/SKILL.md) 答疑）。
- "帮我预测下个月" → 明确说系统只有历史事实数据，可给近几期趋势，不做预测承诺。
