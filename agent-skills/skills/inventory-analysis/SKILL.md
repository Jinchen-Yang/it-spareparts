# 库存查询与滞销分析

## 触发

- "XX 还有货吗 / 在哪个仓 / 有几个" — 单型号库存
- "这个还能卖多久 / 要不要补货" — 周转判断（补多少 → 转 [procurement-pricing](../procurement-pricing/SKILL.md)）
- "哪些货压着不动 / 呆滞料 / 库存值多少钱" — 滞销与库存价值分析

## 单型号库存查询

1. 按 [part-identify](../part-identify/SKILL.md) 解析型号。
2. `get_part_overview` → 报分仓明细 + 合计。
3. 口径提醒（见 [data-dictionary](../../references/data-dictionary.md)）：
   - 同一商品同仓可能多行（PN 合并后保留源 PN 行）——报**合计**，明细里带源 PN 标注；
   - 库存有人工修正（is_qty_overridden）时如实说"系统数 X / 人工修正后 Y"；
   - 库存是导入快照，不是实时账——回答时带上口径意识（"按最近一次导入"）。

## 周转判断（"还能卖多久"）

核心算式：**可售月数 ≈ 库存合计 ÷ sales_velocity（近 90 天日均出货）**

| 信号 | 解读 |
|---|---|
| 可售 < 1 个月 且动销快 | 提示补货风险，建议看采购（转 procurement-pricing） |
| 1–6 个月 | 健康 |
| > 6 个月 或 90 天零出货 | 滞销信号，提示占用资金 = 库存 × 成本（标注成本法口径） |

sales_velocity 基于近 90 天——季节性/项目型出货会失真，数据样本小要明说。

## 滞销/库存价值分析（管理层）

当前工具没有"全库存扫描"原语，按现有能力诚实处理：

1. 用户给了范围（某品类/某几个型号）→ 逐个 overview 或 `lookup_prices_bulk` 取库存合计，
   汇总成表（型号/库存/近90天出货/可售月数/库存价值），用 `write_report` 出美化报表。
2. 用户要全库滞销榜 → 如实说当前助手没有全库扫描工具，建议走 Web 端库存查询页；
   可先用 `get_profit_ranking(part)` 找出营收头部型号逐个核查作为替代路径。
3. 库存价值必须标成本法口径（移动加权/FIFO），成本缺失的行注明"无成本数据"。

## 边界与变通

- 🔴 库存数字只来自工具返回；"应该还有货"这类推测不许说。
- 缺货但有**替代料**时主动提（"XX 没货了，可替代的 YY 还有 N 件"）——这是这套数据最值钱的联动。
- 销售角色看库存不受限（库存不是同事经营数据），但成本字段按其角色可见性返回什么就说什么。
