# 型号识别与消歧

**解析错型号 = 报错价格 = 害用户背锅。** 型号匹配宁可多确认一步。这是整个系统最容易出错的环节。

## 触发

- 任何对话里出现型号/品牌/描述文本（"super 4089RT-x 准系统"、"V100 显卡"、"金士顿 32G 内存"）。
- 新人问"XX 是什么 / 干嘛用的 / 和 YY 什么区别"。

## 流程

1. `search_parts` 用**用户原话**搜索（工具自带容错：连字符、大小写、中英品牌混写、历史别名），
   不要自己先"修正"用户的写法再搜——会丢别名召回。
2. 看结果状态分流：

| 状态 | 含义 | 动作 |
|---|---|---|
| 精确匹配（用户敲了完整 PN） | 没有歧义 | **直接干活，别啰嗦** |
| `ambiguous` 多个高分候选 | 用户说的是"系列名"，库里有多个具体规格 | 🔴 列候选差异让用户选，**禁止擅自挑一个** |
| `low_confidence` / 空 | 库里可能没有 | 换关键词重搜一次（去后缀/只留核心 token）；仍没有→如实说"库内未找到"，建议用户给更准型号 |
| 带 `redirected_from` | 旧 PN 已合并 | 正常继续，但要说明"X 已合并到 Y，以下数据属于 Y" |

3. 确认唯一型号后 → `get_part_overview` 取全景，进入对应业务 skill。

## 消歧示例（必须照此风格）

用户问"V100 显卡多少钱"，搜索返回多个高分候选：

✅ "咱们库里 V100 有好几种规格，价格差距不小，您要哪种？
① V100 PCIE 16G ② V100 32G ③ V100S 32G（更新款）④ NVLINK 接口版。客户有没有说显存和接口？"

❌ 直接挑 V100 PCIE 16G 报价（客户要的可能是 32G，价格差几千块）。

**批量场景例外**：询价单几十行时不要逐行停下来问——能唯一确定的直接处理；
ambiguous 行在备注写"需确认：候选A(16G) / 候选B(32G)"；not_found 行写"库内未找到"；
最后汇总哪些行需人工确认。这叫变通，不叫擅自决定（详见 [inquiry-batch](../inquiry-batch/SKILL.md)）。

## 解释型号（新人教学场景）

用大白话讲这是什么、用在哪：

1. 以工具返回的 描述/品牌/品类 为事实基础，结合硬件常识展开
   （如"准系统 = 不含 CPU/内存/盘的整机底座，客户买回去自己配件"）。
2. 描述为空时可以基于 PN 命名规则推断，但必须注明 **"以下是基于型号规则的推断"**。
3. 附近期成交价和库存，让新人对"这东西值多少钱、咱们有没有货"有体感。
4. 讲区别（V100 vs V100S）时，规格差异可用常识，**价格差异必须分别查库**。

## 表达约定

- 回答用中文、结论先行。
- 不复述工具内部字段名（low_confidence / score / pn_std 这类英文词），
  用自然语言："匹配度不高"、"有多个规格"、"标准型号是…"。
- 候选标注"PN待复核"= 录入不规范、"已治理排除"= 打包/非标型号价格仅供参考——都要转述提醒。
