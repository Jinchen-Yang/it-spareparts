# 询价单/清单批量处理

## 触发

- 上传了 xlsx 询价单（"帮我把价格填上"）。
- 对话里粘贴一串型号（"这几个都查一下：…"）。

## 流程（上传 Excel）

1. **`inspect_file` 看结构**。客户格式千奇百怪（标题行、空行、合并单元格、表头在第 4 行…），
   **自己判断**表头在第几行、哪列是型号、哪列是数量。拿不准就先把判断说给用户听再继续
   （"我看第 4 行是表头，B 列是型号 D 列是数量，对吗？"），而不是猜错了白干。
2. **`read_file_rows` 读完所有数据行**（行多就分页，最大 200 行/次，读完为止）。
3. **`lookup_prices_bulk` 批量查价**（一次最多 60 个，超过分批）。
4. **`write_excel` 回填**：默认基于原文件（`base_file_id`）在**右侧空列**追加，原格式不动；
   用户明确要新表才自建。追加列建议：匹配型号 / 最近采购价 / 近90天均售价 / 库存 / 备注。
   - **每个追加列都要在表头行写列名**（与原表头同一行），不许出现无名列。
   - 行处理规则（批量消歧，详见 [part-identify](../part-identify/SKILL.md)）：
     - `ok` → 直接填；
     - `ambiguous` → 备注写"需确认：候选A(16G) / 候选B(32G)"，价格列留空；
     - `not_found` → 备注写"库内未找到"；
     - 带 `redirected_from` → 匹配型号列写规范 PN，备注注明"原 PN 已合并"。
   - 🔴 **成本红线**：客户模板里原有的"单价/报价/价格"列是发给客户的——
     **绝不把内部采购价/成本填进去**。内部数据只进右侧追加列；
     客户报价列要么留空、要么按用户明示填写，并在回复里说明口径
     （完整规则见 [security-compliance](../security-compliance/SKILL.md)）。
5. **回复**：`download_url` + 汇总（共几行 / 几行已填 / 几行需确认并列出原因）+
   提醒"右侧追加列是内部参考，发客户前删除"。

## 流程（粘贴型号清单）

跳过 1-2，直接 `lookup_prices_bulk`，结果用表格回复（型号/匹配状态/最近采购价/参考成交价/库存/备注），
最后问一句要不要生成 Excel（要好看的用 write_report）。

## 边界与变通

- **一个单元格塞多个型号**（"V100 或 A100 均可"）：拆开分别查，备注里写清楚。
- **型号列里混着规格描述**（"32G DDR4 RECC 服务器内存"）：原话直接喂 lookup_prices_bulk
  （解析器对描述有召回），常返回 ambiguous——按规则进备注。
- **数量列缺失/为 0**：照常查价，备注提示"原单未给数量"。
- **超大清单（几百行）**：先告诉用户预计分几批处理，再逐批做完——不要做一半停下。
- **用户催"直接都给我挑一个填上"**：ambiguous 行可以按最高分填，但**必须**在备注标
  "自动选择：候选A（另有候选B）"且在回复里汇总列出，让人工可复核。
- 工具单行报错不中断整单：该行备注"查询失败"，其余照常，最后汇总。
